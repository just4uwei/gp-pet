# 候选参数与标定网格

这里放**候选**参数，不是出厂参数。出厂参数只有一处：[`src/core/params.ts`](../src/core/params.ts)。

按 [ADR-0003](../docs/adr/ADR-0003-来源文档数值不作为出厂默认.md)，出厂默认值必须由
[docs/07 §3](../docs/07-回测与验证方案.md) 的标定流程产出后**由人**写回，工具不自动改文件。

## 两种用法

```bash
# ① 单组候选参数跑一次回测
pnpm backtest -- --codes SH600000,SZ000001 --from 2018-01-01 --to 2026-06-30 \
              --params ./params/classic-macd.json --out ./reports/classic.json

# ② 粗网格标定：训练 / 验证 / 测试三段自动切分
#    折单元默认 4 个标的子集 × 3 个时间片；测试段默认不跑（要读才加 --touch-test）
pnpm backtest -- --codes SH600000,SZ000001 --to 2025-06-30 \
              --grid ./params/grid.example.json --out ./reports/calibration.json
```

标定模式的额外开关（都只在 `--grid` 下生效）：

| 开关 | 默认 | 作用 |
|---|---|---|
| `--code-folds <n>` | 4 | 横截面折数：标的按代码升序**轮转**分组（不是切段，否则某一折全是创业板） |
| `--time-slices <n>` | 3 | 判定窗口内的时间片数 |
| `--min-delta-t <倍>` | 2 | 可分辨门槛：\|Δ\| / 标准误 |
| `--touch-test` | 关 | 读一次测试集。**每加一次都要去 docs/07 §3 ④ 的计数里记一笔** |

折单元是从**同一次模拟**里切出来的（横截面重新合并净值、时间上切区间），
所以 `--code-folds 8 --time-slices 4` 与默认值耗时相同 —— 32 折与 12 折都不多跑一次模拟。
折数往上加的代价是**每折更薄**（标的更少、窗口更短），不是时间。

退出码：`0` = WRITE_BACK 或 KEEP（两者都是结论），`2` = INCONCLUSIVE（判不了）。
`1` 是真的失败 —— 39 只标的上偶发过无声退出（M2 §5.4 工具侧记录），**必须看退出码**。

## 文件格式

两种文件都是「**块级覆盖**」——块内整体替换，不做深合并。半个 `combine` 块比写错的参数更难发现。

- `--params <file>`：一个对象，键是 `DEFAULT_PARAMS` 的块名
- `--grid <file>`：键是块名，值是该块的**候选列表**，展开为笛卡尔积

JSON 没有注释，网格文件里也**不要**塞 `_comment` / `_label` 之类的键：
`expandGrid()` 把顶层每个键都当成一个块展开，多出来的键会静默地把网格乘大一圈。
说明写在本文件里。

| `grid-regime.json` | `adx` × `regime`（7 × 3 = 21 组） | **已跑（2026-08-13）：裁决 `KEEP`，但有正面证据** —— 4 个候选被红线淘汰、3 个显著更差（最差 `baseThreshold = 16`：−1.06pp / t 4.1），出厂 20 的两侧邻居都更差。`maxThreshold` 上侧**算术无效**别再扫。**这张网格每维只有中心 ± 一档，唯一的正向候选落在边界上不能用** —— 要加宽重跑（M2 §5.16 给了取值） |

> **同一条轴上的候选必须落在同一份报告里。** `plateauFlags()` 判「孤峰 / 该侧邻域未测」
> 是在**本次报告的候选集合**里找同轴的相邻取值 —— 把 `hysteresisDays = 1` 与 `3/4/5`
> 拆成两次跑，出厂值 2 就永远看不见它的下侧邻居，孤峰判据形同虚设。
> `grid-regime-hysteresis-wide.json` 明知 3/4/5 上一张已经跑过还是重跑一遍，就是为了这个：
> 少了它们，8 的下侧邻居就成了空的，「8 是孤峰」这条判不出来。
>
> 这也是上面三张网格按「一次只动一个块、另一个块钉在出厂值」拆开、
> 而不是照 `grid-regime.json` 做笛卡尔积的原因：**8 + 8 = 16 组能把两条轴都扫全，
> 而 8 × 8 = 64 组只是把同样的信息买贵四倍。**跨块的交互效应确实测不到了，
> 但 §5.16 那 21 组笛卡尔积里没有一处交互项大过主效应，先不为它付这个价。

`grid-mean-reversion.json` 里 `strategy` 块用的是**一次一因子**（OFAT）而不是 3×3×3 全展开：
① 全展开要跑两个多小时，而这一层的效应量本来就在噪音带附近；
② OFAT 让 docs/07 §3 的第三条红线（邻域 ±20% 是否断崖）可以直接从同一张报告里读出来 ——
每个中心点左右两侧就是它的邻居，不必再单跑一轮扰动。
`pullbackLookback`（T5，属趋势）与 `expandedBbwPct`（属风控）不在标定范围内，全组保持出厂值。

`params/mean-reversion-only.json` 是**测量用**的基线覆盖（只开均值回归），
配 `--params` 使用。`enabledStrategies` 是消融开关、不是可标定参数，
**不得**作为网格的一个维度出现（见 `src/core/params.ts` 的注释）。

## 标定的红线与判据（工具已内置，不必自己盯）

| 红线 | 行为 |
|---|---|
| 训练集交易 < 30 笔 | 直接淘汰 —— 统计上无意义 |
| 训练集 Calmar ≤ 0 | 直接淘汰，且不跑验证集 —— 验证窗口再好也只是运气（M2 §5.14） |
| 验证集年化为负 | 直接淘汰 —— 训练集表现不可信 |
| 验证集 Calmar 相对训练集衰减 > 50% | 标记为疑似过拟合，不当优胜者 |
| 邻域断崖 / 落在网格边界 | 标为「孤峰」/「该侧邻域未测」，不当优胜者（2026-08-13 起**自动判**） |
| 排名依据 | **验证集** Calmar（年化/最大回撤）。用训练集排名等于直接过拟合 |
| 写回门槛 | 逐折与出厂值配对：Δ 均值 > 0、\|Δ\|/标准误 ≥ 2、≥ 2/3 的折为正 |
| 测试集 | 默认不跑；`--touch-test` 才读，且**不允许据此回头调参** |

> **设计网格时要让预期的最优点两侧都有候选，而且出厂值那一行自己也得站得住。**
> 出厂值天然是每个 OFAT 候选的一侧邻居，于是「挑战者比出厂值好一倍以上」在形状上
> 等同于「一格之内绩效断崖」，会被判成孤峰而拿不到 `WRITE_BACK`。这不是判据写反了 ——
> §5.14 的 `voteThreshold.trend = 4` 正是被下侧邻居 3（**出厂值**）否掉的，
> 给出厂值开后门会把那次回归一起放掉。真遇到这个形状，动作是把网格加密 / 放宽，
> 找出高原从哪里开始（§5.10 对 `squeezeBbwPct` 就是这么做的）。

**报告最上面那行 `裁决` 才是结论**，不是「优胜候选」那一行：

- `WRITE_BACK` —— 有挑战者稳定优于出厂值且邻域是高原，走下面的写回流程；
- `KEEP` —— **出厂值站得住，这是结论不是失败**。同时给出「要分辨已观测到的这个 Δ
  大约需要多少折」，据此决定是扩样本还是把这个参数归档为不可标定（清单 4.9c）；
- `INCONCLUSIVE` —— 出厂值自己被红线淘汰、或折数不足，什么都不能说。

为什么要这么麻烦：这套流程 2026-08-13 之前只按「验证集 Calmar 最高」推荐参数，
跑了十一轮、二十来个参数只写回一个 —— 每一轮都是工具报出优胜者、人看表发现它是孤峰
或验证窗口友好然后否掉。判据在人脑子里，就只有人有空的那一轮能推进。见 M2 §5.15。

## 标定完一个参数的三种归档方式

**「产出出厂默认参数」不等于「每个参数都换一个新值」。** 一个参数标定完可以是三种结果，
三种都算这个参数标定**完成**了 —— 混着不分是 docs/08 那一格挂了十一轮的原因之一：

| 裁决 | 归档动作 | 例子 |
|---|---|---|
| `WRITE_BACK` | 下面的 4.9a 流程：改值 + 递增版本号 + CHANGELOG | `strategy.squeezeBbwPct` 10 → 20 |
| `KEEP`（测不出差别） | **不改值**，记「已测、保持出厂值」与依据；`ENGINE_VERSION` 不动 | `combine` 四数（§5.14 / §5.15，15 个候选最大 t = 1.4） |
| `KEEP`（**有正面证据**） | 同上，但要写明「往哪些方向动、代价多大」—— 这比上一档强一档，**别混写** | `adx.baseThreshold = 20` / `volScale = 8`（§5.16，邻居 −1.06pp / t 4.1） |
| 参数惰性 / 算术无效 | 记为「不可标定」（清单 4.9c），**不要反复重跑** —— 先用 `audit:*` 或读公式找结构原因 | `downtrendBuyPenalty` 的幅度、`revertLookback`、`adx.maxThreshold` 的上侧 |

`KEEP` 与「惰性」都**不**递增 `ENGINE_VERSION`：没有改行为，就没有要失效的缓存。
但它们都要留下记录，否则下一轮会有人把同一个网格再跑一遍。

## 写回出厂参数时要做的事

参数是**一个一个**标定完的，所以「写回」与「摘 `-unvalidated` 后缀」是两档动作，
不要合成一步（[M2 清单 4.9a / 4.9b](../docs/checklists/M2-引擎层验收.md)）。

**每标定完一个参数（4.9a）：**

1. 改 `src/core/params.ts`，在该字段注释里写清依据与失效条件
2. `params.ts` 顶部的「已标定」清单加一行
3. 递增 `ENGINE_VERSION` 的**补丁位**，**保留 `-unvalidated` 后缀**
4. CHANGELOG 记录标定依据（数据区间、标的池、优胜候选的三段绩效、什么条件下结论失效）

**整套参数都有依据之后（4.9b）：**

5. `ENGINE_VERSION` 改为 `0.3.0`，摘掉后缀
6. 删掉 `tests/unit/core/params.test.ts` 里断言该后缀存在的那条用例
   —— 删它是一个需要有意识做出的动作

> 为什么不能早摘：摘掉后缀会让回测报告不再打「参数未标定」提示
> （`src/backtest/report.ts` 的 `unvalidatedParams`、M2 清单 5.4），
> 等于用一个参数的证据给其余二十来个转述值背书。

## 诊断工具（不产出参数，产出「该不该标定这个参数」的答案）

标定之前先确认参数**有没有在起作用**。有两条参数在 2026-08-12 的标定里表现为
「取什么值结果都一样」，而根因都不是取值：

```bash
pnpm audit:regime    -- --codes ... --fixtures ./data/history --to 2026-08-11   # regime 判定的成因分解
pnpm audit:subsignals -- --codes ... --fixtures ./data/history --to 2026-08-11   # 子信号触发数与 R2 的合取项分解
```

`audit:subsignals` 会把 R2 的三项合取拆开逐项计数、统计近失与共现 ——
`revertLookback` 的惰性就是这么定位到「其中一项在 49% 的交易日上成立、
另一项的时间常数差一个量级」的（M2 §5.11）。它里面复制了一份 R2 的判定逻辑用于近失分析，
**与 `evaluate()` 的实际触发数不一致就报错退出**；报这个错说明工具与
`strategies/mean-reversion.ts` 漂移了，先修工具。
