# 迭代流程

这个 skill 解决一件事：**每次新会话不用花两小时重建上下文**。

---

## 这个系统最终要长成什么样（2026-08-17 用户确立）

**终局**：一个能协助个人资本做投资配置与自动化管理的**自动交易**个人量化软件，具备自我学习与自我进化的能力。

**当前**：验证与训练阶段 —— **不自动交易**，只在不打断工作的前提下指导用户交易、降低风险、提高预期收益。

这两句之间是**一条有门槛的阶梯，不是一句愿景**。用户的原话是「随着算法的稳定，一步步进化」，
所以「稳定」必须被定义成可检验的条件，否则下一轮会有人直接去接券商 API ——
而今天的策略在训练窗口是 **−1.99%**、红线还过不去。

| 级 | 形态 | 进入条件（**全部满足**才算达成） | 现在 |
|---|---|---|---|
| **L0** | 判定 → 提醒 → 人决策人下单 | — | ✅ **就在这里** |
| **L1** | + 成交记账闭环，执行滑移可测 | 有真实成交记录；`ledger × 影子组合` 的差值能出数（基建已有，见[差距 §1.3](../../../docs/notes/与机构量化系统的差距.md)） | 基建就绪，未用起来 |
| **L2** | + 仓位/配置建议（不只单票买卖） | ① 训练窗口 Calmar > 0（红线过得去）② `GUESS` 与 `BLOCKED` 两档清零、摘掉 `-unvalidated` ③ 有池外参照证明正 alpha | ❌ 三条都未达成 |
| **L3** | 生成订单草稿，人一键确认 | ① L2 稳定运行 ≥ 3 个月 ② 影子运行前向绩效为正且**参数未变**期间累积够长 ③ 风控在真实行情里验证过（不是回测） | ❌ |
| **L4** | 程序化下单 | ① L3 的人工否决率低到有意义 ② 券商接口 + 资金安全 + 断线/异常处置有预案 ③ 单独的风险评审 | ❌ |

**三条不因演进而放松的东西**：

1. **CLAUDE.md 的「不接券商、不下单」在 L0–L2 期间完全有效。** 到 L3 才是重新讨论它的时机，
   而那需要先把 L2 的三个条件做完 —— 不是「先接上再慢慢调」。
2. **五条不可违反的约束**（`src/core` 纯函数、参数值不是事实、零干扰、`null` 不填 0、不新增未论证指标）
   在任何一级都有效。自动化提高的是执行速度，**不降低证据标准**。
3. **越自动，错误越贵。** L0 发错提醒用户会忽略；L4 下错单是真金白银。
   所以每升一级，验证强度只能提高不能降低。

### 「自我学习自我进化」= 什么，≠ 什么

这条最容易被实现成它的反面，所以写死：

| ✅ 是 | ❌ 不是 |
|---|---|
| **前向证据累积**：影子运行按真实时间往前走 | **自动调参**：让程序/模型在同一份历史上搜出「更好的参数」 |
| **知识沉淀**：每轮实验归档到 M2，含失败与被证伪的预测 | **每天产出改进建议**（见下面「等你拍板」那一桶：日信息增量仅 **0.048%**） |
| **信源台账**：哪个数据源可靠、哪里有坑，见下 | 把回测跑更多轮当成学到了更多 |
| **判据升级**：发现旧判据测不到某维度就补新判据（如今天的池外参照缺口） | 放宽判据让候选通过 |

**进化的燃料是新数据与新信息，不是对同一份数据的反复搜索。** 后者有个名字，叫过拟合。

**这句话的可执行形式就是下面那节「学习任务」** —— 它是本 skill 里唯一一个
**主动往系统里加新信息**的动作，其余所有环节都在处理已有的那份数据。

系统分三层，只有中间一层需要每次读：

| 层 | 内容 | 什么时候读 |
|---|---|---|
| 约束层 | `CLAUDE.md` · 4 份 ADR · `docs/01`–`10` | 已在系统提示里；只在动到对应模块时深读 |
| **状态层** | **`pnpm iterate` 的输出** | **每次会话开头，必读** |
| 流程层 | `docs/07 §3.6`（改动门槛）· M2 清单 4.9（归档流程） | 真要动手时才读 |

## 第一步：永远先跑这个

```bash
pnpm iterate
```

它从**真实数据源**算出当前状态，不依赖任何手写的进度记录（那种东西会过期——
CLAUDE.md 里「`risk`/`multiTf` 一个网格都没跑过」那句挂了一整个阶段就是先例）：

- 引擎版本与 62 个叶子参数的六档归档 ← `paramRows()`，有测试钉着
- 最新回测基线 ← `reports/calib/*.json`
- **alpha 配对胜率** ← `reports/calib/random-*.json`
- 真机运行数据 ← `%APPDATA%/gp-pet/market.db`（只读打开）
- 测试集预算 ← `docs/07 §3` 那行计数
- **登记在案的落地项** ← 计划文档与差距文档里的 `<!-- ITEM ... -->` 标记
  （**条目由人登记，做没做由仓库判**，见第二步那一节与学习任务第 5 条）。
  ⚠ **登记 ≠ 承诺做**；「一条都没有」通常不是「没有待落地的东西」。

**读不到的东西它会说「读不到」，不会显示成 0。** 看到 ⚠ 就当真——
把「没测过」读成「0 次」正好反了。

想把快照写进版本控制（`reports/` 是 gitignored 的，换台机器就没了）：

```bash
pnpm iterate -- --write   # 刷新 docs/iteration/看板.md
```

## 第二步：按看板的四个桶决定做什么

看板把任务分成四桶，**它们的处理方式完全不同**：

### 「只能靠时间」——不要试图用工程绕过

M1 跑满一天、M3 自用一周、影子净值点、闸门漏斗数据。
这些没有工程替代品。看到它们**只需要确认用户知道**，不要提方案。

### 「现在就能做」——这才是可以动手的

通常是工程缺口或不一致（基线版本与引擎版本对不上、量表零数据之类）。

### 「等你拍板」——报门槛，不提候选

⚠ **这是授权边界（2026-08-15 拍板），最容易越界的地方。**

看板只说「下一轮改动的前置条件达成了没」。**候选由用户提，或在会话里讨论产生。**
不要主动生成「今天建议改 X」——每天的信息增量只有 **0.048%**
（261 只新增 1 根 ÷ 54.5 万根），一个每天产出改进建议的循环必然是在同一份数据上
反复搜索，那是过拟合的定义。

### 「明确不做」——看到就打断

比如「继续为清 `BLOCKED` 跑 OFAT 网格」。八张网格 82 组候选已经跑完，
出厂值被红线淘汰 ⇒ 裁决必为 `INCONCLUSIVE` ⇒ 产出**零证据**，不是弱证据。

### 第五节：「登记在案的落地项」——与上面四桶**来源不同**，别混

那四桶是**规则从数据推出来的**（门槛达成情况）。这一节是**人登记的条目**
（文档里的 `<!-- ITEM ... -->`），而**每条做没做由仓库判** ——
判据是「落地时必然出现的那个字符串」在不在。

- 它**不放宽授权边界**：条目是人已经论证过、已经决定要做的工程/判据项，
  看板只负责不让它们烂掉，**不负责发明它们**。
- 三组告警都要当真：**「证据显示已落地」= 去删标记**（清单只增不减就没人再看它）·
  **「判不了」= 路径写错或文件被挪走**（那是「不知道」，既不是做了也不是没做）·
  **「登记不合格」= 缺字段**，那条**没有被算进任何一组**。
- **一条都没有登记时不要默认成「没有待落地的东西」** —— 更常见的成因是
  最近几轮的学习/实验结论根本没被登记（登记纪律见学习任务那一节第 5 条）。

## 第二步半：每次迭代必答的四问

看板回答「有什么」，这四问回答「往哪走」。**每次会话都过一遍，答案写进当次的归档**。

### ① 现在在阶梯的哪一级，卡住升级的是哪一条

不要泛泛说「还在验证阶段」。指到上面那张表的**具体某一行条件**上，
并说清它是**只能靠时间**（影子累积、真机运行）还是**有工程可做**。
今天的答案：L0；卡 L2 的第 ① 条（训练窗口 Calmar −0.115，红线过不去）。

### ② 手上有什么资源没用起来

**先过一遍看板的「登记在案的落地项」** —— 那一节存在的全部理由就是这一问：
它列的是**已经论证过、已经决定要做、只是还没做**的东西。
「就绪」那一组里任何一条都比新开一个题更值得动手（论证已经付过了）。

然后再盘点 —— 这个项目已经出现过好几次「基建早就有了但没人用」：

| 类别 | 现有 | 状态示例 |
|---|---|---|
| 工具 | `pnpm backtest` / `audit:regime` / `audit:subsignals` / `audit:random`（含 `--cross-code`）/ `audit:ic` / `iterate` / `fetch:history` / `build-delisted` · `scripts/verify/{dsr,mintrl}.ts` | 都能跑 |
| 数据 | 261 只存活 + 233 只退市的日线（2018 起）· 25 万条历史公告 | 已落盘 |
| 机制 | 影子运行（前向）· 成交记账 · 观察点 · AI 解读 | **记账 × 影子 = 执行滑移，基建有但没用起来** |
| 判据 | 配对 Δ（CR1）· 三态裁决 · 随机基准（四个零点）· rank IC（NW）· DSR · MinTRL | **池外参照仍是真空**；DSR 没接闸门（`dsr-gate`） |

### ③ 这一轮要学/要验的是什么，判据先定死

- 判据、参数、样本**在看到结果之前写下来**（预注册）。
- **每个候选机制只报一次分位**，不许调到达标为止。
- **失败与被证伪的预测同样要归档** —— 今天的 §5.27 就是一次「工具做出来了但没达到设计目标」，
  那条否定结论比工具本身值钱。
- **「要学」那半句有专门一节**：见下面的[学习任务](#学习任务往系统里加新信息的那个动作)。
  它是本 skill 里唯一往系统里**加新信息**的动作，三条道（判据/方法 · 策略/因子 · 竞品/形态）
  纪律各不相同，其中 B 道有一条不能违反的硬纪律。

## 学习任务（往系统里加新信息的那个动作）

**这是「自我进化」在本 skill 里唯一的可执行形式。** 上面那张 ✅/❌ 表说
「燃料是新数据与新信息」，学习任务就是去取那些信息 ——
其余每一个环节（回测、标定、audit、分层）都只是在**已有的那份数据**上反复计算。

**节奏：有缺口就做，不强制每日**（2026-08-20 用户拍板）。
选题从下面那份背景里取，**背景空了就明说「今天没有值得学的」** ——
与「该说今天没事就真这么说」同一条纪律。强制每日会退化成凑数，
而凑出来的「新知识」会被当成证据用，那比不学更贵。

### 三条道（性质不同，纪律也不同）

| 道 | 学什么 | 出口 | 主要风险 |
|---|---|---|---|
| **A. 判据 / 方法** | 外部权威口径：统计量、检验方法、绩效度量 | 搬回来在**已有报告**上重算 ⇒ 判据升级或**判它不能用** | 低。不碰交易逻辑 |
| **B. 策略 / 因子** | 参考站点、论文、开源项目上的**新策略与新因子** | 走完整的候选流程才能进引擎 | **高 —— 见下面那条硬纪律** |
| **C. 竞品 / 形态** | 同类产品（个人量化软件 / 终端 / 策略平台）怎么做 | 产品与形态决策的输入 | 低。但别把竞品的功能清单当路线图 |

### A 道：判据 / 方法 —— 性价比最高，先从这里挑

**已跑过五轮，模式是固定的**（聚宽四轮 §5.38/§5.39/§5.41 + Newey-West 一轮 §5.47）：

1. 读外部源，把**通行定义**抄准（公式 + 归属 + 易读错的地方）；
2. **在已有报告上重算**，不跑新模拟、不碰测试窗口；
3. 判**能用 / 不能用**，两种都是产出。

> **这一道最值钱的产出往往是「不能用」。** 四个候选判据里两个被否，
> 而**被否的那两个恰恰是看起来最专业的**（CAPM alpha 的符号由 `Rf` 决定；
> 日胜率 ≈ 基准下跌天数占比）。不做这次对照，日后某轮很可能会有人算出一个正的 alpha
> 拿去说「风险调整后有效」—— **而那个结论会是错的**。
> ⇒ 被否的判据要**连数字一起写死在代码注释里**，让指标缺口看起来像决定而不是疏漏。

### B 道：策略 / 因子 —— **一条硬纪律，违反它等于重演项目最贵的错误**

**外部策略带回来的每一个数字都是 `GUESS`，不是事实。**
这正是 [ADR-0003](../../../docs/adr/ADR-0003-来源文档数值不作为出厂默认.md) 的由来 ——
`strategy.squeezeBbwPct = 10` 直接抄自来源文档的「BBW_PCT < 10 是变盘前夜」，
它把均值回归卡得几乎不出手，**害得那个策略被判过两次死刑**，
标定之后真值是 **16–30 一整片高原**（出厂值现在是 20）。

所以 B 道的产出**不是**「加了一个因子」，而是三样东西之一：

- **一条可检验的假设** ⇒ 进[差距文档 §8 待验证](../../../docs/notes/与机构量化系统的差距.md)，
  **不许当结论引用**；
- **一个候选** ⇒ 走 `docs/07 §3.6` 的五条门槛（论证先于代码 · 建仓数降幅 ≤ 15% ·
  建仓级胜率不降 · alpha 上移且四子集稳定 · 同一零点），**每个机制只报一次分位**；
- **一条负面证据** ⇒ 同样归档（这是最常见的结果）。

**四条禁令**（都是踩出来的）：

1. **不许因为「外部有人在用」就当它有效。** 本地数据是唯一判据 ——
   横截面得分那件事：外部通行做法是打分排序，而我们实测**买入得分是负向因子**（§5.46）。
2. **不许新增未在文档中论证的指标**（约束 5）。信号质量问题优先查数据质量、参数标定、
   提醒策略三处；**加指标几乎总是错误的应对方式**。
3. **不许抄数值当出厂默认**（ADR-0003 / 约束 2）。抄回来的进 `GUESS` 档，进标定队列。
4. **注意许可**。聚宽协议 5.1/3.2/4.1 禁止把它的数据或加工物提供给第三方或商业使用
   ⇒ 「本机跑一次」可以，落进 `params/*.json` 提交、跟着 `pnpm package` 分发**不可以**。
   碰新站点前先看条款，结论记进台账。

### C 道：竞品 / 形态

判据是**「它解决了一个我们也有的问题吗」**，不是「它有什么功能」。
按功能清单对标会长出一个四不像 —— 本项目已经砍掉过桌宠、皮肤系统、托盘角标、
系统通知、全市场扫描，每一次都是因为**产品判据**而不是因为做不出来。

已做过一次：FinceptTerminal 对比（2026-08-18）。**那次的教训记在台账里**：
因为把 WebFetch 的失败误读成「github 被拦」，**少读了一整份源码**，
结论里有几条只能标「二手」—— 取页失败要先分清是**链路**还是**站点**。

### 取页通路（先读这个，否则会浪费半小时）

| 工具 | 给什么 | 状态 |
|---|---|---|
| **WebSearch**（内置） | 检索结果 + 摘要 + 链接 | ✅ **可用**（2026-08-20 实测） |
| **`pnpm fetch:page`** | **页面正文**（`--render` 驱动系统 Edge/Chrome 抓 SPA） | ✅ 调研取页一律走它 |
| ~~WebFetch~~（内置） | — | ❌ **本机永久不可用** |

- **WebFetch 的失败不是「站点访问不了」的证据** —— 它抓之前要摸 `claude.ai` 做域名校验，
  而那个域在本机不通 ⇒ 它对**所有**域名都失败。**别再拿它的失败去判断站点可用性。**
- **WebSearch 与 WebFetch 是两条链路，别一起判死**（2026-08-20 才确认）。
- ⚠ **WebSearch 的摘要是二手的，且会带归属错误。** 实测：第一次查询把
  `⌊4(T/100)^(2/9)⌋` 归给 Newey-West，第二次查询纠正为 **Andrews (1991)**。
  ⇒ **要落进文档的公式与归属，至少两次独立查询交叉验证**，或用 `fetch:page` 读原文。
- 需要登录的站点由**人在有界面窗口里登录**，会话文件放**仓库之外**（`%LOCALAPPDATA%`）——
  它含 cookie，进仓库等于提交凭据。

### 选题从哪来（**不要自己造题**）

按顺序翻这三处，取第一个还活着的：

1. **[差距文档 §7 优先级](../../../docs/notes/与机构量化系统的差距.md)** —— 主背景，
   带代价估计。08-20 一天勾掉三项（短期反转 · 小市值 · rank IC），剩池外参照 / 执行滑移 / PBO-DSR。
2. **[差距文档 §8 待验证](../../../docs/notes/与机构量化系统的差距.md)** ——
   有假设没证据的那些。
3. **当天实验自己长出来的缺口** —— 最高优先级，因为它是热的。
   今天（08-20）就是这一类：§5.46 把 IC 的 t 写进主判据、又自己标了「t 是上界别引用」
   ⇒ 主判据事实上是空的 ⇒ 当天补 Newey-West（§5.47）。

**背景全空 ⇒ 说「今天没有值得学的」。** 造题的产出是凑数，而凑数会被当证据。

### 一次学习任务算做完的条件

**五样**缺一不可：

1. **口径抄准**：公式 + **归属** + 至少一处「容易读错的地方」。
   （今天两处：`L` 是滞后截断阶不是带宽；那条经验规则归 Andrews 不归 NW。）
2. **落到本地**：在已有报告/数据上重算出一个数，或明确判「不能用」。
   **只有转述、没有本地对照的，不算做完** —— 那正是 ADR-0003 要防的形状。
3. **预注册 + 记分**：判据与**预测**写在看结果之前，事后**逐条记分**。
   **预测错了要写清错在哪个方向** —— 今天 3 处预测错误全是同一个方向
   （把 HAC 调整的威力估大了），那条比结论本身更有信息量。
4. **归档四处**（见「做完之后」那张表）+ **台账记一笔**（信源可靠性，含否定结论与日期）。
5. **可落地 / 可测试的结论要登记成条目**（2026-08-21 加，见下）。

#### 第 5 条：**归档不等于推进**

这一条是踩出来的。2026-08-20 两轮学习任务（DSR · MinTRL）各长出了可落地或可测试的结论 ——
影子面板缺样本充分性标注 · 回测报告该印显著性门槛 · `adx` 网格该往下探 ·
Lo (2002) 的口径该补。四条都规规矩矩归了档（M2 / CHANGELOG / 差距文档 / 台账），
**然后没有任何一处会在第二天提醒任何人**。
而同一天刚好又证过一次：§5.44 的预注册里写着「不许拿它当新基线」，
纪律在文档里却没有东西执行它，**当天就被 `pnpm iterate` 自己违反了**
⇒ **写下一条纪律不等于装上一道闸门。**

所以每一条「可以落地」或「可以测试」的结论都要加一行标记，
**登记在它论证所在的那一节里**（一件事仍然只有一个出处）：

```
<!-- ITEM id=shadow-sample-gate | 类=落地 | 桶=就绪 | 代价=小 | 来源=M2 §5.49 | 判据=src/renderer/panel/ShadowPanel.tsx:样本不足 | 标题=影子面板的夏普缺一道「样本够不够」的标注 -->
```

| 字段 | 取值与规矩 |
|---|---|
| `类` | `落地`（改软件）· `待测`（跑实验）· `拍板`（等用户） |
| `桶` | `就绪` · `等条件` · `等拍板` · `不做`。**刻意不复用任务那四个桶名** —— 「等条件」不是「只能靠时间」，DSR 接闸门等的是「出现夏普为正的候选」，那不是日历问题 |
| `前置` | `桶=等条件` 时**必填**，写清等的是什么。不写它就与「不做」没有区别 |
| `判据` | **必填**，`路径:字符串` —— **落地时必然会出现的那个字符串**。登记时要确认它**现在还不存在**（存在就说明这条早已落地，看板会立刻报反常） |
| 登记在哪 | 计划文档（§3/§4）或差距文档 §7 —— 就是它论证所在那一节。**M2 不放条目**（那是实验流水，放了就变成两个出处） |
| 怎么关 | **删掉那行标记**，连同勾掉散文。看板不记状态，每次从仓库现算 |

**为什么判据必填**：没有判据的条目**关不掉**，而关不掉的清单只增不减 ——
几周之后没人再看它，于是它变成又一个「归了档但没人推进」的东西，正是这一条要防的。

**⚠ 登记 ≠ 承诺做。** 「就绪」只表示没有前置条件挡着；排期仍然是人的事。
机制与三态（`OPEN` / `LANDED` / `UNREADABLE`）见
[`tools/iterate/backlog.ts`](../../../tools/iterate/backlog.ts) 头注释。

### 学习任务**不做**什么

- **不碰测试窗口。** 学习是取信息，不是消耗那个消耗品。
- **不改引擎参数**（哪怕外部源说得再确定）。
- **不因为「学到了」就立刻改判定逻辑** —— 那要走 `docs/07 §3.6`，是另一件事。
- **不把学到的新度量拿去重读已经报过的实验。**
  用新度量回头读旧结果与「换个参数重跑到通过」是同一件事：**移动球门**。
  新判据的唯一用途是**下一次预注册时从里面挑，挑完写死再跑**。

## 信源台账（每次碰数据源都要更新）

出处：**[`docs/notes/信源台账.md`](../../../docs/notes/信源台账.md)**

**为什么单列**：这个项目在数据源上反复踩同一类坑 —— 「curl 判 eastmoney 不可用」
（实际是客户端指纹）、「退市股取不到日线」（实际取得到，卡的是名单）、
「新浪 delisting 节点」（返回空）。**每一次都花了几十分钟到几小时重新试。**

记录规则：

1. **可用性要带口径**：谁调的（undici / curl）、成功率、什么条件下失败。
   「能用」「不能用」这种二值判断已经错过两次。
2. **坑要记在可用条目里**，不要另起一条 —— 腾讯日线**可用**，但退市整理期尾段的后复权是
   加性的（会变负）。两句必须一起读，分开记就会有人只看到前半句。
3. **否定结论同样记**，并注明**是什么时候、用什么方法**试的。否则下一轮会重试一遍。
4. **每条带日期**。数据源会变，三个月前的实测不能当今天的事实。

## 第三步：真要改判定逻辑时，走这个顺序

**顺序不能换。** 判据必须在看到结果之前定下来，否则就是自己给自己找台阶。

1. **先写论证** → `docs/04`（或 `docs/05`）加一节，**必须包含「这条论证可能错在哪」**。
   一条只能事后解释、无法事先陈述的规则，与对着数据刻出来的规则在形式上无法区分。
2. **确认判据** → 读 `docs/07 §3.6` 的四条门槛。不要凭记忆，那一节会更新。
3. **才动代码** → 改完递增 `ENGINE_VERSION`。
4. **补测试** → ⚠ 见下面「测试的一个坑」。
5. **跑验收** → 基线重跑 + `pnpm audit:random --match-regime --shuffle-spans`。
   **每个候选机制只报一次分位**，不许反复调到达标为止——那等于把随机基准变成
   新的过拟合目标，而它是目前唯一可信的判据。
6. **归档** → M2 偏差报告新增一节 + CHANGELOG + 更新 `params-view.ts` 的 `STATUS`
   + **更新 CLAUDE.md 概述**（第 6 步最容易漏，docs/09 §1.1 那个过期说法就是这么来的）。

### 测试的一个坑

**没有任何 fixture 能走到 `TREND_UP`**（实测三个突破类 fixture 在关键根上全是 `TRANSITION`，
`rangeBound` 是 `RANGE`）。所以「造一个上升趋势 fixture 然后断言某信号不触发」
会**因为构造不出那个状态而假通过**——与 §5.19 那六条从未绿过的用例是同一形状。

正确写法：**同一根 K 线、同一套指标，只换 `ctx.regime`** 的对照。
先用能触发的那一档证明原始条件确实都成立，再换成目标状态看它消失。
现成例子在 `tests/unit/strategies/trend.test.ts` 的「TREND_UP 里 BUY 不计票」那一组。

## 读数纪律（每次看数都要过一遍）

这几条是踩出来的，不是推出来的：

1. **判据是 alpha 配对胜率，不是绩效。** 绝对收益、Calmar、夏普都会把 beta
   与「少做」记成策略的功劳。今天砍掉 9.6% 交易让全期从 −0.94% 变 −0.09%——
   那**不是**策略变好了。
2. **加权与中位背离时以中位为准。** 一笔妖股能翻转加权的符号：
   `T1+T2+T3+T4` 的加权 95 分位对应中位 0 分位，元凶是 SZ002969 一笔 **+325.8%**。
3. **凡是拿真实 `holdingBars` 做配对的读数都被内生性系统性压低**，
   要看 `--shuffle-spans` 那一档（`TREND_UP` 3.5% → 19.5%，差一倍）。
4. **胜率有两个口径**：逐笔 28.45% vs 建仓级 44.85%，同一份数据。用户体验到的是后者。
5. **砍掉一批负 alpha 交易必然提升剩余的 alpha——那是算术不是发现。**
   所以「砍掉一批」类改动必须额外过子集稳定性检验（四个切法都同向），
   否则分不清「找对机制」与「删掉任何一批差交易」。

## 做完之后

更新对应的出处，**一件事只有一个出处**：

| 内容 | 出处 |
|---|---|
| 实验过程与数字 | `docs/notes/M2-偏差报告.md` 新增一节 |
| 决策与候选清单 | `docs/notes/下一阶段取舍与迭代计划.md` |
| 参数归档状态 | `src/main/settings/params-view.ts` 的 `STATUS`（有测试拦漏归档）|
| 引擎行为变更 | `CHANGELOG.md`（写清动了什么、依据、**什么条件下结论失效**）|
| **判据变更** | `CHANGELOG.md`（与引擎变更同一处，但要写明**引擎数字没动**，只动了标准误/口径）|
| 状态快照 | `pnpm iterate -- --write` |
| **学习任务：选题背景勾项** | `docs/notes/与机构量化系统的差距.md` §7/§8（勾掉时写清是「做了」还是「刻意不做」）|
| **学习任务：信源可靠性** | `docs/notes/信源台账.md`（**含否定结论与日期**，见那一节的四条记录规则）|
| **学习任务：可落地 / 可测试的结论** | 一行 `<!-- ITEM ... -->` 标记，登记在**它论证所在的那一节**（计划文档 §3/§4 或差距文档 §7）。格式与规矩见上面第 5 条 |

**看板本身不记决策**——它是全自动生成的，手改会被下次刷新覆盖。
**它也不记条目状态** —— 登记项的「做没做」每次从仓库现算，看板上那几行是快照不是台账。

**一次学习任务的归档是五处**：M2 一节（预注册 + 结果 + **预测记分**）·
CHANGELOG（若动了判据）· 差距文档勾项 · 台账一笔 · **可落地结论登记成条目**。
少一处，下一轮会重学一遍同一件事 —— 少最后那一处，是学完了但**没人接手**。
