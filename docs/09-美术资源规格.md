# 09 · 美术资源规格与交付标准

本文件是**外包/生成方的唯一依据**，与具体形象无关。工程侧不接受与本文件不符的资源。

上游约束来自 [docs/06 §5 皮肤系统](./06-桌宠交互与非干扰设计.md)（目录与 `skin.json` 结构）、[§3 状态机](./06-桌宠交互与非干扰设计.md)（状态清单）、[§6 性能预算](./06-桌宠交互与非干扰设计.md)（帧率上限）、[§7](./06-桌宠交互与非干扰设计.md)（@2x 与极简模式）。本文件只做细化，**不覆盖** docs/06；若发现冲突，以 docs/06 为准并回报。

## 1. 适用范围

### 1.1 本文件约束什么、不约束什么

| | 内容 |
|---|---|
| **约束** | 交付物清单、文件命名与目录、像素与色彩技术规格、画布内定位、动画清单与每个动画必须表达的语义、`skin.json` 取值、验收标准 |
| **不约束** | 形象是谁、长什么样、什么风格、什么配色、用什么动作演绎 |

形象层面的一切（造型、配色、道具、分镜的具体演绎）由**每套皮肤各自的《形象设定说明》**承载，模板见 [附录 A](#附录-a形象设定说明模板)，建议存放于 `docs/skins/<skinName>.md`。

这样切分的目的是**多形象可替换**：只要满足本文件，任意形象（人形、动物、机械、抽象造型）都能装进同一套加载器与状态机，互相之间可直接切换而无需改代码。

### 1.2 能力对等原则

皮肤之间必须**能力对等**——每套皮肤都要实现 §3 的**全部 9 个动画 key**，且六个 `PetState` 齐备。缺任何一个，加载器会 schema 校验失败并回退默认皮肤（docs/06 §5），等于整套皮肤作废。

若某个形象在生理上无法表达某个动画（例如无眼形象做不了 `blink`），**不允许省略该动画**，须以等效手段表达同一语义，并在《形象设定说明》中写明替代方案。

### 1.3 语义固定色（项目级，跨形象不变）

以下色值承载**产品语义**而非造型，任何形象都必须原样使用，不得替换、不得调整色相：

| 语义 | 用途 | 色值 |
|---|---|---|
| 风险 / 减仓提示 | `alert` 的提示元素 | `#E8721C`（中） `#F59D4E`（亮） |
| 机会提示 | `excited` 的提示元素 | `#F2C230`（中） `#F8DE7A`（亮） |
| 离线灰阶 | `offline` 的去饱和四档 | `#4A4E5A` `#9AA0B4` `#C8CCD9` `#ECEEF2` |
| 极简模式六色 | `minimal.png` | 见 [§6.1](#61-极简模式色点) |

**禁止**用红色或绿色承载「卖出 / 警示 / 安全」语义——A 股红涨绿跌，红色作警示会与涨跌色冲突（docs/05 §7）。形象自身的固有色（例如一件红色外套）不承载语义，不受此限。

除以上语义色，造型用色完全由形象自定，但须满足 §2.4 的限色要求。

## 2. 技术规格

### 2.1 分辨率与像素网格

| 项 | 值 |
|---|---|
| 逻辑网格 | **100 × 100**（一格逻辑像素 = @1x 的 2×2 屏幕像素） |
| @1x 帧尺寸 | **200 × 200** px（与 docs/06 §5 `canvas` 一致；Pet 窗口 220×220） |
| @2x 帧尺寸 | **400 × 400** px |
| 放大方式 | 整数倍**最近邻**。@2x 必须是 @1x 的严格 2 倍最近邻放大 |
| 抗锯齿 | **禁止**。不得出现半透明边缘像素 |
| Alpha | **二值**：每个像素 alpha 只能是 0 或 255 |
| 格式 | PNG-24 + alpha，非隔行，无 ICC / EXIF |

Alpha 二值是硬要求：docs/06 §2.2 的命中判定方案 2 要读 alpha 通道做像素级命中测试，半透明边缘会让点击穿透（C2）行为不可预测。

「逻辑网格 100×100」意味着所有造型必须落在 100×100 的整数格上再放大。**不接受**先画高分辨率再降采样的做法——像素画降采样必糊，且会破坏 alpha 二值与限色。

### 2.2 主体在画布中的定位

以下均为**逻辑坐标**（0–99），左上角为原点。适用于任何形象，不论人形与否。

| 项 | 要求 |
|---|---|
| 镜像轴 | `x = 50`。形象若为左右对称造型，对称元素须严格对称 |
| 主体基线 | 主体的**着地/最低边缘**固定在 `y = 94`（含描边到 95） |
| 顶部留白 | 主体最高点 `y ≥ 3` |
| 主体高度 | 占画布 **85 % – 92 %**（约 85–92 逻辑像素）。过小则 200px 下五官不可辨，过大则没有起伏与道具余量 |
| 主体宽度 | ≤ 60 逻辑像素。超出后靠边缘的道具无处可放 |
| 左右安全边距 | 主体本体 ≥ 2 px；道具可延伸至画布边缘但不得裁切 |
| 整体升降预算 | `Δy ∈ [−3, +2]`。超出即被裁切 |

**主体基线必须逐帧对齐。** 除 §4 明确允许纵向位移的动画外，所有帧的最低非透明行必须完全相同。差 1 px 就会让桌宠在待机时「抖脚」——这是最容易被交付方忽略、又最容易被用户看见的缺陷。

**同一皮肤内比例必须一致。** 各动画之间主体的高度、宽度、各部位比例不得漂移；切换状态时不应出现「胖了一圈」或「矮了一截」。

### 2.3 精灵图布局

- 单行横向排列，`1 行 × N 列`
- 帧间**无间隙、无内边距**，第 1 帧左边缘对齐 x=0
- 图集总宽 = `帧尺寸 × 帧数`，总高 = 帧尺寸
- 每帧的像素不得越过该帧的 200 px（@2x 400 px）格线，避免播放时相邻帧渗色

### 2.4 限色与调色板文件

| 项 | 要求 |
|---|---|
| 单张图颜色数 | ≤ **40** 色（不含全透明） |
| 全套一致性 | 同一皮肤下所有图集的颜色集合，必须是该皮肤 `palette.json` 的子集 |
| 描边色 | 每套皮肤**只允许一个**描边色，登记在 `palette.json` 的 `outline` 槽位；剪影外缘统一 1 逻辑像素 |
| 部件分界 | 主体内部不同部件之间用**浅色**分界线（如暗部色），不要额外深色描边——深色分界会把剪影切碎 |
| 语义色 | `palette.json` 的 `semantic` 段必须与 §1.3 固定值逐字一致 |

`palette.json` 与 `skin.json` 同目录，**仅供验收校验，不参与运行时加载**：

```jsonc
{
  "outline": "#2A2028",
  "colors": ["#2A2028", "#F8E2D0", "..."],   // 该皮肤全部使用色，≤ 40
  "semantic": {
    "riskAmber":   ["#E8721C", "#F59D4E"],
    "chanceGold":  ["#F2C230", "#F8DE7A"],
    "offlineGray": ["#4A4E5A", "#9AA0B4", "#C8CCD9", "#ECEEF2"]
  }
}
```

## 3. 动画清单

九个动画。与 `PetState`（[src/shared/ipc-types.ts](../src/shared/ipc-types.ts)）的关系：

- **六个状态动画** `idle` `watching` `excited` `alert` `sleepy` `offline` —— 由主进程 `push:petState` 直接切换，六态必须齐备
- **两个点缀动画** `blink` `look` —— IDLE 期间由渲染层随机插播，实现 docs/06 §3 的「呼吸、偶尔眨眼、左右张望」。做成独立动画而非塞进 `idle` 循环，是为了让插播间隔可随机化；否则 1 秒一次的机械眨眼很出戏
- **一个手势动画** `shush` —— 双击进入免打扰时的反馈（docs/06 §4）

| key | 用途 | 帧数 | fps | loop | minHold | @1x 图集尺寸 |
|---|---|---|---|---|---|---|
| `idle` | IDLE | 8 | 8 | ✔ | — | 1600 × 200 |
| `blink` | IDLE 插播 | 4 | 12 | ✘ | — | 800 × 200 |
| `look` | IDLE 插播 | 10 | 8 | ✘ | — | 2000 × 200 |
| `watching` | WATCHING | 6 | 8 | ✔ | — | 1200 × 200 |
| `excited` | EXCITED | 12 | 12 | ✘ | 3000 | 2400 × 200 |
| `alert` | ALERT | 10 | 10 | ✘ | 3000 | 2000 × 200 |
| `sleepy` | SLEEPY | 6 | **4** | ✔ | — | 1200 × 200 |
| `offline` | OFFLINE | 4 | **4** | ✔ | — | 800 × 200 |
| `shush` | 双击反馈 | 6 | 10 | ✘ | 1200 | 1200 × 200 |

合计 **66 帧**（@1x 与 @2x 各一套）。

`sleepy` / `offline` 压到 4 fps 是为了兑现 **C7 休市零开销**（docs/06 §1）：休市期间这两个动画常驻，且相邻帧差异必须小——帧间大位移在低帧率下会明显卡顿。

## 4. 每个动画的表达契约

本节规定**必须传达什么**与**动作预算**，不规定怎么演。具体分镜由《形象设定说明》给出并须在此约束内。

「关键节拍」中的帧区间是**建议划分**，可在总帧数不变的前提下调整比例；「必需元素」与「禁止项」不可调整。

### 4.1 `idle` — 待机（8 帧 / 8 fps / 循环）

| 项 | 要求 |
|---|---|
| 必须传达 | 活着、在待机、没有事情发生 |
| 关键节拍 | 一个完整的呼吸周期：下沉 → 回位 → 下沉 → 回位 |
| 动作预算 | 整体位移 ≤ 1 px；基线固定 |
| 必需元素 | 至少一处**与主体呼吸不同周期**的次级摆动（发梢、衣角、尾巴、飘带之类）。缺了它整体会像机械上下弹 |
| 禁止项 | 眨眼（属 `blink`）、任何幅度超过 1 px 的动作、任何提示元素 |
| 首尾衔接 | 末帧必须与首帧可无缝接续 |

### 4.2 `blink` — 眨眼插播（4 帧 / 12 fps / 单次）

| 项 | 要求 |
|---|---|
| 必须传达 | 一次短暂的注意力中断 |
| 关键节拍 | 睁 → 半闭 → 全闭 → 睁 |
| 动作预算 | **主体不得有任何位移**，只有眼部（或等效部位）变化 |
| 无眼形象 | 须以等效手段表达，例如镜头/明度短暂变化、指示灯闪灭，并在设定说明中写明 |
| 起止姿态 | 首帧与末帧必须与 `idle` 首帧完全一致（插播后要能无缝回到 idle） |

### 4.3 `look` — 左右张望插播（10 帧 / 8 fps / 单次）

| 项 | 要求 |
|---|---|
| 必须传达 | 主动环视周围 |
| 关键节拍 | 正面 → 向一侧转 → 回正 → 向另一侧转 → 回正 |
| 动作预算 | 头部（或等效朝向部位）横向偏移 ≤ 2 px |
| 必需元素 | **仅头部及其附属物移动，躯干与下半身静止**。整体平移会读成「滑步」而非「张望」 |
| 起止姿态 | 首帧与末帧必须与 `idle` 首帧完全一致 |

### 4.4 `watching` — 盯盘（6 帧 / 8 fps / 循环）

| 项 | 要求 |
|---|---|
| 必须传达 | 有信号正在计算、注意力集中在屏幕上 |
| 关键节拍 | 前倾并保持 → 朝向微幅左右扫视 |
| 动作预算 | 上身前倾 ≤ 1 px；呼吸幅度**小于** `idle`（专注时呼吸变浅） |
| 必需元素 | 与 `idle` 一眼可区分的「专注」特征（睁大、竖起、前倾、指示灯亮起等任选） |
| 禁止项 | 提示元素（`watching` 是「在算」，不是「有结论」） |
| 首尾衔接 | 末帧必须与首帧可无缝接续 |

### 4.5 `excited` — 买入机会（12 帧 / 12 fps / 单次 / minHold 3000）

| 项 | 要求 |
|---|---|
| 必须传达 | 发现了机会、正向情绪的峰值 |
| 关键节拍 | 蓄力下沉 → 纵向跃起 → 空中峰值 → 落地 → 回稳 |
| 动作预算 | 蓄力 `Δy = +2`，峰值 `Δy = −3`；**本动画允许基线浮动**，但末帧必须回到基线 |
| 必需元素 | 1. 至少 4 帧的**离地**表现<br>2. 机会提示元素（§1.3 金黄色系），出现在空中峰值之后、消失在末帧之前<br>3. 一个明确的正向情绪表情/姿态峰值 |
| 禁止项 | §7.1 全部禁止元素；跃起高度超出 `Δy = −3` |
| 末帧 | 须接近 `idle` 首帧，便于回落 |

### 4.6 `alert` — 卖出 / 风险（10 帧 / 10 fps / 单次 / minHold 3000）

| 项 | 要求 |
|---|---|
| 必须传达 | 警惕、需要注意的风险，**不是恐慌** |
| 关键节拍 | 察觉 → 戒备 → 举出提示元素 → 提示元素持续摆动 |
| 动作预算 | 整体位移 ≤ 1 px。风险提醒时桌宠自己乱动会加剧焦虑 |
| 必需元素 | 1. 与 `idle` 一眼可区分的戒备特征<br>2. 风险提示元素（§1.3 暖橙色系），第 3 帧前出现并持续到末帧<br>3. 提示元素须有 ≥ 1 px 的持续摆动，保证在静态截图外也能被注意到 |
| 禁止项 | 红色或绿色的提示元素（§1.3）；夸张的惊恐表情；§7.1 全部禁止元素 |

### 4.7 `sleepy` — 休市 / 免打扰（6 帧 / 4 fps / 循环）

| 项 | 要求 |
|---|---|
| 必须传达 | 休息中、不会打扰你 |
| 关键节拍 | 低头/闭合 → 保持 → 点头 → 回抬 → 一次打哈欠或等效放松动作 |
| 动作预算 | **相邻帧差异必须小**：任何单帧位移 ≤ 1 px。4 fps 下大位移会明显卡顿 |
| 必需元素 | 一个「睡意」符号（`Z`、气泡、渐弱指示灯等），须有上浮或明灭变化 |
| 可见性 | 脱离主体的符号**必须带浅色外圈**——深色壁纸上纯深色小图标会整块消失 |
| 首尾衔接 | 末帧必须与首帧可无缝接续 |

### 4.8 `offline` — 数据源全部失败（4 帧 / 4 fps / 循环）

| 项 | 要求 |
|---|---|
| 必须传达 | 拿不到数据、当前的沉默不代表没有信号 |
| 实现方式 | **同一套形体换色，不重画**：用 §1.3 离线灰阶做去饱和映射 |
| 关键节拍 | 断线图标显示 2 帧 → 隐藏 2 帧（约 0.5 s 明灭） |
| 动作预算 | 主体姿态静止（可与 `idle` 首帧同姿态，仅换色 + 垮肩等静态调整） |
| 必需元素 | 一个「无信号」图标，带浅色外圈 |
| 可见性 | 灰调后**轮廓仍须可辨**。去饱和不等于降对比，明暗层次要保留 |

### 4.9 `shush` — 双击进入免打扰（6 帧 / 10 fps / 单次 / minHold 1200）

| 项 | 要求 |
|---|---|
| 必须传达 | 收到，我安静了 |
| 关键节拍 | idle 姿态 → 起手 → 定格「安静」手势 → 保持并轻微回弹 |
| 动作预算 | 整体位移 ≤ 1 px |
| 必需元素 | 一个可读的「安静」信号（食指抵唇、闭嘴、指示灯熄灭等任选），第 3 帧前定格 |
| 首帧 | 须与 `idle` 首帧一致 |
| 禁止项 | 任何提示元素（此刻的语义是「静音」，不是「有信号」） |

## 5. `skin.json`

结构由 docs/06 §5 定义，本节补充取值要求。**由交付方一并提供**，`frames` 必须与图集实际宽度一致。

```jsonc
{
  "name": "<皮肤显示名>",
  "canvas": { "width": 200, "height": 200 },

  // 气泡尖端指向的锚点（相对本帧左上角，@1x 像素）。
  // 取主体最高点上方留 6px 间隙；横向取镜像轴
  "anchor": { "bubbleX": 100, "bubbleY": 14 },

  // 命中区：矩形近似（docs/06 §2.2 方案 1）。
  // 覆盖主体躯干即可；外伸的附属物（发梢、尾巴、衣摆、飘带、道具等）故意不算命中 ——
  // 宁可少覆盖，也不要吞掉本该穿透的点击（C2 是底线）
  "hitRects": [
    { "x": 86, "y": 14, "w": 28, "h": 30 },
    { "x": 80, "y": 44, "w": 40, "h": 76 }
  ],

  "states": {
    "idle":     { "sheet": "idle.png",     "frames": 8,  "fps": 8,  "loop": true  },
    "blink":    { "sheet": "blink.png",    "frames": 4,  "fps": 12, "loop": false },
    "look":     { "sheet": "look.png",     "frames": 10, "fps": 8,  "loop": false },
    "watching": { "sheet": "watching.png", "frames": 6,  "fps": 8,  "loop": true  },
    "excited":  { "sheet": "excited.png",  "frames": 12, "fps": 12, "loop": false, "minHold": 3000 },
    "alert":    { "sheet": "alert.png",    "frames": 10, "fps": 10, "loop": false, "minHold": 3000 },
    "sleepy":   { "sheet": "sleepy.png",   "frames": 6,  "fps": 4,  "loop": true  },
    "offline":  { "sheet": "offline.png",  "frames": 4,  "fps": 4,  "loop": true  },
    "shush":    { "sheet": "shush.png",    "frames": 6,  "fps": 10, "loop": false, "minHold": 1200 }
  }
}
```

- `hitRects` 的示例值仅为占位，**每套皮肤须按自己的实际剪影测量**
- `@2x` 不写进 `skin.json`：加载器按 `<name>@2x.png` 命名约定自行查找
- `states` 的 key、`frames`、`fps`、`loop`、`minHold` 是**跨皮肤统一的契约**，不得按形象调整
- 字段之外不要新增键；确有需要请先提出

## 6. 其他资源

### 6.1 极简模式色点

docs/06 §7：桌宠可替换为一个 32×32 的小圆点，只靠颜色表达状态。给不喜欢卡通形象但仍要提醒的用户一个出口。

**此资源跨皮肤统一，不随形象变化**——它存在的意义正是「不要形象」。每套皮肤交付一份完全相同的文件即可，或由工程侧统一提供。

| 项 | 值 |
|---|---|
| 文件 | `minimal.png`（32×32 × 6 帧 = 192×32）、`minimal@2x.png`（384×64） |
| 帧顺序 | **必须**为 `SLEEPY, IDLE, WATCHING, EXCITED, ALERT, OFFLINE`（渲染层按 PetState 索引取帧） |
| 造型 | 实心圆 + 1 px 深色描边 |

| 帧 | 状态 | 填充色 | 描边 | 形状标记 |
|---|---|---|---|---|
| 1 | SLEEPY | `#9AA0B4` | `#6F748A` | 无 |
| 2 | IDLE | `#FDFBF5` | `#2A2028` | 无 |
| 3 | WATCHING | `#6C8EBF` | `#2A2028` | 无 |
| 4 | EXCITED | `#F2C230` | `#2A2028` | 深色上三角 |
| 5 | ALERT | `#E8721C` | `#2A2028` | 深色下三角 |

### 6.2 托盘与应用图标

**每套皮肤各自提供**（托盘图标要跟随当前皮肤）。

托盘图标取形象**最具辨识度的局部**（人形取头肩、动物取头部、抽象造型取主体特征），必须在 16×16 上**单独排布**，不得由全身图缩小——像素画降采样必糊。

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `tray.png` | 16×16 | 托盘，100 % 缩放 |
| `tray@2x.png` | 32×32 | 托盘，200 % 缩放 |
| `tray-muted.png` | 16×16 | 免打扰 / 桌宠已隐藏时的灰调版（用 §1.3 离线灰阶） |
| `tray-muted@2x.png` | 32×32 | 同上 |
| `icon.png` | 256×256 | 应用图标 |
| `icon.ico` | 16 / 32 / 48 / 64 / 128 / 256 | electron-builder 打包用 |

`icon.ico` 各尺寸**按尺寸单独排布**（icon 设计的常规做法），不要用同一张图缩放。小尺寸（16–48）用局部特征，大尺寸（64–256）可用全身。

## 7. 视觉纪律

以下来自 [CLAUDE.md 措辞纪律](../CLAUDE.md) 与 docs/05 §7，**优先于任何视觉效果，且不因形象而异**。

### 7.1 不得暗示收益

提示元素只能作为「有机会 / 有风险」的氛围隐喻。任何皮肤的任何素材中**不得出现**：

- 涨跌箭头、K 线、蜡烛图、收益曲线
- 任何百分比、数字、货币符号（¥ / $ / %）
- 「必涨」「抄底」「稳赚」「牛股」等任何文字

理由：本产品不接券商、不下单，任何绩效感的视觉暗示都会越过工具的定位。

### 7.2 提示色不得与涨跌色冲突

见 §1.3。风险一律暖橙，机会一律金黄，禁止红绿承载语义。

### 7.3 危险与争议元素的出现范围

形象自带的道具若包含武器、烟酒、宗教或政治符号等争议元素：

- 须在《形象设定说明》中显式登记
- 默认**只允许出现在静态待机类动画**（`idle` / `watching` / `sleepy` / `offline`）
- **不得**出现在 `excited` / `alert` / `shush` —— 这三个动画正是产品在向用户传达理财判断的时刻，此时出现武器会严重偏离工具定位
- 不得指向画面外、不得有使用动作

### 7.4 不承担交互责任

素材不得依赖任何「需要用户点击关闭」的视觉暗示（如叉号、按钮）。气泡完全不可点击（docs/06 §2.3），提醒 6 s 自动消失（C6）。

## 9. 验收标准

以下标准与形象无关，任何皮肤一律适用。

### 9.1 可自动校验（建议实现为 `pnpm verify:assets`，CI 门禁）

| # | 检查项 |
|---|---|
| A1 | `<anim>.png` 尺寸 = `200 × frames` × `200`；`@2x` = `400 × frames` × `400` |
| A2 | alpha 通道只含 0 与 255 |
| A3 | 每张图颜色数 ≤ 40（不含全透明） |
| A4 | 所有图集的颜色集合 ⊆ `palette.json` 的 `colors`；`semantic` 段与 §1.3 逐字一致 |
| A5 | `@2x` 是 `@1x` 的严格 2 倍最近邻放大：每个 2×2 块四像素全等，且等于 `@1x` 对应像素 |
| A6 | 每帧的格线内 1 px 边缘无非透明像素（刻意贴边的道具须在偏差说明中列出） |
| A7 | `skin.json` 的 `frames` 与图集宽度一致；`states` 覆盖全部 9 个 key；六个 `PetState` 齐备；`fps`/`loop`/`minHold` 与 §3 契约一致 |
| A8 | 主体基线一致：逐帧最低非透明行完全相同（`excited` 除外） |
| A9 | 主体尺寸达标：非透明包围盒高度占 85 %–92 %，宽度 ≤ 60 逻辑像素（等效 ≤ 120 @1x px） |
| A10 | `hitRects` 落在剪影内：矩形内 alpha>0 的像素占比 ≥ 85 % |
| A11 | `minimal.png` 为 6 帧且帧序与配色符合 §6.1 |
| A12 | `blink` / `look` / `shush` 的首帧与 `idle` 首帧逐像素一致（插播/手势后能无缝回落） |
| A13 | 循环动画（`idle` / `watching` / `sleepy` / `offline`）末帧与首帧的像素差异 ≤ 5 %，保证接缝不跳 |

### 9.2 人工验收

| # | 检查项 |
|---|---|
| M1 | 200 px 实际尺寸下主体特征可辨（表情或状态特征能看出来，不是一团色块） |
| M2 | 纯白、纯黑、花色壁纸三种背景下轮廓都清晰，脱离主体的小图标都可见 |
| M3 | 逐动画按标称 fps 播放：无抖脚、无跳帧、循环动画首尾衔接自然 |
| M4 | 九个动画的语义可被不知情的人正确说出（盲测：只看动画猜「它在干什么」） |
| M5 | `idle` 与 `watching` 一眼可区分；`excited` 与 `alert` 一眼可区分方向性 |
| M6 | 六个状态在 32×32 极简色点下互相可区分 |
| M7 | 全部素材无 §7.1 禁止元素；无红/绿语义色；争议元素符合 §7.3 |
| M8 | 各动画之间主体比例一致（§2.2） |

M4 是最终把关：如果需要看文档才知道某个动画在表达什么，那这个动画就没做到。

## 10. 多形象与皮肤切换

| 项 | 约定 |

## 11. 变更约定

- §3 的**帧数、fps、loop、minHold** 是跨皮肤契约，一经确认即写入 `skin.json`。改动须同步改文档与全部已交付皮肤，否则加载器会按 `skin.json` 播放而与图集脱节
- 若交付方需要调整某个动画的帧数，提前提出并同步更新 §3、§4、§5
- §1.3 语义固定色与 §6.1 极简色点的改动视为**产品级变更**，须同步 docs/05 与 docs/06
