# 04 · 指标与信号引擎

> 本文是把 [reference/量化策略买卖时机判断.md](./reference/量化策略买卖时机判断.md) 里的自然语言策略，翻译成**可实现、可测试、无歧义**的工程规范。
> 凡是原文含糊、自相矛盾或缺定义之处，本文给出明确取舍并在「⚠ 与来源的差异」中说明理由。

## 0. 分层

```
Candle[] (前复权日线) ──▶ ① 指标层 IndicatorSet
                              │
                              ├──▶ ② 市场状态层 Regime
                              │
                              ├──▶ ③ 策略层 SubSignal[]   (趋势 / 均值回归 / 多周期)
                              │
                              ├──▶ ④ 组合层 CombinedSignal (等权汇总 + 投票)
                              │
                              └──▶ ⑤ 风控层 GatedSignal   (见 05)
```

每层是纯函数：`f(输入数据, 参数) → 输出`，无副作用、无 IO、无时间依赖（「现在几点」由调用方作为参数传入）。这是能被单元测试和回测复用的前提。

## 1. 指标层

### 1.1 通用约定

- 输入为**前复权**日线，按 `trade_date` 升序，无缺口（缺口在数据层已补齐或标记）。
- 所有指标返回**与输入等长的数组**，预热期不足的位置填 `null`，绝不填 0。用 0 冒充未定义值是回测结果失真的经典来源。
- 浮点比较统一用 `Math.abs(a - b) <= 1e-9`，穿越判定见 §1.9。

### 1.2 SMA / EMA

```
SMA(n)[i] = mean(close[i-n+1 .. i])                       i >= n-1，否则 null

EMA(n)[i] = α·close[i] + (1-α)·EMA(n)[i-1]                α = 2/(n+1)
EMA(n)[n-1] = SMA(n)[n-1]                                  种子值
```

使用周期：SMA 5 / 10 / 20 / 60 / 120。EMA 仅供 MACD 内部使用。

> ⚠ 原文提到用 LLT（二阶 IIR 低延迟趋势线）替代均线以降低滞后。**首版不做**——它引入两个未标定的参数，且原文未给出公式与验证。留作 P2，见 [08](./08-开发路线图.md)。

### 1.3 MACD

```
DIF  = EMA(fast) - EMA(slow)
DEA  = EMA(DIF, signal)
HIST = 2 × (DIF - DEA)          ← 采用国内平台（通达信/同花顺）口径
```

| 参数集 | 值 | 用途 |
|---|---|---|
| `AShareOptimized`（默认） | fast=12, slow=17, signal=9 | 来源文档推荐 |
| `Classic` | fast=12, slow=26, signal=9 | 对照组，设置中可切换 |

> ⚠ **(12,17,9) 是未经本项目验证的外部主张。** 原文称其「贴合 A 股一周半交易周期、降低信号延迟」，但未给出可复现的推导。工程上它必然更灵敏（快慢线间距缩小 → 交叉更早也更频繁），代价是假信号增多。因此：
> 1. 两套参数都实现，出厂默认前**必须**用 [07 回测](./07-回测与验证方案.md) 在用户自己的自选股上对比胜率与盈亏比；
> 2. 参数暴露在设置里，不写死。
>
> HIST 采用 `2×(DIF-DEA)` 而非原文的 `DIF-DEA`，只影响柱子高度的显示尺度，**不影响任何穿越或正负判定**，为的是与用户在行情软件里看到的柱子一致。

### 1.4 布林带与带宽分位

```
MID   = SMA(20)
STD   = 总体标准差(close[i-19..i])        ← 除以 n，非 n-1，与国内平台一致
UPPER = MID + 2·STD
LOWER = MID - 2·STD
BBW   = (UPPER - LOWER) / MID × 100 = 4·STD / MID × 100
BBW_PCT[i] = BBW[i] 在 BBW[i-249..i] 中的百分位排名 (0..100)
```

`BBW_PCT` 需要 20 + 250 = **270 根**日线才有第一个有效值。分位数用「小于等于当前值的样本数 / 总样本数 × 100」。

> **「除 n 不除 n−1」已被外部证实**（2026-08-19，[M2 §5.38](./notes/M2-偏差报告.md)）：
> 与聚宽公开数据字典的示例值逐位一致（相对差 **1e-14**），而改成除 n−1 的相对差是 3e-4~7e-4
> ⇒ 这次对照有分辨力，不是「精度内说不清」。同一次对照里 RSI 也逐位一致（1e-9），
> `HIST = 2×(DIF−DEA)` 由他们印的三组 (DIF, DEA, 柱) 代数确认。

阈值语义：

| BBW_PCT | 含义 | 用途 |
|---|---|---|
| < 10 | 极度压缩，变盘前夜 | 提升突破信号权重 |
| < 30 | 收敛 | 震荡市判定条件之一 |
| > 70 | 扩张 | 趋势信号有效性提高 |
| > 90 | 极度扩张 | 趋势末端警惕，不再新增买入 |

### 1.5 ADX / DMI（Wilder 平滑，周期 14）

```
TR    = max(H-L, |H-PC|, |L-PC|)
upMove   = H - PH ;  downMove = PL - L
+DM   = (upMove > downMove && upMove > 0)   ? upMove   : 0
-DM   = (downMove > upMove && downMove > 0) ? downMove : 0

Wilder(x, n)[i] = Wilder[i-1] - Wilder[i-1]/n + x[i]      种子 = sum(x[0..n-1])
ATR  = Wilder(TR, 14)
+DI  = 100 × Wilder(+DM,14) / ATR
-DI  = 100 × Wilder(-DM,14) / ATR
DX   = 100 × |+DI - -DI| / (+DI + -DI)                    分母为 0 时 DX = 0
ADX  = Wilder 平滑的 DX，种子 = mean(DX[0..13])
```

ADX 第一个有效值需要约 **28 根**日线。ADX 不含方向，方向由 `+DI vs -DI` 给出。

> ⚠ **这里的 ADX 与行情软件显示的 ADX 不是同一个数**（2026-08-19 实测，[M2 §5.38](./notes/M2-偏差报告.md)）。
> 通达信/东财/同花顺/聚宽那一套是 `EXPMEMA`（α = 2/(N+1) = 2/15，比 Wilder 的 1/14 快一倍）
> 平滑 DI，**且 ADX 的平滑周期是 MM = 6 而不是 14**；ATR 那边差别更直白 ——
> 他们是 `MA(TR,14)` 简单算术平均，我们是 `Wilder(TR)/14`。
> 我们池子里 699,907 个「股票·交易日」上：我们的 ADX 中位 **23.06**、通达信口径 **30.26**，
> 「ADX ≥ 20」的结论在 **30.4%** 的日子上相反。
>
> **口径不改**（Wilder 是 ADX 的原始定义，两套都自洽），但下面那条动态阈值里的 `20`
> **转述自国内平台语境**，因此它抄对了数值、没抄对量纲 —— 分位等价值约 **17.29**。
> 出厂值 20 站得住是[本地标定](./notes/M2-偏差报告.md)的功劳，不是转述的功劳（ADR-0003 的又一个实例）。

**动态阈值**（原文只说「波动率高时提到 25+，低时降到 22 左右」，无公式，此处补全）：

```
volPct = ATR14/close 在过去 250 日中的百分位 (0..1)
adxTrendThreshold = clamp(20 + 8 × volPct, 20, 28)     // 强趋势线
adxRangeThreshold = adxTrendThreshold - 5              // 震荡线
```

### 1.6 RSI（Wilder，周期 14）

```
gain[i] = max(close[i]-close[i-1], 0) ;  loss[i] = max(close[i-1]-close[i], 0)
avgGain = Wilder(gain,14) / 14 ;         avgLoss = Wilder(loss,14) / 14
RS  = avgGain / avgLoss                  // avgLoss = 0 → RSI = 100
RSI = 100 - 100/(1+RS)
```

**动态阈值**——原文此处自相矛盾（说「牛市降低超买阈值至 85」，但 85 高于默认 70，是**上调**；说「熊市提高超卖阈值至 15」，15 低于 30，是**下调**）。按其真实意图重新定义：

```
s = 市场情绪指数 ∈ [0,1]
  = 基准指数(默认沪深300)近 20 日收益率在过去 250 日同类样本中的百分位

rsiOverbought = 65 + 20·s        // s=0 熊市→65   s=0.5→75   s=1 牛市→85
rsiOversold   = 15 + 20·s        // s=0 熊市→15   s=0.5→25   s=1 牛市→35
```

牛市里超卖线抬高，意味着「浅回调即视为买点」；熊市里超买线压低，意味着「小反弹即视为卖点」。这与原文的意图一致，且单调、连续、无矛盾。

### 1.7 成交量

```
VOL_MA20 = SMA(volume, 20)
放量比 ratio = volume[i] / VOL_MA20[i]
```

**盘中必须做时间归一化**，否则 10:00 的半日成交量和 20 日全天均量比较，结论永远是「缩量」：

```
盘中 ratio = 当日累计成交量 / (VOL_MA20 × 已完成交易时间占比)
已完成交易时间占比 = 已过连续竞价分钟数 / 240
```

判定：`ratio ≥ 1.2` 为放量确认；`ratio ≤ 0.8` 为缩量；`ratio ≥ 1.5` 但价格未突破关键位 → 标记为可疑（诱多/诱空）。

### 1.8 周线聚合

周线由日线本地聚合，不单独取数：按自然周分组，`open` 取周首、`close` 取周末、`high/low` 取极值、`volume` 求和。**当周未结束时，最后一根周线是 provisional 的**，与日线同理处理（§6）。周线上计算 MACD 与 ADX，供多周期共振使用。

### 1.9 穿越（金叉/死叉）判定

```
crossUp(a, b)[i]   = a[i-1] <= b[i-1] && a[i] > b[i]
crossDown(a, b)[i] = a[i-1] >= b[i-1] && a[i] < b[i]
```

任一侧为 `null` 则结果为 `false`。**穿越只在相邻两根之间判定一次**，不做「N 日内曾金叉」的模糊匹配——那会让同一次交叉在多个 tick 重复触发，去重责任本应在提醒层而非指标层。

### 1.10 数据充分性门槛

| 需求 | 最少日线 |
|---|---|
| MA5/MA20 + MACD | 40 |
| ADX | 40 |
| BOLL | 25 |
| BBW 分位 | 270 |
| 全功能 | **300** |

不足 300 根时（次新股、刚加入自选股尚未回补），引擎进入**受限模式**：跳过依赖 BBW 分位的规则，信号得分乘以惩罚系数 0.8，并在 UI 上标注「数据不足，信号可靠性降低」。少于 40 根直接不产出信号。

## 2. 市场状态层（Regime）

### 2.1 分类

| 状态 | 判定条件（同时满足） |
|---|---|
| `TREND_UP` | `ADX > adxTrendThreshold` **且** `+DI > -DI` **且** `close > MA20` **且** 多头排列得分 ≥ 2/3 |
| `TREND_DOWN` | `ADX > adxTrendThreshold` **且** `-DI > +DI` **且** `close < MA20` **且** 空头排列得分 ≥ 2/3 |
| `RANGE` | `ADX < adxRangeThreshold` **且** `BBW_PCT < 30` **且** `|close - MID| / MID < 0.03` |
| `TRANSITION` | 以上都不满足，或命中任一突变条件（见下） |

多头排列得分 = `[MA5>MA20, MA20>MA60, close>MA5]` 中为真的个数。

突变条件（任一即 `TRANSITION`）：
- `ADX` 3 日变化 > 5（趋势快速形成或瓦解）
- `BBW_PCT` 3 日变化绝对值 > 30
- `成交量 ratio > 1.5`

### 2.2 迟滞（防抖）

Regime **必须连续 2 个交易日给出同一结论才发生切换**，否则维持上一状态。震荡市里 ADX 在阈值附近反复穿越是常态，没有迟滞会导致策略权重每天翻转，比任何单一策略都糟。

盘中 regime 用 provisional 日线计算，仅用于**显示与盘中预警**；正式的 regime 切换只在收盘确认轮发生。

## 3. 策略层

每个子信号返回：

```ts
interface SubSignal {
  id: string                    // 'T1_MA_GOLDEN_CROSS'
  strategy: 'TREND' | 'MEAN_REVERSION' | 'MULTI_TF'
  direction: 'BUY' | 'SELL'
  score: number                 // 0..1，该子条件自身的强度
  weight: number                // 该子条件在所属策略内的权重
  evidence: Record<string, number | string | boolean>   // 触发时的指标原值
}
```

`evidence` 是「信号可解释」这条产品目标的落点，必须记录判定用到的每一个数值。

### 3.1 趋势跟踪策略（TREND）

| ID | 方向 | 条件 | 权重 |
|---|---|---|---|
| `T1_MA_CROSS` | BUY | `crossUp(MA5, MA20)` 且 `ADX > adxRangeThreshold` | 0.20 |
| | SELL | `crossDown(MA5, MA20)` | 0.20 |
| `T2_MACD_ZERO_CROSS` | BUY | `crossUp(DIF, DEA)` 且 `DIF > 0` 且 `HIST` 连续 2 日放大 | 0.25 |
| | SELL | `crossDown(DIF, DEA)` 且 `DIF < 0` | 0.25 |
| `T3_BREAKOUT` | BUY | `close > UPPER` 且 `BBW_PCT` 上升 且 `量比 ≥ 1.2`<br>**且 `regime ≠ TREND_UP`**（见 §3.1a） | 0.25 |
| | SELL | `close < LOWER` 且 `BBW_PCT` 上升 且 `量比 ≥ 1.2` | 0.25 |
| `T4_ALIGNMENT` | BUY | `MA5>MA20>MA60` 且 `close>MA20` 且 `ADX > adxTrendThreshold` | 0.15 |
| | SELL | `MA5<MA20<MA60` 且 `close<MA20` | 0.15 |
| `T5_PULLBACK_HOLD` | BUY | 近 5 日曾触 `UPPER`，当日回踩 `MID` 未跌破，且 `DIF > 0` | 0.15 |
| | SELL | 近 5 日曾触 `LOWER`，当日反弹至 `MID` 未站上，且 `DIF < 0` | 0.15 |

强度打分示例（`T2`）：`score = clamp(0.5 + 0.5 × min(HIST[i]/HIST[i-1] - 1, 1), 0.5, 1)` —— 柱子放大越快分越高。每个子信号的打分函数在实现时写在同一文件内并配黄金用例。

**背离检测**（`T6`，P1）：价格创 20 日新高但 `DIF` 未创新高 → 顶背离，作为卖出加成；反之为底背离。背离实现容易过拟合（「新高」的窗口选择敏感），首版只做提示不计入得分。

### 3.1a 为什么 `T3_BREAKOUT:BUY` 在 `TREND_UP` 里不成立（2026-08-15）

> **这一节是判定逻辑改动的论证，按约束 5 与 [ADR-0003](./adr/ADR-0003-来源文档数值不作为出厂默认.md)
> 必须先于代码写下来。** 验收门槛见 [docs/07 §3.6](./07-回测与验证方案.md)，
> 实测数字见 [M2 §5.24](./notes/M2-偏差报告.md)。

#### 论点：同一个指标在不同市场状态下的信息含量不同

`T3_BREAKOUT:BUY` 说的是「**收在上轨之外 + 带宽正在扩张 + 放量**」。

- 在 **RANGE / TRANSITION** 里，这是一个**状态转换**的信号：价格此前被区间约束，
  现在带着量能走出去了，「趋势可能开始」是新信息。
- 在 **已经被判定为 `TREND_UP`** 的状态里，「在涨」这件事**已经是判定前提**。
  再叠一个「又创了新高」不增加任何信息 —— 它与 `T4_ALIGNMENT`（多头排列）
  几乎必然同时成立（实测 `T4` 出现在 396/396 = **100%** 的 TREND_UP 建仓里，
  在这个状态下它已经退化成常量）。
  而「**带宽正在扩张**」这一项，在趋势中段是延续、在趋势末端是加速赶顶，
  两者在日线上无法区分。

**所以 `T3` 在 `TREND_UP` 里贡献的不是「趋势要开始了」，而是「已经涨了不少而且在加速」——
那是追高的定义。** 它在组合层的作用因此是**反向**的：把票投给了最危险的时刻。

#### 与两条已知事实的一致性

1. **票数线上的脆弱性**：TREND_UP 的 396 次建仓里 **365 次（92.2%）恰好 3 票**，
   而趋势策略的线就是 3。也就是说这些信号**全靠凑满最低票数**才触发，
   而其中一票来自一个在该状态下无信息的规则。
2. **`T4` 的零区分度**（§5.20 ⑧）：既然 `T4` 在 TREND_UP 里恒成立，
   `T2+T3+T4` 实际上只有 `T2` 与 `T3` 两条在做区分 —— 去掉无信息的 `T3` 之后
   只剩一票，本来就够不到线。

#### 边界：只动 BUY，只动 TREND_UP

- **`T3:SELL` 不动。** 跌破下轨 + 带宽扩张在任何状态下都是风险扩大的信号，
  上面那套「已经是判定前提」的推理对它不成立（`TREND_DOWN` 在本项目的实测里一次都没建过仓）。
- **`RANGE` / `TRANSITION` / `TREND_DOWN` 不动。** 论点只适用于「上升已成既定事实」的状态，
  拿一个状态的结论去改全局是 §5.5 那次乘性耦合的老毛病。
- **不新增任何数值。** 这是一条结构条件（某规则在某状态下不计票），
  不引入阈值 —— 因此不产生新的 `GUESS` 参数。这是它相对
  「趋势持续 N 根后不买」那个方案的决定性优势：后者的 `N` 只能从绩效数据里读，
  是循环论证。

#### 这条论证可能错在哪（写下来是为了将来能否证它）

- 若实测显示改动后 **`RANGE` 的表现同时变差**，说明 `T3` 的作用不是我说的这样，
  而是通过某种间接路径（比如影响了 regime 判定的下游）——那要推翻本节重来。
- 若 **砍掉的那批交易在部分子集上并不更差**，说明它抓住的是某段特定行情而不是机制。
  验收因此必须带子集稳定性检验（docs/07 §3.6 第 4 条）。

### 3.2 均值回归策略（MEAN_REVERSION）

| ID | 方向 | 条件 | 权重 |
|---|---|---|---|
| `R1_RSI_BAND` | BUY | `RSI < rsiOversold` 且 `low ≤ LOWER` | 0.30 |
| | SELL | `RSI > rsiOverbought` 且 `high ≥ UPPER` | 0.30 |
| `R2_REVERT_TO_MID` | BUY | 近 `revertLookback` 日曾 `close < LOWER`，当日 `crossUp(close, MID)` 且 `HIST` 在改善 | 0.30 |
| | SELL | 近 `revertLookback` 日曾 `close > UPPER`，当日 `crossDown(close, MID)` 且 `HIST` 在走弱 | 0.30 |
| `R3_SQUEEZE` | BUY | `BBW_PCT < squeezeBbwPct` 且 `low ≤ LOWER` | 0.20 |
| | SELL | `BBW_PCT < squeezeBbwPct` 且 `high ≥ UPPER` | 0.20 |
| `R4_MID_REVERSION` | BUY | `RANGE` 状态下 `close` 位于 `MID` 下方超过 1.5×STD | 0.20 |
| | SELL | `RANGE` 状态下 `close` 位于 `MID` 上方超过 1.5×STD | 0.20 |

> ⚠ 均值回归在下跌趋势中是**接飞刀**。因此 §4 的权重机制里，`TREND_DOWN` 状态下均值回归的买入信号权重额外乘 0.5。原文的权重表未区分趋势方向，只区分「趋势 / 震荡」，这是一个明显缺口。

> **R3 的压缩线不要再照抄 §1.4 的「< 10」。** 那个 10 是来源文档对带宽分位的定性描述
> （「变盘前夜」），直接当阈值用会让 R3 几乎不出手，进而让**整个均值回归策略测不出贡献**。
> 2026-08-12 的标定（[M2 §5.10](./notes/M2-偏差报告.md)）显示：`squeezeBbwPct = 10`
> 在两种基线下都被 docs/07 §3 的验证集红线淘汰，而 16–30 是一整片通过的高原 ——
> 换成高原上任意一个值，均值回归对组合的边际贡献从 +0.14pp（噪音带内）变成 +2.0 ~ +3.4pp。
> **出厂值已于 2026-08-12 经人工复核写回为 20**（高原上唯一在训练集与验证集上都靠前的值），
> `ENGINE_VERSION` 递增到 `0.2.5-unvalidated` —— 后缀留着，因为其余参数仍未标定。
> 依据与失效条件见 [CHANGELOG](../CHANGELOG.md)。§1.4 那张表里的「< 10 极度压缩」
> 保留原样 —— 它描述的是带宽分位的**语义分档**，不是 R3 的判定线，两者不再是同一个数。
>
> 同一轮标定还查出两条**结构**问题，不是调参能解决的：
> - `R2` 对它唯一的参数 `revertLookback` 完全惰性 —— 取 2 / 3 / 5 的回测结果逐位相同。
>   **已于 2026-08-12 改写口径**，见下方「R2 的两个条件为什么改写」。
> - `R1` 的 RSI 带宽在收紧方向上近乎惰性（±5 点内验证集分数不变），放松则更差。
>   它的双重条件（深度超卖 **且** 触轨）本来就很少同时成立。**未改**：R1 的两个条件
>   各自都是有意义的约束（不像 R2 的原第二项那样等于没有条件），惰性来自交集小，
>   属于「这条规则本来就罕见」，不构成口径错误。

#### R2 的两个条件为什么改写（2026-08-12）

原写法：`近 N 日曾 close < LOWER` **且** `当日 close > MID` **且** `HIST 转正`。
在 39 只 × 61534 根判定日上只触发 **90 次（0.15%）**，且对 `revertLookback` 逐位惰性。
用 `pnpm audit:subsignals` 把三项合取拆开逐项计数（[M2 §5.11](./notes/M2-偏差报告.md)），
根因是两项写错了，方向相反：

**① `close > MID` 太松，根本不是约束项。** 它在 **49%** 的判定日上成立 ——
价格在中轨上方或下方本来就各占一半。一个条件成立一半的时间，
放在合取里等于不存在。而它一旦不是约束项，`revertLookback` 就没有东西可以约束：
窗口放宽只会让「曾在轨道外」更容易成立，而真正卡住的那一项与窗口无关，
结果自然逐位相同。**「回归中轨」在语义上是一个事件（穿过去那一刻），
不是一个状态（已经在那边）**，这与 §2 的穿越纪律（只在相邻两根间判定一次）一致，
原写法是那条纪律的一处漏网。

**② `HIST 转正` 太紧，而且与回溯窗口的时间常数差一个量级。**
`HIST` 过零等价于 `DIF` 上穿 `DEA`，是慢事件：实测在一次收盘破下轨之后，
到最近一次 `HIST` 过零的中位数间隔在 **35 根以上**，19–26% 的样本 60 根内根本没有。
而 `revertLookback` 只有 2–5 根。两个条件在时间尺度上凑不到一起 ——
这不是阈值取错，是把两个不同量级的时间常数写进了同一个合取。
`HIST` 在这里的职责只是「动量别还在恶化」，**软确认足够，不需要它翻转过零**。

改后：**曾在轨道外（窗口）+ 今日穿越中轨（事件）+ `HIST` 朝有利方向（软确认）**。
触发数 90 → **213（0.35%）**，`revertLookback` 变成活参数且单调
（取 3 → 213、取 5 → 592、取 11 → 1807）。

> ⚠ **改写没有换来绩效，这一点必须如实记着**：全期（39 只，2018-01-01→2026-08-11）
> 769 笔 / +5.93% / 夏普 0.54，对比改写前 762 笔 / +6.25% / 0.57，略差；
> `revertLookback` ∈ {3,5,8,12,20} 的**验证集结果逐位相同**（Calmar 全 0.084）。
> 保留改写的理由是口径正确、参数可标定，不是它更赚钱。
>
> 而验证集为什么仍然不动，共现测量给出了答案，它指向**组合层而不是这一层**：
> 213 次 R2 触发里 **185 次（87%）是孤立的** —— 同一根上没有任何同方向的其他
> 均值回归子信号。原因是几何互斥：R2 要求价格**在中轨上**，而 R1 / R3 要求触外轨、
> R4 要求偏离中轨 ≥ `midReversionStd × STD`。而 `combine.voteThreshold.meanReversion = 2`
> 要求同策略两票。**R2 靠自己永远凑不够票**，只能通过得分微调影响结果。
> 真正的约束落在票数线上，那是 §4.2 的参数，归入 `combine` 那一轮标定。

### 3.3 多周期共振（MULTI_TF）

| ID | 方向 | 条件 | 作用 |
|---|---|---|---|
| `M1_WEEK_MACD_DAY_RSI` | BUY | 周线 `crossUp(DIF,DEA)`（近 3 周内）且 日线 `RSI < 45` | 加成 +0.10 |
| | SELL | 周线 `crossDown(DIF,DEA)`（近 3 周内）且 日线 `RSI > 55` | 加成 +0.10 |

## 4. 组合层

### 4.1 策略等权（动态权重已于 2026-08-12 删除）

**两个策略等权相加。市场状态不再影响任何一个方向的得分**，只剩一处方向级抑制：

| 条件 | 系数 | 参数 |
|---|---|---|
| `TREND_DOWN` 状态下**均值回归的买入**信号 | ×0.5 | `combine.downtrendBuyPenalty` |
| 其余全部情形 | ×1 | — |

那条折价的理由见 §3.2 末尾：下跌趋势里抢反弹是接飞刀。它只乘在均值回归那一项上 ——
是「别接飞刀」，不是「下跌趋势里什么信号都不可信」。它**从未被单独标定过**（ADR-0003）。

> **这里原本有一张按市场状态切换策略权重的表**（`TREND_UP` 0.70/0.30、`RANGE` 0.30/0.70…），
> 它是整套设计的核心假设：「按市场状态切换策略权重能提升表现」。假设被测了两轮：
>
> 1. 第一轮发现权重表与 `scoreThreshold` 存在乘性耦合（详见 §4.2 的 ⚠ 块），
>    `TRANSITION` 下单策略信号在算术上无法触发 —— 那是口径 bug，先解掉；
> 2. 第二轮在解耦后重测：动态权重与固定 0.5/0.5 的差值在四个参数点上正负交替、
>    都在 1pp 以内。**看不出效果，且这次不能再归咎于耦合。**
>
> [docs/07 §2.2](./07-回测与验证方案.md) 对这种情况的规定是「这个假设就该被推翻，
> 而不是保留一套复杂而无效的机制」，于是权重表整张删除，回测里的固定权重对照组一并删除。
> 判据见 [M2 偏差报告 §5.5–§5.8](./notes/M2-偏差报告.md)，决策记录见
> [docs/08 关键决策点 2](./08-开发路线图.md)。
>
> **不要把它加回来。** 要重新表达「某状态下某策略更可信」，得先说清楚新机制与旧机制差在哪，
> 并单独标定；尤其不能靠压低某一行的两个数来表达「这个状态整体不可信」——
> 那会原样复现第 1 条那个耦合坑。

### 4.2 得分与投票

```
对每个方向 d ∈ {BUY, SELL}：
  part(s,d)   = 加权平均( 已成立子信号的 sub.score, 按 sub.weight )    // 0..1，策略内平均强度
  penalty(s,d)= 均值回归 & BUY & TREND_DOWN ? downtrendBuyPenalty : 1  // §4.1 的唯一一处抑制
  rawScore(d) = clamp( Σ_strategies  part(s,d) × penalty(s,d), 0, 1 )
  adjusted(d) = rawScore(d) + Σ multiTfAdjustments(d)
  final(d)    = clamp(adjusted(d), 0, 1) × dataSufficiencyPenalty
  votes(s,d)  = 该策略里满足 sub.score ≥ 0.5 的子信号个数            // 按策略分开数

触发条件：final(d) ≥ 0.60  且  **任一策略** votes(s,d) ≥ voteThreshold[s]
方向裁决：
  两个方向都触发 → 取 final 较高者
  |final(BUY) - final(SELL)| < 0.15 → 判为矛盾，不产出信号（记录到 signal 表但 direction=NONE）
```

阈值 `0.60` 与票数线来自原文「3/5 策略一致确认胜率提高至 68%」的说法，属于**待标定参数**，出厂值由回测确定，并暴露在设置中（「灵敏 / 均衡 / 保守」三档预设分别对应 0.50/(2,2)、0.60/(3,2)、0.72/(4,3)）。

**票数线为什么按策略分开**（2026-08-12）：趋势有 5 个子信号（T1–T5），均值回归只有 4 个（R1–R4）。
共用一条「≥ 3 票」，对前者是五中取三（60%）、对后者是四中取三（75%）—— 同一句「一致性要求」
落到两个策略上不是同一个门槛。实测后果很直接：出厂参数下均值回归**一次都没独立触发过**
（[M2 §5.7](./notes/M2-偏差报告.md)）。现在每档按同一个比例换算再取整：
趋势 2/3/4 票即 40%/60%/80%，均值回归 4 × 同比例 = 1.6/2.4/3.2 ⇒ 2/2/3 票。

合并规则取「**任一策略达到自己的线**」，不是把两边的票加起来：票数衡量的是
*同一个策略内部*有多少条规则互相印证，「趋势 2 票 + 均值回归 1 票」凑出来的 3 不具备这个含义
（跨策略的互相印证已经由 §4.2 第一行的得分相加表达过了）。

得分与票数分工明确：**强度由 `final` 负责、一致性由 `votes` 负责**。

**冲突裁决「压掉双方」已经过消融验证（2026-08-12）**，是四个 combine 参数里第一个有实测依据的
*机制*（不是取值）。争议在于矛盾时该压掉双方还是让弱侧让路 —— 后者等价于 `conflictBand = 0`
（差值 < 0 恒假），不需要改代码就能测。全期 39 只、`sq20` + 新 R2：

| `conflictBand` | 交易 | 总收益 | 夏普 | 最大回撤 | 交易成本 |
|---|---|---|---|---|---|
| 0.00（= 弱侧让路） | 897 | +5.67% | 0.473 | 2.50% | 48966 |
| 0.05 | 847 | +5.72% | 0.497 | 2.47% | 45680 |
| **0.15（出厂）** | **769** | **+5.93%** | 0.543 | 2.44% | 42067 |
| 0.30 | 689 | +5.56% | 0.572 | 2.13% | 36485 |
| 0.50 | 679 | +5.82% | **0.596** | 2.13% | 36214 |
| 0.80 | 679 | +5.82% | 0.596 | 2.13% | 36214 |

**弱侧让路在每一个维度上都更差**：多出来的 128 笔交易带来 −0.26pp 收益、−0.070 夏普、
+0.06pp 回撤和 +6900 的手续费。多空得分几乎相等时，那一笔本来就不该做。

0.50 与 0.80 **逐位相同** —— 机制在此饱和（897 − 679 = 218 笔是「可争议」交易的全部，
band ≥ 0.5 时全部被压掉）。这条饱和很重要：它说明夏普的单调上升**不是**「少交易所以看起来稳」
的无界代理，否则把 band 一路放大应该一路变好。

> ⚠ **这张表证的是机制，不是取值。** 它跑的是全区间，没有走 docs/07 §3 的三段切分，
> 因此**不能**据此说「`conflictBand = 0.15` 已标定」—— 收益在 0.15 最高但 0.50 的夏普更高，
> 两者收益差 0.11pp 在噪音带内。取值仍要在 `combine` 块那一轮按训练/验证集定。
> 数据见 [M2 §5.12](./notes/M2-偏差报告.md)。
`rawScore` 的含义是「已成立规则的平均强度」，在四个 Regime 之间可比 ——
`alert.bubbleScore` 这类分级线才有一致含义。两个策略同向共振时和会超过 1，夹到 1；
夹紧点放在加调整项**之前**，否则 §3.3 的 `M3_FALSE_BREAKOUT`（−0.15）会被溢出的那一截吸收掉，
在最该起作用的强共振场景里反而失效。代价是顶部不再有分辨率，那一段的区分交给 `votes`。

> ⚠ **式子里为什么没有策略权重了 —— 一个值得记住的坑。**
> 原式写作 `strategyWeight × Σ_subs`，而 `Σ_subs` 在实现里是**已成立子信号的加权平均**
>（0..1，见 [M2 偏差报告 §1](./notes/M2-偏差报告.md)），两者相乘的后果是
> **单策略得分的上限恰好等于该策略在当前 Regime 的权重**：
>
> | Regime | 只有趋势 | 只有均值回归 |
> |---|---|---|
> | `TREND_UP` | 0.70 | 0.30 |
> | `RANGE` | 0.30 | 0.70 |
> | `TRANSITION` | **0.50** | **0.50** |
>
> 按上表，出厂阈值 `0.60` 在 `TRANSITION` 下**单策略永远无法触发**，而实测 `TRANSITION`
> 占判定根的 66.6%；保守档 `0.72` 高于所有单策略上限，任何状态下都只能靠两个策略同向共振。
> 这两个数取自来源文档的不同段落，从未相互校对（ADR-0003 的典型场景）—— 2026-08-12 的归因才发现
> （[M2 偏差报告 §5.5](./notes/M2-偏差报告.md)，含 `pnpm audit:regime` 的成因分解）。
>
> 当时的修法是除以「该 Regime 行内的最大权重」，把权重表降格成「相对可信度」；
> 后来权重表整张删掉（§4.1），这个分母也就一并没有了。但**填掉这个坑的是删除，不是设计** ——
> 只要将来有人再引入状态相关的系数，同样的耦合就可能复现。
> 因此 `tests/unit/combine/combine.test.ts` 单独钉着一条不变量：
> **任何 ≤1 的阈值，在任何市场状态下都必须够得着**（出厂档与保守档各一条）。
> **它变红是提醒你回来复核本节，不是让你改断言。**

### 4.3 置信度展示

`confidence = final(d)`，UI 上展示为百分比。**明确不把它叫做「胜率」**——它是规则一致性的度量，不是概率预测。这个措辞区分在 UI 文案评审时要守住。

## 6. 盘中临时值 vs 收盘确认

这是本项目最容易出错、也最影响用户体验的一点。

| | 盘中（`PROVISIONAL`） | 收盘后（`CONFIRMED`） |
|---|---|---|
| 数据 | 最后一根 K 线由实时快照构造，会持续变化 | 真实收盘 K 线 |
| 指标 | 会抖动，穿越可能出现又消失 | 稳定 |
| 用途 | 预警：「可能出现买点，注意观察」 | 结论：「今日收盘确认买入信号」 |
| 提醒强度 | 最高 L2（气泡，无声） | 可达 L3（系统通知） |
| 得分 | × 0.9 折扣 | 原值 |

**确认轮**（15:00–15:10）：重算当日全部自选股，把当日 `PROVISIONAL` 信号逐条比对：

- 收盘仍成立 → `stage = CONFIRMED`，发 L3
- 收盘不再成立 → `stage = INVALIDATED`，**主动发一条撤销提示**（L1，仅表情+面板标记，不弹窗）

主动告知失效，比让用户自己发现「早上那个提醒没了」更可信。

## 7. 测试策略

`src/core` 的每个指标都需要三类测试：

1. **黄金用例**：一段固定的 60 根 K 线 fixture，逐指标断言前 10 个与后 10 个值（数值来自独立实现的交叉验证，见 [07](./07-回测与验证方案.md)）。
2. **边界用例**：全平（无波动 → STD=0，BBW 除零）、单调上涨（RSI=100、avgLoss=0）、含涨跌停、长度不足、数据带缺口。
3. **属性测试**：如 `SMA` 输出必须落在窗口 min/max 之间；`RSI ∈ [0,100]`；`ADX ∈ [0,100]`；`UPPER > MID > LOWER`（STD>0 时）。

策略层测试用**人工构造的场景 fixture**（「一段标准的金叉放量突破」「一段假突破」），断言产出的 `SubSignal.id` 集合与方向，而不断言具体分数——分数会随参数标定变化，断言它会让测试变成噪音。
