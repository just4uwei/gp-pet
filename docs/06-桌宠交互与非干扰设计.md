# 06 · 桌宠交互与非干扰设计

## 1. 零干扰契约

桌宠常驻置顶，天然具备干扰性。以下每一条都是**硬性验收项**，实现时逐条写成手工验收清单：

| # | 契约 | 验证方法 |
|---|---|---|
| C1 | 永不抢焦点 | 打字过程中触发提醒，输入不中断、光标不丢失 |
| C2 | 非本体区域鼠标事件穿透 | 桌宠矩形窗口内的透明部分，点击应作用于下层应用 |
| C3 | 不出现在任务栏与 Alt-Tab | `skipTaskbar: true`；`Alt+Tab` 列表中不可见 |
| C4 | 不遮挡全屏应用 | 全屏/演示状态下自动隐藏或降为最底层 |
| C5 | 默认无声 | 仅 L3 且用户显式开启才发声 |
| C6 | 提醒自动消失 | 气泡 6s 后淡出，不需要用户点击关闭 |
| C7 | 休市零开销 | 休市时 CPU ≈ 0，动画降至 6fps 或暂停 |
| C8 | 一键静默 | 双击桌宠立即进入免打扰，无需进设置 |
| C9 | 可完全隐藏 | 托盘菜单「隐藏桌宠」后只保留托盘，功能不减 |
| C10 | 崩溃不留残影 | 进程异常退出不残留置顶透明窗口 |

**C1 与 C2 是底线**，任何为了视觉效果而牺牲它们的方案一律否决。

## 2. 窗口配置

### 2.1 Overlay 窗口（悬浮条 / 桌宠两形态）

常驻置顶的那个窗口有两种形态，由 `AppSettings.appearance` 决定：

| 形态 | 值 | 尺寸 | 内容 | 素材依赖 |
|---|---|---|---|---|
| **悬浮条**（**出厂默认**） | `BAR` | 240×38 | 状态点 + 一只标的的名称/价格/涨跌 + 今日信号条数 | **无** |
| 桌宠 | `PET` | 220×220 | 皮肤精灵图（缺资源回退占位皮肤） | `resources/pet/<skin>/` |

**两种形态共用同一个窗口类**（`src/main/windows/OverlayWindow.ts`）与下面这一整套配置 ——
形态之间只差窗口尺寸与渲染入口（`src/renderer/bar/` vs `src/renderer/pet/`）。
C1/C2/C3/C10 的实现因此与形态无关，换形态不需要重新论证零干扰契约。
IPC 通道名仍是 `pet:*`（历史原因，改名要动 preload 与两个渲染入口而无功能收益）。

> **出厂默认为什么是悬浮条**：这是 2026-08-13 的产品选择，**不是** [docs/08 决策点 1](./08-开发路线图.md)
> 那条退路被触发 —— C1/C2 尚未真机验收，没有任何证据说明桌宠形态做不到。
> 选它的理由是「一行字比一只猫更快说清发生了什么」，且默认形态不再依赖外包素材。
> 桌宠没有被删，托盘菜单「外观」可随时切回。

```ts
new BrowserWindow({
  ...OVERLAY_SIZE[form],       // BAR 240×38 / PET 220×220
  transparent: true,
  frame: false,
  resizable: false,
  alwaysOnTop: true,
  skipTaskbar: true,
  focusable: false,          // ← C1 的根本保证
  hasShadow: false,
  show: false,               // 就绪后用 showInactive()
  webPreferences: { contextIsolation: true, nodeIntegration: false, sandbox: true },
})
win.setAlwaysOnTop(true, 'screen-saver')   // 高于普通置顶窗口，但低于全屏独占
win.setVisibleOnAllWorkspaces(true)
```

`focusable: false` 意味着窗口内**无法接收键盘事件**。两种形态都不需要键盘输入，交互全靠鼠标；需要键入的场景（搜索股票、改设置）都在 Panel 窗口里，Panel 是正常可聚焦窗口。这个划分让 C1 成为结构性保证而非小心翼翼的运行时约束。

**悬浮条形态下 C2 的形状不同**：桌宠窗口比本体大一圈、四周是透明留白，所以命中区要描出轮廓；
悬浮条是**窗口即本体**，只有四个圆角需要穿透，命中区因此是「整块减掉四个角」的三个矩形
（`src/renderer/bar/App.tsx` 的 `barHitRects`）。判据仍是同一个 `hitTest`。

### 2.2 点击穿透（C2）

Electron 只提供窗口级的 `setIgnoreMouseEvents`，没有像素级命中测试。方案：

```
默认状态：win.setIgnoreMouseEvents(true, { forward: true })
           ↑ forward:true 让窗口仍能收到 mousemove 事件用于判定

渲染层监听 mousemove → 用命中区判定鼠标是否落在桌宠本体上
  ├─ 进入本体 → IPC 通知主进程 setIgnoreMouseEvents(false)  → 可点击、可拖拽
  └─ 离开本体 → IPC 通知主进程 setIgnoreMouseEvents(true, {forward:true})
```

命中区的三种实现，按精度递增：

1. **矩形近似**（首版）：皮肤配置 `skin.json` 里声明若干矩形，覆盖桌宠身体与气泡触发点。实现简单、零性能开销，边缘略不精确。
2. **Alpha 掩码**：加载精灵图到离屏 canvas，读 `ImageData` 的 alpha 通道，鼠标位置 alpha > 阈值即命中。精确，需在皮肤加载时预计算一张位图掩码。
3. CSS `pointer-events` + `document.elementFromPoint`：适合 DOM 构成的桌宠，对精灵图动画不适用。

首版走 1，皮肤系统预留 2 的接口。

> **已知坑**：`forward: true` 在部分 Windows 版本下，若窗口完全透明且下层是 DirectX 全屏应用，`mousemove` 可能不达。因此 C4 的全屏检测独立于此机制，不依赖鼠标事件。

### 2.3 Bubble 窗口

与 Pet 同配置，额外：`setIgnoreMouseEvents(true, {forward:true})` 常开——气泡**完全不可点击**，只能等它自己消失或被新气泡替换。可点击的气泡会诱使用户去关它，那本身就是打断。要看详情请点桌宠打开面板。

### 2.4 Panel 窗口

正常窗口：有边框、可聚焦、出现在任务栏、可最大化。它是「主动查看」的场所，不受零干扰契约约束。默认懒加载，首次打开才创建，关闭时 `hide()` 而非 `destroy()`。

## 3. 桌宠状态机

```
                  ┌──────────────┐
     休市/免打扰 ─▶│   SLEEPY     │ 打哈欠、闭眼、极低帧率
                  └──────┬───────┘
                         │ 开盘
                  ┌──────▼───────┐
        无事发生 ─▶│    IDLE      │ 呼吸、偶尔眨眼、左右张望
                  └──┬────────┬──┘
        有信号在算 ──▶│        │◀── 信号消失/被确认
                  ┌──▼──────┐ │
                  │ WATCHING│ │ 竖起耳朵、盯屏幕
                  └──┬──────┘ │
          买入信号 ───┤        ├─── 卖出信号
        ┌────────────▼┐    ┌──▼───────────┐
        │  EXCITED    │    │  ALERT       │
        │ 跳跃、亮眼  │    │ 警惕、举旗   │
        └─────────────┘    └──────────────┘
                  ┌──────────────┐
   数据源全部失败 ▶│  OFFLINE     │ 灰调、断线图标
                  └──────────────┘
```

状态由主进程推送（`push:petState`），渲染层只负责播放对应动画。**状态优先级**：`OFFLINE > ALERT > EXCITED > WATCHING > IDLE > SLEEPY`，高优先级状态播完最短驻留时长（3s）后回落。

情绪强度映射信号得分：得分 0.6→轻微反应，0.9→夸张反应。同一状态用一套动画 + 强度参数，而非做两套素材。

## 4. 交互手势

| 操作 | 行为 |
|---|---|
| 左键拖拽 | 移动桌宠；松手时若靠近屏幕边缘（< 30px）则吸附 |
| 单击 | 打开/关闭 Panel 窗口 |
| 双击 | 切换免打扰（C8），桌宠做一个「嘘」的动作反馈 |
| 右键 | 上下文菜单：打开面板 / 免打扰 30min·2h·至收盘 / 隐藏桌宠 / 设置 / 退出 |
| 悬停 1s | 显示极简 tooltip：当前市场状态 + 未读信号数（不显示具体股价，避免旁人窥屏） |
| 滚轮 | 无绑定（避免与下层应用滚动冲突） |

多显示器：位置以「显示器 ID + 相对坐标」存储，显示器拓扑变化（拔插外接屏）时校验坐标是否仍在可见区域内，越界则回落到主屏右下角。

## 5. 皮肤系统

```
resources/pet/<skinName>/
├─ skin.json
├─ idle.png        精灵图集
├─ excited.png
├─ alert.png
└─ ...
```

```jsonc
// skin.json
{
  "name": "默认",
  "canvas": { "width": 200, "height": 200 },
  "anchor": { "bubbleX": 100, "bubbleY": 20 },   // 气泡相对桌宠的锚点
  "hitRects": [ { "x": 60, "y": 70, "w": 80, "h": 110 } ],
  "states": {
    "idle":    { "sheet": "idle.png", "frames": 8, "fps": 8, "loop": true },
    "excited": { "sheet": "excited.png", "frames": 12, "fps": 12, "loop": false, "minHold": 3000 }
  }
}
```

用户皮肤放在 `%APPDATA%/gp-pet/skins/`，同名覆盖内置。加载时对 `skin.json` 做 schema 校验，失败则回退默认皮肤并在面板提示——**不弹窗**。

## 6. 性能预算

| 场景 | CPU（单核占比） | 内存 |
|---|---|---|
| 休市待机 | < 0.5% | < 200 MB |
| 盘中 IDLE 动画 | < 2% | < 250 MB |
| 盘中 tick 计算（100 只） | 峰值 < 15%，持续 < 500ms | +30 MB 瞬时 |
| Panel 打开 | < 5% | +80 MB |

手段：
- 动画用 CSS `transform` + `will-change`，走合成层，不触发布局
- 窗口不可见 / 免打扰时调用 `win.webContents.setFrameRatesLimit`-等价手段降帧，或直接 `cancelAnimationFrame`
- 指标计算是纯 CPU，100 只 × 300 根的全量重算实测应在 100ms 量级；若超预算则移入 `utilityProcess`，**不放主线程阻塞窗口响应**
- 增量计算：只有最后一根 K 线变化时，MA/EMA/Wilder 类指标可 O(1) 增量更新（保留内部状态），首版可先全量，性能不足时再优化
