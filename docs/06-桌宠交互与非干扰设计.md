# 06 · 悬浮条交互与非干扰设计

> **文件名里的「桌宠」是历史。** 2026-08-13 移除了桌宠形态与整套皮肤系统，
> 常驻置顶窗口只剩**悬浮条**一种形态。文件名没改是因为它被 CLAUDE.md 与另外几篇文档
> 按路径引用，改名的收益不抵改链接的噪音。

## 1. 零干扰契约

常驻置顶窗口天然具备干扰性。以下每一条都是**硬性验收项**，实现时逐条写成手工验收清单：

| # | 契约 | 验证方法 |
|---|---|---|
| C1 | 永不抢焦点 | 打字过程中触发提醒，输入不中断、光标不丢失 |
| C2 | 非本体区域鼠标事件穿透 | 窗口内的透明部分（悬浮条的四个圆角），点击应作用于下层应用 |
| C3 | 不出现在任务栏与 Alt-Tab | `skipTaskbar: true`；`Alt+Tab` 列表中不可见 |
| C4 | 不遮挡全屏应用 | 全屏/演示状态下自动隐藏或降为最底层 |
| C5 | 永不发声 | 提醒没有任何声音渠道（2026-08-13 起系统通知连同发声能力一并移除） |
| C6 | 提醒自动消失 | 气泡 6s 后淡出，不需要用户点击关闭 |
| C7 | 休市零开销 | 休市时 CPU ≈ 0，动画降至 6fps 或暂停 |
| C8 | 一键静默 | 右键菜单 / 托盘菜单一步进入免打扰，无需进设置页（见 §4 的注） |
| C9 | 可完全隐藏 | 托盘菜单「隐藏悬浮条」后只保留托盘，功能不减 |
| C10 | 崩溃不留残影 | 进程异常退出不残留置顶透明窗口 |

**C1 与 C2 是底线**，任何为了视觉效果而牺牲它们的方案一律否决。

## 2. 窗口配置

### 2.1 Overlay 窗口（悬浮条）

常驻置顶的窗口只有一种形态（`src/main/windows/OverlayWindow.ts`）：

| 尺寸 | 内容 | 素材依赖 |
|---|---|---|
| 300×38 | 状态点 + **全部自选轮流滚过**（名称/价格/涨跌 + 方向标注）+ 今日信号条数 | **无** |

IPC 通道名仍是 `pet:*`（历史原因，改名要动 preload 与渲染入口而无功能收益）。

> **桌宠形态去哪了**：2026-08-13 连同整套皮肤系统一起移除。这**不是** [docs/08 决策点 1](./08-开发路线图.md)
> 那条退路被触发 —— C1/C2 尚未真机验收，没有任何证据说明桌宠形态做不到。
> 理由是产品选择：「一行字比一只猫更快说清发生了什么」，且这样整个产品不依赖任何美术素材。
> 相关代码、`resources/pet/`、`tools/asset-build/` 与 docs/09 都已删除，历史在 git 里。

```ts
new BrowserWindow({
  ...OVERLAY_SIZE,             // 300×38
  transparent: true,
  frame: false,
  resizable: false,
  alwaysOnTop: true,
  skipTaskbar: true,
  focusable: false,          // ← C1 的根本保证
  hasShadow: false,
  show: false,               // 就绪后用 showInactive()
  webPreferences: { contextIsolation: true, nodeIntegration: false, sandbox: true },
})
win.setAlwaysOnTop(true, 'screen-saver')   // 高于普通置顶窗口，但低于全屏独占
win.setVisibleOnAllWorkspaces(true)
```

`focusable: false` 意味着窗口内**无法接收键盘事件**。悬浮条不需要键盘输入，交互全靠鼠标；需要键入的场景（搜索股票、改设置）都在 Panel 窗口里，Panel 是正常可聚焦窗口。这个划分让 C1 成为结构性保证而非小心翼翼的运行时约束。

**C2 的形状**：悬浮条是**窗口即本体**，没有透明留白，只有四个圆角需要穿透 ——
命中区因此是「整块减掉四个角」的三个矩形（`src/renderer/bar/App.tsx` 的 `barHitRects`），
圆角半径必须与 `styles.css` 的 `border-radius` 一致，大了会盖到圆角外、吞掉本该穿透的点击。
**命中区必须跟着窗口尺寸重算**，不能只在挂载时算一次 —— 尺寸一旦与命中区不符，
鼠标压在条子上却被判成穿透，症状是「点什么都没反应」，而用户无从归因（2026-08-13 实际发生过，
成因见 `OverlayWindow.moveTo` 的注释：`setPosition` 在非 100% 缩放的显示器上会把窗口一点点撑大）。

**内容是一条跑马灯**（2026-08-13 改）：全部自选依次滚过，每只带一个方向标注
（买入 / 卖出 / 减仓 / 明日观察 / 观察，措辞与面板的今日信号列表同源）。顺序判据是纯函数
`src/shared/ticker.ts`：**今日有未静默信号的在前**（按置信度降序），其余按 |涨跌幅| 降序，
同分同幅按代码升序兜底。三条约束跟着零干扰契约与措辞纪律走：

- **今天没有信号写「无信号」**，不写「观望」「持有」之类看起来像结论的词 —— 引擎没说话，条子不替它说。
- **装得下就不滚**（内容宽度 ≤ 可视区时不加动画），**休市 / 离线 / 免打扰时暂停**（C7），鼠标悬停时也暂停。
  **悬停这一半的「离开」只有主进程判得准**（2026-08-14 修了两次）。
  不能用 CSS `:hover`：鼠标一离开本体，主进程就 `setIgnoreMouseEvents(true, { forward: true })`，
  窗口从此不参与 OS 命中测试，mouseout 送不到渲染层，`:hover` 永久停在 true。
  **换成渲染层的命中判定也不够**：它跑在 `mousemove` 上，而鼠标移出窗口之后就没有
  `mousemove` 了 —— 最后收到的那一次坐标仍然落在本体内。`document` 上的 `mouseleave`
  本来是兜底，实测在这个窗口上不可靠。
  现在「进入」归渲染层（只有它知道四个圆角），「离开」归 `OverlayWindow.watchPointer()`：
  按 `screen.getCursorScreenPoint()` 轮询（只在压着条子时跑，拖拽期间闭嘴），
  结论经 `push:overlayPointer` 回渲染层，与 C7 那三种情况合成同一个 `.track--paused`。
  这条同时补上了 **C2 的一个洞**：窗口停在可交互状态会吃掉下层那一小块的点击，
  而用户只会觉得「那个位置有时候点不动」。
- 条子上出现了方向标注，那句固定小字（§5「仅供参考，非投资建议」）就跟着轮播过一遍；没有标注时不占位置。

### 2.2 点击穿透（C2）

Electron 只提供窗口级的 `setIgnoreMouseEvents`，没有像素级命中测试。方案：

```
默认状态：win.setIgnoreMouseEvents(true, { forward: true })
           ↑ forward:true 让窗口仍能收到 mousemove 事件用于判定

渲染层监听 mousemove → 用命中区判定鼠标是否落在悬浮条本体上
  ├─ 进入本体 → IPC 通知主进程 setIgnoreMouseEvents(false)  → 可点击、可拖拽
  └─ 离开本体 → IPC 通知主进程 setIgnoreMouseEvents(true, {forward:true})
```

命中区用**矩形近似**：渲染层按窗口尺寸算出三个矩形并经 `pet:setHitRegion` 上报，
判定在渲染层用 `src/shared/hit-test.ts` 完成。悬浮条是矩形本体，这个近似是精确的
（唯一的近似发生在四个圆角上，而那里的取舍是「宁可少覆盖」）。

**命中区必须跟着窗口尺寸重算**，不能只在挂载时算一次 —— 尺寸一旦与命中区不符，
鼠标压在条子上却被判成穿透，症状是「点什么都没反应」，而用户无从归因（2026-08-13 实际发生过，
成因见 `OverlayWindow.moveTo` 的注释：`setPosition` 在非 100% 缩放的显示器上会把窗口一点点撑大）。

> **已知坑**：`forward: true` 在部分 Windows 版本下，若窗口完全透明且下层是 DirectX 全屏应用，`mousemove` 可能不达。因此 C4 的全屏检测独立于此机制，不依赖鼠标事件。

### 2.3 Bubble 窗口

与 Overlay 同配置，额外：`setIgnoreMouseEvents(true)` 常开（`forward: false` —— 气泡不做命中判定，连 mousemove 都不必收）。气泡**完全不可点击**，只能等它自己消失或被新气泡替换。可点击的气泡会诱使用户去关它，那本身就是打断。要看详情请双击悬浮条打开面板。

**气泡是提醒唯一的可见出口**（2026-08-13 起）：托盘角标、图标闪烁与系统通知都已移除，所以它建不出来 = 用户什么都看不到。锚点跟着悬浮条走，条子被隐藏（C9）时退到主屏右下角，仍然要弹。

### 2.4 Panel 窗口

正常窗口：有边框、可聚焦、出现在任务栏、可最大化。它是「主动查看」的场所，不受零干扰契约约束。默认懒加载，首次打开才创建，关闭时 `hide()` 而非 `destroy()`。

**标题栏由页面自己画**（2026-08-13）：`titleBarStyle: 'hidden'` + `titleBarOverlay`，
颜色取 `--gp-surface`，与页面头部**同一个色**，于是顶部只有一条连续的深色横条而不是
「白标题栏 + 暗面板」的分界。窗口控件（最小化/最大化/关闭）仍由系统绘制 ——
自绘控件在 Windows 上永远差一口气（悬停高亮、Snap Layouts、高对比度主题都得自己补）。

> 为什么不用 `nativeTheme.themeSource = 'dark'`：那只能换来系统那个近黑灰（#1f1f1f 一类），
> 与面板仍差一档，「一致」这个要求达不到。
>
> 代价有两条，改头部时必须一起想到：
> 1. 拖窗口靠头部的 `-webkit-app-region: drag`，所以**头部里每一个可点的东西都要 `no-drag`**
>    （否则点它等于拖窗口，症状是按钮「点不动」）。
> 2. 右上角那块归系统（三颗控件约 3×46px，高 `TITLE_BAR_HEIGHT = 40`），头部第一行留了
>    `pr-[144px]`。`PanelWindow.ts` 与 `panel/App.tsx` 这两个数**成对**，别只改一处。

**布局是两栏，页面本身不滚**（`src/renderer/panel/`）：

```
┌─────────────────────────────────────────────────────┐
│ 蹲点            [导出配置][导入配置][刷新]           │  头部：品牌 + 全局动作
│ 时段 上午盘  自选 12 只  eastmoney 正常 98% …        │  状态 chip 行
├──────────────────────────┬──────────────────────────┤
│ 自选股            12 只  │ 今日信号     含被静默 3 条│
│ [添加自选…    ][添加]    │ ┌──────────────────────┐ │
│ ├ 名称  代码  价 涨跌 ⚙  │ │ 卖出 XX  置信 78%  ▸ │ │
│ │  （持仓录入就地展开）  │ │ [卖出4条][买入1条] ▸ │ │
│ └ …（内部滚动）          │ │  └ 展开：旧信号+分时 │ │
│                          │ │ …（内部滚动）        │ │
│                          │ └──────────────────────┘ │
│                          │ 提醒日志  2 条未读  展开 │
└──────────────────────────┴──────────────────────────┘
│ 仅供参考，非投资建议                                 │
└─────────────────────────────────────────────────────┘
```

**点自选行打开详情抽屉**（2026-08-14）：一只标的一个抽屉，三个页签 ——
行情（当日分时 + 60 根日 K）· 信号（今日全部 + 依据 / AI）· 持仓（成交录入 + 流水 + 盈亏）。
三个入口各自落在对应页签：行本体 → 行情，「仓」按钮 → 持仓，信号徽标行 → 信号。
**同一只股票只有一个详情页** —— 做成两个抽屉的话，用户得记住自己是从哪进来的。

持仓不再有「直接改股数与成本」的入口：它由成交流水推出来（docs/03 §4.3 的 `trade_log`）。
覆盖式改数与流水记账并存会让两者静默分叉，而**一个对不上的盈亏数字比没有这个数字更坏**。

左栏是**我关心哪些票**（自选 + 持仓概要），右栏是**今天发生了什么**（信号 + 提醒判定）。
拆栏的理由不是「填满宽度」，而是这两件事的刷新节奏不同：自选是偶尔改一次的清单，
信号是每轮 tick 都在长的流水 —— 挤在一列里滚动时，改自选要先滚过一屏信号。

**今日信号按标的分组**（2026-08-14）：同一只票一天里会出好几条（盘中每轮 tick 都可能
产出 `PROVISIONAL`，收盘轮再来一条 `CONFIRMED` 或 `INVALIDATED`），平铺时一只票就能把
这个 ~300px 宽的列表刷满。现在同一 `code` 收成一组，常显最新那条，其余折叠在徽标行下 ——
**外加用户正展开着的那一条**（见下面第 3 条，那是个会烧钱的坑）。

五件事要一起看：

1. **两个入口是分开的。** 主行点击 → 就地展开依据（+ 一个开 AI 抽屉的按钮）；
   徽标行点击 → **打开右侧抽屉**（同股全部信号 + 带坐标轴的当日分时图）。
   并成一个会变成「点一下弹出两坨东西」，而这两件事想看的时机完全不同。
   抽屉走 portal 挂在 `document.body` 上（右栏 `overflow-hidden` 会裁掉 `absolute`），
   **`top` 从 40px 起** —— 面板的右上角那一块归系统窗口控件，盖住它用户就关不掉窗口了。

   **AI 解读是第三层的入口**（2026-08-14）：它自己一层抽屉，叠在 `StockDrawer` 之上，
   状态挂在 `App`。这不是版面问题而是正确性问题 —— 它原先内嵌在信号行里，
   而那个列表每轮 tick 都在重排，正在流式生成的解读会被卸载、请求被取消，
   用户看到的是「等了四十秒的分析界面自己没了」，且那次调用已经计过费。
   连带三条：**关抽屉不取消**（请求跑完并落库，重开时靠 service 的在途去重接上）；
   **打开抽屉不等于发请求**（先查内存缓存、再查 `ai_explain`，两层都没有才真发）；
   两层抽屉都在 `window` 上听 Esc，所以下面那层要 `escDisabled` 让路，
   否则按一次 Esc 两层一起关。抽屉里同时列**这只票的全部历史解读**，可按时间前后翻，
   删除要用户手动点（永不自动裁剪，docs/03 §4.3）。
2. **徽标的计数 = 展开后真能看到的条数。** 「含被静默的」那个开关先过滤，再分组
   （`@shared/signal-group` 是纯函数，`tests/unit/shared/signal-group.test.ts` 钉着这条）。
   反过来会出现「写着 4 条、展开只有 1 条」，那种对不上比少显示难排查得多。
3. **正展开着的那条必须留在组里**（`pinnedSignal`，2026-08-14 修）。
   只渲染组头时，同一只票再来一条信号就会把用户**正展开着、AI 解读正在流式生成**
   的那条挤出列表 —— `AiExplain` 是卸载即取消的，于是等了四十秒的分析界面自己没了，
   而那次调用已经按对方规则计过费。组头照旧是最新那条（新信号必须立刻可见），
   正在看的那条钉在它下面，两条都在，并写一行说明「同一只票为什么多出一行」。
   **修法不是去掉卸载即取消** —— 那条纪律防的是「用户已经不看了钱还在烧」。
4. **走势图有两种来源，图上必须分得出来**（`IntradaySeries.source`，docs/03 §2.5）。
   `REMOTE` 是数据源的逐分钟分时（打开抽屉时拉一次，覆盖全天，带均价线）；
   `LOCAL` 是拉不到时退回的本机留痕 `quote_tick`（docs/03 §4.3）——
   覆盖范围 = 应用开着且取数成功的时段，**它不是完整分时**。
   两种来源都按「相邻点超过 5 分钟就断线」画（午休与「当时没开机」由同一条规则暴露），
   **不许把缺口用直线连过去**：那条斜线看着像分时线，但那段时间里什么都没被观测到。
   **x 轴折叠午休**（11:30 与 13:00 同一点，2026-08-14）—— 430px 的图不该白让掉 27%
   给一段永远没有内容的空白。代价是「午休没交易」只剩断线与那条合并刻度的虚线在说，
   两样都不许省。
   `LOCAL` 还必须额外标注覆盖起点 —— 有坐标轴的图看起来很「正式」，
   一条半截曲线被当成全天的概率比想象中高。
5. **x 轴那一天由 `tradeDate` 推，不是由「今天」推。** 休市日打开抽屉时数据源给的是
   上一个交易日那条曲线，按今天画就是一张日期错位、图上却毫无破绽的假曲线。

三处可滚区域（自选列表、信号列表、提醒日志）各自独立，最外层 `overflow: hidden`；
窄到 `md`（768px）以下退回单列，改由中间那层容器整体滚动。
分层用「亮度差 + 一条极淡描边」而不是阴影 —— 暗色界面上阴影几乎不可见。

## 3. 状态机

悬浮条左端那颗**状态点**的颜色语义：

```
                  ┌──────────────┐
     休市/免打扰 ─▶│   SLEEPY     │ 暗灰，跑马灯停滚
                  └──────┬───────┘
                         │ 开盘
                  ┌──────▼───────┐
        无事发生 ─▶│    IDLE      │ 常态色
                  └──┬────────┬──┘
        有信号在算 ──▶│        │◀── 信号消失/被确认
                  ┌──▼──────┐ │
                  │ WATCHING│ │ 稍亮
                  └──┬──────┘ │
          买入信号 ───┤        ├─── 卖出信号
        ┌────────────▼┐    ┌──▼───────────┐
        │  EXCITED    │    │  ALERT       │
        │  机会色     │    │  警示色      │
        └─────────────┘    └──────────────┘
                  ┌──────────────┐
   数据源全部失败 ▶│  OFFLINE     │ 灰调
                  └──────────────┘
```

状态由主进程推送（`push:petState`），**渲染层不得自己从 `signal:history` 推断** ——
判定者只有 `PetStateMachine`，而它只接受**过了四道闸门**的提醒（docs/05 §4）。
渲染层自己点亮等于开一条绕过冷却与免打扰的旁路。
（跑马灯上的方向标签不受这条约束：它复述的是「引擎判了什么」，不是「有没有提醒你」。）

**状态优先级**：`OFFLINE > ALERT > EXCITED > WATCHING > IDLE > SLEEPY`，
高优先级状态有最短驻留（3s）后回落 —— 一轮 tick 30s，不设驻留会让一次变色挂满半分钟，
而立刻回落则根本看不见。回落靠主进程的定时重推（`controller.schedulePetFallback`）。

## 4. 交互手势

| 操作 | 悬浮条 |
|---|---|
| 左键拖拽 | 移动；松手时若靠近屏幕边缘（< 30px）则吸附 |
| 单击 | **无绑定** |
| 双击 | 打开/关闭 Panel 窗口 |
| 右键 | 上下文菜单：打开面板 / 免打扰 30min·2h·至收盘 / 隐藏悬浮条 / 设置 / 退出（与托盘右键同一份） |
| 悬停 | 无 tooltip（条子本身就在显示这些）；悬停会暂停跑马灯 |
| 滚轮 | 无绑定（避免与下层应用滚动冲突） |

> **为什么单击是空的**（2026-08-13）：这条子是要被拖着走的，而一次拖拽以一个
> click 事件收尾 —— 单击绑面板时，每挪一次位置都会顺手开一次面板。把动作挪到双击，
> 拖拽与开面板就不会互相误触；单击留空也让「不小心碰到条子」不产生任何后果，
> 这与零干扰契约同向。
>
> **代价是 C8 没有单一手势**：双击已经被面板占用，切换免打扰退到右键菜单与托盘菜单
> （两者共用同一份，「免打扰 30min / 2h / 至收盘」「解除免打扰」都在）。
> C8 的验收口径因此读作**「不必进设置页」而不是「一个手势」**。
> 若日后要把它还原成一个手势，中键（`button === 1`）是没被占用的位置 ——
> 滚轮**滚动**才是明确不绑的那个。
>
> 菜单里的「解除免打扰」只管得着**手动**那一项（`manualQuiet`）：用聚合的 `quiet` 去判，
> 会让静默时段或全屏应用期间的点击变成「解除一个我没开过的开关」，点了没反应。

多显示器：位置以「显示器 ID + 相对坐标」存储，显示器拓扑变化（拔插外接屏）时校验坐标是否仍在可见区域内，越界则回落到主屏右下角。

## 6. 性能预算

| 场景 | CPU（单核占比） | 内存 |
|---|---|---|
| 休市待机 | < 0.5% | < 200 MB |
| 盘中 IDLE 动画 | < 2% | < 250 MB |
| 盘中 tick 计算（100 只） | 峰值 < 15%，持续 < 500ms | +30 MB 瞬时 |
| Panel 打开 | < 5% | +80 MB |

手段：
- 动画用 CSS `transform` + `will-change`，走合成层，不触发布局
- 窗口不可见 / 免打扰时调用 `win.webContents.setFrameRatesLimit`-等价手段降帧，或直接 `cancelAnimationFrame`
- 指标计算是纯 CPU，100 只 × 300 根的全量重算实测应在 100ms 量级；若超预算则移入 `utilityProcess`，**不放主线程阻塞窗口响应**
- 增量计算：只有最后一根 K 线变化时，MA/EMA/Wilder 类指标可 O(1) 增量更新（保留内部状态），首版可先全量，性能不足时再优化

## 7. 无障碍与观感兜底

- 高对比度模式下气泡使用系统色而非自定义半透明背景
- 支持系统缩放（125%/150%）：托盘图标提供 @2x（Electron 按命名约定自动选取）。
  **移动窗口一律走 `OverlayWindow.moveTo`**（把宽高一起写回），不用 `setPosition` ——
  非 100% 缩放下 Electron 会在 DIP 与物理像素间两头取整，一次拖拽几百次调用会把条子撑大
- 深浅色主题跟随系统
- **「减少动态效果」必须有真实的退路**（不是「关掉动画就完了」）：Windows 关掉「显示动画」
  （辅助功能 → 视觉效果，**远程桌面会话里默认就是关的**）会让 Chromium 报
  `prefers-reduced-motion: reduce`。跑马灯一旦不滚，用户**永远只看得到第一只**、而且被右边框
  裁掉一半 —— 那台机器上「滚动显示全部自选」等于不存在。所以改成**一次显示一只、定时换**
  （`src/renderer/bar/App.tsx` 的 `usePrefersReducedMotion`），2026-08-13 在打包版上实测到。
- ~~提供「极简模式」：桌宠替换为一个 32×32 的小圆点~~ —— 悬浮条本身就是这个出口，
  而且比一个纯色圆点多给了名称与价格。`AppSettings.minimalMode` 已随皮肤系统一并删除。
