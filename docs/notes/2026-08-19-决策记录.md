## 一、口径对照：两项一致，两项不同

方法上值得记一笔：**不需要账号、不需要 Python、不触碰 JQData 协议** ——
聚宽公开数据字典页里每个指标函数都印着返回值示例，而他们的备注是
「计算方式与通达信、东方财富和同花顺相同」⇒ 拿它对等于一次性与三家国内平台对照。
工具落成 `scripts/verify/jq-crosscheck.ts`。

| | 结果 |
|---|---|
| BOLL | ✅ 逐位一致（1e-14）⇒「标准差除 n 不除 n−1」被外部证实，且除 n−1 的变体相对差 3e-4~7e-4 ⇒ **这次对照有分辨力** |
| RSI | ✅ 逐位一致（1e-9） |
| MACD 柱 | ✅ `2×(DIF−DEA)` 由他们自己印的三组数字代数确认（与日期无关） |
| ATR | ⚠ 口径不同：他们 `MA(TR,14)`（残差 0），我们 `Wilder(TR)/14` |
| ADX/DMI | ⚠ 口径不同：他们通达信 `EXPMEMA`（α=2/15）+ **ADX 用 MM=6**，我们 Wilder + 14 |
| 夏普 | ⚠ 口径不同：他们 `(年化几何 − 4%)/σ`，我们 `日均×√243 / σ, rf=0` ⇒ 沪深300 2005–2017 我们 **0.533** vs 他们 **0.281** |

**最花时间的一步单独记**：他们示例里写的 `check_date='2017-01-04'` 与打印出来的数值
**不是同一天**（真实日期靠 MA20 + 标准差反查是 2017-01-26）。第一版对照全红，
看起来像我们整套指标都错了。

**ADX 那条的后果最大**：`adx.baseThreshold = 20` 转述自国内平台语境，
而两套 ADX 在 699,907 个「股票·交易日」上「≥20 与否」有 **30.4%** 结论相反
⇒ **抄对了数、没抄对量纲**（约束 2 最隐蔽的一种形状）。分位等价值 **17.29**
落在已测邻域（18/20/22）之外 ⇒ 下一轮 `adx` 网格把下侧探到 16–18（**待办，非结论**）。

## 二、缺陷：后复权价位让部分标的静默地不建仓（4 只真被吞、10 只价位上够不着）

拿聚宽的「未来函数」四类清单逐条对 docs/07 陷阱表时，发现「复权」那一行还写着
「全程用前复权序列」（2026-08-12 就换成后复权了）。顺着核实语义撞出来的：

- 回测 fixture 的 `*Adj` 是**后复权、锚在上市日** ⇒ 平安银行 2018 首根真实 13.7 元、
  后复权 **2069 元** ⇒ 一手 20.7 万 > 默认每标的 10 万 ⇒ `lotsAffordable` 返回 **0 手**；
- 实测：`SZ000001` / `SH600309` / `SZ000858` **0 笔交易**，同批 `SH600000` 正常 9 笔。
  报告上只显示「收益 0.00% / 0 笔」，**与「引擎没给信号」无法区分**，无任何告警；
- 范围：主池 261 只里 **10 只**受影响，按「标的·交易日」加权 **1.48%**；
- **偏差方向不随机**：后复权倍数 ≈ 累计分红送转 ⇒ 命中的是分红历史最长的大盘股。

**用户当天拍板走 A（只让它可见），已实施**：`CodeResult.unaffordable` 计数 + 报告告警行
（点名标的与次数），两条用例钉着。**绩效数字一个没变**（同命令重跑：总收益 −1.99% ·
建仓 1097 次 · 建仓胜率 43.21% · 平均每次 −477 元，与既有基线逐位一致）。

**实施后才拿到确切量级**（此前只知道「0 笔」）：训练窗口 **31 次建仓意图被吞掉 / 1097 次建仓
= 2.8%**，真被吞的是 4 只（`SZ000001`×13 · `SH600309`×7 · `SZ000858`×7 · `SH600809`×4）。
⚠ **「10 只受影响」（按价位算）与「4 只真被吞」（按建仓意图算）不是同一个数**，引用别混。

候选 B（按真实价定手数）**仍挂着**，不是被否 —— 它要重跑全部基线。

## 三、方向：**停止在个股日线择时上找边缘**（用户拍的）

### 决定前的事实（比 08-17 提这个问题时变了形状）

问题原本的提法是「只在 RANGE 里有边缘（65%），而 66.6% 的时间处在 TRANSITION（22%）」。
两次实测把这个前提改掉了：

| | 原（08-17） | 现 |
|---|---|---|
| RANGE | 65% | **35.5%**（[§5.35](./M2-偏差报告.md)：对照组收窄到「当天也有信号的票」之后） |
| TRANSITION | 22% | 26.0%（同上）· 38.5%（[§5.36](./M2-偏差报告.md) 相关性调整后的无条件口径） |
| TREND_UP | — | **99.5%**（§5.35，154 次建仓）—— 一个**新假设**，不是救援 |
| 分类器改造上界 | — | 三条突变条件**整条删掉**，TRANSITION 只从 66.6% 降到 53.7% |

⇒ **占样本 88% 的两个最大层（RANGE + TRANSITION）都低于 50%。**
「只在 RANGE 里有边缘」这句话已经不成立了。

### 决定

**不再投入研发去修「个股 · 日线 · 择时」这条线的边缘**，力气转向：

1. **仓位 / 配置层** —— [§5.37](./M2-偏差报告.md) 那条分叉（纯波动率目标化：W1 夏普 +0.288、
   回撤 72.30% → 41.67%，W2 归零 ⇒ 主判据不通过但**不是干净的否**），
   三条可能的下一步在[配置形态-论证](./配置形态-论证.md) §8；
2. **ETF 双轨的前向记录** —— 它不需要新的研发，**时间自己在攒证据**
   （ETF 池是唯一见过训练窗口 Calmar > 0 的形态，但 59 次建仓 + 验证窗口反向 ⇒ 还不算测试）。

### ⚠ 这个决定**不是**什么（写清楚，免得下一轮读成别的）

- **不是「个股路线死亡」。** 个股照常评估、照常提醒、照常进影子运行与实盘记账 ——
  停的是**研发投入**，不是功能。CLAUDE.md 那条「『个股无法进化』由用户主观认定」仍然有效，
  用户**没有**做那个认定。
- **不是「回测/标定工具作废」。** 工具照用（配置形态实验就在用），只是不再拿它去搜
  「哪个参数能把个股择时救回来」。
- **不是把 A/C 判死。** A（TRANSITION 不出手）与 C（改分类器）是**因为已知上界太低**而不选：
  A 砍 30% 建仓且剩下的 RANGE 也只有 35.5%，C 的天花板实测只有 12.9pp。
  哪天有新证据改变这两个上界，可以重开。
- **不是丢掉 TREND_UP 99.5%。** 它进待办（见下），**等样本，不等灵感**。
