## 2. 换机器后的恢复步骤

### ① 代码与小产物：`git pull` 就有

`params/float-shares.json`（264 KB，110 只 / 10434 个「票·月」）**已进版本控制**。
它是这一轮唯一难重出的东西。

### ①b 更快的办法：直接拷两个目录（但**只拷两个**）

判据是**重出的代价**，不是大小：

| 目录 | 大小 | 重出方式 | 代价 | 拷不拷 |
|---|---|---|---|---|
| `data/history` | 214 MB | `pnpm fetch:history` | 30–60 分钟 + 撞腾讯 501 要分批 | ✅ |
| `reports/` | 78 MB | 一次次重跑回测 | 每次 4 分钟；**`pnpm iterate` 的 alpha 与基线都读它**，没它全显示「读不到」 | ✅ |
| `data/announcements` | 30 MB | `pnpm fetch:announcements` | 约 30 分钟 | 顺手 |
| `data/liquidity-em` | 30 MB | **离线**从 `params/float-shares.json` 展开 | **1 秒** | ❌ |
| `data/liquidity` | 55 MB | **离线**从 fixture 算 | 几秒 | ❌ |

那两个 liquidity 目录正是「把 208 KB 产物塞进 git」的理由 —— 79 MB 的东西 1 秒能重建，拷它纯属浪费。

JSON 压得很狠（实测单份 fixture **8.5×**），322 MB 打包约 **40 MB**：

```bash
tar -czf gp-data.tgz data/history reports data/announcements   # 旧机器
tar -xzf gp-data.tgz                                           # 新机器，仓库根目录
```

**验证不要数文件，跑一次基线** —— 它一次性验证 fixture 完整 + 代码一致 + 口径没漂：

```bash
CODES=$(node -e "console.log(JSON.parse(require('fs').readFileSync('params/universe-broad.json','utf8')).codes.join(','))")
pnpm backtest -- --codes "$CODES" --fixtures ./data/history --from 2018-01-01 --to 2023-12-31 --quiet
```

应当打出**总收益 −1.99% · 最大回撤 2.96% · 建仓 1097 · 建仓级胜率 43.21%**。
对不上就是拷漏了或版本不一致，**别接着往下跑实验** —— 基线错了，差值就没有意义。

### ② 日线 fixture（214 MB，可重出，约 30–60 分钟）

```bash
CODES=$(node -e "console.log(JSON.parse(require('fs').readFileSync('params/universe-broad.json','utf8')).codes.join(','))")
pnpm fetch:history -- --codes "$CODES" --from 2018-01-01 --concurrency 2
# 退市那 19 只
DEL=$(node -e "console.log(JSON.parse(require('fs').readFileSync('params/universe-delisted.json','utf8')).codes.join(','))")
pnpm fetch:history -- --codes "$DEL" --from 2018-01-01 --concurrency 2 --benchmark none
```

⚠ **两个坑**（台账 §1 有详细口径）：

- **腾讯按 host 拦**：约 1800 个请求（≈ 99 只）之后清一色 `HTTP 501` + JS 挑战页，
  十分钟不恢复。脚本备了三个同源门会自动换，但**并发上限压到了 2**，别调高。
  撞上了就**分批跑**：先 130 只，等十几分钟再跑剩下的（脚本逐只落盘，前面的不会丢）。
- **`fetch:history` 不跳过已有文件**，重跑会重抓。补漏要用 `--codes` 只点缺的那几只。
- 3 只源上就没有 `hfqday`（`SZ001330` / `SZ301583` / `SZ301717`），**抓不到是对的**，
  别去改断言。它们本来就不在 261 只池里。

### ③ 流动性文件：从产物离线展开（一秒钟，不联网）

```bash

```

这一步把产物里的逐月股本 × fixture 的日收盘价展开成逐日 `floatCap`。
往返核对过：与直接抓日线得到的中位市值相比，**87 只里最大偏差 1.89%**
（月内股本变动那一部分，已知且有界）。

### ④ 成交额那一份（只有流动性支要用，同样离线）

## 3.5 两台机器分头抓、再合并 —— 合法且省时间

限流是按**出口 IP** 记的，所以两台机器各抓一部分、最后合并是有效的。
合并**安全**，因为 `data/history/` 与 `data/liquidity-em/` 都是**一码一文件、没有索引也没有跨文件状态**，
脚本的续跑判据就是「文件存在 → 跳过」⇒ 合并就是取并集。

```bash
tar -czf part.tgz data/history data/liquidity-em      # 另一台机器
tar -xzf part.tgz -C /tmp/part                        # 这台机器
cp -rn /tmp/part/data/history/.      data/history/     # -n = 不覆盖已有
cp -rn /tmp/part/data/liquidity-em/. data/liquidity-em/
```

⚠ **必须用 `-n`（不覆盖）**：`liquidity-em` 里可能有两种来源 ——
`source: "eastmoney"`（日线真值，逐日股本）与 `source: "…monthly-shares…"`
（月度采样 + fixture 价，展开而来，最大差 1.89%）。同一只票两边都有时保留本机原件，
别让展开件盖掉真值件。

合并完**立刻更新产物并提交**，否则下次换机器又要重来：

```bash
node scripts/fetch-liquidity.mjs --collect-shares params/float-shares.json --out data/liquidity-em
git add params/float-shares.json && git commit -m "chore:流动性股本产物更新到 N 只"
```

核对三件事（缺一件都可能让市值支静默跑在半个池子上）：

```bash
ls data/liquidity-em | wc -l          # 目标 280（261 只有 fixture 的 + 19 退市）
node -e "const fs=require('fs');const d='data/liquidity-em';const s={};let n=0;
for(const f of fs.readdirSync(d)){const j=JSON.parse(fs.readFileSync(d+'/'+f,'utf8'));
s[j.source]=(s[j.source]??0)+1;if(!(j.capBars>0))n++}console.log(s,'无市值',n)"
# 无市值必须是 0；source 里**不许出现** fixture-proxy（那是成交额代理，属于 data/liquidity/）
```

## 4. 一条纪律：两个目录不许合并

`data/liquidity/`（成交额代理，`floatCap` 全 null）与 `data/liquidity-em/`（真实股本）
**刻意分开**。混在一个目录里跑 `--drop-cap-pct` 时，代理那些票会因「缺数不剔」
被排除在横截面之外 —— 过滤只作用于一部分池子，而**报告上一切正常**。

`createPoolFilter` 的 `noData()` 就是为这件事加的：那一档所需的列一根都没有值的标的
超过一成 **直接抛错**，一成以内打 warn。别把这个守卫去掉。
