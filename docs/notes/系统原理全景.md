## 1. 一句话原理

对每一只自选标的**单独**跑一条五层流水线，从日线（+ 盘中快照）算出「今天该不该动手」，
然后交给提醒层决定「要不要真的打扰用户」。**没有下单，也没有横截面比较** ——
每只票的结论只由它自己的历史决定，不与别的票排名。

```
                      ┌────────────── src/core（纯函数，可回测，不读时钟）──────────────┐
Candle[]（日线，前复权）│                                                                │
   + 盘中临时线         │ ① 指标层 → ② 市场状态 → ③ 策略层 → ④ 组合层 → ⑤ 风控层        │
   + 快照 Snapshot     │  7 类原始因子   4 种 regime   12 条规则   得分+投票   抑制/改写 │
   + 持仓 Position     └────────────────────────────────┬───────────────────────────────┘
   + 大盘情绪 s                                          │ GatedSignal（方向 + L1/L2/L3）
   + 行业集中度                                          ▼
                        src/main：四道提醒闸门 → 状态点 / 气泡 → alert_log
                                              └→ 影子运行（前向绩效） / signal 表
```

入口只有一个函数：[`evaluate()`](../../src/core/engine.ts#L68)（`src/core/engine.ts:68`）。
`src/main`（实盘）与 `src/backtest`（回测）**共用它**，这是「回测与实盘同源」的落点（ADR-0004）。
纯函数、不读时钟：「现在几点」「大盘情绪多少」全部由调用方传进来，未来函数由架构消除。

## 2. 输入与口径

| 输入 | 来源 | 口径纪律 |
|---|---|---|
| 日线 `Candle` | 腾讯 / 东财 / 新浪三源冗余 | **指标全用前复权字段（`closeAdj` 等）；展示、持仓成本、止损、观察点用不复权** |
| 回测 fixture 的 `*Adj` | `pnpm fetch:history` | 是**后复权**，不是前复权（腾讯前复权在高分红股上会变负数，实测中远海控 714 根 ≤ 0） |
| 盘中临时线 | 快照拼出的当日 K | `provisional = true` → 信号只能是 `PROVISIONAL`，得分再乘 0.9，最高只到 L2 |
| 快照 `Snapshot` | 30s 轮询 | 连续竞价里超 5 分钟没更新 → `STALE_SNAPSHOT` 硬抑制 |
| 预热长度 | `lookback = 320` 根 | < 40 根不产出任何信号；< 300 根或 BBW 分位未就绪 → 受限模式，得分 ×0.8 |
| 周线 | 由日线聚合（`aggregateWeekly`） | 只算周 MACD 与周 ADX，不算全套 |

**未定义的指标值一律 `null`，绝不填 0**（约束 4）。这不是洁癖：用 0 冒充未预热的 RSI 会让
所有 `RSI ≤ 30` 的条件在预热期全部成立。

## 3. 第①层：指标层 —— 全部原始因子

`src/core/indicators/`，一次算**全序列**（策略要回溯「近 5 日曾触上轨」）。

| # | 因子 | 参数 | 实现 | 口径要点 |
|---|---|---|---|---|
| 1 | **MA** | 5 / 10 / 20 / 60 / 120 | `ma.ts` | 前复权收盘 SMA |
| 2 | **MACD** DIF / DEA / HIST | 12 / 17 / 9 | `macd.ts:27` | `HIST = 2×(DIF−DEA)`（国内平台口径，不影响穿越判定）；17 而非经典 26，来自来源文档，**未验证** |
| 3 | **BOLL** MID / UPPER / LOWER / BBW / **BBW_PCT** | 20, k=2, 分位回看 250 | `boll.ts:27` | 标准差**除 n 不除 n−1**；`BBW=(U−L)/MID×100`；`BBW_PCT` 是 250 日百分位，**第 269 根才有首值**（本项目对数据长度要求最高的因子） |
| 4 | **DMI**：ADX / +DI / −DI / **ATR** | 14，Wilder | `dmi.ts:27` | ADX 首值约需 28 根；`atr` 导出的是 `Wilder(TR)/14`（通行 ATR），不是和式 |
| 5 | **RSI** | 14，Wilder | `rsi.ts:17` | `avgLoss=0 → 100`、`avgGain=0 → 0`、双 0 → 50 |
| 6 | **量能**：VOL_MA20、**量比** | 20 | `volume.ts:38` | **盘中必须按已完成交易时间归一化**，否则上午永远「缩量」，放量确认类信号整个上午无法触发 |
| 7 | **周线** 周 DIF/DEA/HIST、周 ADX | 同 MACD / ADX 参数 | `indicators/index.ts:81` | 只供多周期共振用 |

派生的几个中间量（进 `evidence`，供「为什么是这个结论」追问）：
`volPct`（ATR/close 的 250 日分位）、多头/空头**排列得分** 0–3、`midDistance = |close−MID|/MID`、
`ADX 3 日变化`、`BBW_PCT 3 日变化`、`bars`（数据充分性）。

### 3.1 两条自适应阈值（这是系统里唯一的「自动调节」）

```
① ADX 门槛随本标的自身波动率走         thresholds.ts:38
   volPct   = ATR/close 在过去 250 日的分位 ∈ [0,1]
   adxTrend = clamp(20 + 8×volPct, 20, 28)      ← 高波动标的要更高的 ADX 才算「有趋势」
   adxRange = adxTrend − 5

② RSI 超买/超卖线随**大盘情绪**走        thresholds.ts:93
   rsiOverbought = 65 + 20×s        s=0（熊）→ 65   s=1（牛）→ 85
   rsiOversold   = 15 + 20×s        s=0       → 15   s=1     → 35
```

⚠ `adx.maxThreshold = 28` 在出厂配置下**算术上咬不住**：`20 + 8 = 28` 恰等于上界，
所以往上调它逐位无变化（实测 28→34 动 0/12 折）。别扫它的上侧。

## 4. 第②层：市场状态（regime）—— 每只票自己的，不是大盘的

`src/core/regime/index.ts:54`。四种状态，**按标的逐只判定**：

| 状态 | 条件（同时满足） |
|---|---|
| `TREND_UP` | ADX > adxTrend 且 +DI > −DI 且 close > MA20 且 多头排列得分 ≥ 2 |
| `TREND_DOWN` | ADX > adxTrend 且 −DI > +DI 且 close < MA20 且 空头排列得分 ≥ 2 |
| `RANGE` | ADX < adxRange 且 BBW_PCT < 30 且 midDistance < 0.03 |
| `TRANSITION` | 以上都不满足，**或**命中任一突变条件 |

三条突变条件（命中即 `TRANSITION`，优先于上面三条）：
`|ADX 3 日变化| > 5` · `|BBW_PCT 3 日变化| > 30` · `量比 > 1.5`。

**迟滞**：原始判定与当前状态不同时，要连续 `hysteresisDays = 2` 根给出同一新结论才切换
（`classifyRegimes`，regime/index.ts:154）。没有迟滞，震荡市里 ADX 在阈值附近来回穿越会让状态天天翻转。

整条序列每次**一次算完**，而不是「读上次状态 + 增量推进」—— 否则盘中临时线的抖动会被记进历史。

> 实测：`TRANSITION` 占判定根的 **66.6%**，而且把三条突变条件整条删掉也只降到 53.7%
> —— 所以「信号出不来」先别去动 regime 阈值（`pnpm audit:regime` 已量化过这个上界）。

## 5. 第③层：策略层 —— 12 条判定规则

三个策略互不知晓，可以同时给出买和卖（裁决是组合层的事）。
**权重是策略结构的一部分，不在 `params.ts` 里**，每个策略内部权重和为 1（有用例断言配平）。

### 5.1 趋势跟踪 T1–T5（`strategies/trend.ts`）

| ID | BUY | SELL | 权重 |
|---|---|---|---|
| `T1_MA_CROSS` | MA5 上穿 MA20 且 ADX > adxRange | MA5 下穿 MA20 | 0.20 |
| `T2_MACD_ZERO_CROSS` | DIF 上穿 DEA 且 DIF > 0 且 HIST 连 2 日放大 | DIF 下穿 DEA 且 DIF < 0 | 0.25 |
| `T3_BREAKOUT` | close > UPPER 且 BBW_PCT 上升 且 量比 ≥ 1.2 **且 regime ≠ TREND_UP** | close < LOWER 且同上 | 0.25 |
| `T4_ALIGNMENT` | MA5>MA20>MA60 且 close>MA20 且 ADX > adxTrend | 反向排列且 close<MA20 | 0.15 |
| `T5_PULLBACK_HOLD` | 近 5 日曾触 UPPER，今日最低触 MID 但收在 MID 上，DIF>0 | 近 5 日曾触 LOWER，今日最高触 MID 但收在 MID 下，DIF<0 | 0.15 |

SELL 侧普遍比 BUY 侧宽松（T1/T4 不要求 ADX 确认）—— 刻意的，「离场宁可早」。

**T3 那个 `regime ≠ TREND_UP` 是全项目第一次判定逻辑改动**（2026-08-15，`ENGINE_VERSION` 0.2.8，
trend.ts:128 有完整论证）：在已判定为上升趋势的状态里，「又创新高 + 带宽扩张」不提供新信息 ——
`T4_ALIGNMENT` 实测在 **396/396 = 100%** 的 TREND_UP 建仓里出现、已退化成常量，而带宽扩张
在趋势中段是延续、末端是加速赶顶，日线上分不开。于是 T3 那一票投给的恰恰是最危险的时刻。
只动 BUY、只动 TREND_UP、不引入任何新数值。

### 5.2 均值回归 R1–R4（`strategies/mean-reversion.ts`）

| ID | BUY | SELL | 权重 |
|---|---|---|---|
| `R1_RSI_BAND` | RSI < rsiOversold 且 low ≤ LOWER | RSI > rsiOverbought 且 high ≥ UPPER | 0.30 |
| `R2_REVERT_TO_MID` | 近 3 日曾收在 LOWER 外 + **今日上穿 MID（事件）** + HIST 在改善 | 近 3 日曾收在 UPPER 外 + 今日下穿 MID + HIST 在走弱 | 0.30 |
| `R3_SQUEEZE` | BBW_PCT < **20** 且 low ≤ LOWER | BBW_PCT < 20 且 high ≥ UPPER | 0.20 |
| `R4_MID_REVERSION` | **仅 RANGE**：close 低于 MID 超过 1.5×STD | 仅 RANGE：close 高于 MID 超过 1.5×STD | 0.20 |

两条结论值得记住：

- **R3 的 20 是全项目唯一一个被标定过的出厂参数**。原值 10（来源文档的「BBW_PCT<10 是变盘前夜」）
  把 R3 卡得几乎不出手，让整个均值回归看起来只值 +0.14pp、两次被提议砍掉。16–30 是一整片
  通过的高原，20 是高原上唯一在训练集与验证集都靠前的值。换上之后均值回归的边际贡献变成
  **+2.0 ~ +3.4pp 收益 / +0.11 ~ +0.24 夏普**。
- **R2 靠自己凑不够票，这不是它没用**：R2 要求价格回到 MID 附近，R1/R3/R4 要求偏离 MID，
  **几何互斥** —— 213 次触发里 185 次（87%）是孤立的，而票数线要 2 票。约束在组合层不在这里。

### 5.3 多周期共振 M1–M3（`strategies/multi-tf.ts`）

**不产出信号，只给组合得分加减**（可为负）：

| ID | 条件 | 调整 |
|---|---|---|
| `M1_WEEK_MACD_DAY_RSI` | 周线近 3 周金叉 且 日 RSI < 45（卖：死叉 且 RSI > 55） | ±0.10 |
| `M2_WEEK_ADX_CONFIRM` | 日线突破轨道 且 周 ADX > 25 | +0.10 该方向 |
| `M3_FALSE_BREAKOUT` | 日线突破**上**轨 且 周 ADX < 20 | **−0.15** BUY |

M3 只惩罚向上突破 —— 「跌破下轨但周线没趋势」照样可能是下跌起点，不给对称惩罚。

> `multiTf` 整块 7 个参数在标定归档里全是 `INERT`（惰性）。

## 6. 第④层：组合层 —— 得分与投票

`src/core/combine/index.ts:83`。**两个策略等权**（动态权重表已于 2026-08-12 整张删除，实测无效）。

```
part(策略,方向)  = 加权平均(已成立子信号的 score, 按子权重)          ← 不是加权和
raw(方向)        = clamp01( part(趋势) + part(均值回归) × penalty )
adjusted(方向)   = raw + Σ 多周期调整项
final(方向)      = clamp01(adjusted) × 数据充分性折价(1 或 0.8) × 盘中折价(1 或 0.9)
votes(策略,方向) = 该策略里 score ≥ 0.5 的子信号个数
触发             = final ≥ 0.60  且  （趋势票 ≥ 3  或  均值回归票 ≥ 2）
```

四个要点，每一个都是踩出来的：

1. **策略内取加权平均而非加权和**。按字面「未成立按 0 计入」读，趋势市要过 0.60 得 5 条规则
   里 4 条同时满分，而同一节又写着「3 票即可触发」—— 两个数在字面读法下不可能同时成立。
   改成平均后：**强度由得分负责，一致性由票数负责**。
2. **票数线按策略给**（趋势 3 / 均值回归 2），判据是「**任一策略达到自己的线**」，
   **不是两边相加**。趋势有 5 个子信号、均值回归只有 4 个，共用一条整数线对后者系统性不利。
   跨策略相加会让「趋势 2 票 + 回归 1 票」冒充「某个策略有 3 条规则互相印证」。
3. **`penalty` 只有一处不为 1**：`TREND_DOWN` 里均值回归的 **BUY** 再乘 0.5
   （`downtrendBuyPenalty`，「别接飞刀」）。它是方向级抑制，不是策略可信度。
4. **裁决三态**（`adjudicate`，combine/index.ts:194）：两方向都触发 → 取高者，
   差值 < `conflictBand = 0.15` 判为**矛盾（NONE）**；只有一方触发但对侧得分也过线且差值小
   → 同样判矛盾；都没触发 → 区分是「得分不够」还是「票数不够」（面板要能回答「为什么没提醒」）。

出厂的「矛盾时压掉双方」已经与「弱侧让路」对比测过，**每个维度都更优**，别去改它。

## 7. 第⑤层：风控层

`src/core/risk/index.ts`。不下单，所以这一层做三件事：**抑制**、**改写**、**标注**。

### 7.1 持仓强制通道（独立，不经过组合层得分）

按严重程度排序，**命中第一条即定案**。哪怕当天一条子信号都没成立，成本线被击穿就必须提醒。

| # | 规则 | 条件 | 动作 | 级别 |
|---|---|---|---|---|
| ① | `STOP_LOSS` | 亏损 ≥ 8%（或跌破**用户重画的**那条线 `stopFloor`） | FORCE_SELL | L3 |
| ② | `TRAILING_STOP` | **当前**浮盈 ≥ 5% 且自最高点回撤 ≥ 3% | FORCE_SELL | L3 |
| ③ | `DRAWDOWN_REDUCE` | 自最高点回撤 ≥ 7% 且 ① 还没接手 | FORCE_REDUCE 50% | L3 |
| ④ | `PROFIT_PROTECT` | **曾达**浮盈 ≥ 5% 后回落到 < 2% | FORCE_REDUCE | L2 |

② 取**当前**浮盈、④ 取**曾达**浮盈，这个区分是必须的：两者都按 peak 读的话 ② 会把 ④ 整个吃掉。

### 7.2 硬抑制（无执行意义 → 一律降 L1，但**照样入库并带原因**）

`SUSPENDED`（停牌或全日无成交）· `INSUFFICIENT_DATA`（< 40 根）· `NEW_LISTING`（上市 < 60 根）·
`HARD_LIMIT_UP`（买入遇涨停）· `HARD_LIMIT_DOWN`（卖出遇跌停）· `STALE_SNAPSHOT`（连续竞价 5 分钟无更新）。

**不制造信息黑洞**：用户要能在面板里回答「这只票为什么从来不出信号」。

### 7.3 降级规则（只作用于 BUY —— 离场不该因为「风险大」而少提醒）

`T1_LATE_BUY`（14:50 后买入 → 改写成 **`NEXT_DAY_WATCH`**）· `ST_RISK` · `INDUSTRY_CONCENTRATION`
（同行业持仓占比 > 20%）· `VOLATILITY_EXPANDED`（BBW_PCT > 90）。每命中一条退一档，L1 是地板。

> **收盘确认轮的买入 100% 会被改写成「明日观察」，这是算术不是概率**：`minuteOfDay` 在收盘后
> 恒等于 900，而尾盘窗口是 890–910。实测 182 次 BUY 对应 182 次 `T1_LATE_BUY`。
> 所以「买入」标签**只可能来自盘中轮**。次日出口是 `carryover()`，判据是**两次独立成立**
> （昨天已 CONFIRMED 的 `NEXT_DAY_WATCH` **且今天自己也判 BUY**）—— 昨天的结论不构成今天的理由。

### 7.4 分级

```
L3  CONFIRMED 且 score ≥ 0.75；或持仓强制 ①②③
L2  score ≥ 0.75 但仍是 PROVISIONAL；或持仓强制 ④
L1  过了阈值但 score < 0.75；或被降级；或被硬抑制
```

另有一条挂在 `GatedSignal.tTrade` 的**日内做T建议**（`risk/intraday-t.ts`）：只对持仓、只在盘中、
**不发提醒、不落库、不进回测**。它**不是一个方向**，刻意不并进 `GatedDirection` ——
`signal` 表、回测、影子运行都只读 `direction`，混进去等于让那三处认识「日内位置」，而它们只有日线。

## 8. 引擎之外：提醒的四道闸门

`src/main/alerts/dispatcher.ts`。**这是状态点与气泡的唯一点亮路径**，渲染层不许绕过它去读 `signal:history`。

| 闸门 | 规则 | 不过的后果 |
|---|---|---|
| ① 防抖 | 盘中信号需连续 **2** 个 tick 成立（约 60s） | **丢弃**（记 `suppressed_reason`） |
| ② 同键冷却 | 同 `code:direction`：L1 30min / L2 2h / L3 当日一次 | **丢弃** |
| ③ 频率上限 | 单标的每日 L2+L3 ≤ **4**；全局每小时 ≤ **6**；全局每日 L3 ≤ **10** | **降为 L1** |
| ④ 免打扰 | 静默时段 / 全屏 / 专注助手 / 手动 / 锁屏 | **降为 L1** |

持仓强制类**不受冷却限制**，改为「每次跌幅每扩大 2% 提醒一次」。
提醒的**可见出口只有气泡**（托盘角标、图标闪烁、系统通知、声音全部已移除）。

**双轨**（2026-08-17）：内置「行业ETF」组那 15 只走 `OBSERVE` 轨 —— 自己一份日配额（2 条）、
**不碰 `PRIMARY` 的任何计数器**、抢不到气泡。所以自选股的提醒行为逐位不变。

## 9. 引擎之后：三把尺子

| 工具 | 量什么 | 纪律 |
|---|---|---|
| **回测** `pnpm backtest` | 历史绩效、参数网格、消融 | 排名口径是**验证集 Calmar**，但训练集亏钱的候选先淘汰；配对 Δ 要 `\|Δ\|/stderr ≥ 2` |
| **标定** `--grid` | 某个参数该取多少 | 三态裁决：`WRITE_BACK` / `KEEP`（**是结论，不是失败**）/ `INCONCLUSIVE` |
| **影子运行** `src/main/shadow/` | 策略值不值钱（前向） | 四条纪律：不补跑历史 · 成交价用**次日开盘** · 成本照扣 · 只吃 CONFIRMED。**引擎参数一变立刻停止累积** |

被提醒闸门挡掉的信号**照样**进影子组合（影子量策略，不量提醒策略），
但**风控硬抑制的不进**（那是「无执行意义」）—— 这两句看着像一回事，是相反的两个决定。

## 10. 有没有判断整体环境？——有，但只有一条通道，影响面积很小

这是全文最容易被误解的一节，所以按「作用范围」分五层讲清楚。

### 10.1 唯一的真·大盘环境变量：`marketSentiment s ∈ [0,1]`

```
s = 沪深300 近 20 日收益率，在过去 250 个同类样本中的分位
                                        core/indicators/thresholds.ts:116
```

- 基准硬编码为 **SH000300**（`main/engine/signals.ts:39`），回测默认同值（`--benchmark` 可改）。
- 基准日线不足时返回 **0.5（中性）而不是 0** —— 0 意味着「确定处于熊市」，那是缺数据编出来的结论。
- **它的唯一去处是 RSI 的两条动态阈值线**（§3.1 ②）。

**而那两条线只被 R1 一个子信号读**（实测 grep：`rsiOverbought` / `rsiOversold` 在 `src/core` 里
只出现在 `mean-reversion.ts:59-60`）。于是：

> **大盘情绪 → RSI 阈值 → R1（12 条规则里的 1 条，权重 0.30 的均值回归子信号）**，
> 而 R1 还要求**同时触及布林轨道**才成立。
>
> ⇒ 「整体环境」在这套系统里**不控制仓位、不控制出手与否、不控制方向**，
> 只让「什么算超买超卖」在牛市里整体上移 20 个 RSI 点。**影响面积就这么大。**

顺带说明：多周期 M1 里那两个 RSI 门（`dayRsiBuyMax = 45` / `dayRsiSellMin = 55`）是**固定值**，
**不随情绪走** —— 它们不经过 `thresholds.ts`。

### 10.2 个股自己的「环境」：regime（§4）

`TREND_UP / TREND_DOWN / RANGE / TRANSITION` 是**逐只标的**判的，**不是大盘状态**。
它是系统里实际起作用最多的「环境」概念，共三处影响：

- `R4_MID_REVERSION` **只在 RANGE 触发**；
- `TREND_DOWN` 里均值回归 **BUY 得分 ×0.5**；
- `TREND_UP` 里 `T3_BREAKOUT:BUY` **不计票**（0.2.8 那次逻辑改动）。

### 10.3 更长周期的同一只票：周线共振 M1–M3（§5.3）

周 MACD 拐头、周 ADX 强弱。这是**时间维度**的确认，仍然不是大盘。

### 10.4 组合层面的环境：行业集中度

`industryShares()`（`main/engine/signals.ts:174`）按**持仓市值占比**算，同行业 > 20% →
该行业新买入信号**降一档**。这是系统里唯一一个「跨标的」的判据 —— 但它只看用户的持仓，
不看市场的行业强弱。

### 10.5 只给人看、不进引擎的环境：日报「今日环境」一节

`main/report/environment.ts`（2026-08-15）：沪深300 涨跌幅 + 15 只行业 ETF 按涨跌幅排序 +
**涨跌宽度**（几只涨/几只跌/几只平）+ 显式列出缺行情的代码。

三条硬纪律：**只陈述不评价**（不许出现「今天环境不好，注意风险」，那读起来像结论但背后没有依据）·
**独立成节**（不进 `stocks` / `overview`，否则用户 7 只票会被 15 只观察标的埋掉）·
**不喂给 AI**（喂了就得进 `reportFactDigest`，而它含盘中快照、每轮都变 ⇒「已过期」提示恒亮）。

### 10.6 明确**没有**的环境判断

| 缺什么 | 现状 |
|---|---|
| 大盘风险开关 / 总仓位控制 | **没有**。不存在「大盘跌破年线就全部空仓」这类总闸 |
| 指数择时 / beta 对冲 | **没有**，而且**已经测过且结论为负**（见下） |
| 行业轮动 / 板块强弱因子 | **没有**。行业只用于持仓集中度与日报陈述 |
| 横截面排序（选最强的 N 只） | **没有**。每只票独立判定，互不比较 |
| 市场宽度 / 涨跌家数进引擎 | **没有**。宽度只在日报里陈述 |
| 宏观（利率、汇率、CPI） | **没有** |

> **「在大盘上择时」这条路已经实测且答案是负面的**（M2 §5.32，2026-08-18）：
> ① 引擎在指数上**几乎不出手** —— 沪深300 **11.5 年 8 次**建仓，其 ETF 五年半 2 次；
> ② 2005–2017 池外参照：指数被动持有 **+301.70%**，同期择时只拿到 **+24.14%**（占用 11.5%）
> ⇒ **在 beta 上择时远不如被动持有**；
> ③ 12 只 ETF 池那个唯一见过正 Calmar 的结果，**信号来自行业 ETF 的残差波动而不是 beta**
> （59 次建仓里行业 9 只贡献 44 次、宽基 3 只只有 15 次）。
>
> 所以「加一个大盘环境总闸」不是一个未做的改进项，而是一个**已经有负面证据的方向**。
> 目前有一份待拍板的提议走的是相反的路（把产出从「买/卖哪只」换成「总暴露多少」），
> 见 [配置形态 · 论证](./配置形态-论证.md)。

## 11. 因子清单的反面：完全没有用到的因子类别

这一节存在的理由是：只列「用了什么」会让人以为别的都在里面。

| 类别 | 用了吗 | 说明 |
|---|---|---|
| **基本面**（PE / PB / ROE / 营收 / 净利润） | **零** | 一个字段都没有 |
| **资金流**（北向、龙虎榜、大单、主力净流入） | **零** | |
| **横截面因子**（动量排序、市值、价值、质量） | **零** | 系统是**时序**的，不做截面比较（这是与机构系统的**结构性**差距，改它等于换产品） |
| **舆情 / 新闻情绪** | **零** | 公告功能是**只列不判**：确定性分类白名单高亮，**刻意不做 AI 解读**（模型看到的和用户看到的是同一行标题，没有信息不对称） |
| **微观结构**（订单簿、逐笔、tick） | **零** | 分时数据只用于画图与日内做T建议，不进任何信号判定 |
| **另类数据** | **零** | |
| **机器学习 / 因子挖掘** | **零** | 全部规则手写、可逐条解释。「自我进化」**不等于自动调参** —— 那是过拟合的定义 |
| **流动性因子** | 只做过实验 | 流动性/市值过滤（H0）测过，没过主判据 |

所以准确的说法是：**这是一套单标的、日线级、纯技术面的规则型择时系统**，
12 条规则全部由 7 类经典技术指标算出。

## 12. 证据现状 —— 读上面任何数字之前先读这一节

**原理讲得通不等于它赚钱。** 当前的实测结论是负面的，必须一起说：

- **62 个叶子参数里只有 1 个被标定过**（`strategy.squeezeBbwPct = 20`）。
  其余：`KEPT` 16 · `INERT` 13 · `UNTESTABLE` 11 · `BLOCKED` 21 · `GUESS` 0。
  `ENGINE_VERSION` 的 **`-unvalidated` 后缀因此还在**，UI 与文档不得据此宣称任何绩效。
  以 `params-view.ts` 的 `STATUS` 表为准（有用例钉着），本文这份概述会过期。
- **`GUESS = 0` 不等于「都测过了」**：`BLOCKED` 那 21 个是「网格跑过了，但出厂值自己被
  『训练集 Calmar ≤ 0』红线淘汰 ⇒ 裁决必为 `INCONCLUSIVE`」。后续动作与 `GUESS` **相反**
  （`GUESS` 去跑网格，`BLOCKED` 要先让基线转正再重测）。
- **在 261 只代表性标的池上，出厂参数是亏钱的**：全期 **−0.94%**，训练窗口 2018→2023
  **−2.55% / Calmar −0.125**。别再引用 40 只旧池的 +5.93%。
- **问题已被重新定义**（2026-08-17）：每次建仓期望 **−477 元 /（10 万名义）**，其中
  **327 元是成本（69%）** ⇒ **入场信号的原始边缘只有 −0.15%**。
  （`trade.costs` **不含滑点**，算成本占比必须跑 `--slippage 0` 对照。）
- **「改出场」这条路已走完且为负**：四条风控规则各关一次 + `drawdownReducePct` 三点网格，
  训练窗口 Calmar 最好 **−0.057**，全部没过红线。关键发现是每个出场改动都只在
  **胜率与盈亏比之间搬家**（乘积始终为负）—— 那是「边缘约等于零」的指纹。
- **唯一见过 Calmar > 0 的形态是 12 只 ETF 池**（训练窗口 +2.14% / Calmar +0.092），
  但只有 59 次建仓、验证窗口反向 ⇒ **不算测试**。且 `N_eff = 2.97`（有效独立标的数），
  **扩池或剔冗余都改善不了统计功效** ⇒ 判据换成「前向记录攒够时间」。
- **口径提醒**：「胜率」有两个 —— 逐笔 33.16% vs **建仓级 49.28%**（同一份数据）。
  用户体验到的是后者。另外「超额收益」离开「平均资金占用率」（实测 **4.15%**）会被读反。

## 13. 顺手查出的一处：`rsi.sentimentIndex` 是死参数

`src/core/params.ts:46` 声明了 `sentimentIndex: 'SH000300'`，但**全项目没有任何地方读它**
（grep 只有那一行）。实际基准写在两处：`main/engine/signals.ts:39`（硬编码 `SH000300`）
与 `backtest/args.ts:155`（默认值，`--benchmark` 可覆盖）。

**目前无行为影响**（三处同值），但**改这个参数不会生效**，而它看起来会。
这与 `AppSettings.sensitivity` 曾经的问题同一类，也同样隐蔽。两个可选处置：
把它删掉（承认基准由调用方决定），或让 `signals.ts` 的 `benchmarkCode` 默认读它。
**这是一个待拍板项，本文只记录，未改代码。**
