## 1. 与 docs/04 的口径差异（已在源码里逐条注明）

| # | 位置 | 文档写的 | 实现的 | 为什么 |
|---|---|---|---|---|
| 1.1 | `indicators/dmi.ts` | `ATR = Wilder(TR,14)`（**和式**） | `atr = Wilder(TR,14) / 14`（均值） | 导出的 `atr` 会被 [docs/05 §2.3](../05-风控与提醒规则.md) 的自适应止损（`2×ATR/close`）与波动率分位直接使用，和式会让那两处静默地偏大 14 倍。DI 是两个和式相除，除不除都一样 |
| 1.2 | `indicators/boll.ts` | 「20 + 250 = **270** 根才有首个分位值」 | 第 **269** 根（下标 268） | 文档把当根重复计了一次。实现按「窗口严格取 250 个样本」，差 1 根，不影响任何判定 |
| 1.3 | `regime/index.ts` | 突变条件「ADX 3 日变化 > 5」 | 取**绝对值** | 原文括注为「趋势快速形成**或瓦解**」，瓦解就是下降。与 BBW 那条（原文明确写了绝对值）保持一致 |
| 1.4 | `combine/index.ts` | 冲突条款只提「两个方向都触发」 | 「对侧得分也过阈值、只是票数不够」时同样判为矛盾 | 多空得分几乎相等的本质是规则互相打架，与对侧差一票无关。此时提醒用户买入是不负责任的 |
| 1.4b | `combine/index.ts` | `rawScore = Σ strategyWeight × (Σ sub.score × sub.weight)` | 策略内取**加权平均**（除以已成立子信号的权重和） | 见下 |
| 1.4c | `risk/index.ts` | 移动止损「盈利 ≥ 5% 后，从 peak 回撤 ≥ 3%」 | 取**当前**浮盈 ≥ 5%（盈利保护那条取「曾达」浮盈） | 见下 |

### 1.4b 组合层得分为什么改成加权平均

字面读法是「未成立的子信号按 0 计入」。那样一来，趋势市里要过 0.60 就得让 5 条趋势子信号中的
4 条同时接近满分（`0.7 × 0.857`），而同一节又写着「`votes ≥ 3` 即可触发」——
**两个数在字面读法下不可能同时成立**，票数条件形同虚设，而实际效果是引擎几乎永远不出信号。

取加权平均后，得分的含义变成「已成立规则的平均强度 × 该策略在当前状态下的权重」：
一致性由票数负责、强度由得分负责，0.60 / 3 票才是一组自洽的阈值。
副作用是**震荡市里纯趋势信号最高只有 0.3，永远够不着 0.60** —— 这正是动态权重该有的效果，
也正是回测的分 Regime 归因要检验的那个假设。

### 1.4c 移动止损与盈利保护为什么必须一个取「当前」一个取「曾达」

两条都按 peak 浮盈读的话，④ 盈利保护几乎永远够不着：
`peakProfit ≥ 5%` 且 `profit < 2%` 反推出 `fromPeak ≤ -2.86%`，与 ② 移动止损的 `-3%` 几乎重合，
② 会把 ④ 整个吃掉（写完用例才发现 ④ 是死代码）。

按「当前 / 曾达」区分后两条规则不重叠，各自都有明确语义：
② 是「趁还赚着落袋」，④ 是「已经回吐大半，保住剩下的」。
原文（docs/05 §2.3）的措辞正是「盈利 ≥ 5% **后**」与「**曾达** +5% 后」。
| 1.5 | `strategies/trend.ts` | T2 打分式 `0.5 + 0.5×min(HIST[i]/HIST[i-1]−1, 1)` | `HIST[i-1] ≤ 0` 时改用固定 0.6 | 金叉当日柱子刚由负转正，几乎必然 `HIST[i-1] ≤ 0`，直接套公式会得到负比值甚至除零 |
| 1.6 | `risk/index.ts` | 「新股次新：上市 < 60 个交易日」 | 用**已入库根数**近似 | 上市日期数据源不一定给。回补目标是 320 根，因此 `bars < 60` 基本只可能是次新股或回补失败，两种情况都不该出信号 |

### 1.7 票数判据实际等价于「成立的子信号个数」

docs/04 §4.2 的 `votes(d) = 满足 sub.score ≥ 0.5 的子信号个数`，而 `strategies/context.ts`
的统一打分把 **0.5 定义为「刚好满足条件」**，1.0 为「满足到 span 倍」。
因此任何成立的子信号分数都 ≥ 0.5，票数 = 成立的子信号个数。

这与原文「3/5 策略一致确认」的意图一致，但**「≥ 0.5」这道门槛事实上不起筛选作用**。
若标定时发现票数门槛没有区分度，应当改的是打分函数的下界（比如让弱条件给 0.3），
而不是调票数阈值 —— 记在这里，免得下一个人对着 `votes` 调半天。

## 3. 结构上的取舍

### 3.1 `regime` 每次从头算整条序列，而不是「读上次状态 + 增量推进」

盘中最后一根是临时线。若把它的结论持久化，收盘后就再也分不清
「状态是真的切了」还是「上午那次抖动被记成了历史」。整条重算的代价是 O(n)，可以忽略。

### 3.2 `src/backtest` 用相对路径 import，且自带一个 SQLite 只读壳

- CLI 由 tsx 直接跑，而根 `tsconfig.json` 是 solution 风格、不带 `paths`，tsx 解析不到 `@core/*`。
- 按 CLAUDE.md 的分层，`src/backtest` 只复用 `src/core`。十几行驱动壳换来的是「回测不依赖主进程装配」。

### 3.3 仓位模型：每只标的一个等额独立仓位

组合净值 = 各仓位净值之和，缺 K 线的日子前值填充（停牌期间那部分资金确实还在）。
这不是资金管理策略，只是让「信号本身值不值钱」可比 —— 引入调仓与权重优化会让绩效差异
分不清是策略的还是资金管理的。报告里标注了这一点。

### 3.4 回测里「明日开盘观察」= 买入

收盘确认的 BUY 信号必然落在 T+1 尾盘规则之后（判定时刻是 15:00），因此风控会把它改写为
`NEXT_DAY_WATCH`。而回测的成交模型本来就是**次日开盘**成交 —— 两者是同一件事。
这反过来验证了 T+1 规则与回测执行模型自洽。

### 3.5 信号落库去重

盘中每 30s 一轮，100 只股票一天 800 轮。落库签名取
`日期 | 方向 | 阶段 | 级别 | 是否抑制 | 首要依据`，**刻意不含得分** ——
得分随临时 K 线连续抖动，含它等于没去重。

## 4. 文档没写、但实现绕不过去的

### 4.1 基准指数要跟着自选股一起回补

RSI 的动态阈值靠沪深300 的近 20 日收益分位算（docs/04 §1.6），但基准不在自选股表里。
`tick.ts` 因此多了一个 `auxCodes()`：需要日线、但不产出信号也不取快照的代码。
少了它，情绪值会一直退化为中性 0.5，RSI 阈值静默地停在 75/25，**没人看得出来**。

### 4.2 大盘情绪的「逐根序列」与「当期标量」必须同源

实盘只需要当期一个值（`marketSentiment`），回测每根都要（`sentimentSeries`）。
两者若分叉，回测用的 RSI 阈值曲线就和实盘不是同一条。
有一条用例专门断言「序列末值 === 当期值」。

### 4.3 `IndicatorSet.thresholds` 里的 RSI 两条阈值是「当期值铺满整条序列」

情绪是**当期**标量，历史位置上的阈值不代表当时的真实阈值 —— **只有最后一根有意义**。
回测里每根 K 线各自调用一次引擎，那时的「最后一根」才是被判定的那根，因此不受影响。
已写进 `types.ts` 与 `thresholds.ts` 的注释。

### 4.4 收盘确认轮只改库里的 `stage`，不发提醒

docs/04 §6 的确认轮包含「主动发一条撤销提示」，那属提醒层（M3）。
M2 实现了 `PROVISIONAL → CONFIRMED / INVALIDATED` 的状态推进，
否则 M3 上线时会拿到一堆永远停在 PROVISIONAL 的历史行，分不清哪些当初被确认过。

### 5.1 为什么没做参数标定

> **2026-08-12 更新：数据这条障碍已排除，本节原来的判断是错的。**
> 原文写「三家接口全部不通」，实测**三家都能用**：
> tencent 的 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 与 sina 快照稳定 200；
> eastmoney 在 undici 下也能通（成功率约 78%，重试可过），只有 curl 对它 100% 失败 ——
> 即 M1 偏差报告 §2「出口网络拦截」的诊断是 curl 单一客户端的假象。
> 而标定要的恰恰是历史日线，腾讯那个接口不复权与前复权两轨都给。
> `scripts/fetch-history.mjs`（`pnpm fetch:history`）已能把 2018 年至今拉成回测 fixture，
> 并已跑出第一份基于真实行情的报告。**未做的部分从「拿不到数据」变成了「标的池未定、
> 标定结论未复核」**，见 §5.4。

标定要 2018–2026 的真实日线。当时的判断是本机到三家行情接口全部不通
（见 [M1 偏差报告 §2](./M1-偏差报告.md)），`market.db` 里一根真实 K 线都没有。

**不能用合成数据代替**：合成序列的统计性质是我自己编的，在它上面「标定」出来的参数
只反映我编数据时的假设，比不标定更危险 —— 它会带着一份看起来很正规的报告。

### 5.2 因此 M2 交付的是「标定的能力」，不是「标定的结论」

已就绪、可直接用的：

```bash
# 单组参数的回测报告（含分 Regime 归因 + 固定权重对照组）
pnpm backtest -- --codes SH600000,SZ000001 --from 2018-01-01 --to 2026-06-30 --out reports/a.json

# 粗网格标定：训练/验证/测试三段切分，自动执行 docs/07 §3 的三条过拟合红线
pnpm backtest -- --codes ... --grid params/grid.json --out reports/calibration.json
```

红线已内置：交易 < 30 笔直接淘汰、验证集年化为负淘汰、验证集相对训练集断崖衰减标记为疑似过拟合、
排名用**验证集** Calmar（用训练集排名等于直接过拟合）、测试集只跑一次。

**工具不会自动改 `params.ts`** —— 自动写回会让「出厂默认值从哪来」变成没人复核过的黑箱，
而 ADR-0003 的整个立场就是不接受未经复核的数值。

| `0.50 / 2 票` | 952 | 354 | -0.08 | 淘汰：验证集年化为负 |
| `0.72 / 4 票` | **3** | — | — | 淘汰：训练集仅 3 笔（< 30） |

优胜候选的三段表现：

| 段 | 交易 | 年化 | 最大回撤 |
|---|---|---|---|
| train | 1343 | **-0.14%** | 5.05% |
| validation | 406 | +0.19% | 4.07% |
| test | 408 | **-0.03%** | 3.01% |

三段全部在零附近，训练集与测试集还是负的 —— 这不是「绩效一般的参数」，是**没有信号**。
顺带看清了出厂默认的另一面：`0.60 / 3` 在 39 只 × 6 年的训练集上只出 **44 笔**
（约每只每 6 年 1 笔），`0.72 / 4` 只出 3 笔。这两组阈值不是保守，是不工作。

所以标定的产出是：**`params.ts` 一个数都不能改**，理由是没有候选值得改成：

- **出厂默认 `0.60 / 3` 被红线淘汰** —— 验证集年化为负。它不是「保守」，是不成立；
- 优胜者的验证集 Calmar 是 **0.05**，与 0 没有实质区别，样本外还亏 0.28%。
  把它写进 `params.ts` 等于用噪音替换猜测，比保留猜测更糟 —— 后者至少诚实地标着未标定。

`ENGINE_VERSION` 的 `-unvalidated` 后缀保留。这一次它的含义变了：
不再是「没跑过标定」，而是「跑过了，没有候选够格」。

#### 下一步该做什么（以及不该做什么）

按 [约束 5](../../CLAUDE.md) 与 docs/08 关键决策点，**不要加指标**。三条发现指向的是同一个地方：
信号率。建议顺序是

1. 先查 `regime` 为什么三分之二时间停在 TRANSITION（迟滞窗口 / ADX 与 BBW 阈值）——
   它同时压着发现 2 与 3；
2. 再看 §1.7 记的那件事：票数门槛「≥ 0.5」事实上不起筛选作用，
   若要让票数有区分度，该改的是**打分函数的下界**而不是票数阈值；
3. 组合层阈值的标定要等前两条稳定之后重跑，否则标的是一个会变的靶子。

#### 工具侧记录的两件事

- **`fetch:history` 的抓取行为**：见下面第 1–4 条。
- **标定 CLI 在 39 只标的上偶发无声退出**：exit 1，stdout / stderr 都为空，
  同样的命令重跑即通过（6 次里挂了 3 次，挂的位置不固定 —— 有一次在候选 13/20 的中途，
  有一次在跑完全部候选之后）。8 只标的时未复现。**没有定位到原因**；
  曾怀疑与 `--out` 有关，但中途挂的那次发生在任何写盘之前，不成立。
  跑大网格时**必须检查退出码**，不能只看有没有报告文件 —— 它失败时什么都不留。

抓取侧有三条口径必须记住（都写在 `scripts/fetch-history.mjs` 的文件头）：

1. **复权轨用后复权（hfq），不是 docs/04 写的前复权 —— 这是被迫的，也是本次最重要的一条。**
   腾讯的前复权是加性的（减价差，[M1 §5.5](./M1-偏差报告.md) 实测），高分红股上累计分红
   一旦超过当年股价，前复权价就变**负数**：实测 SH601919（中远海控）2018–2026 有
   **714 根 `closeAdj` ≤ 0**，最低 -5.145。负价格上算出来的 MA / MACD / RSI / 布林带全部无意义，
   而回测又按复权价计净值 —— 这不是可以「记进报告」的偏差，是数据不可用。
   换后复权后，该股「复权后跳变 > 20%」的可疑计数从 **42 降到 0**，SZ000157 从 1 降到 0，
   反过来证明那些跳变本就是加性前复权的假象。
   **对判定与绩效等价**：指标全是比率型（MACD 穿越点、BBW、RSI、ADX 的 TR/ATR）在整条序列
   乘正常数后不变，净值用相邻复权价之比算，常数约掉；真实成交价那一路用的是不复权 `close`
   （止损与持仓成本），本来就没走复权轨。附带好处是 **hfq 的历史值不随抓取日变**，
   序列可复现，而 qfq 每天重抓都是新的一条。
   代价：`Candle.*Adj` 的字段语义与 docs/04 的措辞不一致（没改字段名 —— 那要动 core 的类型契约）。
   `fetch-history.mjs` 里有「复权价必须恒正」的断言，改回 qfq 会立刻炸。
2. **腾讯日线的量是「手」**，脚本 ×100 转股；日线不给成交额，`amount` 一律 `null`。
3. **当天那根一律剔除**：盘中它是临时 K 线，混进标定集等于让结论依赖跑它的时刻。
   首次跑就撞上了 —— 个股两轨只有一轨有当天，指数两轨都有。
4. **不写 `profile`**：响应带证券名称，但那是今天的名称，用它标 2018 年那根的 ST 状态
   是未来函数。宁可留着 `fallbackProfile` 那个方向已知的乐观偏差。

主源 eastmoney 的 fixture 仍未录成（间歇性失败 + `record-fixtures.mjs` 没有重试），
[M1 偏差报告 §2](./M1-偏差报告.md) 那条待办不受影响。

### 5.5 追查「TRANSITION 占 67%」（2026-08-12）：根因不在 regime 层

> 本节的**诊断**仍然成立，但其中的**回测数字都是解耦前的**（组合层口径已于同日改掉）。
> 要看改后的数、以及被这次改动修正的一处结论，直接读 [§5.6](#56-解耦得分上限与阈值2026-08-12口径改了决策点-2-的答案没变)。

§5.4 的三条发现里，发现 2 与 3 都指向 regime 层，所以先查它。结论是**方向错了**：
regime 层的判定确实很难成立，但让信号出不来的不是它，是组合层的一处乘性耦合。

新增工具 [`pnpm audit:regime`](../../src/backtest/regime-audit.ts)：读 regime 层自己发布的
`evidence` 字段（不复写判定逻辑 —— 复写的话审计与被审计对象可以一起错），
判定根集合与 `simulate.ts` 逐条对齐（同样的 warmup / 跳过末根 / 跳过 `hasGap` / 同样的
`lookback` 切片），因此占比可以直接与回测报告对账：审计得到 41003/61534，与 §5.4 的数字一致。

#### 成因分解（39 只宽基样本，61534 根判定）

| 成因 | 根数 | 占比 | 说明 |
|---|---|---|---|
| ① 未预热 | 0 | **0.0%** | 预热与数据量**不是**原因 |
| ② 突变条件命中 | 15012 | 24.4% | 三条突变线中「量比 > 1.5」独占 9.9% |
| ③ ADX 死区 | 11719 | 19.0% | ADX 落在 `[adxRange, adxTrend]` 之间，趋势与震荡都不可判 |
| ④ 四条件合取不满足 | 14086 | 22.9% | ADX 够了，但 DI / MA20 / 排列不配合 |
| ⑤ 迟滞压制（与①–④交叉） | 4017 | 6.5% | 原始判定已非 TRANSITION，生效仍是 |

**迟滞不是原因**：原始判定 TRANSITION 占 66.3%，带迟滞后 66.6% —— 几乎不动。
`hysteresisDays: 2` 温和到近乎无操作，§5.4 里「该查迟滞」的猜测不成立。

ADX 的动态阈值恰好落在实际分布的正中间：ADX 均值 **25.04**，`adxTrend` 均值 **23.85**，
于是 47.1% 的根在趋势侧、28.8% 在震荡侧、24.1% 卡在中间的死区。

#### 四个反事实探针：TRANSITION 有个约 50% 的地板

| 探针 | 改动 | TRANSITION | 相对出厂 |
|---|---|---|---|
| — | 出厂默认 | 66.6% | — |
| A | 三条突变条件**全部关闭** | 53.7% | −12.9 |
| B | 突变放宽（量比 3 / ADX 10 / BBW 40） | 55.8% | −10.8 |
| C | ADX 死区 `rangeGap` 5 → 2 | 63.0% | −3.6 |
| D | B + C 同时 | 51.6% | −15.0 |

即使把三条突变条件整条删掉，TRANSITION 仍有 53.7%；死区几乎消灭（24.1% → 6.8%）
只买回 3.6 个点，腾出来的根大半掉进「④规则不满足」而不是变成 RANGE。
**调 regime 的阈值最多买回 15 个点，买不到「四种状态各占相当比例」那个设计前提。**

#### 根因：得分上限 = 策略权重，与 `scoreThreshold` 乘性耦合

[`combine/index.ts`](../../src/core/combine/index.ts) 第 128 行：

```
raw = w_trend × trendPart + w_meanRev × meanRevPart      // 两个 part 都是 0..1 的加权平均
```

两个 part 是**已成立子信号的加权平均**（§1 那条偏差的产物，本身是对的）。
后果是：**只有一个策略出信号时，`raw` 的上限恰好等于该策略在当前 regime 的权重。**

| Regime | 只有趋势 | 只有均值回归 | 出厂阈值 0.60 可达？ |
|---|---|---|---|
| TREND_UP | 0.70 | 0.30 | 趋势可，均值回归**不可能** |
| TREND_DOWN | 0.70 | 0.15（BUY） | 买入**不可能**（这条是设计意图） |
| RANGE | 0.30 | 0.70 | 趋势**不可能**，均值回归可 |
| **TRANSITION** | **0.50** | **0.50** | **两者都不可能** |

**在 66.6% 的判定根上，单策略信号在算术上无法触发。** 唯一出路是趋势与均值回归
同向共振 —— 而它们本就是对立的两套逻辑。这解释了 §5.4 全部三条发现：

- 92 笔交易里 **84 笔来自 TREND_UP** —— 唯一一个单策略（趋势 0.70）能过 0.60 的状态；
- RANGE 与 TREND_DOWN 合计 11378 根判定、**0 笔交易**；
- 保守档 `0.72` 高于**所有**单策略上限（最高的 TREND_UP 趋势也只有 0.70）
  → 任何 regime 下单策略都不可能触发，标定里它 6 年只出 3 笔；
- 标定的网格排名其实不是在比信号质量，是在比「阈值有没有掉到上限以下」：
  0.35 → 3567 笔、0.40 → 1343、0.50 → 952、0.60 → 44、0.72 → 3，
  断崖正好落在 TRANSITION 的 0.50 上限处。

权重表（docs/04 §4.1）与 `scoreThreshold`（§4.2）来自来源文档的不同段落，
**两者从未相互校对过** —— ADR-0003 说的正是这种情况。已在
[`tests/unit/combine/combine.test.ts`](../../tests/unit/combine/combine.test.ts)
用一组用例把这个上限固化下来（固化现状，不主张现状正确：改权重表、改阈值、
或改成按贡献策略归一化，都会让它们失败，那时应当连同 docs/04 §4.1 一起复核）。

#### 决策点 2 的答案：没有证据说明动态权重有效

出厂参数下动态只有 92 笔、固定只有 11 笔，都不够 docs/07 §3 的 30 笔红线，比不出东西。
把阈值降到上限以下后交易量足够了，于是同一次运行里的对照组可以直接比：

| 组合层参数 | 动态权重 | 固定 0.5/0.5 对照 |
|---|---|---|
| `0.60 / 3`（出厂） | 92 笔 / -1.16% / 夏普 -0.38 | 11 笔 / -0.32% / -0.46 |
| `0.40 / 2`（标定优胜） | 2187 笔 / **+0.21%** / 0.02 | 1687 笔 / **+2.94%** / **0.15** |
| `0.35 / 1` | 5902 笔 / **-9.06%** / -0.16 | 5676 笔 / **-6.54%** / **-0.11** |

两个交易量足够的参数点上，**固定权重在总收益与夏普上都赢了动态权重**，
成本差只解释了缺口的约三成（0.40/2：成本差 2.9 万，盈亏差 10.4 万）。

> ⚠ 这个差距的**大小**是耦合的产物。解耦后同样三点重测，差值缩到 1pp 以内且正负交替
>（[§5.6](#56-解耦得分上限与阈值2026-08-12口径改了决策点-2-的答案没变)）。
> 「看不出动态权重有效」这个方向没变，但**不要引用上表的幅度**。

分 Regime 归因（`0.40 / 2`，2187 笔）更直接：

| Regime | 交易 | 判定根 | 胜率 | 平均盈亏 |
|---|---|---|---|---|
| TREND_UP | 1135 | 9153 | 30.1% | -1.93% |
| RANGE | 273 | 5208 | 30.8% | -1.83% |
| TRANSITION | 769 | 41003 | **33.9%** | **-1.58%** |
| TREND_DOWN | 10 | 6170 | 0% | -1.54% |

`0.35 / 1` 下同样的形状（32.6% / 33.6% / 32.8%，平均盈亏 -1.27% / -1.46% / -1.49%）。
**各状态的胜率与平均盈亏没有可辨别的差异，而「无法分类」的 TRANSITION 反而最好。**
regime 对交易结果不携带区分信息 —— 这正是 [docs/08 关键决策点 2](../08-开发路线图.md)
说的「归因显示动态权重切换无效」的情形，按其规定应当**在此处停下来重新设计组合层**。

注意这里比的是「动态 vs 固定」，不是「哪组参数好」：三个参数点的绝对绩效都在零附近
或为负，没有一组构成可用策略。上表**不得**用于宣称任何绩效。

#### 因此，下一步

§5.4 列的三步里，第 1 步（查 regime）已执行完毕，结论是**不要在 regime 层继续调阈值**。
修正后的建议：

1. ~~**先解掉得分上限与阈值的耦合**~~ —— 已于同日执行，见
   [§5.6](#56-解耦得分上限与阈值2026-08-12口径改了决策点-2-的答案没变)。
   实现时否掉了「按有贡献策略的权重和归一化」这一种（它会把 §4.1 的压制意图一起删掉），
   改成除以行内最大权重。
2. **然后才谈组合层的去留。** ——已可以谈了：解耦后重测，动态权重仍看不出效果，
   决策点 2 的触发条件在排除口径 bug 之后依然满足。
3. 组合层阈值的标定要等第 1 步落定之后重跑：现在的靶子会随口径一起动。
   ——仍然成立，而且现在要等的是**第 2 步的拍板**（组合层留不留决定了标定什么）。

**不要做的事**：加指标（约束 5）、继续微调 regime 的三条突变线与 `rangeGap`
（探针 A–D 已经量化过上界，最多 15 个点，且买不到设计前提）、
以及把上面任何一个数字写进 `params.ts`（ADR-0003）。

### 5.6 解耦得分上限与阈值（2026-08-12）：口径改了，决策点 2 的答案没变

执行 §5.5 第 1 步。**只改口径，一个参数值都没动**（`params.ts` 里的数字仍是 ADR-0003 的初始猜测），
`ENGINE_VERSION` 因算法变更递增到 `0.2.1-unvalidated`。

#### 改法与为什么是这一种

```
改前：raw = Σ_s  w_s × part_s                              // part_s ∈ [0,1] ⇒ 单策略上限 = w_s
改后：raw = clamp( Σ_s (w_s / max_s' w_s') × part_s, 0, 1 ) // 主策略满分 = 1.0
```

§5.5 提了两种解法，实现时否掉了「按**有贡献策略的权重和**归一化」那种：
单策略出手时它的分母恒等于分子里那个权重，得分永远是 1.0，
于是**震荡市里的孤立趋势信号与趋势市里的一样强** —— docs/04 §4.1 想表达的压制意图会被一起删掉。
除以行内最大权重则两头都保住：

| Regime | 趋势可信度 | 均值回归可信度 |
|---|---|---|
| `TREND_UP` / `TREND_DOWN` | 1.00 | 0.43（`TREND_DOWN` 的 BUY 0.21） |
| `RANGE` | 0.43 | 1.00 |
| `TRANSITION` | 1.00 | 1.00 |

两条不变量写进了 `tests/unit/combine/combine.test.ts`：**可达性**（每个状态都存在能拿满分的单策略信号）
与**区分度**（次策略单独出手只有 `w_minor / w_major`）。两条同时钉着，才不会退回原来的坑、
也不会滑到「归一化过头、权重表形同虚设」的另一头。

三个副作用要记下来：

1. **权重表的含义变了**：只有行内比值有意义，`0.70/0.30` 与 `0.35/0.15` 等价。
   「`TRANSITION` 整体不如 `TREND_UP` 可信」这层意思**丢掉了** —— 它原先是靠 `0.5 < 0.7` 顺带表达的，
   而那正是不可达的成因。真要表达，得新增一个显式的状态级折价参数并单独标定，不能再塞回权重表。
2. **夹紧点在加调整项之前**：共振时商可到 2.0，不夹的话 §3.3 的 `M3_FALSE_BREAKOUT`（−0.15）
   会被溢出的那截吸收掉，在最该起作用的场景里失效。代价是顶部没有分辨率了，那段交给票数。
3. **`alert.bubbleScore = 0.75` 这类分级线现在才有一致含义**：改前它在 `TRANSITION` 下不可达。

#### 出厂参数点：从「基本不出信号」变成「会出信号」

同一份数据（39 只、2018-01-01 → 2026-08-11、`--fixtures ./data/history`、每只 10 万本金）：

| 出厂 `0.60 / 3` | 交易 | 总收益 | 夏普 | 胜率 |
|---|---|---|---|---|
| 解耦前 | 92 | -1.16% | -0.38 | — |
| 解耦后 | **414** | **+1.73%** | **+0.22** | 34.1% |

分 Regime 归因也从「84/92 挤在 TREND_UP」变成两态分担：

| Regime | 交易 | 判定根 | 胜率 | 平均盈亏 |
|---|---|---|---|---|
| TREND_UP | 216 | 9153 | 31.0% | -1.67% |
| TRANSITION | **198** | 41003 | **37.4%** | **-1.12%** |
| RANGE | 0 | 5208 | — | — |
| TREND_DOWN | 0 | 6170 | — | — |

`TRANSITION` 从 0 笔变成 198 笔，正是这次要修的那条。

> ⚠ **绝对绩效仍不构成任何结论**：+1.73% 是 8.6 年累计，同期 SH000300 基准 +14.10%，超额 -12.37pp。
> 这些数字只用于**比较口径与参数**，不得用于宣称绩效，标的池本身也带选择偏差（见 §5.4 的标的池说明）。

#### `RANGE` / `TREND_DOWN` 仍是 0 笔 —— 现在卡的是票数，不是得分

补跑一个只降票数的探针（`0.60 / 2`，得分线不动）：

| 参数 | 总交易 | RANGE | TREND_DOWN | 总收益 | 夏普 |
|---|---|---|---|---|---|
| `0.60 / 3` | 414 | 0 | 0 | +1.73% | 0.22 |
| `0.60 / 2` | 2520 | **239** | **10** | -4.33% | -0.15 |

得分线不变、只放松一票，`RANGE` 就从 0 笔变成 239 笔 —— 所以这两个状态的沉默是
**3 票的一致性要求**造成的，不是得分够不着。均值回归只有 4 条子信号（趋势有 5 条），
要求其中 3 条同时成立是个很强的过滤器。它显然在做实事（放松后总收益从 +1.73% 掉到 -4.33%），
但「票数门槛对两个策略不等价」是个待处理的口径问题，不要靠调 `voteThreshold` 一个数糊过去。

#### 决策点 2：解耦后重测，答案没变

| 组合层参数 | 动态权重 | 固定 0.5/0.5 对照 | 差（动态 − 固定） |
|---|---|---|---|
| `0.60 / 3`（出厂） | 414 笔 / +1.73% / 0.22 | 419 笔 / +1.74% / 0.22 | -0.01pp |
| `0.60 / 2` | 2520 / -4.33% / -0.15 | 2540 / -3.24% / -0.11 | -1.09pp |
| `0.40 / 2` | 2636 / -2.80% / -0.09 | 2602 / -3.38% / -0.11 | **+0.58pp** |
| `0.35 / 1` | 6541 / -11.20% / -0.19 | 6575 / -10.80% / -0.18 | -0.40pp |

**差值在四个参数点上正负交替、量级都在 1pp 以内 —— 这是噪音，不是效果。**
动态权重仍然没有可辨认的收益。

同时要更正 §5.5 的一句话：那里写「三个参数点上固定权重都不输于动态权重」，
其中 `0.40/2` 的 +2.94% vs +0.21% 那个显眼的差距**是耦合的产物**，解耦后缩到 0.58pp 并且反了号。
结论的方向没变（看不出动态权重有效），但当时那个差距的**大小**不能当证据用。

分 Regime 归因同样没有变：出厂参数下 `TRANSITION`（37.4%）的胜率高于 `TREND_UP`（31.0%），
`0.40/2` 与 `0.35/1` 下四态的胜率仍都落在 31%–34% 的窄带里（`0.35/1` 的 `TREND_DOWN` 是 99 笔 47.5%，
样本太小且与其余三态方向相反，不能当信号）。**「无法分类」的状态不比「分类清楚」的状态差**
这一现象，在解耦后依然成立。

#### 因此，下一步（决策点 2 已经可以判了）

按 [docs/08 关键决策点 2](../08-开发路线图.md)，「归因显示动态权重切换无效」的条件已经满足，
且这次是在**排除了口径 bug 之后**满足的 —— 上一轮还可以说「是耦合压着它」，这一轮不能了。
规定动作是**简化为单一策略 + 风控，砍掉组合层复杂度**。这件事改的是产品的引擎形态，
需要人来拍板，本报告只把判据摆齐，不代劳。

若决定保留组合层，那么保留的理由不能是绩效（上表没有），只能是别的（比如「多策略投票让
『为什么提醒』更好解释」）—— 那就要明说，并且**不要再把 regime 权重当成绩效手段**来标定。

在拍板之前**不要**做的事：重跑阈值标定（靶子会随组合层去留一起动）、
把上面任何数字写进 `params.ts`（ADR-0003）、加指标（约束 5）。

### 5.7 策略消融（2026-08-12）：出厂参数下均值回归贡献 0 笔，且拿掉它更好

§5.6 把决策点 2 的判据摆到了「动态权重无效」这一步，但那还不足以在
「只砍动态权重」和「一路砍到单一策略 + 风控」之间做选择 —— 差一个数：
**均值回归到底贡献了几笔交易**。这一节把它测出来了。

#### 先说为什么需要新加一个开关

不能靠「把某策略的权重设成 0」做消融。组合层的**票数不分策略**
（任何 `sub.score ≥ 0.5` 都计一票，见 `combine/index.ts`），权重 0 的策略得分贡献是 0、
票照投 —— 那测的是「关掉它的得分、留着它的票」，不是关掉这个策略。

因此新增 `params.enabledStrategies`（`{ trend, meanReversion }`，出厂两项皆 `true`）：
被关掉的策略在 `runStrategies` 里一个子信号都不产出，对组合层既不供分也不供票。
多周期调整项不受影响（它不属于这两个策略）。`ENGINE_VERSION` 因参数结构变更递增到
`0.2.2-unvalidated`；出厂形态下重跑基线得到与 §5.6 完全一致的 414 笔 / +1.73% / 夏普 0.22，
**开关本身对默认行为是中性的**。

它是测量工具，不是可标定参数 —— 网格标定不得把它当维度扫。

#### 结果（39 只宽基样本 · 2018-01-01 → 2026-08-11 · 每标的 10 万）

| 组合层参数 | 启用的策略 | 交易 | 总收益 | 夏普 | 最大回撤 |
|---|---|---|---|---|---|
| `0.60 / 3`（出厂） | 趋势 + 均值回归 | 414 | +1.73% | 0.22 | 2.46% |
| `0.60 / 3` | **只留趋势** | **435** | **+2.67%** | **0.32** | 2.17% |
| `0.60 / 3` | 只留均值回归 | **0** | — | — | — |
| `0.60 / 2` | 趋势 + 均值回归 | 2520 | -4.33% | -0.15 | 10.10% |
| `0.60 / 2` | 只留趋势 | 2439 | -3.61% | -0.13 | 10.15% |
| `0.60 / 2` | 只留均值回归 | 292 | +0.15% | 0.03 | 2.13% |

三条读数：

1. **出厂参数下均值回归单独出手一次都没有。** 不是「贡献小」，是 0。
   直接成因是票数：它只有 4 个子信号（R1–R4），要凑够 3 票得四中有三同时成立；
   趋势有 5 个（T1–T5），同一条 `voteThreshold` 对两者并不对等。
2. **它在组合里是净负贡献。** 加上它，交易从 435 笔降到 414 笔（`TRANSITION` −20、`TREND_UP` −1），
   收益 +2.67% → +1.73%，夏普 0.32 → 0.22。机制是它的反向子信号触发了冲突裁决
   （`conflictBand`）把趋势那一侧的信号也一并压掉 —— 它自己不出信号，却在拦别人。
   在 `0.60 / 2` 上同向重现（−3.61% → −4.33%）。
3. **它并非「结构上永远不可能出信号」。** 把票数放到 2，它能出 292 笔，且几乎全在 `RANGE`
   （290 笔，`TRANSITION` 只有 2 笔）—— 与 §4.1 想表达的「震荡市靠均值回归」是一致的。
   但那 292 笔的成绩是 +0.15% / 夏普 0.03，接近零。

#### 这个结果能证明什么，不能证明什么

**能证明**：在当前这组未标定参数、这套票数规则下，均值回归对最终交易没有正贡献，
把它整条拿掉反而更好。决策点 2 里「简化为单一策略 + 风控」的规定动作，
现在有了直接判据，而不只是「动态权重无效」这个间接判据。

**不能证明**：均值回归这类策略本身没用。至少三个混淆项没有被排除 ——
(a) R1–R4 的阈值（RSI 极值、`revertLookback`、`midReversionStd`…）全是 ADR-0003 说的初始猜测，
从未标定过；(b) 4 子信号 vs 5 子信号共用一条 `voteThreshold`，对它系统性不利；
(c) 冲突裁决目前是「压掉双方」，另一种写法是「弱侧让路」，那会改变第 2 条读数。
**所以这里测到的是「这一版实现 + 这一组猜测参数下的均值回归」，不是「均值回归」。**

#### 三条可选路径（这一步需要人拍板，报告不代劳）

| 路径 | 动作 | 代价 | 风险 |
|---|---|---|---|
| A. 砍到底 | 删掉均值回归策略与组合层的权重/裁决，只留趋势 + 风控 | 改动最大，docs/04 §3.2/§4 大段作废 | 若失败原因其实是 (a)(b)(c)，等于把没调过的东西判了死刑 |
| B. 只砍动态权重 | 权重表固定 0.5/0.5、删 regime → 权重链路，保留得分/票数/裁决 | 纯删除，风险最低 | 留着一个已知净负贡献的策略 |
| C. 先修不对等再判 | 给两个策略各自的票数线（或改成按权重比例的票数），标定 R1–R4 后重测 | 多一轮标定 | 可能标定完仍是这个结论，多花一轮 |

按已测到的东西，**A 与 B 都不会让绩效变差**（A 直接 +0.94pp，B 实测 ±0.01pp）。
差别在于「保留多少可标定的空间」。C 是唯一能把混淆项 (a)(b) 排除掉的路径，
但它要求先接受「再花一轮标定」。

在拍板之前，§5.6 末尾那三条「不要做的事」继续有效。

### 5.8 拍板（2026-08-12）：删掉动态权重，均值回归暂留一轮

选的是路径 **B**。

#### 判据是「机制是否惰性」，不是绩效差值

这一点值得写清楚，因为它决定了为什么不顺手把均值回归一起砍掉（那可是白捡的 +0.94pp）。

§5.6 里，动态权重与固定 0.5/0.5 的差值在四个参数点上是 ±1pp 以内、正负交替，
我据此判它「看不出效果」。那么 §5.7 里「只留趋势」比「两个都留」好的 +0.94pp，
是同一个量级的数 —— 用它来支持一个删除决定，就是拿同一把尺子量出两个相反的结论。

能把两件事分开的不是绩效，是**成因是否已经查清**：

- 权重表：两轮测量（带口径 bug 的和解耦后的）都测不出效果，而且现在知道它唯一还在起作用的
  地方是**把 `RANGE` 里的趋势单策略得分钉死在 3/7 ≈ 0.43**（够不着 0.60）—— 那是副作用，不是效果。
  它是惰性的，且惰性的原因已经查清。
- 均值回归：0 笔有一个明确的、**尚未排除**的成因（4 子信号 vs 5 子信号共用 `voteThreshold = 3`，
  即 §5.7 的混淆项 (b)）。在排除它之前判死刑，就是给一个没调过的东西判死刑。

所以：删已经查清是惰性的那个，留下一个能在一小时内排除的混淆项先去排除。

#### 实际删了什么

| 删除对象 | 位置 |
|---|---|
| `weights` 表（四行状态 × 两个策略） | `src/core/params.ts` |
| `weightsFor()` 与得分式里的权重项 | `src/core/combine/index.ts` |
| 「每行和为 1」「趋势市与震荡市取向相反」两条不变量 | `tests/unit/core/params.test.ts` |
| 固定权重对照组（`fixedWeightParams()`、`--no-fixed-weights`、报告里的对照块） | `src/backtest/{args,cli,report}.ts` |

得分式从

```
raw = clamp01( (w_t·part_t + w_mr·part_mr·buyPenalty) / max(w_t, w_mr) )
```

变成

```
raw = clamp01( part_t + part_mr · buyPenalty )
```

`downtrendBuyPenalty`（下跌趋势里均值回归**买入**的 0.5 折价）**保留**：它是方向级抑制
（docs/04 §4.1 的「别接飞刀」），与「按状态切换策略可信度」不是一回事，且从未被单独测过。
`ENGINE_VERSION` → `0.2.3-unvalidated`。

删除处都留了墓碑注释，写明「不要把权重表加回来 —— 它已经被测过一次了」。

#### 删完的实测（出厂 `0.60 / 3`，39 只，2018-01-01 → 2026-08-11）

| | 交易 | 总收益 | 夏普 | 最大回撤 | 胜率 | 平均持仓 |
|---|---|---|---|---|---|---|
| 删除前（动态权重） | 414 | +1.73% | 0.22 | 2.46% | 34.06% | 14.3 日 |
| 删除后（等权） | **419** | **+1.74%** | **0.22** | 2.53% | 34.13% | 14.8 日 |

总量几乎没动，但分状态归因下面换了一批交易：

| Regime | 删除前 | 删除后 |
|---|---|---|
| `TREND_UP` | 216 | 197（−19，胜率 31.02% → 30.96%） |
| `TREND_DOWN` | 0 | 0 |
| `RANGE` | **0** | **24**（胜率 37.50%） |
| `TRANSITION` | 198 | 198（胜率 37.37% → 36.87%） |

两处变化各有成因，都是权重行内比值的直接后果：

- **`RANGE` 从「一笔都没有」变成 24 笔** —— 0.3/0.7 那一行让趋势单策略的得分封顶在
  3/7 ≈ 0.43，够不着 0.60，**震荡市里的趋势信号在算术上不可能触发**。这是 §5.5 那个耦合坑的
  残留分支：§5.6 的「除以行内最大权重」解掉了「上限恰等于权重」，但没解掉「行内比值压制弱侧策略」。
- **`TREND_UP` 少了 19 笔** —— 反方向的同一件事。0.7/0.3 曾把均值回归在趋势市里的得分压到
  3/7，现在它满额参与，于是更多反向子信号进入冲突裁决，压掉了一部分趋势侧交易。
  这与 §5.7 第 2 条读数（均值回归「自己不出信号，却在拦别人」）是同一个机制，
  权重表删掉后它拦得更多了 —— **等权化本身没有削弱这个已知问题，反而略微放大了它。**
  这条也是下一步先修票数线、暂不砍策略的另一个理由：现在均值回归的净影响比 §5.7 测的更大，
  更值得把混淆项排干净再判。

> 一个口径提醒：删除前那一列的「固定 0.5/0.5 对照组」曾测得 419 笔 / +1.74%，与删除后完全一致，
> 但两者**不是同一份配置** —— 旧对照组顺手把 `meanReversionBuyPenalty` 也设成了 1，
> 新引擎保留 0.5。数字撞上是因为 `TREND_DOWN` 两边都是 0 笔，那条折价没有作用对象。
> 别把「对上了」当成两份配置等价的证据。

绝对绩效仍然不构成任何结论：+1.74% 是 8.6 年累计，同期基准 +14.10%（超额 −12.37%）。
这一步做的是**删掉一个测不出效果的机制**，不是「提升了绩效」。

#### 还没做的

下一步是 §5.7 路径 C 的前半段：**给两个策略各自的票数线**，把 4 vs 5 的不对等修掉再跑一次消融。
预期是救不回来（2 票时均值回归已经是 292 笔 / +0.15% / 夏普 0.03），
但跑完之后再执行路径 A，才不是在给一个没调过的东西判死刑。

在这一步跑完之前，仍然**不重跑阈值标定**（靶子会随组合层去留一起动）。

### 5.9 修掉票数线的不对等（2026-08-12）：均值回归被救回来了，但仍然测不出贡献

§5.7 混淆项 (b) 说的是：趋势 5 个子信号、均值回归 4 个，共用一条 `voteThreshold = 3`，
对后者是四中取三（75%）、对前者是五中取三（60%）。这一节把它修掉再测。

#### 改了什么

`combine.voteThreshold` 从一个整数变成 `{ trend, meanReversion }`，三档灵敏度按**同一个比例**
换算再取整：趋势 2/3/4 票即 5 个子信号的 40%/60%/80%，均值回归 4 × 同比例 = 1.6/2.4/3.2 ⇒ 2/2/3。
出厂档因此从「3 票」变成「趋势 3 票 / 均值回归 2 票」。`ENGINE_VERSION` → `0.2.4-unvalidated`。

同时**合并规则也变了**：触发要求从「两边票数之和 ≥ 线」改成「**任一策略达到自己的线**」。
这是必然的 —— 一条按策略给的线没法和一个跨策略的总和比。理由本身也站得住：
票数衡量的是同一个策略内部有多少条规则互相印证，「趋势 2 票 + 均值回归 1 票」凑出来的 3
不具备这个含义。但它确实是**第二处改动**，所以下面分两步测，不把两者混在一起。

#### 第一步：只换合并规则（两条线都设 3 票）

| | 交易 | 总收益 | 夏普 | 最大回撤 |
|---|---|---|---|---|
| §5.8 的基线（总票数 ≥ 3） | 419 | +1.74% | 0.22 | 2.53% |
| 分策略计票，线仍是 3/3 | 414 | +2.02% | 0.26 | 2.30% |

差 5 笔 —— 那 5 笔正是靠「跨策略凑票」触发的，现在不算数了。绩效变化在噪音带内，
这一步的意义是**把语义改动的影响量化出来只有 5 笔**，后面那一大段变化都不是它造成的。

#### 第二步：把均值回归的线降到 2（新的出厂档 0.60 / 3 / 2）

| 启用的策略 | 交易 | 总收益 | 夏普 | 最大回撤 | 胜率 | 盈亏比 |
|---|---|---|---|---|---|---|
| 趋势 + 均值回归 | **662** | **+2.98%** | 0.31 | 2.58% | 32.02% | 2.54 |
| 只留趋势 | 459 | +2.84% | **0.33** | **2.16%** | 35.08% | 2.36 |
| 只留均值回归 | 292 | +0.15% | 0.03 | 2.13% | 31.51% | 2.21 |

分状态（趋势 + 均值回归 那一行）：`TREND_UP` 200 · `TREND_DOWN` 0 · `RANGE` **275** · `TRANSITION` 187。

**均值回归从「0 笔」变成「292 笔独立出手」，其中 290 笔在 `RANGE`** —— 这正是 §4.1 给它设计的
位置（震荡市靠均值回归）。所以 §5.7 的读数 1「它一次都没独立出手」确实是票数线不对等造成的，
**不是这个策略结构上出不了信号**。混淆项 (b) 到此排除。

#### 但贡献仍然测不出来

把它加到趋势上：收益 +2.84% → +2.98%（**+0.14pp**），夏普 0.33 → 0.31（**−0.02**），
最大回撤 2.16% → 2.58%（**+0.42pp**），胜率 35.08% → 32.02%。

这是同一条「±1pp 内、正负交替」的噪音带 —— 我用它判过动态权重无效（§5.6），
也用它拒绝过「+0.94pp 就砍均值回归」（§5.8）。**同一把尺子量下来，现在的结论是
「加不加它，测不出差别」，而不是「它有用」或「它有害」。**

值得单独记一笔的是冲突裁决的损耗：459 + 292 = 751，合起来只有 662，**89 笔被裁决压掉**
（`RANGE` −47、`TRANSITION` −32、`TREND_UP` −10）。§5.7 读数 2 说的「它自己不出信号却在拦别人」
现在变成「两边互相拦」—— 这一层的代价是实打实的，而收益是测不出的。

#### 现在的状态与还剩的混淆项

- 混淆项 (b)（票数线不对等）：**已排除**。
- 混淆项 (a)（R1–R4 从未标定）：**仍在**，但性质变了 —— 之前均值回归根本不出手，标定它没有意义；
  现在它有 292 笔可优化的交易，**标定 R1–R4 第一次成为一件做得动的事**。
- 混淆项 (c)（冲突裁决「压掉双方」vs「弱侧让路」）：**仍在**，且这次量化了代价（89 笔）。

顺带一提，新出厂档 `0.60 / 3 / 2` 的绝对数字（662 笔 / +2.98% / 夏普 0.31）比 §5.8 的
`0.60 / 3`（419 笔 / +1.74% / 0.22）好，但**这不构成「参数标定完成」** —— 它仍是同一份
39 只、全样本内的数据，没过 docs/07 §3 的三段切分与三条红线。同期基准 +14.10%，超额仍是 −11.12%。

**下一步该由人拍板**：均值回归是按路径 A 砍掉（判据：贡献测不出，且要为冲突裁决付 89 笔的代价），
还是先标定 R1–R4 再判（判据：混淆项 (a) 现在第一次可测）。组合层的其余部分已经收口，
**阈值标定的靶子不再会动**，两条路都可以立刻开跑。

### 5.10 标定 R1–R4（2026-08-12）：贡献测不出来的原因是 R3 的压缩线，不是策略本身

选了后一条路。结论先写在前面：

> **均值回归留下。** §5.9 里那条「测不出贡献」的读数是 `strategy.squeezeBbwPct = 10` 造成的 ——
> 那个 10 直接来自来源文档的「BBW_PCT < 10 是变盘前夜」（docs/04 §1.4），是 ADR-0003 说的
> 典型「未经验证的转述值」。把它放宽到 16–30 之间的任意一个值，均值回归的边际贡献就从
> **+0.14pp（噪音带内）跳到 +2.0 ~ +3.4pp（噪音带的两三倍以上）**，而且回撤不变。
> 这是本项目第一个**由标定流程产出、而不是靠猜**的参数结论。

#### 怎么标的

两个网格文件、两种基线配置，四次运行：

| 网格 | 扫什么 | 基线 |
|---|---|---|
| `params/grid-mean-reversion.json` | `rsi`（R1 带宽，3 档）× `strategy`（R2/R3/R4，9 组 OFAT）= 27 组 | ① 只开均值回归 ② 完整引擎 |
| `params/grid-mean-reversion-squeeze.json` | `strategy.squeezeBbwPct` ∈ {16, 24, 30, 40, 50}，两条 R2/R4 剖面 = 10 组 | 同上 |

- 三段切分是 docs/07 §3 的默认：训练 2018-01-01→2023-12-31 / 验证 2024-01-01→2025-06-30 /
  测试 2025-07-01→2026-08-11。标的池仍是 `params/universe-broad.json` 的 39 只。
- 「只开均值回归」用 `params/mean-reversion-only.json` 经 `--params` 传入。
  `enabledStrategies` 是消融开关、**不是网格维度**，两个网格文件里都没有它。
- `strategy` 块内刻意用**一次一因子**（OFAT）而不是 3×3×3 全展开：全展开要跑两个多小时，
  而 OFAT 让 docs/07 §3 的第三条红线（邻域 ±20% 是否断崖）可以直接从同一张报告里读出来。
- 第二个网格是因为第一个网格的最优点 `squeezeBbwPct = 20` **落在网格边界上**，
  而 5 → 10 → 20 是单调上升的 —— 不往外扩就只知道「20 好过 10」，不知道 20 是不是峰。
  扩展的依据是验证集的单调性与缺失的 ±20% 邻居，**不是**测试集数字（见文末的纪律说明）。

#### 读数 1：R2 对它唯一的参数是**惰性的**

`revertLookback` 取 2 / 3 / 5，在两种基线 × 三档 RSI 共 6 条剖面上，
训练集与验证集的**笔数与收益逐位相同**：

| 配置 | rv2 | rv3 | rv5 |
|---|---|---|---|
| 只开均值回归 · rsi 出厂 | 199 笔 / −0.98% | 199 笔 / −0.98% | 199 笔 / −0.98% |
| 完整引擎 · rsi 出厂 | 409 笔 / +1.19% | 409 笔 / +1.19% | 409 笔 / +1.19% |

把回溯窗口从 2 日拉到 5 日，一笔交易都没多、没少。R2 的三个条件里
「近 N 日曾收在轨道外」根本不是约束项，真正卡住它的是同一根上的
「HIST 转正/转负」翻转（docs/04 §3.2）。**`revertLookback` 不是一个可标定参数**，
调它等于什么都没调 —— 这一条要么接受（保持 3），要么改 R2 的结构，标定给不出答案。

#### 读数 2：R1 在收紧方向上几乎也是惰性的

RSI 带宽三档（`osBase/obBase` = 20/60、15/65、10/70，即 s=0.5 时的 30/70、25/75、20/80）：

| 剖面（只开均值回归，训练集） | 20/60 | 15/65（出厂） | 10/70 |
|---|---|---|---|
| sq10 rv3 md1.5 | 208 笔 / −0.60% | 199 笔 / −0.98% | 197 笔 / −0.88% |
| sq20 rv3 md1.5 | 357 笔 / +0.60% | 351 笔 / −0.54% | 339 笔 / −0.82% |

出厂 → 更严（15/65 → 10/70）只少 2~12 笔，验证集分数**逐位相同**；
放松（→ 20/60）多出 6~9 笔，验证集在几乎每一行都更差。
也就是说 R1 在「RSI 深度超卖**且**触下轨」这个双重条件下本来就很少成立，
带宽在 ±5 点内怎么挪都改不了什么。

#### 读数 3：R3 的压缩线是唯一有效的杠杆，出厂值 10 明显偏紧

验证集 Calmar（排名依据；rv3 / md1.5 / rsi 出厂剖面）：

| `squeezeBbwPct` | 5 | 10（出厂） | 16 | 20 | 24 | 30 | 40 | 50 |
|---|---|---|---|---|---|---|---|---|
| 只开均值回归 | −0.02 ✗ | −0.01 ✗ | 0.31 | **0.36** | 0.26 | 0.16 | 0.06 | 0.04 |
| 完整引擎 | −0.01 ✗ | −0.01 ✗ | 0.05 ⚠ | 0.08 | 0.09 | **0.17** | 0.05 | 0.05 |

✗ = 被红线淘汰（验证集年化为负）；⚠ = 被标记疑似过拟合（相对训练集衰减 > 50%）。

**出厂的 10 在两种基线下都被红线淘汰**，而 16 以上是一整片高原 —— 不是一个孤立的峰值。
docs/07 §3 的第三条红线（±20% 邻域是否断崖）因此直接读得出来：以 20 为中心，
16 = 0.31、24 = 0.26，都在中心值的一半以上，**不是噪音峰值**。
完整引擎那一行的 30 反而更脆（40 = 0.05 < 0.17 的一半）。

两种基线给出的「最优」不同（只开均值回归 → 20，完整引擎 → 30），但结论不依赖于选哪个：
**16 到 30 之间的任何一个值都远好过出厂的 10。** 若要在高原上挑一个，
`20` 是唯一在训练集与验证集上**同时**靠前的（完整引擎训练集 +1.60%，是该剖面最高的一档）；
工具按验证集 Calmar 排名会给出 30，但它的训练集只有 +0.41%。**这一步是人的选择，本报告不代劳。**

#### 读数 4：换成标定后的压缩线，均值回归的贡献一下子测得出来了

全区间（2018-01-01 → 2026-08-11，39 只，每标的 10 万，出厂 `0.60 / 3 / 2`）：

| 配置 | 交易 | 总收益 | 夏普 | 最大回撤 |
|---|---|---|---|---|
| 只留趋势（不受 R3 影响） | 459 | +2.84% | 0.33 | 2.16% |
| sq10（出厂）两个都留 | 662 | +2.98% | 0.31 | 2.58% |
| sq16 两个都留 | 737 | +5.37% | 0.51 | 2.27% |
| **sq20 两个都留** | **762** | **+6.25%** | **0.57** | **2.16%** |
| sq24 两个都留 | 788 | +4.87% | 0.44 | 2.08% |
| sq30 两个都留 | 805 | +5.66% | 0.49 | 2.19% |

均值回归的**边际贡献**（相对「只留趋势」）：

| `squeezeBbwPct` | 收益 | 夏普 | 回撤 |
|---|---|---|---|
| 10（出厂） | +0.14pp | −0.02 | +0.42pp |
| 16 | +2.52pp | +0.18 | +0.11pp |
| 20 | **+3.41pp** | **+0.24** | ±0.00pp |
| 24 | +2.03pp | +0.11 | −0.08pp |
| 30 | +2.82pp | +0.16 | +0.03pp |

用同一把尺子：我判动态权重无效、判 §5.9 里的均值回归「测不出贡献」，用的都是
「差值在 ±1pp 内、正负交替」这条噪音带。**这里的 +2.0 ~ +3.4pp 在整片高原上同号、
是噪音带的两三倍以上，而且不以回撤为代价** —— 按同一判据，这次是能测出来的。

#### 这个结果不能证明什么

- **不是「标定完成」。** 只标了 R1–R4 中的一个参数有效维度（R3），
  `combine` 的四个数、`macd`/`adx`/`regime`/`risk` 全块、`downtrendBuyPenalty` 都还没标。
  `ENGINE_VERSION` 仍带 `-unvalidated`，**没有任何数值被写回 `src/core/params.ts`** ——
  那是人的动作（ADR-0003 / docs/07 §3 ⑤）。
- **均值回归单独跑仍然不赚钱。** 35 组候选里，只开均值回归的**训练集总收益全是负的**
  （−0.43% ~ −2.93%），唯一的正数出现在 18 个月的验证窗口里。
  它的价值体现在与趋势的组合上，不体现在自己身上 —— 这与「它该在 `RANGE` 里补位」的设计一致，
  但也意味着**不能单独把它作为一个策略推给用户**。
- **样本仍是那 39 只、仍带幸存者偏差**（§5.4），同期基准 +14.10%，`sq20` 的超额仍是 **−7.85%**。
  这一层改的是「引擎内部哪个参数错得离谱」，不是「这套策略跑赢了市场」。
- **测试集的纪律被削弱了一点，要如实记下**：docs/07 §3 ④ 要求测试集只跑一次。
  实际上每次 `--grid` 调用都会对该次的优胜者跑一遍测试窗口，而我为了处理「最优点落在网格边界」
  跑了两轮网格 × 两种基线 = 四次。四次的测试集读数分别是
  +1.46% / 57 笔（只开均值回归 · sq20）、+1.24% / 56 笔（同 · sq16）、
  +2.77% / 131 笔（完整引擎 · sq20 rv5 md1）、+2.79% / 123 笔（完整引擎 · sq30）。
  **扩网格的决定是照着验证集的单调性做的，不是照着这些数字做的**，但「只跑一次」这条已经不成立，
  上面的结论应当只按训练集 + 验证集来读。出厂 sq10 的测试窗口数字**没有跑**，
  正是为了不让它变成一个选择依据。

#### 三个混淆项的收口状态

- (a) R1–R4 从未标定：**已解决**，且答案是「问题出在 R3」。
  附带查清 R2 对参数惰性、R1 近乎惰性 —— 这两条是**结构问题，标定解决不了**。
- (b) 票数线不对等：§5.9 已排除。
- (c) 冲突裁决「压掉双方」vs「弱侧让路」：**仍在**。代价还变大了：
  459 + 491 = 950 → 762，`sq20` 下有 **188 笔**被裁决压掉（出厂 sq10 时是 89 笔）。
  结果照样变好，说明被压掉的不全是好交易，但这一层依然没被单独测过。
  → **已在 §5.12 测完，出厂机制是对的。** 另外这里的 188 笔是个错数
  （消融差值把三件事算成了一件），单独关掉裁决测出来是 128 笔。

#### 拍板（2026-08-12）：写回 20，后缀留着

人工复核后 `strategy.squeezeBbwPct` 由 10 改为 **20**，`ENGINE_VERSION`
`0.2.4-unvalidated` → `0.2.5-unvalidated`，依据与失效条件记入 [CHANGELOG](../../CHANGELOG.md)。
**这是本项目第一个被标定过的出厂参数。**

取 20 而不是工具按验证集 Calmar 排出的首选 30：30 只在完整引擎口径下领先（0.17 vs 0.08），
在只留均值回归的口径下明显更差（0.16 vs 0.36），说明它靠的是与趋势策略的交互而非 R3 本身变准 ——
两个口径分歧时取两段都靠前的那个值，证据更厚。

**`-unvalidated` 后缀没有摘。** 原先 M2 清单 4.9 把「写回参数」与「摘后缀」绑成一条，
那是按「整套参数一次标定完」写的；实际是一个一个标定的。此刻摘后缀会让回测报告
不再打「参数未标定」提示（`src/backtest/report.ts` 的 `unvalidatedParams`、清单 5.4），
等于用一个参数的证据给另外二十来个转述值背书。清单 4.9 因此拆成
**4.9a 部分写回**（递增补丁位、保留后缀、`params.ts` 顶部维护一张逐项的「已标定」清单）与
**4.9b 标定完成**（改 `0.3.0`、删掉 `params.test.ts` 的后缀断言）。

#### 建议的下一步（按性价比排序）

1. **R2 的结构**：它对唯一的参数惰性，等于四个子信号里有一个不可调。
   要么接受、要么按 docs/04 §3.2 重新论证它的触发条件 —— 不属于标定的范畴。
   → **已做，见 §5.11。结论比预期难看：口径确实错了、改了，但绩效没变好，
   而且真正的约束被证明在组合层的票数线上。**
2. 混淆项 (c)：冲突裁决现在压掉 188 笔，值得单独做一次消融。
   → **已做，见 §5.12。出厂机制（压掉双方）正确，弱侧让路在每个维度上都更差；
   顺带修正：裁决的实际作用量是 128 笔，不是 188 笔。**
3. 其余参数块的标定（`combine` 四个数、`downtrendBuyPenalty`、`adx`/`regime`）。
   **§5.11 给这一项加了一个必测维度：`voteThreshold.meanReversion`；
   §5.12 给 `conflictBand` 划出了取值区间（机制已验证，取值待三段切分）。**
4. **超额为负这件事**：`sq20` 全期 +6.25%，同期基准 +14.10%，超额 −7.85%。
   前面所有标定都是在「相对自己的其他参数」这把尺子上比的，没有一条回答过
   「这套策略比买入持有好吗」。它可能推翻的是策略本身而不是某个参数，量级最大。

### 5.11 修 R2 的口径（2026-08-12）：错找到了、改了，但绩效不动，约束在组合层

§5.10 附带查出「R2 对 `revertLookback` ∈ {2,3,5} 逐位惰性」。这一节是它的收口。
新增诊断工具 `pnpm audit:subsignals`（`src/backtest/subsignal-audit.ts`）：
它按子信号 ID × 方向统计触发数，并对 R2 把三项合取**逐项拆开**计数、
统计「只差一项」的近失数与「②③ 都成立时，最近一次在轨道外距今几根」的分布。

> 工具的诚实性保证：近失分析必须重算 `evaluate()` 在条件不成立时不会发布的合取项，
> 因此工具里复制了一份判定逻辑。`main()` 里有一条硬自检 ——
> **重算的 R2 触发数与 `evaluate()` 实际产出的不相等就直接报错退出**，不是打个 warning。
> 一旦 `strategies/mean-reversion.ts` 改了而工具没跟上，先修工具再看结论。

#### 读数 1：三项合取里，一项形同虚设，一项永远等不到

39 只 × 2018-01-01→2026-08-11，61534 根判定日，出厂 `revertLookback = 3`：

| 合取项 | 单独成立的根数 | 占比 |
|---|---|---|
| ① 近 3 日曾 `close < LOWER` | 3168 | 5.1% |
| ② `close > MID` | ~30100 | **49%** |
| ③ `HIST` 转正（过零翻转） | 2646 | 4.3% |
| ②③ 同时 | 1529 | 2.5% |
| ①②③ 同时（= R2 实际触发） | **45** | **0.073%** |

（BUY 方向的数；SELL 方向同构，两方向合计 90 次 / 0.15%。）

**② 成立于一半的交易日 —— 放在合取里等于不存在。** 而它一旦不是约束项，
`revertLookback` 也就没有东西可约束：把窗口从 2 放宽到 5，只是让本就不稀缺的 ①
更容易成立，卡住结果的 ③ 与窗口无关，于是回测逐位相同。**这是惰性的机制**，
不是「窗口取值不敏感」。

#### 读数 2：③ 与 ① 的时间常数差一个量级

②③ 都成立的 1529 根上，「最近一次收盘在轨道外距今几根」的分布：

| 距今 | ≤2 根 | ≤4 根 | ≤10 根 | ≤30 根 | 60 根内没有 |
|---|---|---|---|---|---|
| 累计占比 | 2.9%（45 根） | 10% | ~22% | 40% | 19–26% |

`d ≤ 2` 的 45 根**正好等于** R2 的实际触发数（`existsWithin` 含当根，
窗口 3 的有效回溯是 2 根）—— 分解与 `evaluate()` 对得上。
中位数落在 **35–40 根**：`HIST` 过零就是 `DIF` 上穿 `DEA`，是个慢事件，
而 `revertLookback` 是 2–5 根。**两个条件在时间尺度上凑不到一起，
任何 `revertLookback` 取值都救不了它** —— 这确认了「标定解决不了」。

#### 改法与效果

改成 **曾在轨道外（窗口）+ 今日穿越中轨（事件，`crossUp`/`crossDown`）+
`HIST` 朝有利方向（软确认，不要求过零）**。论证写在 [docs/04 §3.2](../04-指标与信号引擎.md)。

| | 触发数 | 占判定根 | `revertLookback` |
|---|---|---|---|
| 旧口径 | 90 | 0.15% | 惰性（2/3/5 逐位相同） |
| 新口径 | **213** | **0.35%** | **活的**：3 → 213、5 → 592、11 → 1807 |

`crossUp(close, MID)` 自身在 5.7% 的判定日成立 —— 从「49% 的伪条件」变成了真正的约束项。

#### 但绩效没有变好

全期（39 只，2018-01-01→2026-08-11，出厂 `0.60 / 3 / 2`，`sq20`）：

| 口径 | 交易 | 总收益 | 夏普 | 最大回撤 |
|---|---|---|---|---|
| 旧 R2 | 762 | +6.25% | 0.573 | 2.16% |
| 新 R2 | 769 | +5.93% | 0.543 | 2.44% |

差 −0.32pp 收益 / −0.03 夏普 —— 按本报告一直用的那条噪音带（±1pp、正负交替）读，
**这是「测不出差别」，不是「改坏了」**。更说明问题的是网格：
`params/grid-r2-lookback.json`（`revertLookback` ∈ {3,5,8,12,20}，其余固定）
的五个候选，**验证集 Calmar 全是 0.084、验证集交易数全是 127**，
训练集交易数 489/485/485/485/486。参数活了，输出还是不动。

#### 为什么不动：R2 与其余三个子信号几何互斥，凑不够票

工具的共现统计（新口径 213 次触发）：

| | 次数 | 占比 |
|---|---|---|
| 自身 `score ≥ 0.5`（够一票） | 213 | 100% |
| 同一根上有同方向的其他均值回归子信号 | 28 | 13% |
| —— 其中陪跑者是 `R3_SQUEEZE` | 28 | 全部 |
| **孤立触发（没有任何同方向同伴）** | **185** | **87%** |

原因是条件在几何上互斥：**R2 要求价格在中轨上**，而 R1 / R3 要求当根触外轨、
R4 要求 `|close − MID| ≥ midReversionStd × STD`。同一根上不可能既在中轨附近
又深度偏离中轨。那 28 次例外全是 R3，因为 R3 用的是当根**最高/最低价**而非收盘价 ——
长影线可以同时满足「收在中轨上」与「最低价触下轨」。

而 `combine.voteThreshold.meanReversion = 2` 要求同策略两票。
**R2 在结构上无法自己促成一次触发**，它 0.30 的权重只能给得分一点微调。
所以 R2 改得再准，也要等票数线让它有意义 —— 约束从子信号层转移到了组合层。

#### 这一节的处置

- **改写留下。** 理由是口径正确（穿越是事件，与 §2 的穿越纪律一致）+ 参数从死变活，
  **不是它更赚钱**。`ENGINE_VERSION` → `0.2.6-unvalidated`（口径变更，非参数标定），
  记入 [CHANGELOG](../../CHANGELOG.md)。
- **`voteThreshold.meanReversion` 进入 §5.10 下一步第 3 项（`combine` 块标定）的必测维度**，
  不单独为它开一轮 —— 它本来就是那一块的参数，单独测会再触碰一次测试窗口。
- **R1 的惰性不改。** R1 的两个条件各自都是真约束（不像 R2 的原 ②），
  惰性来自交集小，属于「这条规则本来就罕见」，不构成口径错误。
- 遗留：`sensitivityFlags()` 仍未接进 CLI —— 若它已接上，R2 的逐位相同本该在
  §5.10 那一轮就被自动标出来，而不是靠人去比较两份 JSON。

### 5.12 混淆项 (c) 收口（2026-08-12）：冲突裁决「压掉双方」是对的，弱侧让路每个维度都更差

§5.7 起挂了三个混淆项，(a) 与 (b) 已解决，(c)「冲突时压掉双方 vs 弱侧让路」一直没测。
这一节把它测完。

**不需要改代码**：`adjudicate()` 判矛盾的条件是 `gap < conflictBand`，
把 `conflictBand` 设为 0 会让它恒假，行为**恰好等于**「取 final 较高者」——
也就是弱侧让路。于是这个机制之争可以直接用一次参数扫描回答。

全期 39 只、2018-01-01→2026-08-11、`sq20` + 新 R2、其余出厂：

| `conflictBand` | 交易 | 总收益 | 夏普 | 最大回撤 | 胜率 | 交易成本 |
|---|---|---|---|---|---|---|
| 0.00（= 弱侧让路） | 897 | +5.67% | 0.473 | 2.50% | 32.8% | 48966 |
| 0.05 | 847 | +5.72% | 0.497 | 2.47% | 33.3% | 45680 |
| **0.15（出厂）** | **769** | **+5.93%** | 0.543 | 2.44% | 33.2% | 42067 |
| 0.30 | 689 | +5.56% | 0.572 | 2.13% | 33.8% | 36485 |
| 0.50 | 679 | +5.82% | **0.596** | 2.13% | 33.9% | 36214 |
| 0.80 | 679 | +5.82% | 0.596 | 2.13% | 33.9% | 36214 |

#### 读数 1：弱侧让路更差，而且是全维度更差

出厂 0.15 相对 band = 0：少 128 笔交易，收益 **+0.26pp**、夏普 **+0.070**、
回撤 **−0.06pp**、手续费 **−6900**。没有任何一个维度支持「让弱侧让路能救回一些交易」。
**多空得分几乎相等时，那一笔本来就不该做** —— 文档里那句「此时提醒用户买入是不负责任的」
现在有实测支持了。

#### 读数 2：机制在 0.50 处饱和，所以夏普的上升不是「少交易」的代理

0.50 与 0.80 **逐位相同**：897 − 679 = **218 笔**是被裁决触及的全部交易，
band ≥ 0.5 时全部压掉，再放宽没有东西可压。这条饱和是这一节里最该记住的 ——
夏普从 0.473 单调升到 0.596，如果它只是「交易越少越稳」的假象，那么继续放宽 band
应该继续变好，但它到顶了。同时收益不是单调的（0.15 最高、0.30 回落、0.50 又回升），
0.15 与 0.50 的收益差 0.11pp 在噪音带内。

#### 读数 3：顺带修正一个此前的数字

§5.10 写过「`sq20` 下有 188 笔被裁决压掉」，那是从 `459 + 491 = 950 → 762` 推出来的差值，
**把三件事算成了一件**：裁决压掉的、两个策略得分相加后新触发的、以及单标的单持仓约束挤掉的。
直接测出来的裁决口径是 **128 笔**（897 → 769，新 R2 口径下）。
教训与 §5.11 同源：**消融差值不等于某个机制的作用量**，要测这个机制就得单独关掉它。

#### 这一节不能证明什么

- **不是「`conflictBand = 0.15` 已标定」。** 这是全区间跑的，没走 docs/07 §3 的三段切分，
  而且 0.15 是出厂值 —— 拿全期数据说「出厂值最好」正是标定流程要防的那种论证。
  证的是**机制方向**（压掉双方 > 弱侧让路，且效应有界），取值仍归 `combine` 块那一轮。
- 样本仍是那 39 只、仍带幸存者偏差，超额仍为负。

#### 三个混淆项的最终状态

- (a) R1–R4 从未标定：**已解决**（§5.10，问题出在 R3 的压缩线）。
- (b) 票数线不对等：**已解决**（§5.9）。
- (c) 冲突裁决：**已解决**（本节，出厂机制正确）。
  §5.11 又新挂了一条待测：`voteThreshold.meanReversion = 2` 让 R2 无法参与投票。
  它不是混淆项，是一个明确的标定维度，归 `combine` 块。

### 5.13 「超额为负」先别急着推翻策略（2026-08-12）：平均资金占用只有 4.15%

§5.10 把「全期超额 −7.85%」列为量级最大的待查项，说它「可能推翻的是策略本身」。
查了。**在现在这个口径下，这个数不能用来判定策略好坏**，因为分母不是同一回事。

新 R2 + `sq20` 全期（39 只，2018-01-01→2026-08-11，2088 个交易日，初始资金 390 万）：

| | 策略 | 基准（沪深300 满仓） |
|---|---|---|
| 总收益 | +5.93% | +14.10% |
| 年化 | +0.67% | +1.55% |
| 最大回撤 | **2.44%** | **45.60%** |
| Calmar（年化 ÷ 最大回撤） | **0.275** | 0.034 |
| **平均资金占用** | **4.15%** | 100% |
| 超额 / 信息比率 | −8.17pp / −0.143 | — |

**策略平均只用了 4.15% 的资金**（持仓市值 × 持仓日数 ÷ 初始资金 × 交易日数，按建仓价计价）。
拿一个几乎全程空仓的策略去比满仓指数，−8.17pp 里有多少是「策略不行」、
多少是「钱根本没投进去」，光看超额一个数分不出来。同一张表里回撤是 2.44% vs 45.60%，
Calmar 是 0.275 vs 0.034 —— **风险调整后方向是反过来的。**

#### 但也不能反过来吹

按占用资金折算，8.56 年 +143%（年化约 10.8%）。**这个数不许拿去说事**，三条理由：
- 折算隐含「闲置的 95.85% 资金可以另作他用」，而策略并不能提前告诉你什么时候会用到它；
- 回测里闲置资金按 0 收益计，折算等于把这部分机会成本一笔勾销；
- 分母小 24 倍，噪音同样被放大 24 倍 —— 折算后的数字比原数字更不稳。

#### 这解释了一件一直没解释的事

前面所有消融的差值都在 ±1pp 这条噪音带里打转（动态权重、均值回归贡献、R2 改写）。
**那条带子是在总资金口径上的**：4.15% 的占用意味着总资金口径把所有差异压扁了约 24 倍。
这不改变任何排名（分母对所有候选相同），但说明「差值只有 0.5pp 所以无关紧要」
这种读法是错的 —— 该看的是差值相对同口径其他差值的大小，本报告一直用的
「正负交替 = 噪音」判据没有这个毛病，继续用它。

#### 处置

- **报告里加了 `performance.exposure`**（`src/backtest/metrics.ts` 的 `averageExposure()`），
  文本报告中**紧挨着超额那一行**打印，并注明「基准为满仓 100%」。
  这不是新指标，是让一个已有指标不再被误读的必要上下文。
- docs/07 §「输出指标」补了口径说明。
- **`--benchmark` 的语义没变**，仍是沪深300 满仓买入持有。要做同占用率的基准对照
  （或「每单位持仓时间的收益」这个更贴合提醒工具的口径）是另一件事，未做。
- **扩标的池仍然要做**：这一节回答的是「超额为负能不能证明策略失败」（不能），
  没有回答「这套策略有没有用」。39 只的幸存者偏差、样本量、以及只有一个 8.5 年区间
  这三条都没变。

### 5.14 标定 `combine` 块（2026-08-12）：四个参数一个也定不下来，但查出了标定工具的两处测量缺陷

`params/grid-combine-ofat.json`，OFAT 16 个候选（中心 = 出厂值，四个维度各自单独变），
39 只 × 2018-01-01 → 2026-08-11，三段切分同 docs/07 §3。

**这一轮的直接结论是否定的：`combine` 块的四个参数，没有一个能从这份数据里定出值来。**
但过程里查出了标定工具本身的两处测量缺陷，那部分是确定的收获。

#### 先说工具：分段绩效的 `bars` 里混进了预热前缀

`simulateCode` 对喂进去的**每一根** K 线都 push 一个净值点，包括 `split.from` 之前的预热段
（`warmupForSplit` 故意把段前历史全喂进去，见 §5.4）。`runSplit` 又把整条曲线交给
`performanceOf`，于是验证集的 `bars` 是 **1816**（数据起点 → 2025-06-30）而不是本段的 **359**。
后果按严重程度排：

| 指标 | 受影响 | 验证集实测（修正前 → 修正后） |
|---|---|---|
| `benchmarkReturn` / `excessReturn` | **完全错** | **−3.70% → +16.23%**（差 19.9pp，**连符号都反了**） |
| `annualized`（及由它算的 Calmar / `score`） | 压小 `bars` 倍 | 0.17% → **0.87%**（5.1×）；Calmar 0.084 → **0.427** |
| `sharpe` | 被一串 0 收益稀释 ≈ ×√(本段/全长) | 0.274 → **0.618**（预测 0.617） |
| `totalReturn` / `maxDrawdown` | 不受影响 | 1.28% / 2.03% 不变（预热段净值恒等于初始资金） |

`benchmarkReturn` 那一行最离谱：验证集拿的是**沪深300 在 2018→2025-06 全程**的涨跌，
去减一个只赚了 18 个月的策略收益。

**段内排名不受影响**（同一段里每个候选的 `bars` 相同），16 个候选按修正口径重排后
名次逐位相同 —— 所以下面的读数仍然成立。**但跨段的「Calmar 衰减 > 50%」红线是坏的**：
这一轮它对 3 个候选报了过拟合（`conflictBand` 0.25 / 0.40，`scoreThreshold` 0.72），
修正后这三个的衰减分别是 **−68% / −43% / −78%**，也就是验证集比训练集**更好**，三个全是假阳性。

**已修**：`runSplit` 把净值曲线按 `point.date >= split.from` 切回本段再算绩效。
修完用单候选网格实跑验证过，上表右列就是实跑数（不是推算）。

> **没有完全消掉的部分**：训练集的 `from` 就是数据起点，切了也还是 1457 根，
> 其中头 300 根是预热死区（占 21%）。这是训练窗口的真实属性（那 300 根里策略确实没法交易），
> 不是记账错误，所以不改。但它仍然让训练集的 Calmar 系统性偏低 ≈1.26 倍，
> 方向是**让衰减红线更不容易触发**。跨段比 Calmar 时要知道这一层。

#### 再说工具：没有任何一条红线拦得住「训练集亏钱、验证集赚钱」

`voteThreshold = {trend:3, meanReversion:1}` 这个候选，训练集 **1047 笔 / −3.73% / 夏普 −0.29**，
验证集 **359 笔 / +2.77% / Calmar 0.539**，按验证集 Calmar 排**第 2**。
三条红线一条都不拦：训练集交易数 1047 远超 30；验证集年化为正；衰减红线的判据带
`trainScore > 0` 前置，训练集 Calmar 是负的，判都不判。

排名用验证集本身是对的（用训练集排名等于直接过拟合），但它有这个盲区。
**已加第四条红线**：训练集 Calmar ≤ 0 直接淘汰，且不跑验证集

#### 逐维读数

**① `downtrendBuyPenalty` 是惰性的 —— 这是第三次遇到同一种病。**
0.25 / 0.5 / 0.75 三个值**训练集与验证集逐位相同**（489 笔 / +1.33% / 127 笔 / +1.28%）。
只有 1.0（= 不折价）动了训练集（499 笔 / +1.14%），而验证集**连 1.0 都不动**。
也就是说这个参数实际是个二值开关（折不折价），**幅度完全没有作用**，
而且连那个二值差别都传不到验证集。

根因与 §5.11 是同一个：下跌趋势里的均值回归**买入**几乎从不是**单独**的触发者
（R2 有 87% 的触发是孤立的，而孤立的均值回归子信号凑不够两票）。折价作用在一个
「本来也不决定成败」的得分项上，所以调它的幅度没有可观测后果。

**这不构成删掉它的理由。** docs/04 §4.1 的「别接飞刀」是方向级抑制的原则，
标定说的只是「在这 39 只 / 这个窗口 / 当前票数线下测不出差别」。出厂值保持 0.5。

**② `voteThreshold.meanReversion = 1`（§5.11 挂下来的那个问题）：能让 R2 参与，但那些交易在训练集上是亏的。**
票数线降到 1 之后交易数从 489 → **1047**（翻倍多），这印证了 §5.11 的判断 ——
约束确实在票数线上，R2 那 185 次孤立触发在 `= 1` 时全都能自己成事。
但多出来的 558 笔把 6 年训练集从 +1.33% 打成 **−3.73%**、夏普 0.195 → −0.29。
验证集的 +2.77% 是那 18 个月正好友好，不是稳健性。**不采用。**
（也正是这个候选暴露了上面第二条工具缺陷。）

另一端 `= 3` 同样不行：训练集 194 笔 / +0.49%，验证集直接转负 −0.08%，被红线淘汰。
**所以 `meanReversion = 2` 是这三个取值里唯一站得住的，出厂值不动。**

**③ `voteThreshold.trend = 4` 是名义优胜者，但不建议写回。**
验证集 Calmar 0.887，是第二名的 1.6 倍。但同一行的训练集是 **340 笔 / +0.40% / Calmar 0.029** ——
在 14 个非负候选里几乎垫底（中心是 0.090）。**训练集与验证集给出相反的方向**，
而验证集那一侧只有 **59 笔**交易撑着。这正是「验证窗口正好友好」的形状，
只是它没触发上面新加的红线（训练集是正的，只是很小）。
docs/07 §3 的「参数敏感性」红线本来就是拦这个的：3（0.427）→ 4（0.887）是孤峰不是高原，
而 2（`2/2` 那行）是 −0.233。**孤峰不采用。**

**④ `conflictBand`：§5.12 的「越宽越好」是训练窗口的假象，三段切分把它反过来了。**
训练集 Calmar 随带宽单调上升（0.05→0.089、0.10→0.107、0.15→0.090、0.25→0.141、0.40→0.179），
**验证集反过来**（0.370 / 0.427 / 0.427 / 0.299 / 0.322）。0.10 与 0.15 的验证集逐位相同，
区分不开；0.25 与 0.40 在验证集上明显更差。
§5.12 那张全区间表当时就写了「证的是机制不是取值」—— 这一轮证实了那句谨慎是必要的。
**机制结论（压掉双方 > 弱侧让路）不变，取值仍定不下来，保持 0.15。**

**⑤ `scoreThreshold`：训练集与验证集的梯度方向相反，没有高原。**
训练集偏好高（0.5→0.079 … 0.72→0.159），验证集偏好低（0.55→0.517 最高，0.66→0.340 最低）。
两边打架、且验证集上 0.5/0.55/0.6 的差距（0.505 / 0.517 / 0.427）小于同一参数换个冲突带
就能造出的差距。**读作噪音，保持 0.6。**

#### 为什么整块都定不下来（不是「网格设计得不好」）

三个可叠加的原因，都不是靠加密网格能解决的：

1. **测量对象只有总资金的 4%**（§5.13）。所有候选的验证集收益都挤在 −1.4% ~ +2.8% 之间，
   而这是**总资金口径**；折到实际占用的资金上差别会放大约 24 倍，但噪音同样放大。
2. **`combine` 是二阶旋钮。** 到目前为止唯一测出一阶效果的参数是 `strategy.squeezeBbwPct`
   （子信号的门），它决定「有没有信号」；`combine` 的四个数只决定「已有的信号怎么合」。
   §5.11 的 87% 孤立率说明这一层的实际自由度比参数个数小得多。
3. **验证集只有 359 根 / 59–503 笔。** 18 个月一个市场状态，`trend = 4` 那行 59 笔就能排第一，
   本身就说明这个窗口分辨不出这个量级的差异。

#### 处置

- **`combine` 块四个参数全部保持出厂值**（0.6 / {3,2} / 0.15 / 0.9 / 0.5），
  `ENGINE_VERSION` 不动 —— 没有写回，就没有要记的标定依据（ADR-0003 / docs/07 §3 ⑤）。
- **两处工具缺陷已修**（净值切段 + 训练集红线），带测试。**这两处修的是测量，不是参数**，
  所以不占「写回出厂参数」的流程（params/README「四件事」）。
- **测试窗口这一轮没有被读**：验证实跑用的是 `--to 2025-06-30`，测试段没有数据。
  网格本身跑出的 `test` 块（`trend=4` 的 57 笔 / +2.02%）**不作为结论使用** ——
  它的优胜者按上面 ③ 已被判为孤峰。累计触碰次数按 docs/07 §3 ④ 记：**5 次**。
- **`adx` / `regime` 块的标定（`params/grid-regime.json`，21 组）必须在修完的工具上跑**，
  修之前跑出来的分段 Calmar 和衰减标记都不能用。

### 5.15 重写标定工具（2026-08-13）：把判据搬进工具，并换掉逐折统计量

#### 为什么重写：十一轮标定，工具报了十一个优胜者，人否掉了十个

到 §5.14 为止，工具的输出是「按验证集 Calmar 排序的候选表」，**推荐 = 第一行**。
但真正的判据一直在人脑子里，而且每一轮都用上了：

| 轮次 | 工具报的第一名 | 人否掉的理由 |
|---|---|---|
| §5.10 | `squeezeBbwPct` 某个值 | 最优点落在网格边界 → 扩网格重跑，才找到 16–30 的高原（**唯一写回的一次**） |
| §5.11 | `revertLookback` 五个候选 | 验证集逐位相同 —— 参数是惰性的，排第一没有意义 |
| §5.14 ③ | `voteThreshold.trend = 4`（0.887，第二名的 1.6 倍） | 训练集垫底 + 验证集只有 59 笔 + 3→4 是孤峰不是高原 |
| §5.14 ② | `voteThreshold.meanReversion = 1`（排第 2） | 训练集 −3.73% —— 这一条后来变成了工具的第四条红线 |

**判据留在人脑子里，就只有人有空的那一轮能推进。** 十一轮、二十来个参数、一个写回，
不是因为参数都定不下来，而是因为每一轮的产出都是「一张要人再判一次的表」。
这一轮把上面四种理由全部变成工具里的代码。

#### 改了什么

| 改动 | 说明 |
|---|---|
| **折单元** | 判定窗口切成 `--code-folds` 个标的子集 × `--time-slices` 个时间片（默认 4 × 3 = 12 折）。折是从**同一次模拟**里切出来的，`--code-folds 8` 不多跑一次回测 |
| **配对 Δ** | 每个候选与出厂值**逐折相减**，报 Δ 均值 / 标准误 / t / 胜折数。出厂值那一行由工具自动注入（`queue.unshift({})`），不必写进网格 |
| **三态裁决** | `WRITE_BACK` / `KEEP` / `INCONCLUSIVE`，印在报告最上面。`KEEP` **是结论不是失败** |
| **自动标记孤峰 / 边界** | OFAT 轴上左右邻居的绩效断崖 → 「孤峰」；候选落在网格端点 → 「该侧邻域未测」。§5.14 ③ 那次人工判断现在是机器判的 |
| **分辨率** | `KEEP` 时报「要分辨已观测到的这个 Δ 大约需要多少折」，据此决定扩样本还是归档为不可标定（清单 4.9c） |
| **`--touch-test` 默认关** | 测试集要显式加开关才读，每次按 docs/07 §3 ④ 记账 |
| **退出码** | `0` = WRITE_BACK 或 KEEP，`2` = INCONCLUSIVE，`1` 是真的失败 |

标的按代码升序**轮转**分组，不是切段 —— 切段会让某一折全是创业板。

#### 逐折统计量：Calmar 不能按折算，换成本折总收益

第一版用「本折 Calmar」当逐折得分，跑完 `combine` 才发现这个统计量在折的粒度上是坏的。
两处硬伤，都是实测：

**① 分母塌了。** 出厂值 12 折的 Calmar 是
`−1.97, 13.53, 1.25, −0.80, 3.41, 5.83, −0.21, −1.42, 17.67, −1.50, −1.80, −0.97`。
一折三四十只标的、一百多根 K 线，最大回撤经常只有零点几个百分点，
年化除下去就飞到 13 / 17。**折间量纲差一个数量级，均值与标准误都被两三折支配。**
`trend = 4` 的逐折 Δ 是 `0.12, −1.39, 0.73, —, 0.30, −3.59, 4.56, —, −9.00, −0.18, −0.10, 16.53`：
均值 +0.796 全部来自最后一折的 +16.53 和第九折的 −9.00。

**② 候选不交易的折被静默丢掉 —— 而那正是它赢的折。** 上面那两个 `—`：
`trend = 4` 在第 4、第 8 折一笔没做，最大回撤为 0，Calmar 无定义，
于是配对比较在 **10 折**而不是 12 折上做（`cells: 10`）。
但这两折出厂值是**亏的**（−0.15% / −1.49%），「不出手」在这两折上是候选的胜利。
**把「候选没动作」的折丢掉，等于系统性地惩罚更保守的候选。**

换成**本折总收益**后同两折变成 `0.00000`，Δ = +0.149pp / +1.493pp，正常计入。
新口径下 `trend = 4` 的逐折 Δ 是
`+1.31, −0.48, +0.25, +0.15, −0.41, −1.86, +0.92, +1.49, −1.30, −0.55, +0.06, +1.69`（pp）——
没有哪一折支配结果，胜 7/12。

**这不是把结论改得好看了，是把两个结论的符号改回来了。** 同一份数据、同一批候选，
换统计量之后有两个候选的 Δ **翻了符号，且翻成与整池排名一致**：

| 候选 | 整池验证 Calmar | 逐折 Calmar 口径 Δ | 逐折总收益口径 Δ |
|---|---|---|---|
| `scoreThreshold = 0.55` | **0.517**（优于出厂 0.427） | **−0.599**，胜 1/12 | **+0.05pp**，胜 2/5 |
| `scoreThreshold = 0.72` | **0.356**（劣于出厂 0.427） | **+0.567**，胜 6/12 | **−0.01pp**，胜 4/9 |

旧口径下「整池说好、配对说坏」两次都出现，方向还相反 —— 那是分母塌了的症状，不是真发现。

> **合成用例里最容易把这一层测糊。** `pairedDelta` 在折数 < 2 **或方差为 0** 时
> `stderr` 与 `t` 都返回 `null`，不是「无穷显著」。随手写「候选每折都恰好比出厂值高 0.10」
> 的 fixture，stderr 只剩浮点误差、t ≈ 6e15，用例是绿的但测的是 IEEE754。
> `calibrate-folds.test.ts` 里为此钉了两条：折间 Δ 必须真的抖一下，且 t 有**上界**。

#### `combine` OFAT 在新工具上重跑：**裁决 KEEP**，这次是机器判的

`reports/folds/combine-ofat-v2.json`，同一个网格（16 组 OFAT）、同一批 39 只标的、
判定窗口收到 `--to 2025-06-30`（测试段不跑），12 折。
出厂值：训练 489 笔 / +1.33% / Calmar 0.090，验证 127 笔 / +1.28% / Calmar 0.427。

|---|---|---|---|---|---|---|

**结论与 §5.14 逐条相同，但这一轮没有一处需要人来判**：三条红线自己淘汰了三个候选，
孤峰与边界标记自己排除了名义第一名，剩下的没有一个 Δ 大于自己的抖动（最大 t = 1.4，
门槛是 2）。§5.14 里「训练集垫底 + 只有 59 笔 + 孤峰」那段人工论证，
现在被 `Δ +0.11pp ± 0.32pp, t = 0.3` 一行代替 —— **而且是更强的说法**：
「比第二名好 1.6 倍」那个头条本身就落在它自己的折间噪音里。

#### 「动了 N/12 折」把惰性说得比 §5.14 更准

新报的 `affected`（Δ ≠ 0 的折数）直接量出了参数的作用范围：

- `downtrendBuyPenalty` 的 0.25 / 0.75 / 1.0 与 `conflictBand = 0.10`：**动 0/12 折**，
  即在判定窗口内**逐折逐位相同**。§5.14 只能说「验证集整池数字相同」，
  现在能说「切成 12 个互不重叠的子样本，每一个都相同」—— 这不是效应小，是**没有效应**。
- `conflictBand = 0.05` 只动 2/12 折，`scoreThreshold = 0.55` / `0.66` 只动 5/12。
  胜率因此按 `affected` 算而不是按 12 算，否则「动了 2 折、赢 0 折」会被读成「胜 0/12」，
  看着像大败，其实只有两折有信息。

#### 分辨率那一行怎么读

报告末尾：**观测到的最大改进 Δ = 0.11pp，12 折下的可分辨门槛 0.64pp，
要让它可分辨约需 430 折。**

先看这个门槛是从哪来的 —— 出厂值自己 12 折的总收益（pp）：

```
−2.44  2.14  0.44  −0.15  4.66  3.05  −0.11  −1.49  2.73  −0.69  −2.14  −1.16
```

均值 +0.40pp，**折间标准差 2.25pp**。也就是说**换 10 只票、换半年行情，
同一套参数的结果就能差好几个 pp**，而整个 `combine` 块 15 个候选的动态范围是
**−0.44pp ~ +0.11pp**。效应量比折间抖动小一个量级 —— 这就是这一格十一轮定不下来的
数据侧原因，现在它有数了。

430 折不是「去凑 430 折」的施工单。它等价于说「在当前标的池 / 窗口 / 4% 的平均资金占用下，
`combine` 这一层的效应量比测量噪音小一个量级」。对应动作是 params/README 的第三档：
**归档为不可标定（清单 4.9c），不要再重跑同一个网格**。
真要推进只有两条路，都不在这一轮里：扩标的池（往两三百只走）、或换成占用率对齐的口径
让 4% 那个压扁因子（§5.13）消失。

#### 扩样本能不能解决？能，但代价与偏差要一起算

430 折 ÷ 12 折 ≈ **36 倍**。一折 ≈ 10 只 × 半年 ≈ 5 个「标的年」，
所以 430 折 ≈ 2150 标的年的判定窗口，而现在是 39 × 1.5 ≈ **58 标的年**。
折算成标的数：在同一个 18 个月窗口里要 **1400 只左右**。A 股全集 5542 只
（`params/universe-broad.json` 的 `universeSize`），所以这**不是做不到** ——
它是一个数据获取工程（现在 39 只 23MB，1400 只约 1GB、抓取要几小时）。

但三条必须一起说，否则「扩到 1400 只就能定参数」会变成一句错的承诺：

1. **横截面折之间不独立。** A 股同涨同跌，市场因子是所有折的共同项，
   `√n` 的收敛只在独立样本下成立。**430 折是下界**，真实需要更多。
2. **幸存者偏差不随样本量减小**（§5.4）。退市股在免费接口上取不到，
   扩到 1400 只仍然全是活着的票，方向仍是绩效被系统性高估。
3. **`combine` 是二阶旋钮**（§5.14 读数）。它只决定「已有的信号怎么合」，
   而 §5.11 测出 R2 有 87% 的触发是孤立的 —— 这一层的实际自由度比参数个数小得多。
   花几小时抓 1400 只票去分辨 0.11pp，性价比明显低于先去测那些**一个网格都没跑过**
   的一阶参数（`adx` / `regime` 的门、`risk` 的止损线）。

#### 还有一类参数，日线回测**原理上**给不出依据

docs/08 那一格的原话是「产出出厂默认参数」。但 `params.ts` 里有一批数值
回测永远走不到那条分支：

| 参数 | 为什么测不到 |
|---|---|
| `combine.provisionalDiscount` | 只在 `stage === 'PROVISIONAL'` 时生效（`combine/index.ts:85`），而回测喂的全是收盘定稿的 K 线，`engine.ts:74` 判出来永远是 `CONFIRMED` |
| `alert.bubbleScore` | 提醒分级的线，属 M3；回测不产生提醒 |
| `risk.lateBuyCutoffMinutes` | 盘中分钟口径，日线回测没有分钟 |
| `data.staleSnapshotMs` | 实时快照新鲜度，回测没有快照 |

这四个的归属不是「还没标定」，而是**要靠影子运行（docs/07 §2.3）或 M3 的提醒日志**
才可能有依据。把它们算进这一格，这一格就永远不可能勾掉 —— 所以 docs/08 那一条已经
按「回测能定的 / 回测定不了的」拆开重写。

#### 这一节不能证明什么

- **没有证明出厂的 `0.6 / {3,2} / 0.15 / 0.5` 是好参数。** 证明的是
  「在 39 只 × 18 个月这个测量精度下，网格里没有一个候选能被判定为更好」。
  这两句话差别很大，别混用。
- **`--code-folds` / `--time-slices` 的取值本身没有标定过。** 4 × 3 是拍的：
  折太少估不出离散度，折太薄每折没有交易。改这两个数会改变 `requiredCells` 的数值，
  但不会改变「效应量 ≪ 折间抖动」这个结论 —— 那个比值在任何切法下都是同一个量级。
- **`resolution.requiredCells` 是量级估计，不是样本量计算**：它假设 Δ 与离散度都不随样本变，
  且折间独立（上面刚说了不独立）。
- **判据变严了，代价是「真有效但幅度小」的参数也会被判 KEEP。** 这是有意的取舍：
  ADR-0003 的立场是宁可留着标着「未标定」的猜测，也不写回一个用噪音换来的数。

#### 处置

- **`combine` 块四个参数仍然全部保持出厂值**（0.6 / {3,2} / 0.15 / 0.9 / 0.5），
  `ENGINE_VERSION` 不动。§5.14 的结论不变，这一轮把它从「人看表判的」升级成「工具判的」。
- **`downtrendBuyPenalty` 的幅度与 `conflictBand` 归档为不可标定**（动 0/12 与 2/12），
  按清单 4.9c 记，别再重跑。**归档不等于删参数** —— `downtrendBuyPenalty` 的方向级抑制
  是 docs/04 §4.1 的原则，标定说的只是「在这 39 只 / 这个窗口下测不出幅度差别」。
- **测试集这一轮仍然没读**（`--to 2025-06-30`）。累计触碰次数不变：**5 次**。
- 旧口径的那份报告 `reports/folds/combine-ofat.json` 留着做对照，
  **但它的逐折 Δ / t / 胜率不可引用**（分母塌 + 丢折两处硬伤都在里面）。

## 6. 指标交叉验证的验证状态

docs/07 §2.1 要求三方比对（我们的实现 / Python TA-Lib / 行情软件截图）。实际做到的：

| 参照 | 状态 |
|---|---|
| **独立参照实现**（`scripts/verify/reference.mjs`，不 import src/core，风格刻意相反） | ✅ 已比对，23 条序列全部一致（相对误差 < 1e-6） |
| Python `pandas-ta` / TA-Lib | ❌ **未执行** —— 本机无 Python 环境，且脚本要真实日线才有意义 |
| 行情软件截图人工抽查 | ❌ **未执行** —— 需要真实标的与真实软件 |

即：**算法一致性已验证，口径一致性未验证**。
「我们的 MACD 柱是否与通达信显示的一致」「STD 除 n 是否与同花顺一致」这两个问题，
现在只有代码注释与文档的说法，没有实证。`scripts/verify/README.md` 记了具体做法。

用于比对的 500 根日线是**合成**的（`scripts/verify/synthetic.mjs`，固定种子），
原因同 §5.1。合成序列刻意串了「上涨 → 震荡 → 下跌 → 再上涨」四段，
保证 ADX / BBW 分位不是一条直线。

## 7. M2 明确没做的

- **提醒分发**：气泡、系统通知、托盘角标、防抖、冷却、频率上限、免打扰探测 —— 全是 M3。
  信号在 M2 的唯一出口是**面板列表**。
- **桌宠表情仍不由信号驱动**：`WATCHING` / `EXCITED` / `ALERT` 一律不点亮。
  表情属于提醒分级的表现层，而分级要经过 docs/05 §4 的四道闸门才算数。
  提前点亮等于绕过还没实现的闸门直接骚扰用户。
- **`signal:markRead`**：要写 `alert_log`，而那张表在 M3 才有内容。仍列在启动日志的未实现通道里。
- **背离检测（T6）**：docs/04 §3.1 明确「首版只做提示不计入得分」，M2 连提示也没做 ——
  它容易过拟合，且没有回测就无从判断，留到有数据之后。
- **持仓录入 UI**：通道已通，界面属 M3（持仓风控强制通道在那时才有意义）。
- **影子运行**：M4。
