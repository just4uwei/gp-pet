# 信源台账：每个数据源可靠到什么程度、坑在哪

> 2026-08-17 起草。**由[迭代 skill](../../.claude/skills/迭代/SKILL.md) 的第四问驱动 —— 每次碰过数据源就回来更新。**
>
> **为什么单独一份**：这个项目在数据源上反复踩同一类坑，每一次都花了几十分钟到几小时重新试：
> 「curl 判 eastmoney 不可用」（实际是客户端指纹差异）、「退市股取不到日线」（实际取得到，
> 卡的是名单）、「新浪 delisting 节点」（返回空）。这些结论散在偏差报告的各节里，
> 下一轮没人找得到。
>
> ## 四条记录规则
>
> 1. **可用性要带口径** —— 谁调的（undici / curl / 浏览器）、成功率、什么条件下失败。
>    「能用 / 不能用」这种二值判断在本项目已经错过两次。
> 2. **坑记在可用条目里，不要另起一条**。腾讯日线**可用**，但退市整理期尾段的后复权是加性的
>    （会变负）—— 两句必须一起读，分开记就会有人只看到前半句。
> 3. **否定结论同样记**，并注明**什么时候、用什么方法**试的。否则下一轮会重试一遍。
> 4. **每条带日期**。数据源会变，三个月前的实测不能当今天的事实。

## 1. 行情 · 日线

### ✅ 腾讯 `fqkline`（历史日线主源）

`https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`（另有 `ifzq.gtimg.cn` /
`proxy.finance.qq.com` 两个**同源**门，`hfqday` 逐位相同）

| 项 | 实测 |
|---|---|
| 可用性 | 稳定。是 `fetch:history` 的唯一源 |
| **退市股** | **有完整日线，一直延伸到退市日，两轨都在**（2026-08-17 实测 236 只候选中 240/348 有 2018 后数据） |
| 单次上限 | **640 根**，且是从 `to` 往回数的最后 N 根（`from` 只当上界）。count 给 2500 直接 `param error` |
| 列序 | 日期, **开, 收, 高, 低**, 量（不是开高低收） |
| 量单位 | **手**（×100 转股）；**不给成交额** ⇒ `amount` 落 `null` |
| 指数 | 请求 `hfq` 也只返回 `day` —— 指数无复权，这是对的（`assertKey` 放行） |

**坑（必须与上表一起读）**：

- ⚠ **按 host 拦截**：`--concurrency 4` 拉到第 99 只（约 1800 请求）起清一色 `HTTP 501` + JS 挑战页，
  十分钟不恢复（2026-08-14）。**并发上限已压到 2**，撞 501 自动换门。
  判断它恢复没有**只能拿同一个 URL 再探**，别拿别的接口（sina 一直是通的，看它会以为网络没问题）。
- ⚠ **前复权是加性的**（减价差）⇒ 高分红股会变**负数**（中远海控 2018–2026 有 **714 根** ≤ 0，最低 −5.145）。
  **所以拉后复权**，脚本有断言挡着，别改回 qfq。
- ⚠ **后复权在退市整理期的尾段也是加性的**（2026-08-17 新发现）：SH600091 最后 19 根、
  SZ000502 最后 15 根、SH600767 最后 4 根为负（−0.02 ~ −0.96），而前面几年完全正常。
  ⇒ `merge()` 按**位置与占比**分流：尾部 ≤ 10% 截断并告警，中间出现或占比大则抛错。
  实测正确拒绝 SH600870（88.9%）与 SZ000693（17.9%）。
- ⚠ 少数标的**源上就没有 `hfqday` 那一轨**（`SZ001330` / `SZ301583` / `SZ301717` / `SH600083`），
  `assertKey` 拒绝用不复权顶替 —— 这是对的失败方式。

### ⚠ eastmoney `push2*`（应用内主源之一）

- **不是被封，是间歇性的**：undici（应用用的客户端）成功率约 **78%**，失败症状 `other side closed`，重试能过。
- ❌ **curl 对它 100% 失败**（客户端指纹差异，2026-08-12 与 2026-08-17 两次确认）。
  **别再用 curl 的结果判断这个接口的可用性** —— 本项目已经因此误判过一次。

### ✅ sina `Market_Center.getHQNodeData?node=hs_a`

今天**在交易**的 A 股全集，按 symbol 升序翻页（100/页）。`build-universe.mjs` 用它。
三层内（沪主板/深主板/创业板）**4594 只**（2026-08-17）。

- ❌ **`delisting` / `tuishi` / `shtsgp` 三个节点都返回空数组**（2026-08-15 实测，`sh_a` 对照正常）
  ⇒ 它**给不出退市股名单**。这条曾让「补退市股」这件事停在「等一份 Tushare token」上两天。

## 2. 证券清单

### ✅ 巨潮 `szse_stock.json` —— **含退市股，这是名单问题的解**

`http://www.cninfo.com.cn/new/data/szse_stock.json`

| 项 | 实测（2026-08-17） |
|---|---|
| 规模 | **6234 只**，**沪深两市都在里面**（尽管文件名叫 szse） |
| **含退市股** | ✅ 名称就是退市后的名称（「乐视退」「退市保千」「康得退」「中弘退」） |
| 字段 | `code` / `orgId` / `zwjc`（中文简称）/ `category` |
| 用途 | ① 抓公告要的 `orgId`；② **退市股名单** = 巨潮三层内 4942 ∖ 新浪 4594 = **348 候选** |

- ❌ `sse_stock.json` 返回的是 HTML，**不能用**。
- ⚠ 差集 348 只里混着两类**不是**退市清盘的：2002 年前退市的（`PT金田A`，拉不到 2018 后数据 ⇒ 自动出局）
  与**吸收合并/代码变更**的（`深赤湾A` → 招商港口、`外运发展`、`中航善达`）。
  后者股东是换股不是亏光 —— 按名称筛不掉（274/348 名称带「退」或 ST），只能承认这层偏差。

### 未实测（不要当结论）

- **BaoStock `query_all_stock(day=…)`** — 号称能查**某个历史交易日**的证券列表（即时点快照）。
  只有 Python SDK。本项目最终没用它（巨潮就够），**没有实测过**。
- **Tushare `stock_basic(list_status='D')`** — 退市清单，需要 token。**没有实测过**。

## 3. 公告

### ✅ 巨潮 `hisAnnouncement/query`（POST）

2026-08-16 实测：264 只 × 2018-01-01~2026-08-15 → **256,419 条 / 79,310 个「股票·公告日」/ 0 失败 / 约 30 分钟**。

- ⚠ **`stock` 参数必须是 `代码,orgId`**，只给六位代码**静默返回 0 条**（不报错）。这是这个接口最坑的一点。
- ⚠ **`pageSize` 上限就是 30**，要 100/200 都只给 30 ⇒ 翻页次数是硬成本。
- ⚠ **`display_time` 与 `notice_date` 是两个东西**，切「昨收盘之后」的窗口要用**前者**
  （实测 `display_time = 2026-08-14 17:30` 对应 `notice_date = 2026-08-15`）。
- ⚠ 时刻一律走 `shanghaiToEpochMs` 解析：**`Date.parse` 对那个格式不报错**（毫秒是冒号分隔的，
  V8 照样吃），只是按本机时区给出偏掉的时刻。
- ⚠ 六位数字**不许按 SH → SZ → BJ 顺序试**：SH 段表里有 `['000','INDEX']`，会把**整个深市 000 段**
  判成上证指数。走 `resolveAnnounceCode`（`ann_type` 优先）。

**结论层面**（不是数据可用性）：公告作为二值筛子对入场质量**零增量**，
建仓在公告日上**零富集**（13.5% vs 14.4%），见 [M2 §5.25](./M2-偏差报告.md)。

## 5. AI 服务（协议，不是数据）

- **协议按「路径形状」选，不按厂商选**：OpenAI 兼容 `{base}/chat/completions` 与
  Anthropic 兼容 `{base}/v1/messages`，差异只有四点，全在 `src/main/ai/protocols.ts`。
- ⚠ **同一家可能两条路都提供且形状不同**：火山方舟 `…/api/coding` 是 Anthropic 协议、
  `…/api/coding/v3` 才是 OpenAI 兼容（实测两条路都存在，返回 401 而非 404）；
  coding 与 plan 两种订阅的 key **互不通用**。
- ⚠ **选错协议的症状是「HTTP 200 但一个字都没有」** —— 不报错、不断流，就是没字。
  `createAiClient` 因此在 `sawAny === false` 时必须抛错并点名协议。
- ⚠ **Anthropic 协议只发 `x-api-key`**，不要同时发 `Authorization: Bearer`
  （火山方舟两种都认，但真 Anthropic 同时收到两种凭据会拒）。
