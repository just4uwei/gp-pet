## 0. 核心取舍：停止参数标定主线，转到「判定逻辑是否有效」

### 0.1 砍掉什么

**暂停 docs/09 的主线**——不再为清零剩余 21 个 `GUESS` 而跑 OFAT 网格。

判据不是「跑腻了」，是**算术上出不来结论**：

- 出厂值在 261 只池上训练窗口 **−2.55% / Calmar −0.125**，被 §5.14 的红线「训练集 Calmar ≤ 0 直接淘汰」淘汰；

- 于是**每一张网格的裁决只能是 `INCONCLUSIVE`**（八张网格、82 组候选已实测，退出码 2）。

继续跑网格产出的不是弱证据，是**零证据**。再跑十张也一样。

**代价要说清楚**（这是取舍不是优化）：

| 放弃的东西 | 后果 |
|---|---|
| M2 出口条件「回测报告产出并据此确定出厂参数」 | **继续未达成**，且不再是下一阶段的目标 |
| `ENGINE_VERSION` 摘掉 `-unvalidated` | 继续挂着。参数表继续逐行标「未测」 |
| docs/09 §6「`GUESS` = 0」 | 明确宣布**在当前池上不可达**，按 docs/09 §2.2 方向 ③ 如实归档 |

**不要**为了让闭环转起来去改红线。十九轮实验的可比性建立在判据不变上，改判据是这个项目里风险最高的动作——
它会让此前所有 `KEEP` 与 `INERT` 的结论失去可比基础，而且**改完之后没有任何办法验证改得对不对**。

#### 拍板题 B：判定逻辑改动，授权到什么程度？

约束 5 与 [ADR-0003](../adr/ADR-0003-来源文档数值不作为出厂默认.md) 要求**先论证再做**。
现在手上有三个候选解释（[M2 §5.20 ⑧](./M2-偏差报告.md)），都还没测：

1. `T3_BREAKOUT` 要求「收在上轨之外 + 带宽在扩张」——**定义本身就是追高**；
2. 得分把「多条规则同时成立」等同于更可信，而趋势末端恰恰如此；
3. 波动率极高时那条风控**只降级不抑制买入**（`expandedBbwPct` 只产 `DOWNGRADE`，`toOrder()` 只读 `direction`）。

**建议的门槛**（三条一起卡，缺一不可）：
- 建仓数**不得下降超过 15%**（否则就是在测「少做」而不是测这个机制）；
- 建仓级胜率不降；
- 与随机基准（§3.1）比较有可辨差异。

这三条要在动手之前写进 docs/07，动手之后再定就是自己给自己找台阶。

## 2. 数据清洗：要改进，但只有两项值得做

跳变 > 20% 标可疑、临时 K 线不要、复权价非正值直接抛错）。
**不要动这些规则**——它们每一条都对应一次踩过的坑。

要改的是**采集覆盖**，不是清洗逻辑。

### 2.1 P2 · 补退市股，把幸存者偏差从「无解」降到「已量化」

[现状盘点 §13](./量化系统现状盘点.md) 把幸存者偏差列为「无解，只能声明」——
因为退市股在腾讯这类免费接口上取不到。261 只全是**今天还活着**的股票，
所以 −0.94% 是**乐观值**，真实数字更差。

**但这条可能不是无解的。** Tushare Pro 的 `stock_basic` 带 `list_status`（含 `D` 退市 / `P` 暂停上市），
`pro_bar` 对已退市标的仍可取历史日线与后复权。如果成立，就能：

- 按同样的分层抽样规则补一批退市股进池；
- **量出幸存者偏差的方向与幅度**——这是这个项目第一次有机会把「只能声明」的东西变成一个数。

**必须先验证再排期**：本项目没有 Tushare 账号，退市股日线是否在免费积分范围内没有实测过。
先花半小时验一只已退市标的能不能取到 `hfq` 轨，取不到就退回「只能声明」，不要投入。

> ⚠ 这条只碰**离线抓取脚本**，不进应用。「免登录、无服务端」约束的是产品，
> `fetch:history` 是开发期工具，产物是 `data/history/*.json` 的 fixture。

### 2.2 P2 · Tushare Pro 作为第二个历史源（顺带解决抓取被拦）

现在 `fetch:history` 从腾讯拉，而**腾讯按 host 拦本机**：`--concurrency 4` 拉到第 99 只
开始清一色 HTTP 501 + JS 挑战页，一次跑掉 165 只，十分钟不恢复。
已经改成三门降级 + 并发上限 2 + 逐只落盘，264 只要跑约 40 分钟。

**池子想再扩就是这里卡着。** 而 `combine` 块要测出差别需要约 1400 只——那在当前抓取方式下不现实。

顺带解决两个数据缺口：

| 缺口 | 现状 | Tushare 能否补 |
|---|---|---|
| `amount`（成交额） | 腾讯日线不给，落 `null`。**凡是需要额的因子现在都做不了** | 能，`daily` 接口带 `amount` |

**保留腾讯做交叉验证**，两源同一只票的后复权序列应当高度一致——不一致本身就是发现。

## 3. 算法：三件离线实验先行，三件改动押后

### 3.1 P0 · 随机基准对比 ★ **已完成（2026-08-15）**

> **结论：假设 B —— 策略有信息，但符号是反的。四个状态里没有一个的入场是正 alpha。**
> 工具 `pnpm audit:random`，全部数字与三条保留意见见 [M2 §5.21](./M2-偏差报告.md)。
>
> TREND_UP 的 −1.01% 拆成四段：池子漂移 **+0.21%** → 站在 TREND_UP 里 **−0.46pp**
> → 状态内挑选 **−0.69pp** → 风控离场 −0.08pp。入场质量在 200 次随机试验里排第
> **1.5%–3.5%** 分位（三个种子稳健）。
>
> **两条改变后续读法的**：① 「不在 TREND_UP 里买」只买回 0.46pp，**剩下 0.69pp 在子信号与
> 得分那一层**，两个方向都得动；② §5.20 ⑧ 的「唯一赚钱的引擎是 RANGE 的 R3+R4」要改读法
> —— RANGE 赚的是 **beta 不是 alpha**（+0.34% 低于同 regime 随机的 +0.48%）。
> 于是 §1.1 拍板题 A 的**方向 ② 已被排除**：40 只池上的正收益同样是 beta。

**这是全部工作里最值钱的一件，因为它给所有数字装上零点。**

在同一个标的池、同一段时间、同一套成本模型、**匹配持仓根数分布与资金占用率**的前提下随机买入，
跑 N 次（建议 200+）得到一个零假设分布。

它区分三种完全不同的结论：

| 随机基准结果 | 意味着 | 该做什么 |
|---|---|---|
| 也在 −1% 左右 | 趋势买入**没有信息**，也没主动作恶；亏的是摩擦与池子漂移 | 问题是「该不该在 TREND_UP 里买」，不是参数 |
| 明显好于 −1% | 策略在**主动挑坏点** | 有信息但符号反了，深挖判定逻辑值得做 |
| 也明显为负且更差 | 池子这段时间本身难做 | −0.94% 的读法要整体重新校准 |

**为什么现在最需要它**：§5.20 ⑧ 测出「得分是反向指标」（TREND_UP 得分 ≥ 0.8 的 198 次是 −1.39%，
而 0.75–0.8 那档打平）。反向指标意味着**里面有信息**——随机的东西不会系统性反向。
但没有零点就证明不了它不是噪音，而这条读数正是拍板题 A 的主要依据。

**副产品**：跑 N 次天然给出置信区间，不用另做 bootstrap。此前列在待办里的「绝对绩效置信区间」由此合并进来。

**成本低**：`simulate.ts`、`costs.ts`、次日开盘成交、手数取整全都现成，只需一个匹配占用率的随机入场生成器。
它与 `audit:regime` / `audit:subsignals` 同类——**只统计，不改参数**。

### 3.2 P0 · 滑点敏感性

`costs.ts` 的滑点是 **0.1%**。行业常规做法给的区间是 **0.2%–0.5%**。

往返摩擦的算术：佣金 0.025%×2 + 印花税 0.1% + 过户费 0.001%×2 + 滑点 0.1%×2 ≈ **0.35%**。
换成 0.3% 滑点，往返变成 **0.75%**，每次建仓多吃 0.4pp。

**方向是明确的：现在的数字如果有偏，偏乐观。** 所以这不是「结论可能被推翻」的风险，
而是「结论比看上去更硬」——但硬多少要跑出来才知道，**因为它决定修好买点需要多大的改善幅度才算够**。

扫 0.1 / 0.2 / 0.3 / 0.5% 四档。**只传参，不改出厂值**——`costs.ts` 是回测 / 影子运行 / 实盘成交记账三方共用的。

### 3.3 P0 · TREND_UP 时间细分

§5.20 ⑧ 已经把 TREND_UP 的 396 次建仓按**入场子信号组合**和**入场得分**拆开了。
唯一没拆的维度是**时间**：这次建仓发生在「刚进入 TREND_UP」还是「TREND_UP 已经走了一段」？

值得做的两个理由：

1. 如果「得分越高越糟」是追高的形状，那「已经涨了多久才买」是追高的**时间维度**度量，两者应当相关；
2. 它与 `regime.hysteresisDays` 的高原发现（2/3/4/5 分辨不出）存在张力——那是**整池 Calmar** 口径，
   如果损失集中在「刚进入就买」，迟滞长度在 TREND_UP 买入这个子集上应当有效果，而聚合口径会把它压平。
   这不推翻 §5.17 的 `KEEP`，是说那条结论的适用范围可能比看上去窄。

**样本量要当心**：TREND_UP 建仓级只有 **396 次**（1245 是逐笔口径，别混用——CLAUDE.md 概述里写的是逐笔数）。
按得分已经拆成 89 / 198 的量级，再叠一层时间维度会掉到几十次一格。**结论必须带 §3.1 的不确定性，不能读点估计。**

### 3.4 P2 · 交互效应随机探索（只探索，不选择）

§5.20 ⑨ 明写了一个死角：「剩下的可能性只有三类：**跨参数交互（没测，笛卡尔积跑不完）**、
判定逻辑本身、或者就是不该在 TREND_UP 里买。」

随机搜索正是「跑不完」的标准答案。但有一条硬前提：**不能用它选参数**。
在没有有效基线的空间里搜索并挑最优，就是教科书上的过拟合。

合法的用法是**探索而非选择**：随机采样几百组，只问一个是非题——
**「参数空间里存不存在一个区域，训练窗口 Calmar > 0？」**

- 答「不存在」⇒ 第一类可能性被排除，三选一收敛到后两类，**这是纯收益**；
- 答「存在」⇒ 那个区域才进入正常的逐折配对流程。

**报告里必须写清这是探索不是标定**，否则下一个人会把它当结论。

> docs/09 §5 列了「贝叶斯优化」为不做项，理由是「27 个 `GUESS` 里还没跑过一格 OFAT」。
> 那个前提已经变了（OFAT 跑完且全部 `INCONCLUSIVE`），但**结论仍然维持**：
> 贝叶斯优化是**选择**工具，而现在缺的是探索。用随机采样，不要上贝叶斯。

### 3.5 P3 · ATR 自适应止损（须先论证）

`risk/index.ts:18` 的头注释已经记着「P1 迭代按 ATR 自适应（docs/05 §2.3 脚注）」，没做。
当前四条止损全是固定比例、**对波动率无感**：止损 8% / 回撤减仓 7% / 盈利保护触发 5% / 移动止损 3%。

有一个自洽的机制把它和病灶连起来：`T3_BREAKOUT` 的成立条件含「带宽在扩张」，
也就是说**趋势买入按定义发生在高波动时刻**。固定 8% 止损在 ATR 口径下因此系统性偏紧，
而实测 TREND_UP 持仓中位数 **8 根**、RANGE **15 根**——「趋势买入更快被风控请出去」。

**张力要说清楚**：§5.20 ⑧ 的结论是「离场结构三种状态几乎一样（`DRAWDOWN_REDUCE` 53–61%、
`STOP_LOSS` 约 11%）⇒ 差异不在卖点」。占比相同不等于时长相同——占比一样而中位持仓差近一倍，
恰恰说明同一套规则在两种波动环境下咬合的紧度不同。两条读数不冲突，但也谈不上互相支持。

**押后的理由**：如果 §3.1 说「趋势买入根本没信息」，那止损松紧就不重要了。**等零点。**

### 3.6 P3 · 高波动时抑制买入而非降级（须先论证）

§5.20 ⑧ 的候选解释 ③，也是三个里唯一「改了就能测」的。
现在 `strategy.expandedBbwPct = 90` 只产 `DOWNGRADE`（改提醒级别），而 `toOrder()` 只读 `direction`,
所以回测里它**五档取值逐位相同**——不是不敏感，是回测读不到它。

改成抑制买入之后它就进得了回测。但这是**判定逻辑改动**，要走拍板题 B 的门槛，
尤其是「建仓数不得下降超过 15%」那条——抑制买入天生就是在减少交易。

### 3.7 P3 · RSI 那条线（唯一「改善不靠少做」的方向）

八张网格里唯一的正向线索：`rsi` 放宽超卖基线（15 → 25）或缩短周期（14 → 6），
让建仓数**增加 24%–35%** 且胜率同时从 43.30% 升到 44.6% / 45.9%。
别的块最好的候选全靠把建仓数压下去换来。

**但它仍然写不回**（出厂值被红线淘汰，配对判据拿不到）。所以它现在的地位是
「拍板题 A 选了方向 ① 之后，第一个该试的方向」，不是一个可以立刻执行的任务。

同理 `risk.drawdownReducePct` 7% → 12%：训练窗口收益 +1.20pp、建仓胜率 +7.5pp、回撤 −0.70pp、
且 ≥0.12 饱和，**方向已第三次同向**，是全项目证据最强的候选——一样卡在同一处。

### 3.8 明确不做

| 项 | 理由 |
|---|---|
| 继续 OFAT 网格清 `GUESS` | §0.1，产出零证据 |
| `combine` 块加密网格 | 需要约 1400 只；二阶旋钮；15 个候选最大 t = 1.4 |
| 新增指标（LLT、背离检测） | 约束 5 |
| 动态策略权重 | 已测两轮删除，`params.weights` 整表已删；且制造过乘性耦合的坑 |
| 前瞻性指标辅助 regime | 撞约束 5；且 `audit:regime` 已量化上界（三条突变条件整条删掉，TRANSITION 只从 66.6% 降到 53.7%） |
| ML 模型进产品 | 撞措辞纪律（置信度不得称概率）、撞「AI 只读不回流」、且产品的价值是可读的 `reasons` |
| 因子化改造（IC / 分层 / 正交化） | 产品形态是「跟踪几十只自选」，没有横截面选股路径；改造成本高、与形态关系不大 |
| 场外信息 / 情绪因子 | 卡在**历史数据可得性**与**时间戳严格性**；进不了回测就无法标定，与 ADR-0003 直接冲突 |
| 组合级熔断 / ATR 仓位管理 | 回测是**单标的独立资金**，没有组合层；产品又不下单，没有作用点 |
| 换 Python / Backtrader / 聚宽 / QMT | `src/core` 纯函数库正是「回测实盘同源」的实现方式，换框架等于放弃 ADR-0004 |

> **ML 有一个不进产品的合法用法**：拿 396 次 TREND_UP 建仓当样本、特征用**触发当时引擎已经算出来的量**
> （子信号集合、ADX、bbwPct、volRatio、regime 置信、得分、票数），跑一次特征重要性，
> 问「赚钱的和亏钱的在触发时刻有什么可观测区别」。产出是一句人能读懂的判据，模型本身不进产品——
> 与 `audit:*` 同类。**但它排在 §3.1–§3.3 之后**，且 396 个样本对树模型偏少，结论要当线索不当证据。

## 4. 沉淀：怎么收集演进必须的数据

**这一章解决的是「三个月后还能不能复现今天的判断」。**
本项目的强项就在这里（CHANGELOG / ADR / 19 节偏差报告 / `STATUS` 表），缺的是三处。

### 4.1 P1 · 闸门拦截率统计 ★ 要赶在 M3 那一周之前做完

`alert_log` 已经**逐行**存了 `suppressed_reason`（[alert.ts:42](../../src/main/storage/repositories/alert.ts#L42)），
但全仓 16 个引用它的文件全是单行读取，**没有任何聚合**。

**用途是硬的，不是「有了更好」**：
- `alert.bubbleScore` 的标定依据 CLAUDE.md 里已经写死是「提醒日志」而不是回测 Calmar；
- `regime.hysteresisDays` 那条 `KEEP` 明确说判据应该是「每日改口次数」；
- M3 的出口条件「判断提醒太吵还是太哑」现在没有量化读数，只能凭感觉。

**两个陷阱必须处理，否则统计出来是错的**：

1. **分母**：`alert_log` 里**没有风控硬抑制的信号**（它们带着原因留在 `signal` 表）。
   从 `alert_log` 单表算的拦截率，分母已经是过滤后的流量 ⇒ 系统性低估整条链路。**完整漏斗要两张表拼。**
2. **短路顺序**：四道闸门串行，被冷却挡下的候选**走不到配额**。`suppressed_reason` 记的是
   **第一个**拦下它的闸门。所以「某道闸门拦截率 < 10% ⇒ 形同虚设」这个判据**在短路结构下是错的**——
   靠后的闸门看起来弱，可能只是前面的把流量吃光了。要得到「若前置放行、这道会不会拦」，
   得在分发路径上多记一列，那不是纯聚合查询。

**建议实现**：先做最简单的一版（按 `suppressed_reason` 分组计数 + 两表拼漏斗），
把「每道闸门独立判定」那一列作为后续增强。**先有量表比量表完美重要**——M3 那一周正在流逝。

### 4.2 P2 · 实验运行的可追溯性

现在每次网格跑完靠人往 [M2 偏差报告](./M2-偏差报告.md) 手写一节。19 节了，还能读，
但已经出现过同一个网格被跑两遍的情况。

**低成本改进**：让 `calibrate.ts` 每次运行落一行结构化记录（时间、网格文件、标的池指纹、
切分、折数、裁决、`--touch-test` 有没有用）。它不替代偏差报告的叙述，
它答的是「这个网格跑过没有、什么时候、在哪个池上」——**那正是被问过两次的问题**。

顺带解决测试集预算的记账：现在累计触碰 5 次，记在 docs/07 §3 的一个手工计数上。

### 4.3 P1 · 影子运行：承认排期冲突，明确它的价值窗口

事实要说清楚：**影子净值曲线现在一个点都没有。**

- 收盘确认轮此前从未成功过（数据源 15:05–15:30 发个股日线，晚于 SETTLE 窗口 15:00–15:10），
  实测两个交易日 `signal` 表 769 行里 `CONFIRMED` **0 行**、`indicator_daily` **0 行**、影子三张表全空；
- 已用「次日盘前补跑」（`engine/settle.ts`）修复，但那条路**刻意不接影子运行**（前向纪律，见该文件边界 2）。

所以影子的第一个净值点要等真机跑起来之后才产生。而**参数一变就停止累积**——
本阶段会改判定逻辑，所以：

**影子运行的价值窗口在拍板题 A/B 落地之后。** 这一阶段不要指望它出绩效。
但**它该跑着**——即使会被清零，跑的过程能暴露工程问题（就像上面那个 CONFIRMED 0 行，
是真机跑起来才发现的，回测跑一万次也发现不了）。

### 4.4 P2 · 实验侧图表

[现状盘点 §8](./量化系统现状盘点.md) 已判为结构性缺口：回测报告是**文本表格 + JSON**，
没有净值曲线、没有回撤图、没有参数剖面图、没有折间分布图。
而 `report.json` 里**有 `equity` 数组**——数据在，只是没有画出来的路径。

**为什么值得做**：本项目每一次「诊断错了」都与看不见形状有关——
`squeezeBbwPct` 的高原是人工在数字表里认出来的、`revertLookback` 的惰性靠逐项计数才发现、
ADX ≈ 8 那个 fixture 缺陷靠打印探针表格才定位。**一张参数-绩效剖面图会让「孤峰 vs 高原」一眼可辨**，
而现在这件事靠 `plateauFlags()` 用规则去猜。

§3.1 的随机基准分布图尤其需要——**一个分布画出来比一个 t 值好读得多**。

**一条纪律**：图是用来看形状的，**结论仍然只能来自数字与判据**。别把「看着像高原」写进归档。

### 4.5 P3 · 指标口径的第三方交叉验证

[M2 §6](./M2-偏差报告.md) 有一项开放缺口：**算法一致性已验证，口径一致性未验证**。
`scripts/verify/reference.mjs` 是刻意风格相反的独立参照实现（23 条序列相对误差 < 1e-6），
但「我们的 MACD 柱是否与通达信显示的一致」这类问题没有实证。

原文写的阻塞理由是「本机无 Python 环境」——**这条已经半失效**：实测本机有 Python 3.15.0b1，只是没装科学计算库。

项目对口径极其敏感（MACD 柱用 `2×(DIF−DEA)`、布林带除 n 不除 n−1，都是**刻意**与国际口径不同的选择），
第三方比对本来就该做。**提醒**：3.15.0b1 是 beta，TA-Lib 那个 C 扩展大概率装不上，
用 `pandas-ta` 或直接 numpy 手写参照更现实。

排 P3 是因为它验的是「显示口径」，而当前的问题在「策略有没有效」——两件事。

### 5.2 阶段出口条件

**不再用「`GUESS` = 0」当出口**（§0.1 已判定不可达）。换成三句必须能说出口、且每句有文件可查的话：

1. **「TREND_UP 的买入相对随机基准是 ___」**——有数、有分布、有区间（§3.1）。
2. **「拍板题 A 选了 ___，理由是 ___」**——写进 docs/09 或本文档的修订，不留在对话里。
3. **「21 个 `GUESS` 已按方向 ③ 如实归档」**——`params-view.ts` 的 `STATUS` 表里没有一项写着「待测」而实际测不了。

第 2 条最重要。这个项目已经有过「选了动作但没回答动作之后怎么办」的先例（docs/09 §2.2 的「已选方向 ①」），
**结果是查完买点之后又停在原地**。

### 5.3 保持不变的四条红线

原样继承 docs/09 §4，一条都不放宽：

1. **测试集预算**——`--touch-test` 累计已触碰 5 次，这一阶段**一次都不许读**。
2. **「提高胜率」不能单独当目标**——`profitProtectTrigger` 调低能机械做到 70% 胜率同时把盈亏比压到 0.5。
   写回门槛是**建仓级胜率不降 + 收益显著提高**两条一起卡。
3. **不许新增指标**（约束 5）。
4. **`enabledStrategies` 不进网格**，权重表不许加回来。

**本阶段新增第 5 条**：

5. **减少交易带来的「改善」不算改善。** 在一个整体亏钱的系统上，少做天然改善绩效。
   任何判定逻辑改动都要同时报建仓数变化，下降超过 15% 的候选**不得作为正面证据引用**。

- **每完成一项 P0/P1**：往 [M2 偏差报告](./M2-偏差报告.md) 加一节（哪次跑、什么结论、什么条件下失效）；

## 6. 一页纸版本

**取舍**：停止为清 `GUESS` 跑参数网格（算术上出不来结论），转去回答「这套判定逻辑有没有效」。
代价是 M2 出口条件继续未达成、`-unvalidated` 继续挂着——**这是承认现状，不是新增损失**。

**最先做的三件（都是离线、都不改代码行为）**：随机基准对比 · 滑点敏感性 · TREND_UP 时间细分。
跑完才有零点，才能拍板。

**同时起头、只花等待时间的三件**：闸门拦截率统计（赶在 M3 那一周之前）· M1 跑满一天 / M3 自用一周 ·
Tushare 退市股可得性验证。

**需要你拍板的三题**：接受哪种结局（建议 ③ + ①）· 判定逻辑改动的授权门槛（建议三条一起卡）·
标定判据要不要改（建议不改）。

**数据清洗**：规则本身别动，要补的是采集覆盖——退市股（把幸存者偏差从「无解」变成一个数）、
`amount` 与 `industry` 两个空列。

**最容易被忽略的一条**：影子运行现在一个净值点都没有，而它是「量策略值不值钱」的那把尺子。
这一阶段它攒不出绩效（参数会变），但**该跑着**——上一次真机跑起来才发现 `CONFIRMED` 长期 0 行，
那种问题回测跑一万次也发现不了。
