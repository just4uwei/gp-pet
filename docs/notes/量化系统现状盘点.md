# 量化系统现状盘点：结构、困难点、已经踩到的问题

> 2026-08-15。按「数据清洗 → 因子计算 → 回测框架 → 数据逻辑校验 → 样本划分 → 风控规则 →
> 跑实验 → 画图表 → 参数敏感性 → 场外信息（AI 情绪因子）→ 运行总结 → 持续迭代」
> 这十二个环节，逐个盘点**当前实现是什么结构、难在哪、已经踩到过什么**。
>
> **这不是设计文档**（设计看 [docs/01–08](../README.md)），也不是计划（计划看 [09](../09-下一阶段开发计划.md)）。
> 它回答的是「今天这套东西站在哪儿」。每个数字都带日期与出处，出处主要是
> [M2 偏差报告](./M2-偏差报告.md)（十九轮实验的原始记录）与 2026-08-14 那轮扩池实验。
>
> **一句话结论**：十二个环节里，① 数据 ② 指标 ③ 回测 ④ 校验 ⑤ 样本划分 ⑥ 风控 ⑦ 实验编排
> ⑫ 迭代留痕这八个是**建起来了、能跑、有纪律**；⑧ 图表、⑨ 敏感性分析的**统计闭环**、
> ⑩ 场外信息因子这三个是**结构性缺口**；⑪ 运行总结的管子铺好了但**还没有真机数据**。
> 而当前真正卡住整条链的不是任何一个环节的实现质量，是一个结果：
> **出厂参数在一个有代表性的标的池上、在训练窗口里是亏钱的**，于是标定的判据闭环打不开。

**架构上唯一的硬约束**（[ADR-0004](../adr/ADR-0004-核心引擎与-electron-解耦.md)）：
`src/core` 是纯函数库，不碰 Electron、不碰 IO、**不读时钟**。
回测与实盘因此跑的是同一份判定代码，未来函数由架构消除而不是靠自律 ——
这是整套东西里最值钱的一个决定，后面每一个环节都在吃它的红利。

## 1. 数据清洗

**现在有什么**

| 侧 | 实现 | 关键机制 |
|---|---|---|
| 应用 | [src/main/providers/](../../src/main/providers/) | 三源（tencent / eastmoney / sina）+ 降级 + 熔断；限流全局并发 4 |
| 离线 | [scripts/fetch-history.mjs](../../scripts/fetch-history.mjs) | 不复权 + **后复权**两轨、按年分页、三个门降级、逐只落盘 |
| 落地 | [src/main/storage/](../../src/main/storage/) | SQLite（WAL）、`kline` 与 `quote_tick` 分表、周期 `VACUUM INTO` 备份 |

清洗规则本身写在 `merge()` 里：**两轨都有的日期才产出一根**（单边补齐等于凭空编一个复权价）、
价格逻辑矛盾（`high < low`、`close > high` …）整根丢弃并计数、相邻复权收盘跳变 > 20% 标可疑、
用基准指数当交易日历标 `has_gap`（停牌段）、当天那根临时 K 线一律不要。
**复权价出现非正值直接抛错**——那是「又拉成加性前复权」的唯一信号。

**困难点**

1. **复权口径**。腾讯的前复权是加性的，高分红股上会变成负数（中远海控 2018–2026 有 **714 根**
   前复权收盘 ≤ 0，最低 −5.145），负价上的 MA/MACD/RSI/BOLL 全是垃圾。因此拉的是后复权：
   对判定与净值等价（指标全是比率型），且历史值不随抓取日变。代价是 `Candle.*Adj` 的语义
   与 docs/04 写的「前复权」不一致，这条偏差单独备案。
2. **展示与判定必须分轨**：持仓成本、止损线、观察点的 `PRICE` 用**不复权**，指标用复权。
   混用会伪造金叉死叉，或在除权日凭空触发一次提醒。
3. **幸存者偏差消不掉**：退市股在任何免费接口上都取不到，样本里必然缺席，方向是**绩效被系统性高估**。
   261 只全是今天还活着的股票，所以 §5.20 那个 −0.94% 是**乐观**的。

**已经踩到的问题**

- **被数据源按 host 拦截**（2026-08-14）：`--concurrency 4` 拉到第 99 只时开始清一色 `HTTP 501` +
  JS 挑战页，一次跑掉 165 只，十分钟不恢复。同一个接口换 `ifzq.gtimg.cn` / `proxy.finance.qq.com`
  两个门照常通、`hfqday` 逐位相同 —— 于是脚本改成三门降级 + 并发上限 2 + **逐只落盘**
  （原先「全拉完再统一写」让前 98 只跟着一起丢）。
- **3 只标的的后复权轨在源上不存在**（`SZ001330`/`SZ301583`/`SZ301717`），断言拒绝用不复权顶替，
  264 只最终只有 261 只可用。这是对的失败方式。
- **eastmoney 不是被封是间歇性的**：undici 成功率约 78%（重试能过），而 curl 100% 失败 ——
  客户端指纹差异。**别再用 curl 判断这个接口的可用性。**
- **`amount`（成交额）腾讯日线不给**，落 `null` 而不是 0。凡是需要额的因子现在都做不了。
- **行业字段没有数据源**：`security.industry` 列在 schema 里，但没有任何 provider 填它。
  后果见 §6。

## 2. 因子计算

**现在有什么**：[src/core/indicators/](../../src/core/indicators/) —— MA、MACD（柱用 `2×(DIF−DEA)` 国内口径）、
BOLL（标准差除 n）、RSI、DMI/ADX + 动态阈值、量比（盘中按时间归一化）、BBW 分位、周线聚合。
纪律有两条硬的：**未定义值一律 `null` 绝不填 0**（`noUncheckedIndexedAccess` 已开）、
**穿越只在相邻两根间判定一次**，不做「N 日内曾金叉」的模糊匹配。

**困难点 —— 这是与「因子系统」最大的结构差异**

当前实现是**规则触发**（`crossUp(MA5,MA20) && adx > adxRange` ⇒ 一条子信号 + 一个 0–1 的强度分），
**不是因子打分**。没有横截面标准化、没有 IC / IR、没有分层回测、没有因子正交化，
也没有「今天全市场按因子值排序取前 N 只」这条路径 —— 因为产品形态是「跟踪用户自选的几十只」，
[全市场扫描评估](./P2-全市场扫描评估.md)的结论是当前取数架构下做不了。

**这带来两个具体后果**：
① **无法回答「这个指标有没有预测力」**，只能回答「用它做的这条规则赚不赚钱」——
后者混着择时、风控、成本三件事，信噪比低得多；
② 参数标定只能整套跑回测（一个候选 4–11 分钟），而因子层面的 IC 计算是**向量化的秒级操作**。
§5.20 那 82 组候选跑了约 5 小时，如果是因子框架，同样的问题几分钟就能扫完。

**已经踩到的问题**

- **口径一致性从未验证**：算法一致性有（`scripts/verify/reference.mjs` 是刻意风格相反的独立参照实现，
  23 条序列相对误差 < 1e-6），但「我们的 MACD 柱是否与通达信显示的一致」这类问题**没有实证**——
  没有 TA-Lib 比对、没有行情软件截图抽查（[§6](./M2-偏差报告.md)）。
- **`ma.periods` 只有一半是活的**：信号层只读 5/20/60，而且是 `trend.ts` 里的**字面量**；
  10/120 算了但信号层没人读（观察点与 AI 上下文在读，所以不能删）。
  想标定「均线周期」必须先把快/慢/长提成显式参数 —— 那是代码改动，不是调参。
- **`volume.shrinkRatio` 全仓没有读者**：docs/04 §1.6 写了「ratio ≤ 0.8 为缩量」，
  但没有任何子信号消费它。文档与实现的这类漂移只有逐个读代码才查得出来。

## 3. 回测框架

**现在有什么**：[src/backtest/](../../src/backtest/) —— `simulate.ts`（判定 → 下单 → 持仓 → 离场）、
`costs.ts`（佣金/印花税/过户费/滑点）、`metrics.ts`、`report.ts`、`cli.ts`。
**关键设计**：与实盘共用 `src/core` 的同一个 `evaluate()`；成交按**次日开盘**；
资金按**单标的独立资金池**；净值用相邻复权价之比；持仓成本另存不复权价。

**困难点**

1. **单标的独立资金 ≠ 组合**。每只票各拿一份资金独立跑，没有资金竞争、没有仓位分配、
   没有「同一天 20 只都出信号该买哪只」。好处是可加性强、归因干净；代价是**平均资金占用只有 3.69%**，
   于是「超额收益 −15.04%」这个数**离开占用率就会被读反**（基准是满仓的）。
   报告因此把 `exposure` 紧挨着超额那一行打印。
2. **成本模型是常数，不是分布**：滑点是一个固定比例，没有冲击成本、没有流动性约束、
   没有涨跌停排队。A 股的 T+1 与涨跌停已经建模（硬抑制），但那是**规则**层面的。
3. **胜率有两个口径，混用就会读错**：一行 `trade` 是一次卖出，而回撤减仓把一次建仓拆成两三行 ——
   同一份数据逐笔胜率 28.45%、**建仓级胜率 44.85%**。用户体验到的是后者。

**已经踩到的问题**

- **分段绩效曾把预热段净值算进去**（2026-08-12 修）：验证集年化被压小 **5.1 倍**、
  基准收益取成全程涨跌**连符号都反**，导致「Calmar 衰减 > 50%」红线 3/16 全是假阳性。
- **分 Regime 归因的「平均」曾是逐行未加权百分比**：四种市况全是 −1.2% ~ −1.6%，
  而净盈亏是 **+231,154 元** —— 半仓那一行和满仓那一行被等同看待了。已改为按仓位加权。
- **`TradeStats.avgPnlPct` 的符号可以与净盈亏相反**，保留但不许用它判断赚没赚。

## 4. 数据逻辑校验

**现在有什么**（这一环节做得比多数环节扎实）：

| 位置 | 挡的是什么 |
|---|---|
| `assertKey()` | 请求复权、返回不复权的**静默降级** |
| `merge()` 的非正值断言 | 又拉成加性前复权 |
| `assertParamsShape()` | `voteThreshold` 写成数字 ⇒ `votes >= undefined` 恒假 ⇒ 一声不响跑出 0 笔 |
| `audit:subsignals` 的自检 | 审计工具重算的合取项数与 `evaluate()` 实际触发数**不一致就报错退出** |
| `verify:indicators` | 指标算法漂移（对独立参照实现） |
| `params-view.test.ts` | 参数漏归档、`CALIBRATED` 集合被悄悄扩大 |
| `VACUUM INTO` | WAL 下 `cp` 出来的库「少了最近的写却照样能打开」 |

**困难点**：**「测试是绿的」与「测试在测东西」是两件事。**

**已经踩到的问题**（[§5.19](./M2-偏差报告.md)）

- **六条用例从写下来那天起就没绿过，跨三次提交**。根因是 fixture：横盘段用的是固定错拍锯齿，
  振幅够但 +DM 与 −DM 长期抵消，320 根之后 **ADX ≈ 8**，而 `adxRange` 是 15–23 ——
  于是 `T1_MA_CROSS:BUY` 与 `T4_ALIGNMENT` 在所有基于它的 fixture 里**结构上无法触发**。
  一度被误判成引擎缺陷，去真实数据上量了才澄清（46 只、2709 次金叉，**60.6% 当日 ADX 就够**）。
- **编排层用例必须把阈值调低到 0.3 分 / 1 票**，否则 fixture 里没有一根凑得够票数，
  去重用例会退化成 `0 === 0` 的假通过。
- **教训已成规矩**：造 fixture 时横盘段的噪音**必须没有周期**；新增场景之后**打印一次子信号集合**，
  别信「断言不触发」自己通过。

## 5. 设计样本划分

**现在有什么**：`DEFAULT_SPLITS` = 训练 2018-01-01→2023-12-31 / 验证 2024-01-01→2025-06-30 /
测试 2025-07-01→今。`warmupForSplit()` 保证每段**身后带着完整历史**（否则 300 根预热会在每段内重来，
测试集 272 根 < 300 根 ⇒ 永远 0 笔）。折单元 = **标的子集 × 时间片**，从**同一次模拟**里切出来，
加折不加耗时。测试集默认**不跑**，`--touch-test` 才读，累计触碰次数记在 docs/07 §3。

**困难点**

1. **折之间不独立**（A 股同涨同跌），所以 `|Δ|/stderr` 只当**量级标尺**用，不是假设检验。
2. **验证窗口只有 18 个月、一种市况**，时间片是为此加的，但换不来更多的市况。
3. **测试集是消耗品**：已累计触碰 5 次，历史上那 5 次的优胜者几乎都没被采用 —— 纯浪费。

**已经踩到的问题**

- **扩池后训练窗口整体亏钱**（2026-08-14，本次最重要的一条）：出厂参数在 261 只上训练窗口
  **−2.55% / Calmar −0.125**，而红线「训练集 Calmar ≤ 0 直接淘汰」把**出厂值自己**淘汰掉 ⇒
  所有候选的配对 Δ 都是 null ⇒ **八张网格 82 组候选的裁决全是 `INCONCLUSIVE`**。
  在 40 只旧池上这个数是 **+1.33%（Calmar +0.09）**，也就是说此前十一轮标定能跑，
  是因为出厂值在小池上**勉强**站住了那条线。
- **扩池不会自己变成 84 折**：`--code-folds` 默认 4，261 只上仍是 4 × 3 = 12 折，必须显式给 28。

## 6. 设定风控规则

**现在有什么**：[src/core/risk/](../../src/core/risk/) 分三类 ——
**持仓强制**（固定止损 8% / 移动止损 / 回撤减仓 / 盈利保护，用户可重画 `stopFloor`）、
**硬抑制**（停牌、涨跌停封死、数据不足、次新股）、**降级**（ST、行业集中度、波动率极高、尾盘买入）。
之上还有提醒层的四道闸门（级别、同键冷却、每日配额、免打扰/全屏探测）。

**困难点**

1. **风控实质上已经是策略的主体**：**96.9% 的离场由风控触发**，策略卖出子信号只占 3.1%。
   也就是说「一次建仓最终赚还是亏」几乎完全由那五个阈值决定 —— 而它们全是未标定的转述值。
2. **降级类规则在回测里读不到**：回测的 `toOrder()` 只读 `direction`，而降级改的是**提醒级别**。
   实测 `strategy.expandedBbwPct` 取 70/80/90/95/98 五档**逐位相同**（建仓 1187、胜率 43.30% 一字不差）。
   这类参数的判据只能是提醒日志，不是 Calmar。

**已经踩到的问题**

- **误归档**：`risk.industryConcentrationCap` 曾记 `KEPT`（「随 risk 块一同上过网格」），
  但它同样只产降级，**而且回测根本不传 `industryShare`** —— 两重读不到，那轮 KEEP 零信息量。
  教训：**「跟着某个块一起上过网格」不等于「这个参数被测过」**。
- **行业数据缺失让这条规则在应用里也变形了**：没有 provider 填 `industry`，
  于是所有持仓都归入「未分类」、该组占比恒为 **100%** > 20% 的上限 ⇒
  **持仓股的每一条非强制信号都被降一档**，理由文案会写「未分类持仓占比已达 100%」。
  持仓强制类（止损等）不受影响（`resolveLevel` 明确跳过降级），所以这不是「跌停那天没响」那一类事故，
  但它是一条**恒真的风控**，等于没有在管它该管的事。
- **止损/减仓的判据曾经分叉**：回撤减仓的「仍盈利或微亏」原本把固定止损的判据抄了一遍，
  用户重画止损线之后两者会分开、中间一段**两条都不响**，现已共用 `belowStop`。

## 7. 跑实验

**现在有什么**：`pnpm backtest`（单组 / `--grid` 网格）、`calibrate.ts` 的**三态裁决**
（`WRITE_BACK` / `KEEP` / `INCONCLUSIVE`）、`audit:regime`、`audit:subsignals`、
应用内**影子运行**（前向模拟，四条纪律：不补跑历史、次日开盘成交、成本照扣、只吃 CONFIRMED）。

**困难点**

1. **计算预算**：一个候选（训练 + 验证两段模拟）在 261 只上 **4–11 分钟**，八张网格 82 组
   **约 5 小时**（三进程并行）。没有指标缓存复用（参数一变指标就得重算）、没有向量化、没有增量。
2. **实验的判据本身是设计出来的**，而不是自然存在的：折单元、配对比较、写回门槛
   （`|Δ|/stderr ≥ 2` 且 ≥ 2/3 折为正 且**建仓胜率不降**）都是 2026-08-13 才搬进工具的 ——
   在那之前十一轮实验的判据在人脑子里，二十来个参数只写回一个。
3. **影子运行与参数迭代顺序冲突**：引擎参数一变影子账本立刻停止累积（混进去的曲线不属于任何一套参数），
   而参数补完期正是反复改参数的时候 —— **影子的价值窗口在参数定下来之后**。

**已经踩到的问题**

- **「提高胜率」可以被机械满足**：把 `profitProtectTrigger` 调低（小赚就跑）能把胜率做到 70%、
  同时把盈亏比压到 0.5。这次在 261 只上它又演了一遍：往上调 Calmar 看着升，
  **建仓胜率从 43.30% 掉到 35.37%**。写回门槛因此是「胜率不降 + 收益显著提高」两条一起卡。
- **`KEEP` 被读成失败**导致同一个网格被重跑过。三态裁决就是为此加的。
- **网格文件里塞 `_comment` 会静默把网格乘大一圈**（`expandGrid()` 把顶层每个键都当参数块）。

## 8. 画图表 —— **结构性缺口**

**现在有什么**：应用侧有两张图（[DailyChart.tsx](../../src/renderer/panel/DailyChart.tsx) 60 根日 K + MA20/60 + 量、
[IntradayChart.tsx](../../src/renderer/panel/IntradayChart.tsx) 分时，折叠午休、断线表达停牌），
都是手写 SVG，纪律清楚（null 不画成 0、红涨绿跌、不复权价并在图下注明）。

**缺的是实验侧的图**：回测报告是**文本表格 + JSON**，没有净值曲线图、没有回撤图、
没有参数曲面/剖面图、没有折间分布图、没有分年/分市况的柱状图。
`report.json` 里**有 `equity` 数组**，也就是说数据在，只是没有画出来的路径。

**这为什么是问题**：本项目每一次「诊断错了」的经历都与看不见形状有关 ——
`squeezeBbwPct` 的高原是人工在数字表里认出来的、`revertLookback` 的惰性是靠逐项计数发现的、
ADX≈8 那个 fixture 缺陷是靠打印探针表格才定位的。**一张参数-绩效剖面图会让「孤峰 vs 高原」
一眼可辨**，而现在这件事靠 `plateauFlags()` 用规则去猜。

## 9. 参数敏感性分析

**现在有什么**：OFAT 网格（一次只动一个参数）、`plateauFlags()` 自动邻域判定
（同一维度上取值相邻的候选互为邻居，孤峰不采用、落在网格边界要标「该侧未测」）、
`pairedDelta()` 逐折配对 + 标准误 + `t` + 胜折比、`Resolution.requiredCells`
（「要分辨这个 Δ 大约需要多少折」）。

**困难点**

1. **分辨力买不起**：§5.18 里全项目最一致的候选 `risk.drawdownReducePct` **t 只有 0.77**，
   外推需要约 82 折 ≈ 264 只 —— 这正是这次扩池的理由。而 `combine` 块要测出差别需要 **~1400 只**。
2. **交互效应完全没测**：全是 OFAT。笛卡尔积在当前算力下跑不完（5 个参数各 4 档 = 1024 组 × 4–11 分钟）。
3. **一维扫描的结论会被「少做」污染**：这次八张网格里几乎所有「改善」都来自建仓数下降
   （`boll.k` 2.5 少做 34%、`midReversionStd` 2.0 少做 20%）—— 在一个整体亏钱的系统上，
   **少交易天然改善绩效**，这不是参数变对了。

**已经踩到的问题**

- **`adx.maxThreshold` 是算术上的死参数**：`clamp(base + volScale×volPct, base, maxThreshold)`
  而 `volPct ∈ [0,1]` ⇒ 被夹项最大 = 20 + 8 = 28 = 出厂值，上界永远咬不住。扫上侧逐折逐位相同。
- **`revertLookback` 的惰性根因不在取值**：同一个合取里另有一项在 **49% 的交易日上成立**
  （等于没有条件），另一项的时间常数差一个量级。**合取里混着一个「几乎总成立」的项，
  会让同组其他参数集体失去作用** —— 这是本项目反复踩到的形状。
- **子信号之间可能几何互斥**：R2（要价格回到中轨附近）与 R1/R3/R4（要偏离中轨）互斥，
  R2 的 213 次触发里 **87% 是孤立的**，而票数线要两票 ⇒ **再怎么改 R2 都换不来一次触发**。

## 10. 用 AI 分析场外消息（政策、公司消息面、情绪因子）—— **结构性缺口**

**现在有什么**：[src/main/ai/](../../src/main/ai/) 是一个**只读的解释层** ——
把已经产生的信号 + 指标截面 + 持仓 + **参数标定状态**组织成上下文，交给 LLM 生成一段解读，
两层缓存防重复计费、在途去重、SSE 流式、只有 `done` 落库、思考链与正文分开累积。
唯一的「落地」形状是**观察点**：模型给一个建议值，**人在表单里确认**后落成一行
`watch_point`，之后每轮做一次**纯比较**（不涉及模型），命中走正常的四道闸门。

**缺的是**：没有新闻/公告/研报/政策的抓取，没有情绪因子，没有事件驱动。
`grep` 全仓只有交易日历里出现过「政策」两个字。也就是说
**「场外消息 → 情绪因子 → 进引擎」这条链一根都没有**。

**困难点（其中两条是刻意的）**

1. **AI 不许回流是一条设计纪律，不是遗漏**：模型的判断不写进 `signal` 表、不改参数、
   不进影子运行。理由是「用户没有办法判断该信哪个」—— 一个与引擎结论相反的 AI 判断
   会让两条结论同时存在而无从裁决。**观察点之所以能落地，是因为中间插了人的确认。**
2. **上下文必须带参数标定状态**：缺了它模型会**默认**引擎结论经过验证，
   然后用非常有说服力的语气把一套未标定的转述阈值讲成定论 —— 而输出上完全看不出上下文漏了一块。
3. **成本与并发**：AI 客户端**不得复用**行情那条 HTTP 层（那层限流器与行情取数共用全局并发 4，
   一次 40 秒的 LLM 调用会把每 30 秒一轮的 tick 饿死，症状是「行情突然不动了」）。
4. **真要做情绪因子，难点不在调 API**，在三件事：**数据源**（公告/新闻的结构化获取与去重）、
   **时间戳的严格性**（未来函数最容易从这里进来 —— 一条 15:30 发布的公告不能用于当天的判定）、
   **可回测性**（历史新闻拿不到就无法进入 §3 的框架，而进不了回测就无法标定，
   进而与 ADR-0003「不接受未经本地验证的数值」直接冲突）。

**已经踩到的问题**

- **选错协议的症状是「HTTP 200 但一个字都没有」**：用 OpenAI 的取字逻辑读 Anthropic 的流，
  每帧都取不出增量，不报错、不断流、就是没字。客户端因此在「一个字都没有」时必须抛错并点名协议。
- **列表重渲染会摘掉正在跑的模型调用**：AI 解读内嵌在信号行里时，同一只票再来一条动态就换人，
  正在流式生成的组件被卸载 ⇒ `ai:cancel` ⇒ 等了四十秒的界面自己没了，**而那次调用已经计过费**。
  现在它是抽屉的一个页签，与列表**没有父子关系**。

## 11. 根据实际运行情况总结数据

**现在有什么**：`alert_log`（发没发、被哪道闸门挡）与 `signal` 表（引擎判了什么）**分开两张**、
影子运行三张表（前向绩效）、[收盘日报](../../src/main/report/build.ts)（**只复述不推导**：
每一项都必须指回一个已经存在的东西）、数据健康度、实盘成交记账（`trades/ledger.ts`，
与回测共用同一套费率，但**绝不套滑点**）。

**困难点**

- **两条出口条件仍未达成**：M1 的「跑满一个交易日 + 健康度 > 99%」要真机联网守一天；
  M3 的「自用一周，判断提醒太吵还是太哑」要真机用一周。**这两件事没有任何工程替代品。**
- **四个参数的判据只能来自真机**（`combine.provisionalDiscount`、`alert.bubbleScore`、
  `risk.lateBuyCutoffMinutes`、`data.staleSnapshotMs`），加上上面提到的降级类参数。
- **影子账本无法重建**（用历史 K 线补出来的叫回测），所以它不进保留策略、不加外键、
  「清缓存」也不碰它 —— 但这也意味着**一旦参数变更，之前攒的就永久停在那儿了**。

**已经踩到的问题**

- **收盘确认轮此前从来没成功过**：数据源发布个股日线在 15:05–15:30，晚于应用的 SETTLE 窗口
  （15:00–15:10），15:10 后引擎当天不再跑 ⇒ 实测两个交易日 `signal` 表 769 行里
  `CONFIRMED` **0 行**、`indicator_daily` **0 行**、影子三张表**全空**。已用「次日盘前补跑」修复。
- **「今日信号」列表曾被一只刷屏的票挤掉整个上午**：`signal:history` 答的是「最近 n 行」，
  664 行让 200 的窗口只覆盖了 82 分钟 —— **界面不报错，只是少了东西**。已改为按股票分组取。
- **签名里混进连续量会让去重失效**：`reasons[0]` 是嵌着百分比的文案，
  −32.7% → −32.6% → −32.7% 来回抖每次都算变，一天落了 **243 行同一条止损**。

## 12. 持续迭代

**现在有什么**（这一环节是本项目的强项）：`CHANGELOG`（只记影响引擎行为的变更，
每条参数标定必须写清**动了哪个数、依据是哪次回测、什么条件下结论失效**）、
四份 ADR、[M2 偏差报告](./M2-偏差报告.md)（19 节实验记录）、
`params-view.ts` 的 `STATUS` 表（逐参数归档，有用例钉着）、验收清单、
以及归档流程 4.9a/b/c（写回 / KEEP / 不可标定三条路各自的动作）。

**困难点**

- **证据不是代码，会过期**：CLAUDE.md 里「`risk`/`multiTf` 一个网格都没跑过」这句
  在跑过之后仍挂了一整个阶段。现在的规矩是「以 `params-view.ts` 的 `STATUS` 表为准」——
  因为**只有它有测试钉着**。
- **十九轮实验只写回过一个参数**（`strategy.squeezeBbwPct` 10 → 20）。这不是效率问题，
  是判据严格的必然结果 —— 但它也意味着**迭代的正反馈非常弱**，很容易让人想去放宽判据。

## 15. 一句话版本

**管子都通了，判据也立起来了，卡住的是结论**：
在一个有代表性的池子上，这套规则目前不赚钱，而所有「换一个参数取值」的补救都被证明无效
（82 组候选最好的一个训练集 Calmar 是 −0.078）。
唯一稳定赚钱的部件是**震荡市里的均值回归**（`R3+R4`，911 次建仓 / +182,213 元），
唯一「改善不靠少做」的方向是 **RSI 那条线**（放宽超卖基线 / 缩短周期 ⇒ 交易更多且胜率更高）。
下一步要么去改买点的判定逻辑（要论证），要么承认这一阶段的结论就是「测不出来」并如实归档。
