# 01 · 产品需求与范围

## 1. 一句话定义

**蹲点** 是一个常驻 Windows 桌面的悬浮条客户端（桌宠形态已于 2026-08-13 整块删除，见 docs/06 §2.1）。它在 A 股交易时段跟踪用户自选的股票代码，用可回测的量化策略判断买卖时机，并在信号出现时以「不打断当前工作」的方式提醒用户。

## 2. 核心目标（按优先级）

| P | 目标 | 验收标准 |
|---|---|---|
| P0 | 跟踪用户设定的股票代码 | 自选股增删改查、本地持久化、重启后恢复；支持沪深主板/创业板/科创板/北交所与 ETF |
| P0 | 用合理的量化策略产出买卖信号 | 指标计算与 [04](./04-指标与信号引擎.md) 规范逐条一致，且通过单元测试的黄金用例 |
| P0 | 及时提醒 | 收盘确认信号 ≤ 30s 内到达提醒层；盘中预警信号 ≤ 一个轮询周期（默认 30s） |
| P0 | 不干扰日常工作 | 见 [06](./06-桌宠交互与非干扰设计.md) 的「零干扰契约」，逐条可验证 |
| P0 | 本地存储、免登录 | 无账号体系、无服务端、无遥测；所有数据落在本机用户目录 |
| P1 | 桌宠表现力 | 待机/行走/喜悦/警惕/困倦等状态动画；信号通过表情与气泡分级表达 |
| P1 | 信号可解释 | 每条信号可展开「触发了哪些子条件、各自权重、当时指标值」 |
| P2 | 本地回测 | CLI 对自选股跑历史回测，输出胜率/盈亏比/最大回撤，用于自行校准参数 |

## 3. 明确不做（Non-Goals）

- **不接券商、不下单、不做资金归集。** 本软件只产出提醒，交易由用户手工执行。这是安全边界，也是合规边界。
- 不做云同步、不做多端、不做用户账号、不做分享社区。
- 不做选股/全市场扫描（首版只跟踪用户手工添加的自选股，上限 100 只）。
- 不做 Level-2 行情、逐笔委托、龙虎榜等付费数据依赖。
- 不做移动端。

## 4. 目标用户与使用场景

单一用户画像：**上班时间在电脑前工作、持有少量 A 股、希望不盯盘也不错过关键买卖点的散户。**

典型一天：

```
08:50  开机，桌宠出现在屏幕右下角，打哈欠（休市待机态）
09:15  集合竞价开始，桌宠睁眼，进入盘中态；此后每 30s 静默刷新
10:32  600xxx 触发「趋势市 + MACD 零轴上金叉 + 放量」→ 桌宠变为警惕态，
       右上角浮出气泡「600xxx 买入预警 · 置信 62%」，6s 后自动淡出，无声音
11:05  用户忙于会议（检测到全屏演示）→ 静默模式，信号只累积到托盘角标，不弹气泡
15:00  收盘，引擎用收盘 K 线重算 → 确认信号，托盘系统通知一次（可带声音）
15:05  用户点击桌宠，展开面板，看到今日 3 条信号与各自触发依据
```

## 5. 功能清单

### 5.1 自选股管理
- 按代码或名称搜索添加（本地代码表 + 在线补全）
- 分组（默认「自选」，可自定义分组，用于分行业集中度提醒）
- 可选填写**持仓成本与数量**——仅用于止损/回撤/盈利保护类提醒的计算，不做账户对接
- 单只标的可覆盖策略参数（高级）

### 5.2 行情与计算
- 交易日历判定，仅在开市时段轮询（详见 [03](./03-数据源与存储设计.md)）
- 日线增量拉取 + 盘中快照轮询；离线时用本地缓存降级
- 指标、市场状态、策略信号分层计算（详见 [04](./04-指标与信号引擎.md)）

### 5.3 提醒
- 三级提醒强度：L1 表情态 / L2 气泡 / L3 系统通知（详见 [05](./05-风控与提醒规则.md)）
- 去重、冷却、防抖，避免同一信号反复骚扰
- 静默时段与免打扰规则
- 信号历史列表，未读角标

### 5.4 悬浮条交互
- 拖拽移动、边缘吸附、多显示器；位置持久化
- 点击穿透（非本体像素不拦截鼠标）
- 双击展开面板、右键菜单（一键静默在这里，不是双击）
- ~~皮肤目录可替换~~ —— **2026-08-13 判为不做并删除既有实现**：形态已定为托盘 + 悬浮条，
  皮肤是纯成本项。产品因此不依赖任何美术素材（见 [06 §2.1](./06-桌宠交互与非干扰设计.md)）

### 5.5 设置
- 轮询频率、提醒强度阈值、静默时段、开机自启、策略参数、数据源优先级、数据目录、清理缓存
- 数据库备份（M4 追加）；首次启动的免责声明确认（见 §8）
- **AI 分析**（P2 追加，2026-08-13）：接口地址、**接口协议**、模型名、API key、超时与 token 上限、测试连接

> **「策略参数」落地成一张只读表**（M4，2026-08-13）。可调的只有**灵敏度三档**
> 与提醒级别偏移，参数本身不给编辑框。
> 判据是 [ADR-0003](./adr/ADR-0003-来源文档数值不作为出厂默认.md)：`params.ts` 里二十来个
> 数值仍是未标定的转述猜测，让用户在没有回测依据的情况下换成另一个同样没有依据的值，
> 期望收益为零，而排查路径很贵 ——「改坏了 → 一条信号都不出 → 以为程序坏了」
> 这条路用户走不出来，也不会想到是自己改的。
>
> 表里每一行标着标定状态（已标定 / 已测保持 / 惰性 / 回测测不到 / 未测），
> 因为一张不分档的参数表会让这些数值看起来同等可信 —— 那正是 ADR-0003 要防的事。
> 真正被标定过并写回的目前**只有一项**。

> **AI 分析这一块的配置不住在 `settings.json`**（P2，2026-08-13）。
> 它单独落 `<用户数据目录>/ai.json`，API key 用系统凭据存储加密。
> 判据很简单：`config:export` 会把整份 `AppSettings` 写进用户选的 JSON 文件，
> 而那个文件的用途恰恰是「发给另一台机器」—— key 放进设置里就等于跟着导出文件走。
> 系统凭据加密不可用时**拒绝保存**而不是明文落盘，并在界面上说明原因。
> 面向渲染层的返回值里**永远没有明文 key**，只有「已保存」与末尾四位。
>
> **接口协议有两种**：OpenAI 兼容（`{地址}/chat/completions`）与 Anthropic 兼容
> （`{地址}/v1/messages`）。这是「选路径形状」而不是「选厂商」—— 同一家可能两条路都提供，
> 例如火山方舟 `…/api/coding` 是 Anthropic 协议、`…/api/coding/v3` 才是 OpenAI 兼容。
> 填地址时自动识别，识别结果显示在选择器上并附一行「实际会发到 …」的完整地址
> （那一行由主进程用真正发请求的代码算出来，不是渲染层自己拼的）。
>
> **AI 解读的第四段可以变成「观察点」**（P2 续）：模型给出带具体数值的失效条件
> （「跌破 8.20 就说明判断错了」）→ 用户在表单里确认（每一项可改）→ 引擎每轮机械比较
> → 命中后走**正常的四道闸门**提醒一次。面板第二屏「观察点」列出正在跟踪的条件与倒计时，
> 标签上带 ACTIVE 计数 —— 这是「软件在按这个继续跟踪」的答案。
>
> 观察点**不是策略参数**：它是用户的、单标的、一次性、会过期，依据是「用户确认」；
> `params.ts` 是引擎的、全局的，依据必须是本地回测标定。两者不能混，
> 否则设置页那张标定状态表就废了。详见 [docs/05 §3.1](./05-风控与提醒规则.md)。
>
> 这块功能的可见出口是信号列表展开区的一个按钮，**未配置时整块不渲染**。
> 输出区固定包着来源标注与免责小字，且那两行是渲染层的 DOM、不经过模型
> —— 提示词里的禁令是尽力而为，DOM 那一层才是保证。详见 [docs/08 §后续](./08-开发路线图.md)。

## 6. 关键约束

| 约束 | 说明 |
|---|---|
| T+1 | 当日买入次日才能卖出。买入信号在 14:50 之后降级为「次日观察」而非「立即买入」 |
| 涨跌停 | 触及涨跌停时信号无执行意义，直接抑制 |
| 盘中数据是临时的 | 未收盘的 K 线会变，指标值会抖。必须区分「盘中预警」与「收盘确认」，见 [04 §6](./04-指标与信号引擎.md) |
| 免费数据源不稳定 | 非官方接口字段可能变动、可能限频。必须多源冗余 + 适配层隔离 |
| 常驻进程 | 空闲内存目标 < 250MB，休市期 CPU 占用 ≈ 0（定时器降频到分钟级） |

## 7. 风险与已知不确定性

1. **策略有效性未经本项目验证。** 来源文档（[reference](./reference/量化策略买卖时机判断.md)）中的胜率、年化、信息比率均引自网络文章，无法复现。本项目把它当作**参数与规则的初始假设**，出厂默认值必须以 [07 回测方案](./07-回测与验证方案.md) 跑出的本地结果为准，并在 UI 中标注「非投资建议」。
2. 免费行情接口可能随时变更或封禁 → 适配层 + 多源降级 + 明确的「数据源异常」可视化。
3. 桌宠常驻 + 置顶天然有干扰风险 → 把「零干扰」当作硬性验收项而非体验优化项，见 [06](./06-桌宠交互与非干扰设计.md)。
