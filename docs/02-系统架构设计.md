# 02 · 系统架构设计

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | Electron 3x + electron-vite | 透明无边框窗口、置顶、点击穿透、托盘在 Windows 上最成熟；悬浮条与气泡用 Web 技术成本最低 |
| 渲染层 | React 19 + TypeScript + Framer Motion | 声明式状态驱动状态点/气泡；动画曲线可控 |
| 样式 | Tailwind CSS | 透明窗口下的原子化样式，避免全局污染 |
| 状态 | Zustand | 轻量，主进程为唯一数据源，渲染层只做投影 |
| 存储 | SQLite（better-sqlite3）+ JSON 配置 | 同步 API 适合主进程；K 线是天然的关系型时序数据 |
| HTTP | undici | Node 原生栈，支持连接复用与超时控制 |
| 核心引擎 | 纯 TypeScript（`src/core`，零 Electron 依赖） | 可单元测试、可被回测 CLI 复用 |
| 测试 | Vitest | 与 Vite 同构，跑 `src/core` 无需启动 Electron |
| 打包 | electron-builder（NSIS + portable） | Windows 优先 |

> 决策记录见 [adr/ADR-0001-选择-electron.md](./adr/ADR-0001-选择-electron.md)。

### 为什么气泡是独立窗口
气泡需要出现在悬浮条**之外**的任意位置（一条 300×38 的条子上放不下四行提醒），且要有自己的点击穿透策略（气泡完全不可点，悬浮条要做命中判定）。塞进 Overlay 窗口会被迫把它放大到能容下气泡，进而使点击穿透的命中测试成本显著上升。独立的小窗口更干净。

**分层铁律**：`src/core` 不允许 `import` 任何 Electron、Node fs/net、或 `src/main` 的东西。它的输入是纯数据数组，输出是纯对象。这条约束决定了引擎能否被测试与回测。

## 4. 数据流：一个信号的完整生命周期

```
① Scheduler 判定「当前处于连续竞价时段」，触发 tick（默认 30s）
       │
② MarketDataService.getContext(code)
       ├─ 从 SQLite 读最近 250 根日线（已缓存，命中即返回）
       ├─ 若日线缺口 → Provider 增量补齐 → 落库
       └─ 拉实时快照 → 与日线拼接为「临时当日 K 线」（provisional=true）
       │
③ IndicatorEngine.compute(candles) → IndicatorSet
       MA/EMA/MACD(12,17,9)/BOLL+BBW+BBW分位/ADX/RSI/量比
       │
④ RegimeClassifier.classify(IndicatorSet) → TREND_UP | TREND_DOWN | RANGE | TRANSITION
       │
⑤ 并行跑策略 → SubSignal[]（每条含 direction、score、evidence）
       TrendFollowing / MeanReversion / MultiTimeframe
       │
⑥ SignalCombiner：按 regime 取权重 → 加权得分 + 一致票数 → CombinedSignal
       │
⑦ RiskGate：T+1、涨跌停、持仓止损/回撤/盈利保护、行业集中度 → 放行 / 降级 / 改写为卖出
       │
⑧ AlertDispatcher：去重(同标的同向冷却) + 防抖(连续 N tick 确认) + 免打扰探测
       │            → 决定 L1 / L2 / L3
       ├─ L1 → IPC 推悬浮条改状态点
       └─ L2/L3 → 状态点 + 弹 Bubble 窗口（showInactive，不抢焦点），6s 淡出
                  （L3 与 L2 的**表现相同**，区别在冷却窗口与每日上限；
                   托盘角标与系统通知已于 2026-08-13 移除）
       │
⑨ 全程落库：signal 表（含 evidence JSON）、alert_log 表（实际提醒了什么）
```

15:00 收盘后额外跑一次**确认轮**：用最终收盘 K 线重算，把当日 provisional 信号升级为 `CONFIRMED` 或标记 `INVALIDATED`。

## 5. IPC 契约设计

所有通道集中声明在 `src/main/ipc/channels.ts` 并由 `src/shared/ipc-types.ts` 提供类型，preload 只做透传。渲染层不允许直接 `ipcRenderer.invoke` 字符串通道。

```ts
// 形态示意（骨架阶段仅定义类型，不含实现）
export interface IpcContract {
  // 请求-响应
  'watchlist:list':    () => WatchItem[]
  'watchlist:add':     (code: string, group?: string) => WatchItem
  'watchlist:remove':  (code: string) => void
  'signal:history':    (q: SignalQuery) => SignalRecord[]
  'signal:explain':    (id: string) => SignalEvidence
  'quote:intraday':    (q: IntradayQuery) => IntradaySeries  // 分时留痕，只在展开信号分组时发
  'watch:remove':      (id: string) => boolean      // 删观察点，主进程先弹系统确认框；false = 用户取消
  'settings:get':      () => AppSettings
  'settings:patch':    (patch: DeepPartial<AppSettings>) => AppSettings
  'config:export':     () => ConfigTransferResult   // 设置 + 自选 + 持仓 → JSON 文件
  'config:import':     () => ConfigTransferResult   // 覆盖式导入，系统模态框确认
  'pet:setHitRegion':  (rects: Rect[]) => void      // 渲染层上报本体命中区
  'panel:toggle':      () => void
  'app:dataSourceHealth': () => ProviderHealth[]
  // 主 → 渲染 推送
  'push:petState':     PetState
  'push:alert':        AlertPayload
  'push:quoteTick':    QuoteTick[]
  'push:engineStatus': EngineStatus
}
```

安全基线：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、禁用 `remote`、CSP 禁止远程脚本、`setWindowOpenHandler` 拒绝一切新窗口。

## 6. 生命周期与资源

| 阶段 | 行为 |
|---|---|
| 启动 | 读设置 → 打开 DB 并跑 migration → 建 Pet 窗口（不建 Panel，懒加载）→ 启动 Scheduler |
| 休市 | Scheduler 降频到 5 分钟心跳，仅做交易日历刷新与自更新检查；渲染层暂停动画帧（`document.hidden` + 手动降帧至 6fps） |
| 盘中 | 30s tick（可配 10–120s）；单次 tick 内所有自选股批量取快照（一次请求多代码），日线按需增量 |
| 休眠/唤醒 | `powerMonitor` 的 suspend/resume 事件重置定时器并补一次全量刷新 |
| 退出 | 托盘菜单显式退出；关闭 Panel 不退出进程；DB 正常 close |

## 7. 错误处理原则

- **降级而非崩溃**：任一数据源失败 → 切下一个源；全失败 → 用缓存 + UI 显示「行情离线」灰态，状态点转为离线色，**不弹错误框**。
- **不静默失败**：所有降级写入 `provider_health` 表，面板可查。
- 主进程未捕获异常写入本地日志（`electron-log`），不上报任何远端。
- **日志按天分文件、保留 7 天**（`src/main/logging.ts`）。electron-log 自带的滚动是按大小的、
  只留一份归档，那意味着「昨天发生了什么」随时可能被今天的一次刷屏挤掉 ——
  而排查提醒漏发恰恰要翻前几天。清理时**认不出名字的文件一律不删**。
- **单实例锁**（`src/main/index.ts`）：拿不到锁的进程立刻退出，不开库、不建窗口。
  这不是体验优化 —— `market.db` 只有一个写者的假设写进了整个存储层，而
  `AlertDispatcher` 的冷却与配额全在内存里，两个实例会让「每小时 ≤ 6 条」变成 12 条，
  且两边日志都显示自己守规矩。再次双击图标走 `second-instance` → 打开面板
  （**不**顺手显示悬浮条：它若是被用户按 C9 隐藏的，替他打开等于否决他的选择）。
