# ADR-0004 · 核心引擎与 Electron 完全解耦

- **状态**：已接受
- **日期**：2026-08-11

## 背景

指标计算、市场状态判定、策略、组合、风控是本项目的全部价值所在，也是最需要被验证的部分。它们既要在应用运行时使用，也要在回测 CLI 中使用。

一种常见做法是把这些逻辑写在主进程的 service 里，回测时再另写一份或用脚本重跑。这会导致「回测的策略」和「实际提醒用的策略」逐渐分叉——回测结论随之失效，而且没人会察觉。

## 决策

`src/core` 是一个**纯 TypeScript 库**，遵守三条铁律：

1. 不 `import` 任何 Electron API
2. 不 `import` 任何 Node 内置 IO 模块（`fs`、`net`、`http`…）
3. 不 `import` `src/main` 的任何东西（依赖方向单向：`main → core`，反向禁止）

推论：
- 不读时钟。「现在几点」「今天是不是交易日」由调用方作为参数传入。
- 不读配置文件。参数由调用方传入 `Params` 对象。
- 不写日志、不发事件。输出即返回值。
- 每个导出都是纯函数：`f(数据, 参数) → 结果`。

用 ESLint 的 `import/no-restricted-paths` 强制执行，违反即 CI 失败。

## 理由

1. **可测试**：`src/core` 的单元测试不需要启动 Electron，Vitest 直接跑，毫秒级。这决定了 90% 覆盖率目标是否现实。
2. **回测与实盘同源**：回测 CLI 与主进程调用完全相同的函数。回测结论对实际行为有效。
3. **无未来函数**：纯函数只能看到传入的切片。回测时传 `candles[0..i]`，物理上无法访问未来数据——[07 §2.2](../07-回测与验证方案.md) 里最危险的陷阱由架构消除，而非靠自律。
4. **可移植**：若将来重估桌面壳（见 [ADR-0001](./ADR-0001-选择-electron.md)），引擎零成本迁移。

## 代价

- 编排层（`src/main/engine`）需要额外一层胶水代码，负责把存储、时钟、配置喂给纯函数。这是刻意付出的成本。
- 增量计算优化会更麻烦（纯函数默认全量重算）。首版接受全量重算；若性能不足，通过显式的「状态对象进、状态对象出」形式实现增量，仍保持纯度。
