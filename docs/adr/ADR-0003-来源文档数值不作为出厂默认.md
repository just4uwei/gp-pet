# ADR-0003 · 来源文档的绩效数值不作为出厂默认参数依据

- **状态**：已接受
- **日期**：2026-08-11

## 背景

项目的需求来源是根目录的 `量化策略买卖时机判断.docx`（已归档为 [reference](../reference/量化策略买卖时机判断.md)）。文档给出了大量具体数值与绩效声明：

- MACD 参数 (12,17,9) 在 A 股「显著降低信号延迟」，年化 17.33%、信息比率 1.96、胜率 58%
- RSI+布林组合把胜率从 41.18% 提升至 45.65%
- 「3/5 策略一致确认」胜率提高至 68%
- 风险平价多策略组合年化 21.47%、最大回撤 20.85%
- 布林带宽 < 10% 分位 + 触下轨买入胜率约 65%
- 8% 止损、7% 回撤减仓、5% 盈利保护

文末标注「(AI生成)」，全部数字引自 90 余条网络链接（CSDN 博客、抖音视频、自媒体文章为主），无原始数据、无代码、无法复现。文档内部还存在自相矛盾之处（如 RSI 动态阈值一段中「降低超买阈值至 85」与「提高超卖阈值至 15」方向与数值不一致）。

## 决策

**分离规则结构与具体数值。**

- **采纳**其规则结构：用哪些指标、如何分层、按市场状态动态切换趋势/均值回归权重、投票确认、多周期共振、三级风控。这部分是合理且常见的工程组织方式。
- **不采纳**其任何绩效数字作为事实，也不以其具体参数值作为出厂默认。所有数值视为**初始猜测**，出厂默认值必须由 [07 回测与验证方案](../07-回测与验证方案.md) 在本地数据上标定产出。
- 文档中矛盾之处由 [04](../04-指标与信号引擎.md) 给出明确、单调、无歧义的重新定义，并在「⚠ 与来源的差异」中说明理由。

## 理由

1. 未经验证的绩效数字若被当作默认值的依据，用户会以为参数是「经过验证的」，而实际上没有任何人验证过。这是对用户的误导，且后果涉及真金白银。
2. 规则结构与参数值的可信度本就不同。结构错了很容易看出来，参数错了却会静悄悄地持续亏损。
3. 分离之后，来源文档仍然完全有价值——它省下了设计策略框架的时间。

## 影响

- 回测 CLI 从「P2 锦上添花」上升为 **M2 必须交付项**，因为它是确定默认参数的唯一手段。
- 所有参数集中在 `src/core/params.ts`，可配置、可标定、可版本化（`engine_version`）。
- UI 措辞受约束：置信度不得称为「胜率」；不得展示任何未经本地验证的绩效数字；应用内常驻免责声明。
- 影子运行（前向模拟）在 M4 引入，满 3 个月前不对策略绩效做正面宣称。

## 反面情形

如果标定后发现来源文档的参数确实表现良好，那也是**回测支持了它**，而不是文档本身。结论相同，依据不同——依据才是重点。
