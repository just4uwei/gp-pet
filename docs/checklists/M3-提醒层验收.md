# M3 出口验收 · 提醒层

[docs/08](../08-开发路线图.md) 给 M3 的出口条件是两句话：

> 自用一周，主观评价「没有被打扰过，也没有漏掉重要信号」；提醒日志中被抑制条目的原因分布合理。

**这两条都只能由人来判**，而且第一条有个陷阱：**主观感受发现不了漏发** ——
被吃掉的那条信号不会来告诉你它被吃了。所以第 4 节（提醒日志复盘）不是可选项，
它是「没漏掉重要信号」这半句的**唯一**证据来源。

```bash
pnpm test                     # 第 1 节：闸门与编排的自动化用例
pnpm typecheck && pnpm lint
pnpm dev                      # 第 2、3 节：真机
```

> 从 agent / CI 的 shell 里跑 `pnpm dev` 会「启动即崩」（`ELECTRON_RUN_AS_NODE=1`），
> 用 `env -u ELECTRON_RUN_AS_NODE pnpm dev`。见 CLAUDE.md。

## 4. 提醒日志复盘（**出口条件的证据**，每天 5 分钟 × 一周）

面板 → 提醒日志 → 展开。逐日回答四个问题：

| # | 问题 | 不合理的样子 |
|---|---|---|
| 4.1 | 今天发出的几条，我事后看**值不值得**被打断？ | 超过 3–4 条就该怀疑 `alert.bubbleScore` 太低 |
| 4.2 | 被静默的那些，原因分布合理吗？ | 「防抖」占绝大多数 → 信号在阈值附近抖，该调阈值不是调防抖 |
| 4.3 | 有没有**该发而没发**的？ | 逐条看「未提醒」那一列。**这是唯一能发现漏发的地方** |
| 4.4 | 冷却挡掉的那些，我当时真的不需要再被提醒一次吗？ | 止损类若出现在这一列 = bug，强制类本不该受冷却 |

### 4.0 先看这一天有没有重启过 —— 重启会污染这份判据（2026-08-17 加）

```bash
grep -c "窗口与托盘就绪" "$APPDATA/gp-pet/logs/main-YYYY-MM-DD.log"
```

**盘中重启过的交易日不能计入「自用一周」。** 分发器的冷却、配额、强制类台阶
全在内存里（§5 第一行），每次重启全部清零 ⇒ 同一条止损会重新发一次。
实测 08-13 启动 **14** 次、08-14 **27** 次（其中盘中 12 次），那两天三只票各发了
10–11 条 L3 气泡，**每一条都能对上一次启动时刻**（首条北京 10:52:10 = 本机 09:52 = 一次启动）。
拿它去回答 4.1「值不值得被打断」会得出「太吵」的结论，而真实原因是开发期在重启。

开发期与自用期因此不能算同一段。**判据是这个 grep 的计数为 0**，
第一个满足的交易日是 **2026-08-17**（自用一周从这天起算）。

### 4.5 第一个干净交易日的复盘（2026-08-17，样例 + 已修的两件事）

那天的日志同时暴露了 4.3 与 4.4 两列各一个真问题，都已修（见 CHANGELOG 同日条目）：

- **4.4 命中了**：三只跌破止损线的持仓整天 **0 条气泡**、**1580 行**「强制提醒台阶」。
  成因不是冷却，是开盘第一轮锁屏把台阶消耗掉了 —— 表格里那句「止损类若出现在这一列 = bug」
  是对的，但要连着看**是哪一道闸门**记的账。
- **4.2 读不出来**：1590 行日志只对应约 6 件事（判重被文案里的连续量打穿）。
  **原因分布必须按离散的 `suppressed_gate` 分组，不能按文案** —— 011 迁移的头注释写着这条。

> 一周结束时把 4.2 的原因分布写进 [M3 偏差报告]（若有意外发现）。
> 按 [docs/08 关键决策点 3](../08-开发路线图.md)：**若结论是「太吵」或「太哑」，
> 回到 docs/04 §4.2 的阈值或 docs/05 §4 的冷却策略去标定，不要增加新指标。**

## 5. 已知边界（不是缺陷，验收时不要当成 bug 记）

| 项 | 说明 |
|---|---|
| 重启后冷却清零 | 分发器状态全在内存里。落库会让「重启后什么都不弹」变成极难查的问题，见 `dispatcher.ts` 头注释 |
| 托盘完全不参与提醒 | 2026-08-13 起托盘只剩图标 + 菜单：未读角标、tooltip 计数、L3 图标闪烁全部移除。未读数在面板的提醒日志里 |
| L2 与 L3 表现相同 | 都是状态点 + 气泡。级别的区别在冷却窗口（2h vs 当日一次）与每日上限，验收 3.2/3.3 看的就是这个 |
| 提醒日志里有 `TRAY` / `OS_NOTIFY` 的旧行 | 2026-08-13 之前的历史值，读取端刻意不过滤 —— 滤掉会让当时真弹过的行看起来像被静默了 |
| 探测最多陈旧一轮 | TTL 15s、tick 30s。刚进入全屏的那一瞬间仍可能弹一条，之后就静默了 |
