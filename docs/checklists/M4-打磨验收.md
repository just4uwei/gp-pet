## 3. 多显示器与 DPI 缩放（**未完成**，docs/06 §7）

代码侧已有的：拓扑变化校验（`display-added` / `removed` / `metrics-changed` → `revalidatePosition`）、
`moveTo` 把宽高一起写回（防「越拖越大」）、命中区跟着 `resize` 重算。

**已知的一条实测差异**（2026-08-13，E2E 在 150% 缩放的 2560×1440 上跑出来的）：
悬浮条标称 300×38，而 `getSize()` 报 **300×40**。缩放比不是 100% 时 Electron 要在 DIP 与
物理像素之间来回换算、两个方向都按「包住」取整，标称高度会被抬 1–2 DIP。
**这不影响 C2** —— 命中区在渲染层按 `window.innerHeight` 实测重算，窗口被抬多少就盖多少。
所以它是外观问题（圆角与内容的留白比预期紧 2px），不是穿透问题。

要人做的：

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 3.1 | 100% 基线 | 主屏设 100%，重启应用 | 条子 300×38，圆角与文字留白正常 |
| 3.2 | 125% | 改成 125%，重启 | 条子不被拉伸/模糊，文字不截断，状态点不出框 |
| 3.3 | 150% | 改成 150%，重启 | 同上。**顺带确认高度被抬的那 1–2px 没有把圆角吃掉** |
| 3.4 | 拖拽不长大 | 在 150% 下把条子来回拖十几次 | 尺寸不增长；**拖完之后点击仍然有反应**（这是那个 bug 的后半段症状） |
| 3.5 | 跨屏拖拽 | 两块缩放比不同的屏（如 100% + 150%），把条子从一块拖到另一块 | 过程中不闪、不变形；松手后仍在工作区内 |
| 3.6 | 热插拔 | 拖到副屏后拔掉副屏 | 条子自动回到主屏工作区内，不停在不存在的坐标上 |
| 3.7 | 改分辨率 | 在条子停在右下角时把分辨率调小 | 条子跟着回到新工作区内 |
| 3.8 | 面板 | 在 150% 下打开面板 | 两栏布局不错位；窄到 720 宽时退回单列 |

> 3.4 是这一节最值得做的一条。CLAUDE.md 记着它的完整形状：撑大之后命中区盖不住窗口，
> 鼠标压在条子上却判成穿透，**表现是「拖完之后点什么都没反应」，看起来像 IPC 挂了**。
> 两处修正（`moveTo` 写回宽高 + 命中区跟 `resize` 重算）都在，但没人在 150% 下真拖过。

### §5 踩过的坑（2026-08-13 实测）

**① `files` 里出现任何一条正向的 `node_modules/...` 条目，会让 electron-builder
原地改写源码树里的 `package.json`。**

具体表现：`scripts` 与 `devDependencies` 整块消失（只剩 name/version/dependencies 那几项），
接着 pnpm 按「没有 devDependencies」把开发依赖**整批剪掉** —— `node_modules/electron` 被删，
下一次打包报 `The specified electronDist does not exist`，看起来像 `electronDist` 配错了。

**这不是产物被改，是仓库被改。** 恢复顺序：

```bash
git checkout -- package.json pnpm-lock.yaml   # 先把源码树救回来
pnpm install --frozen-lockfile               # 装回 devDependencies
node node_modules/electron/install.js        # electron 的 dist/ 要单独解压
```

所以要排除 node_modules 里的东西**只能用排除式 glob**（`'!node_modules/…/!(keep).node'`），
不能写成「先排除整个目录、再正向列出要留的那个」。配置里那几行的注释写着这条。

**② 这台机器的 shell 里 `ELECTRON_RUN_AS_NODE=1`，直接跑打包产物会得到
`bad option: --user-data-dir=…`。** 那是 Electron 以纯 Node 模式启动后 Node 在拒绝一个
Chromium 开关 —— **不是打包坏了**。用 `env -u ELECTRON_RUN_AS_NODE ...`（CLAUDE.md 里那条）。
