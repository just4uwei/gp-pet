# M2 出口验收 · 引擎层

[docs/08](../08-开发路线图.md) 给 M2 的出口条件是三句话：

> `src/core` 覆盖率 ≥ 90%；回测报告产出并据此确定默认参数；分 Regime 归因能回答「权重切换是否有效」。

第一条 CI 能断言，后两条**必须有真实历史行情**才做得了 —— 本机三家行情接口全部不通
（见 [M1 偏差报告 §2](../notes/M1-偏差报告.md)），所以后两条只能等首台能联网的机器。
状态与理由见 [M2 偏差报告 §5](../notes/M2-偏差报告.md)。

```bash
pnpm test:cov                       # 第 1 节：自动化闸门
pnpm verify:indicators -- --check   # 第 2 节：黄金值仍与独立参照实现一致
pnpm dev                            # 第 3 节：真机跑一轮
pnpm backtest -- --help             # 第 4 节：回测与标定（需要真实日线）
```

---

## 1. 自动化闸门（CI 会跑，人只需确认没有被降低门槛）

| # | 项 | 通过标准 |
|---|---|---|
| 1.1 | `src/core` 覆盖率 | 行/语句/函数 ≥ 90%，分支 ≥ 85%（`vitest.config.mts` 的 thresholds） |
| 1.2 | 其余目录覆盖率 | ≥ 60% |
| 1.3 | 黄金用例 | `tests/unit/indicators/golden.test.ts` 全绿，23 条序列相对误差 < 1e-6 |
| 1.4 | 黄金值未被手改 | `pnpm verify:indicators -- --check` 通过 |
| 1.5 | 类型与 lint | `pnpm typecheck && pnpm lint` |
| 1.6 | ADR-0004 未被绕开 | lint 无 `src/core 不得依赖 Electron` / `不得读时钟` 告警 |

> 覆盖率数字**不是目的**。若为了凑数写了一堆断言恒真的用例，这一节就白过了。
> 判据是：`src/core` 里每个 `if` 分支都有一条用例说明「为什么这里要分岔」。

## 2. 引擎正确性（人工抽查，半小时）

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 2.1 | 指标口径 | 拿一只自选股，用行情软件对当日 MACD / BOLL / RSI / ADX | 数值一致（MACD 柱应为软件显示值，即已 ×2） |
| 2.2 | 前复权 | 抽查一只近期除权的股票 | 指标连续，除权日无凭空的金叉/死叉 |
| 2.3 | 盘中量比 | 上午 10:00 看面板信号的 `volRatio` | 不是恒 < 1（未归一化的典型症状） |
| 2.4 | 受限模式 | 加一只上市不足一年的次新股 | 面板提示「数据不足，信号可靠性降低」；不足 60 日的直接被静默 |
| 2.5 | 状态迟滞 | 连续几日看同一只的 `regime` | 不会每天翻转 |

> 2.1–2.3 是 [M2 偏差报告 §6](../notes/M2-偏差报告.md) 说的「口径一致性未验证」那部分，
> **这是本清单里最有价值的三条** —— 它们是自动化测试永远替代不了的。

## 4. 回测与标定（**需要真实历史日线，本机做不了**）

前置：`market.db` 里自选股与 `SH000300` 都有 2018 年以来的日线。

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 4.1 | 回测能跑通 | `pnpm backtest -- --codes <自选股> --from 2018-01-01 --to <今天> --out reports/base.json` | 产出报告，无异常；报告头部带三条免责 |
| 4.2 | 未来函数防护 | 看报告 `warnings` 与用例 `simulate.test.ts` | 不出现「疑似未来函数」抛错 |
| 4.3 | 成交模型 | 抽查报告里的逐笔交易 | 成交价 = 次日开盘 × (1±滑点)；持仓 ≥ 1 日 |
| 4.4 | 交易笔数 | 看报告告警 | 全样本 ≥ 30 笔，否则统计上无意义（docs/07 §3） |
| 4.5 | **分 Regime 归因** | 看报告「分市场状态归因」 | 四个状态各自的笔数与胜率都能看到；某个状态长期 0 笔要能说清是没机会还是够不着阈值 |
| 4.6 | **关键决策点** | 见下方说明 | 已于 2026-08-12 触发并收口 |

> 4.5 / 4.6 **已收口**（2026-08-12）：报告里原本有一块「动态 vs 固定权重对照」，
> 两轮测量都答「无效」，于是 `params.weights` 与那块对照一起删除，两个策略改为等权
>（[M2-偏差报告 §5.5–§5.8](../notes/M2-偏差报告.md)）。所以现在的报告里没有对照块，
> 别再照着旧版本去找它。决策点 2 的另一半（是否退到单一策略）**答案是「不退」**：
> 标定 R1–R4 后均值回归的边际贡献从 +0.14pp 变成 +2.0 ~ +3.4pp
>（[§5.10](../notes/M2-偏差报告.md)），两个策略都留。
| 4.7 | 网格标定 | `pnpm backtest -- --codes ... --grid params/grid.json` | 产出候选排名；淘汰理由与红线一致 |
| 4.8 | 参数敏感性 | 看优胜候选邻域（±20%）的绩效 | 无断崖下跌，否则是噪音峰值，不采用 |

> 4.7 / 4.8 **已跑过多轮真数据**（2026-08-12：R1–R4、`combine` 块；2026-08-13：`combine` 块按新判据重跑、
> `adx` × `regime` 笛卡尔积 21 组、以及 `adx` / `regime` 三张加宽 OFAT 网格）。
> 4.8 的邻域检查**现在由工具自动判**（`plateauFlags()`）：同一维度上取值相邻的候选互为邻域，
> 出厂值那一行天然是 OFAT 候选的一侧邻居，任一侧掉到不足一半标「孤峰」，
> 在网格边界标「该侧邻域未测」。以前这一格靠人看表，而人看表恰好是这条流程唯一
> 真正起作用的判据（M2 §5.15）。
> **纪律缺口已修**：`--grid` 以前每次调用都对该次优胜者跑一遍测试窗口，
> 现在改成显式 `--touch-test`（默认不跑）。历史上累计触碰 5 次，
> docs/07 §3 ④ 的「测试集只跑一次」对那 5 次已不严格成立 —— 那些结论只按训练集 + 验证集读。
>
> **4.7 的通过标准变了**（2026-08-13）：不再是「产出候选排名」，而是
> **「报告最上面那行裁决是 `WRITE_BACK` 或 `KEEP`，不是 `INCONCLUSIVE`」**。
> 只有排名的时候，这一格看起来永远是「跑通了但没结论」；三态裁决把
> 「出厂值站得住」也算成通过 —— 它确实是一个结论。
| 4.9a | **部分写回**（单个参数标定完） | 人工复核后改 `src/core/params.ts` | 递增 `ENGINE_VERSION` 补丁位、**保留 `-unvalidated`**、该字段注释里写清依据与失效条件、`params.ts` 顶部「已标定」清单加一行、CHANGELOG 记录标定依据。`params.test.ts` 的后缀断言**不动** |
| 4.9b | **标定完成**（整套参数都有依据） | 同上 + 摘后缀 | `ENGINE_VERSION` 改为 `0.3.0`、删掉 `params.test.ts` 里断言 `-unvalidated` 的用例、确认回测报告不再打「参数未标定」提示是**名副其实**的 |
| 4.9c | **已测但不写回**（裁决 `KEEP`，或参数惰性） | 只记录，不改代码 | 偏差报告里写清「哪个网格、哪次跑、为什么不写回、什么条件下要重测」；`ENGINE_VERSION` **不动**（没有行为变更就没有要失效的缓存）。惰性参数额外记一条：先用 `audit:*` 找结构原因，**不要反复重跑同一个网格** |

> 4.9 **是人的动作**，标定工具不会自动改文件 —— 自动写回会让「出厂默认值从哪来」
> 变成没人复核过的黑箱，而 ADR-0003 的整个立场就是不接受未经复核的数值。
>
> **4.9c 是 2026-08-13 补的一档，它解释了为什么这一节长期停在「未完成」**：
> 原来只有「写回」和「写回 + 摘后缀」两档，于是「测过了、结论是保持原值」这件事
> 没有归档的地方 —— 每次都只能记成「没有候选够格」，读起来像还没做完，
> 下一轮又有人把同一个网格再跑一遍。三种归档方式的对照表在
> [params/README](../../params/README.md)。
>
> **为什么拆成 a/b 两档**（2026-08-12）：原来这一条把「写回」与「摘后缀」绑在一起，
> 是按「整套参数一次标定完」写的。实际是一个一个标定的 —— 第一个落地的是
> `strategy.squeezeBbwPct`（10 → 20）。此时摘掉 `-unvalidated` 会让回测报告停止打
> 「参数未标定」提示（`src/backtest/report.ts` 的 `unvalidatedParams`、下面 5.4），
> 等于用一个参数的证据给另外二十来个转述值背书。后缀跟的是**整体**状态，不是某一项。
>
> 已按 4.9a 走完一次：`ENGINE_VERSION` `0.2.4-unvalidated` → `0.2.5-unvalidated`，
> 依据见 [CHANGELOG](../../CHANGELOG.md) 与 [§5.10](../notes/M2-偏差报告.md)。
