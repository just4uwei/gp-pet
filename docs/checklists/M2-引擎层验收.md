# M2 出口验收 · 引擎层

[docs/08](../08-开发路线图.md) 给 M2 的出口条件是三句话：

> `src/core` 覆盖率 ≥ 90%；回测报告产出并据此确定默认参数；分 Regime 归因能回答「权重切换是否有效」。

第一条 CI 能断言，后两条**必须有真实历史行情**才做得了 —— 本机三家行情接口全部不通
（见 [M1 偏差报告 §2](../notes/M1-偏差报告.md)），所以后两条只能等首台能联网的机器。
状态与理由见 [M2 偏差报告 §5](../notes/M2-偏差报告.md)。

```bash
pnpm test:cov                       # 第 1 节：自动化闸门
pnpm verify:indicators -- --check   # 第 2 节：黄金值仍与独立参照实现一致
pnpm dev                            # 第 3 节：真机跑一轮
pnpm backtest -- --help             # 第 4 节：回测与标定（需要真实日线）
```

---

## 1. 自动化闸门（CI 会跑，人只需确认没有被降低门槛）

| # | 项 | 通过标准 |
|---|---|---|
| 1.1 | `src/core` 覆盖率 | 行/语句/函数 ≥ 90%，分支 ≥ 85%（`vitest.config.mts` 的 thresholds） |
| 1.2 | 其余目录覆盖率 | ≥ 60% |
| 1.3 | 黄金用例 | `tests/unit/indicators/golden.test.ts` 全绿，23 条序列相对误差 < 1e-6 |
| 1.4 | 黄金值未被手改 | `pnpm verify:indicators -- --check` 通过 |
| 1.5 | 类型与 lint | `pnpm typecheck && pnpm lint` |
| 1.6 | ADR-0004 未被绕开 | lint 无 `src/core 不得依赖 Electron` / `不得读时钟` 告警 |

> 覆盖率数字**不是目的**。若为了凑数写了一堆断言恒真的用例，这一节就白过了。
> 判据是：`src/core` 里每个 `if` 分支都有一条用例说明「为什么这里要分岔」。

## 2. 引擎正确性（人工抽查，半小时）

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 2.1 | 指标口径 | 拿一只自选股，用行情软件对当日 MACD / BOLL / RSI / ADX | 数值一致（MACD 柱应为软件显示值，即已 ×2） |
| 2.2 | 前复权 | 抽查一只近期除权的股票 | 指标连续，除权日无凭空的金叉/死叉 |
| 2.3 | 盘中量比 | 上午 10:00 看面板信号的 `volRatio` | 不是恒 < 1（未归一化的典型症状） |
| 2.4 | 受限模式 | 加一只上市不足一年的次新股 | 面板提示「数据不足，信号可靠性降低」；不足 60 日的直接被静默 |
| 2.5 | 状态迟滞 | 连续几日看同一只的 `regime` | 不会每天翻转 |

> 2.1–2.3 是 [M2 偏差报告 §6](../notes/M2-偏差报告.md) 说的「口径一致性未验证」那部分，
> **这是本清单里最有价值的三条** —— 它们是自动化测试永远替代不了的。

## 3. 主进程接线（`pnpm dev` 真启一次）

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 3.1 | 引擎起来了 | 看启动日志 | 出现 `[app] 数据层与引擎就绪（0.2.x-unvalidated+…）` |
| 3.2 | 基准指数被回补 | `SELECT COUNT(*) FROM kline_daily WHERE code='SH000300'` | ≥ 300 根（否则 RSI 阈值会一直停在中性 75/25） |
| 3.3 | 面板信号列表 | 盘中打开面板 | 有「今日信号」区块；勾选框能显示/隐藏被静默条目 |
| 3.4 | 依据展开 | 点任一条信号 | 展开后能看到子信号、多周期调整、触发时的指标值 |
| 3.5 | 落库去重 | 盘中连续观察 10 分钟 | `SELECT COUNT(*) FROM signal WHERE trade_date=date('now')` 不随 tick 线性增长 |
| 3.6 | 指标缓存 | 收盘后查 `indicator_daily` | 每只每交易日一行，`engine_version` 与日志里的一致 |
| 3.7 | 缓存失效 | 改一个参数（如 macd.slow）后重启 | 日志出现「已清理 N 条旧指标缓存」 |
| 3.8 | 确认轮 | 15:05 之后看当日 PROVISIONAL 信号 | 已变成 CONFIRMED 或 INVALIDATED，没有残留在 PROVISIONAL |
| 3.9 | 零干扰未被破坏 | 重跑 [M0 清单](./M0-零干扰验收.md) 的 C1 / C2 | 仍然通过（M2 动了面板与主进程） |
| 3.10 | 没有提前发提醒 | 全天观察 | **不应**出现任何气泡或系统通知 —— 那是 M3 |

## 4. 回测与标定（**需要真实历史日线，本机做不了**）

前置：`market.db` 里自选股与 `SH000300` 都有 2018 年以来的日线。

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 4.1 | 回测能跑通 | `pnpm backtest -- --codes <自选股> --from 2018-01-01 --to <今天> --out reports/base.json` | 产出报告，无异常；报告头部带三条免责 |
| 4.2 | 未来函数防护 | 看报告 `warnings` 与用例 `simulate.test.ts` | 不出现「疑似未来函数」抛错 |
| 4.3 | 成交模型 | 抽查报告里的逐笔交易 | 成交价 = 次日开盘 × (1±滑点)；持仓 ≥ 1 日 |
| 4.4 | 交易笔数 | 看报告告警 | 全样本 ≥ 30 笔，否则统计上无意义（docs/07 §3） |
| 4.5 | **分 Regime 归因** | 看报告「分市场状态归因」与「动态 vs 固定权重对照」 | 能直接回答「权重切换是否有效」 |
| 4.6 | **关键决策点** | 若 4.5 显示动态权重**不优于**固定权重 | **停下来**，按 [docs/08 关键决策点 2](../08-开发路线图.md) 简化组合层，不要带着无效的复杂度进 M3 |
| 4.7 | 网格标定 | `pnpm backtest -- --codes ... --grid params/grid.json` | 产出候选排名；淘汰理由与红线一致 |
| 4.8 | 参数敏感性 | 看优胜候选邻域（±20%）的绩效 | 无断崖下跌，否则是噪音峰值，不采用 |
| 4.9 | 写回出厂参数 | 人工复核后改 `src/core/params.ts` | 同步递增 `ENGINE_VERSION`、去掉 `-unvalidated`、CHANGELOG 记录标定依据、删掉 `params.test.ts` 里断言该后缀的用例 |

> 4.9 **是人的动作**，标定工具不会自动改文件 —— 自动写回会让「出厂默认值从哪来」
> 变成没人复核过的黑箱，而 ADR-0003 的整个立场就是不接受未经复核的数值。

## 5. 措辞纪律（每次发版都要过一遍）

| # | 项 | 通过标准 |
|---|---|---|
| 5.1 | 置信度 | 面板与报告里不出现「胜率」「概率」描述置信度（回测报告里的 `winRate` 是历史事实，可以叫胜率） |
| 5.2 | 禁用词 | 全局搜索「必涨」「抄底」「稳赚」「牛股」，无命中 |
| 5.3 | 免责 | 面板底部固定「仅供参考，非投资建议」；回测报告尾部同样 |
| 5.4 | 未标定标记 | 只要 `ENGINE_VERSION` 带 `-unvalidated`，报告里必须有「参数未标定」提示 |
