# M1 出口验收 · 数据层

[docs/08](../08-开发路线图.md) 给 M1 的出口条件是三句话：

> 连续运行一个完整交易日，`provider_health` 成功率 > 99%，日线无缺口。

三条都是**运行期事实**，CI 断言不了 —— 单元测试能证明「拿到这样的响应会怎么处理」，
证明不了「真实接口现在返回什么」。所以这一份必须由人跑。

```bash
pnpm dev                                   # 首次真机启动（better-sqlite3 需先 electron-rebuild）
pnpm test && pnpm typecheck && pnpm lint   # 提交前的自动化闸门
```

---

## 0. 先决条件

| # | 检查 | 通过标准 |
|---|---|---|
| 0.1 | 原生模块 ABI | `pnpm dev` 能开库，日志出现 `[db] 迁移完成 → v1` 或 `已是 v1` |
| 0.2 | 主进程真启 | 日志出现 `[app] 数据层就绪`；没有 `数据层装配失败` |
| 0.3 | 网络可达 | 面板顶部三家数据源不全是「不可用」 |

> 0.3 若不通过，后面全部条目都验不了。**本机开发时这一条就是不通的**（见
> [M1 偏差报告](../notes/M1-偏差报告.md) 第 2 条），fixture 是手写的而非录制的
> —— 首次联网真机跑通之前，「provider 能解析真实响应」属于未验证。

## 1. 必须通过（M1 出口）

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 1.1 | 连续运行一个交易日 | 09:00 前启动，收盘后不退出 | 全程无崩溃、无内存持续上涨；`[tick]` 无连续失败 |
| 1.2 | 健康度 > 99% | 收盘后看面板顶部各源成功率 | 至少主源 ≥ 99%（`provider_health` 24h 窗口） |
| 1.3 | 日线无缺口 | 收盘后对任一自选股跑 `SELECT date FROM kline_daily WHERE code=? ORDER BY date` | 与交易日历逐日对齐，无缺失、无重复 |
| 1.4 | 收盘线落库 | 15:05 之后重启，看最后一根日线 | 日期为当日，`provisional = 0`（盘中临时线绝不入库） |
| 1.5 | 复权双轨 | 抽查一只近期除权的股票 | `close` 与 `closeAdj` 不等；`close` 与券商 App 的不复权价一致 |

## 2. 请求礼仪（[docs/03 §2.4](../03-数据源与存储设计.md)）

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 2.1 | 休市零请求 | 周末或 20:00 之后启动，观察一小时 | 除首轮维护外无任何行情请求 |
| 2.2 | 午休零请求 | 11:35–12:55 之间观察 | 同上 |
| 2.3 | 日线不重复拉 | 盘中连续几轮 tick | 日线已补齐后 `backfill` 不再发请求（日志无 `[daily]`） |
| 2.4 | 并发上限 | 自选加到 30 只以上，盘中抓包或看日志 | 同时在途请求 ≤ 4，单源 ≤ 2 |
| 2.5 | 快照分片 | 自选 > 50 只 | 每轮快照按 ≤ 50 只分片发出 |

## 3. 降级与诚实上报

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 3.1 | 主源故障切换 | 断网 → 恢复；或把 `providerPriority` 首位改成一个会失败的源 | 面板该源转「降级/不可用」，价格照常更新（换源） |
| 3.2 | 全源不可用 | 拔网线，等一轮 tick | 面板显示「行情离线」，价格灰显为上一次成功的值；**不弹窗、不崩** |
| 3.3 | 恢复 | 插回网线 | 下一轮 tick 自动恢复，灰态消除（无需重启） |
| 3.4 | 日历不确定 | 直接看（`holidays.json` 的 `verifiedYears` 出厂就是空的） | 面板提示「交易日历尚未核对」；把当年填进 `verifiedYears` 后提示消失 |
| 3.5 | 探测轮纠正 | 在被误判为休市的交易日启动 | 30 分钟内探测到真成交，日志出现 `已纠正为交易日` |

## 4. 自选股与面板

| # | 项 | 操作 | 通过标准 |
|---|---|---|---|
| 4.1 | 多形态输入 | 依次输入 `600000`、`sh600000`、`000001.SZ` | 均添加成功，列表显示为 `SH600000` / `SZ000001` |
| 4.2 | 拒绝而不猜 | 输入 `000300`、`12345`、`abc` | 各给出一条能看懂的中文原因，不写库 |
| 4.3 | 离线可添加 | 拔网线后添加一只新股 | 添加成功，名称暂显代码；联网后下一轮补上真名 |
| 4.4 | 涨跌幅 | 盘中对照券商 App | 数值一致（不复权口径），红涨绿跌 |
| 4.5 | 重复添加 | 添加一只已在列表里的 | 不报错、不重复出现、分组与排序不变 |
| 4.6 | 移除与排序 | 移除、上移/下移 | 立即生效，重启后保持 |
| 4.7 | 数据层未就绪 | 断开数据库文件权限后启动 | 面板显示「数据层尚未就绪」而不是空白或崩溃 |

## 6. 已知的 M1 缺口（不是缺陷）

- **无指标、无信号、无提醒**：M2/M3。状态点只会是 `IDLE` / `SLEEPY` / `OFFLINE`，
  `WATCHING` / `EXCITED` / `ALERT` 一律不点亮 —— 提前点亮就是假信号。
- **`unreadAlerts` 恒为 0**：提醒层未实现，如实报 0 而不是编一个数字。
- **持仓只能通过 IPC 写入**：面板的持仓录入 UI 属 M2（列表已显示「持仓」标记）。
- **设置面板 UI 未做**：`settings:get/patch` 通道已通，界面属 M4。
- **`分组` 只有默认组**：多分组的 UI 属 M4，数据结构已就位。
