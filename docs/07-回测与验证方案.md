# 07 · 回测与验证方案

## 1. 为什么回测是 P0 的前置条件

来源文档给出的所有绩效数字（年化 17.33%、信息比率 1.96、胜率 58%、组合年化 21.47% 等）**均引自网络文章，无数据、无代码、无法复现**。把它们当作既成事实去设定出厂参数，等于把用户的钱押在无法验证的转述上。

因此本项目的立场是：

> 来源文档提供的是**规则结构**（哪些指标、如何组合、如何切换权重），这部分是有价值的。
> 它提供的**具体数值**（12/17/9、ADX 25、8% 止损、0.6 阈值）一律视为**待标定的初始猜测**，出厂默认值必须由本地回测产出。

回测 CLI 因此不是「锦上添花的 P2 功能」，而是决定默认参数的工具，需要在 M2 阶段就可用。

## 2. 三层验证

### 2.1 第一层：指标正确性（单元测试）

指标算错，后面全是空中楼阁。

**交叉验证方法**：取一段真实日线（沪深300 成分若干只，各 500 根），用三方独立实现计算同一指标并比对：

| 参照 | 用途 |
|---|---|
| Python `pandas-ta` / `TA-Lib` 脚本（`scripts/verify/`） | 主要参照，尤其是 Wilder 平滑类（ADX、RSI）易错 |
| 行情软件截图人工抽查 | 校验国内口径差异（MACD 柱是否 ×2、STD 是否除 n） |
| 手算 | 前 3 个值，验证种子值与预热逻辑 |

容差：`|ours - ref| / |ref| < 1e-6`（EMA 类因种子差异可能在前若干根偏离，只比对预热期之后）。

比对脚本产出的期望值固化为 `tests/fixtures/golden/*.json`，成为回归基线。

### 2.2 第二层：策略回测（CLI）

```bash
pnpm backtest --codes SH600000,SZ000001 --from 2020-01-01 --to 2026-06-30 \
              --params ./params/candidate-a.json --out ./reports/a.json
```

**回测引擎设计要点**（每一条都是常见的自欺来源）：

| 陷阱 | 对策 |
|---|---|
| 未来函数 | 引擎只允许访问 `candles[0..i]`；用 `Object.freeze` + 切片传入，禁止把完整数组给策略函数 |
| 信号当日成交 | 信号在第 `i` 根收盘产生 → 成交价用第 `i+1` 根**开盘价**，不用当日收盘价 |
| T+1 | 买入后至少持有到下一交易日 |
| 涨跌停无法成交 | 次日开盘价触及涨跌停则该笔交易作废（买入跳过，卖出顺延） |
| 复权 | 全程用前复权序列；回测报告中的收益率因此已含除权影响 |
| 交易成本 | 佣金双边万 2.5（最低 5 元）+ 卖出印花税千 1 + 过户费万 0.1，可配置 |
| 滑点 | 默认 0.1%，可配置 |
| 幸存者偏差 | 标的池由用户自选股决定，本身就有偏差 → **报告中明确标注「本回测不代表全市场表现」** |

**输出指标**：

```
总收益 / 年化收益 / 基准（沪深300）超额 / **平均资金占用率**
最大回撤 / 回撤持续天数
胜率 / 盈亏比 / 平均持仓天数 / 交易次数
夏普比率 / 信息比率
逐笔交易明细（含触发的子信号 ID，用于归因）
按 Regime 分组的绩效（趋势市 vs 震荡市，看引擎在哪种状态下有效）
```

> **「超额」不能单独读，必须和「平均资金占用率」一起读**（2026-08-12 加）。
> 基准是 100% 满仓的指数买入持有，而信号策略绝大多数时间空仓 ——
> 实测出厂参数下平均资金占用只有 **4.15%**，同期超额 −8.17pp，但最大回撤是
> 2.44% vs 基准的 45.60%，Calmar 0.275 vs 0.034。**风险调整后方向是反过来的。**
> 所以文本报告把占用率打印在超额那一行的正下方，`performance.exposure` 也进了 JSON。
> 反过来「按占用资金折算成年化 10.8%」同样不许拿去说事，理由见
> [M2 §5.13](./notes/M2-偏差报告.md)。

最后一项尤其重要：整套设计的核心假设是「按市场状态切换策略权重能提升表现」。如果分组绩效显示切换后并不优于固定权重，这个假设就该被推翻，而不是保留一套复杂而无效的机制。

> **这个假设已经被推翻了（2026-08-12）**：两轮对照（第一轮带口径 bug、第二轮解耦后）
> 都看不出动态权重优于固定 0.5/0.5，于是 `params.weights` 整张表连同回测里的固定权重对照组
> 一起删除，两个策略改为等权。上面那句话保留在这里不是历史遗迹，而是**这条判据的用法示范**：
> 下一次再想加「按状态切换某某」之前，先说清楚拿什么对照、多大差值才算有效。
> 全部数字见 [M2-偏差报告 §5.5–§5.8](./notes/M2-偏差报告.md)。

**策略消融**：要回答「某个策略到底贡献了几笔交易」，用 `params.enabledStrategies`
（`{ trend, meanReversion }`，出厂两项皆 `true`），经 `--params` 传入即可：

```bash
pnpm backtest -- --codes ... --fixtures ./data/history \
              --params ./reports/probe/abl-trend.json    # {"enabledStrategies":{"trend":true,"meanReversion":false}}
```

**不要用「把权重设成 0」代替它**：组合层的票数不分策略，权重 0 的策略得分贡献是 0、票照投，
测出来的是「关掉得分、留着票」。它是测量工具不是可标定参数，标定网格不得把它当维度扫。
实测结论见 [M2-偏差报告 §5.7](./notes/M2-偏差报告.md)。

### 2.3 第三层：影子运行（Paper Trading）

回测好看不代表实盘可用。M3 起软件内置**影子模式**：

- 每条信号自动记录「若按此信号操作」的模拟持仓
- 面板展示模拟组合的累计收益、胜率、最大回撤
- 与同期沪深300 对比
- 运行满 3 个月前，UI 上对策略绩效**不做任何正面宣称**

影子运行的数据是本地的、真实前向的，比任何历史回测都可信。

## 3. 参数标定流程

```
① 划分数据：训练集 2018-01 ~ 2023-12，验证集 2024-01 ~ 2025-06，测试集 2025-07 ~ 至今
② 在训练集上搜索参数（下节）
③ 在验证集上筛掉过拟合候选（训练集表现好、验证集崩掉的直接淘汰）
④ 测试集只跑一次，作为最终报告，不允许据此回头调参
⑤ 入选参数写入 src/core/params.ts，engine_version +1，并在 CHANGELOG 记录标定依据
```

> ④ 曾经有一个**工具层的缺口**：`pnpm backtest --grid` 每次调用都会对**该次**的优胜者
> 跑一遍测试窗口。于是「测试集只跑一次」在实操上等于「**只准跑一轮网格**」——
> 一旦发现最优点落在网格边界、需要扩网格重跑，测试窗口就被多看了一次。
> 2026-08-12 标定 R1–R4 时就发生了这件事（两轮网格 × 两种基线 = 四次），
> 处理方式是**如实记下来，并只按训练集 + 验证集下结论**
>（[M2-偏差报告 §5.10](./notes/M2-偏差报告.md)）。设计网格时先把取值范围想宽一点，
> 比事后补跑便宜。
> **已修**（2026-08-13）：测试段改成显式开关 `--touch-test`，默认不跑。
> 前 5 次触碰里几乎每一次的优胜者最后都没被采用 —— 也就是说测试窗口是白烧的。
> **累计触碰次数：5 次**（R1–R4 四次 + `combine` 块一次，后者的优胜者已按孤峰判掉、
> 测试块不作为结论，见 [§5.14](./notes/M2-偏差报告.md)）。加一次就在这里改这个数。

### 3.1 判据：与出厂值配对比较，三态裁决

**这一节是 2026-08-13 补的，起因是这套流程跑了十一轮只写回了一个参数**
（[M2 §5.15](./notes/M2-偏差报告.md)）。每一轮的形状都一样：工具按验证集 Calmar 报出一个
优胜者，人看完表判定它是「孤峰」或「验证窗口正好友好」，然后否掉。也就是说
**真正在做决策的判据不在工具里**——唯一被写回的 `strategy.squeezeBbwPct` 靠的是人工
认出「16–30 是一整片高原」并核对两种基线，而不是工具排名的第一名（那是 30，被否了）。

所以「谁的分数最高」不是可用的判据。现在的判据是三件事：

1. **出厂值永远是候选之一，所有比较都与它配对。** 输出不再是「优胜者是 X」，
   而是「X 相对出厂值的改进是 Δ，可分辨 / 不可分辨」—— 后者才是能据以决定
   「改不改 `params.ts`」的形式。
2. **每个候选有一组折上的分数，不是一个点估计。** 同一次模拟按
   **标的子集 × 判定窗口内的时间片**切成折单元（默认 4 × 3 = 12 折，
   `--code-folds` / `--time-slices` 可调），逐折与出厂值配对求差：
   `Δ均值 ± 标准误`。项目一直在口头上用的「±1pp 噪音带」「正负交替 = 噪音」
   由此变成算出来的量。**折是切出来的、不是重跑的**，所以加折不加耗时。
   两个方向都要：横截面折答「换一批标的会不会翻盘」，时间片答「换一段行情会不会翻盘」，
   §5.14 定不下来的两个原因正好各占一个。
   **折上比的量是本折总收益，不是 Calmar** —— 一折只有 ~10 只 × ~120 根，
   最大回撤能小到 0.3%，Calmar 的分母趋零就炸（实测折间标准误 2.07，而整池 Calmar 才 0.427）。
   用总收益还有个附带好处：单位与 §5.5–§5.13 所有消融结论一致，可以直接对比。
   风险调整没丢，它在红线、排名（整池 Calmar）和写回门槛第 ① 条里。
3. **裁决三态**：
   | 裁决 | 含义 | 该做什么 |
   |---|---|---|
   | `WRITE_BACK` | 有挑战者稳定优于出厂值且邻域是高原，三条同时成立：① 整池验证集 Calmar 不低于出厂值 ② 至少 3 折真被改动 ③ `\|Δ\|/标准误 ≥ 2` 且**受影响的折**里 ≥ 2/3 为正 | 走 ⑤，人工复核后写回 |
   | `KEEP` | **出厂值站得住** —— 没有挑战者的改进大于它自己的折间抖动 | **这是结论**。记进偏差报告，该参数归档为「已测、保持出厂值」（清单 4.9c） |
   | `INCONCLUSIVE` | 出厂值自己被红线淘汰，或折数不足以估离散度 | 先解决红线原因或折数，不下任何结论 |

   ② 与「受影响的折」这个口径是必要的：**改一个参数通常只动少数几折**
   （实测 `scoreThreshold` 0.55 只动了 12 折里的 5 折，`downtrendBuyPenalty` 一折都没动）。
   胜率若按总折数算，这类候选永远够不着 2/3 —— 那会把「影响面小但方向一致」
   误判成「无效」。

`KEEP` 时报告给出 `resolution.requiredCells`：**要让已观测到的这个 Δ 变得可分辨，
大约需要多少折**。这把「定不下来」变成一句可执行的话 —— 要么把样本扩到那个量级，
要么承认这个参数在当前数据量下不可标定（按 M2 清单 4.9c 归档，不再反复重跑）。

> 单折的绩效**不可**与整池绩效横向比较（窗口短、标的少、回撤分母小），
> 也不可单独引用。它只有一个用途：同一折上两个候选之差。

**搜索方法**：

- **首版：粗网格 + 人工检查。** 关键参数不多（MACD 三参、ADX 阈值、组合得分/票数阈值、止损比例），粗网格完全够用，且结果可读。
- **P2：贝叶斯优化**（来源文档提及，用高斯过程 + EI）。只有在参数维度真的上去、且已建立可信的验证集流程后才引入——否则更高效的搜索只会更快地过拟合。

**过拟合红线**：
- 参数敏感性检查：最优参数邻域（±20%）的绩效若断崖下跌，说明是噪音峰值，不采用。
  **2026-08-13 起自动判**：同一维度上取值相邻的候选互为邻域（出厂值那一行天然是
  OFAT 候选的一侧邻居），任一侧的邻居掉到不足一半即标「孤峰」，落在网格边界则标
  「该侧邻域未测」。这两条以前都要人工看表，而 §5.14 的 `voteThreshold.trend = 4`
  正是靠人工看表才没被写回的
- 分年度稳定性：若某年绩效为负且幅度大，标注为「该策略在某类行情下失效」，写进文档而非藏起来
- 交易次数下限：全样本交易 < 30 笔的参数组，统计上无意义，直接淘汰
- **训练集年化为负者直接淘汰**（2026-08-12 加）：排名口径是验证集 Calmar，这是对的
  （用训练集排名等于直接过拟合），但它有个盲区 —— 一个在 6 年训练窗口里亏钱、
  却在 18 个月验证窗口里赚钱的候选会排到很前面。那不叫稳健，叫验证窗口正好友好。
  实例见 [M2 §5.14](./notes/M2-偏差报告.md)（`voteThreshold.meanReversion = 1`：
  训练 −3.73% / 验证 +2.77%，原先三条红线一条都拦不住，排第 2）。

> **跨段比 Calmar 时要知道一件事**（2026-08-12）：`--grid` 的每一段都带着完整段前历史做预热
> （否则测试集短于 300 根预热就永远 0 笔），2026-08-12 前分段绩效连预热段的净值点一起算，
> 于是验证集的年化被压小 5.1 倍、基准收益取的是全程涨跌（**符号都是反的**）。
> 已修（净值按 `split.from` 切回本段）。**残留**：训练集的起点就是数据起点，
> 头 300 根预热死区仍算在训练段内（占 21%），使训练集 Calmar 系统性偏低约 1.26 倍 ——
> 这是训练窗口的真实属性不是记账错误，但它让「衰减 > 50%」这条红线更不容易触发。

## 4. 数据质量校验

回测结论的可信度上限由数据质量决定。入库前置检查：

| 检查 | 处理 |
|---|---|
| 日期缺口（相邻两根跨越交易日 > 1） | 标记 `has_gap`，回测时该段跳过 |
| 价格逻辑错误（`high < low`、`close` 越界） | 丢弃该根并告警 |
| 零成交量非停牌 | 标记可疑 |
| 相邻收盘价跳变 > 20%（非除权、非涨跌停板放开） | 标记可疑，人工确认 |
| 复权因子突变 | 触发该标的日线全量重拉 |
| 多源比对偏差 > 1% | 记录到 `provider_health` |

## 5. 测试组织

```
tests/
├─ unit/
│  ├─ indicators/          每个指标：黄金用例 + 边界 + 属性测试
│  ├─ regime/              状态分类与迟滞
│  ├─ strategies/          场景 fixture → 断言 SubSignal ID 集合
│  ├─ combine/             等权汇总与投票的组合逻辑
│  └─ risk/                风控规则表驱动测试
├─ integration/
│  ├─ providers/           用录制的 HTTP 响应 fixture 回放，验证解析与降级
│  ├─ storage/             迁移、裁剪、并发读写
│  └─ engine/              端到端：fixture 日线 → 信号，快照断言
├─ e2e/                    Playwright + Electron：窗口创建、点击穿透、气泡淡出
└─ fixtures/
   ├─ klines/              各类形态样本（金叉放量、假突破、震荡、连续跌停）
   ├─ providers/           各数据源原始响应快照
   └─ golden/              指标期望值
```

**CI 门槛**：`src/core` 行覆盖率 ≥ 90%（这是全部策略逻辑所在），其他目录 ≥ 60%。

## 6. 验收：软件本身的正确性

除了策略绩效，还需验证软件行为。手工验收清单（每次发版执行）：

- [ ] [06 §1](./06-桌宠交互与非干扰设计.md) 的 C1–C10 十条零干扰契约逐条通过
- [ ] 断网 5 分钟：桌宠进入 OFFLINE，无弹窗报错，恢复网络后自动重连
- [ ] 主数据源返回畸形 JSON：自动切备源，面板可见降级记录
- [ ] 系统时间跨越 15:00：确认轮正确触发，PROVISIONAL 信号被升级或作废
- [ ] 休眠 8 小时后唤醒：定时器恢复，补一次全量刷新，无重复提醒轰炸
- [ ] 自选股 100 只满载：单 tick 耗时 < 1s，内存不超预算
- [ ] 删除 `market.db` 后启动：自动重建，不崩溃
- [ ] 数据库为上一版本 schema：迁移成功，备份文件生成
