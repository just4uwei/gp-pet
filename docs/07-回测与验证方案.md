# 07 · 回测与验证方案

## 1. 为什么回测是 P0 的前置条件

来源文档给出的所有绩效数字（年化 17.33%、信息比率 1.96、胜率 58%、组合年化 21.47% 等）**均引自网络文章，无数据、无代码、无法复现**。把它们当作既成事实去设定出厂参数，等于把用户的钱押在无法验证的转述上。

因此本项目的立场是：

> 来源文档提供的是**规则结构**（哪些指标、如何组合、如何切换权重），这部分是有价值的。
> 它提供的**具体数值**（12/17/9、ADX 25、8% 止损、0.6 阈值）一律视为**待标定的初始猜测**，出厂默认值必须由本地回测产出。

回测 CLI 因此不是「锦上添花的 P2 功能」，而是决定默认参数的工具，需要在 M2 阶段就可用。

## 2. 三层验证

### 2.1 第一层：指标正确性（单元测试）

指标算错，后面全是空中楼阁。

**交叉验证方法**：取一段真实日线（沪深300 成分若干只，各 500 根），用三方独立实现计算同一指标并比对：

| 参照 | 用途 |
|---|---|
| Python `pandas-ta` / `TA-Lib` 脚本（`scripts/verify/`） | 主要参照，尤其是 Wilder 平滑类（ADX、RSI）易错 |
| 行情软件截图人工抽查 | 校验国内口径差异（MACD 柱是否 ×2、STD 是否除 n） |
| 手算 | 前 3 个值，验证种子值与预热逻辑 |

容差：`|ours - ref| / |ref| < 1e-6`（EMA 类因种子差异可能在前若干根偏离，只比对预热期之后）。

比对脚本产出的期望值固化为 `tests/fixtures/golden/*.json`，成为回归基线。

### 2.2 第二层：策略回测（CLI）

```bash
pnpm backtest --codes SH600000,SZ000001 --from 2020-01-01 --to 2026-06-30 \
              --params ./params/candidate-a.json --out ./reports/a.json
```

**回测引擎设计要点**（每一条都是常见的自欺来源）：

| 陷阱 | 对策 |
|---|---|
| 未来函数 | 引擎只允许访问 `candles[0..i]`；用 `Object.freeze` + 切片传入，禁止把完整数组给策略函数 |
| 信号当日成交 | 信号在第 `i` 根收盘产生 → 成交价用第 `i+1` 根**开盘价**，不用当日收盘价 |
| T+1 | 买入后至少持有到下一交易日 |
| 涨跌停无法成交 | 次日开盘价触及涨跌停则该笔交易作废（买入跳过，卖出顺延） |
| 复权 | 全程用 `*Adj` 序列（**回测 fixture 里是后复权**，2026-08-12 换的 —— 腾讯的前复权是加性的、高分红股会变负）；收益率因此已含除权影响。⚠ 后复权价可达真实价的一两百倍，见下面那条 |
| 交易成本 | 佣金双边万 2.5（最低 5 元）+ 卖出印花税千 1 + 过户费万 0.1，可配置 |
| 滑点 | 默认 0.1%，可配置 |
| 幸存者偏差 | 标的池由用户自选股决定，本身就有偏差 → **报告中明确标注「本回测不代表全市场表现」** |
| **买不起一手** | ⚠ **已知缺陷，未修**（2026-08-19，[M2 §5.40](./notes/M2-偏差报告.md)）：`--capital` 默认每标的 10 万，而手数按**后复权价**算 —— 平安银行 2018 年一手 20.7 万 ⇒ `lotsAffordable` 返回 0 手，整段一笔不建仓，报告上只显示「0 笔」，与「引擎没给信号」无法区分。主池 261 只里 10 只受影响（1.48% 的标的·交易日），命中的是分红历史最长的大盘股 |

**输出指标**：

```
总收益 / 年化收益 / 基准（沪深300）超额（**减法版 + 除法版两个**）/ **平均资金占用率 + beta**
最大回撤 / 回撤持续天数
逐笔：胜率 / 盈亏比 / 平均持仓天数 / 卖出次数
建仓：**建仓级胜率** / 盈亏比 / 平均每次盈亏 / 中途减仓次数     ← 用户口径
夏普比率 / 信息比率
逐笔交易明细（含触发的子信号 ID，用于归因）
离场规则分布（是策略在卖还是风控在卖）
按 Regime 分组的绩效（趋势市 vs 震荡市，看引擎在哪种状态下有效）
```

> ⚠ **夏普与主流口径差近一倍，只能当内部排序量**（2026-08-19 对照，[M2 §5.39](./notes/M2-偏差报告.md)）。
> 与聚宽（国内平台通行定义）逐条比：**最大回撤、年化公式、日收益标准差三项同口径**；
> 夏普有两处实质差异且同向叠加 —— 无风险利率 **0 vs 0.04**、分子 **日均×√243 vs 年化几何收益**。
> 拿沪深300 被动持有量：2005–2017 我们 **0.533**、主流 **0.281**；2018–2023 我们 **−0.054**、主流 **−0.355**。
> **算法不改**（夏普不参与任何门槛，排名口径是 Calmar），但**一句话都不许拿它与外部策略的夏普横比**。
> 年交易日 243 vs 惯例 250 也差 2.8%，方向保守且 243 更接近 A 股实际，不改。

> ⚠ **超额收益有两个口径，引用时用除法版**（2026-08-19 加，[M2 §5.41](./notes/M2-偏差报告.md)）。
> 减法版 `Rp − Rm` 在基准涨幅大的窗口上给出读不出意思的数（单指数 2005–2017：**−277.56%**），
> 除法版 `(1+Rp)/(1+Rm) − 1` 是 **−69.10%** = 策略净值只有被动持有的 30.9%。
> 两个并存是刻意的：历史上所有引用过的数字都是减法版。
> **beta 紧挨着平均资金占用打印**，它们是「暴露多少」的两种量法（实测逐份同向）——
> 而 **CAPM alpha 与日胜率刻意不做**：前者的符号由 `Rf` 决定（低暴露策略上 rf=0 与 rf=4%
> 结论相反），后者约等于「基准下跌天数占比」⇒ 零信息。两个都在
> `scripts/verify/jq-riskmetrics.mjs` 里可以按需算出来看，**但不进报告、不进任何门槛**。

> **「胜率」有两个口径，报告两个都打，不要混用**（2026-08-13 加）。
> 一行 `trade` 是**一次卖出**，而回撤减仓 / 部分止盈会把一次建仓拆成两三行。于是：
> - **逐笔胜率**回答「每一次卖出动作赚不赚」—— 看止损止盈规则本身用它；
> - **建仓级胜率**（按 `code + entryDate` 归并）回答「我按提醒买了一次，最后赚没赚」
>   —— **这是用户体验到的那个数**，也是「提高胜率」该盯的目标。
>
> 实测出厂参数下两者是 **33.16%** 与 **49.28%**，差 16 个百分点。
> 同一个原因还制造过一处**符号错误**：分 Regime 归因里的「平均」曾是逐行未加权的
> 百分比平均，于是四种市况全打 −1.2% ~ −1.6%，而净盈亏是 **+231,154 元** ——
> 半仓那一行和满仓那一行被等同看待了。已改为**按仓位加权**（`weightedPnlPct`）。
> 详见 [M2 §5.18](./notes/M2-偏差报告.md)。

> **「超额」不能单独读，必须和「平均资金占用率」一起读**（2026-08-12 加）。
> 基准是 100% 满仓的指数买入持有，而信号策略绝大多数时间空仓 ——
> 实测出厂参数下平均资金占用只有 **4.15%**，同期超额 −8.17pp，但最大回撤是
> 2.44% vs 基准的 45.60%，Calmar 0.275 vs 0.034。**风险调整后方向是反过来的。**
> 所以文本报告把占用率打印在超额那一行的正下方，`performance.exposure` 也进了 JSON。
> 反过来「按占用资金折算成年化 10.8%」同样不许拿去说事，理由见
> [M2 §5.13](./notes/M2-偏差报告.md)。

最后一项尤其重要：整套设计的核心假设是「按市场状态切换策略权重能提升表现」。如果分组绩效显示切换后并不优于固定权重，这个假设就该被推翻，而不是保留一套复杂而无效的机制。

> **这个假设已经被推翻了（2026-08-12）**：两轮对照（第一轮带口径 bug、第二轮解耦后）
> 都看不出动态权重优于固定 0.5/0.5，于是 `params.weights` 整张表连同回测里的固定权重对照组
> 一起删除，两个策略改为等权。上面那句话保留在这里不是历史遗迹，而是**这条判据的用法示范**：
> 下一次再想加「按状态切换某某」之前，先说清楚拿什么对照、多大差值才算有效。
> 全部数字见 [M2-偏差报告 §5.5–§5.8](./notes/M2-偏差报告.md)。

**策略消融**：要回答「某个策略到底贡献了几笔交易」，用 `params.enabledStrategies`
（`{ trend, meanReversion }`，出厂两项皆 `true`），经 `--params` 传入即可：

```bash
pnpm backtest -- --codes ... --fixtures ./data/history \
              --params ./reports/probe/abl-trend.json    # {"enabledStrategies":{"trend":true,"meanReversion":false}}
```

**不要用「把权重设成 0」代替它**：组合层的票数不分策略，权重 0 的策略得分贡献是 0、票照投，
测出来的是「关掉得分、留着票」。它是测量工具不是可标定参数，标定网格不得把它当维度扫。
实测结论见 [M2-偏差报告 §5.7](./notes/M2-偏差报告.md)。

### 2.3 第三层：影子运行（Paper Trading）

回测好看不代表实盘可用。软件内置**影子模式**（M4 落地，`src/main/shadow/`）：

- 每条**收盘确认**信号自动记录「若按此信号操作」的模拟持仓
- 面板展示模拟组合的累计收益、两个口径的胜率、最大回撤、平均资金占用 + **beta**
  （2026-08-20 加，与回测报告同口径 —— 两边量的是同一件事，各写一份口径就再也对不上）
- 与同期沪深300 对比。⚠ **面板刻意不算两者的差值**（基准满仓、策略绝大多数时间空仓，
  两个收益率不在同一个分母上）—— 所以**除法版超额在影子这边不给**，
  给了就等于把回测报告里那条「必须与占用率同框」的警告丢在半路上
- 运行满 3 个月前，UI 上对策略绩效**不做任何正面宣称**

影子运行的数据是本地的、真实前向的，比任何历史回测都可信 —— **前提是它真的是前向的**。
这一条不是自动成立的，四条纪律因此写进了代码而不只是文档：

1. **不补跑历史。** 只处理「今天」这一根，永远看不到明天。拿三年前的 K 线把影子曲线
   补长，那不是影子运行，是回测 —— 而它会带着一份看起来像实盘的报告。
2. **成交价用次日开盘**（与 §2.2 的回测同源）。T 日收盘确认的信号在 T+1 开盘成交。
   用当日收盘价成交会凭空多出一段收益：15:00 之后的收盘确认轮里那个价格已经买不到了。
3. **成本照扣**，复用回测那一套（双边佣金 + 印花税 + 过户费 + 0.1% 滑点）。
   来回摩擦约 0.3%，不扣成本的影子绩效不是乐观，是错的。
4. **只吃 CONFIRMED。** 盘中 PROVISIONAL 信号会随最后一根临时 K 线抖动、还可能在收盘轮
   被判 INVALIDATED，按它下单会把**提醒层的抖动**记成**策略的绩效**。

**引擎参数一变就停止累积**（不是继续）。混进去的曲线不属于任何一套参数，
而它无法事后拆开 —— 历史 K 线能重算回测，重算不出前向记录。
UI 会显示「已暂停」并让用户二选一：改回原档位继续，或清空重开（走系统确认框，
默认按钮是取消）。

**记账口径**：一个现金池（起始 100 万）+ 每笔固定名义金额（10 万，与回测的
`capitalPerCode` 对齐、逐笔可比）。回测那边是「每只标的一份等额独立资金」，
影子不能这么记 —— 自选股随时增删，按标的分账会让净值曲线的分母自己在动。
钱不够就不开仓并计一次 `skippedNoCash`，**那个计数必须显示**：
静默跳过会让「信号密集期的收益」凭空消失而报告上看不出来。

**两个胜率口径都给且都标明**（M2 §5.18 的同一件事）：一行 `shadow_trade` 是**一次卖出**，
回撤减仓会把一次建仓拆成两三行，实测两者能差 16 个百分点。
用户体验到的是建仓级（「我按提醒买了一次，最后赚没赚」），所以那一档是主口径。

**超额收益必须与平均资金占用率同框**。基准是满仓的，信号策略绝大多数时间空仓
（回测里实测平均占用只有 4.15%），只看超额会把方向读反（M2 §5.13）。
影子这边的占用率是从**逐日**净值曲线直接算的，比回测那个按建仓价的近似更准。

#### 2.3a 「它到底在不在跑」必须答得出来（2026-08-19）

前四条纪律保证了影子是**可信的**，但它们答不了一个更基础的问题：**它在跑吗？**
真机上跑了两个交易日之后，面板上只有一个「待成交 2」的数字 —— 哪两只、什么规则、
除此之外今天做了什么，全都没有出处。而**全空仓时净值曲线是一条 1000000 的直线，
与「压根没推进」长得一模一样**。

三处补上：

1. **逐日操作流水**（`shadow_journal`，013）：挂单 / 建仓 / 平仓 / 作废 / 顺延 /
   移出自选而了结 / **整轮没推进**，一行一个动作。委托一旦成交 `clearOrder` 就把它删了，
   所以**只靠现有三张表事后拼不出「那天挂了哪两单」** —— 这张表是它唯一的出处。
   它与 `shadow_trade` / `shadow_equity` 同一档：**不进裁剪**（前向记录重建不出来）、
   **不加指向 `signal(id)` 的外键**（那等于把它挂在日志的保留策略上）。
2. **`NOT_ADVANCED` 这一档最值钱**：用户下午才开机时，收盘确认补跑那一刻「次日开盘」
   已经过去，按前向纪律**不喂影子**（`engine/tick.ts` 的 `feedShadow`）⇒ 那一个交易日
   永远不会被推进，净值曲线上是个洞。此前这件事只在主进程日志里出现一行。
3. **运行状态**：最后推进到哪天 + 最后一个已收盘交易日 + 待成交委托的明细。
   ⚠ 面板**不许**把「落后一天」显示成告警：影子按次日盘前推进，正常就晚一天。

#### 2.3b 基准列的回填不算破纪律（2026-08-19）

`shadow_equity.benchmark` 曾经 2/2 行都是 null：推进与日线回补在同一跳里，
回补先失败（腾讯对指数结构性没有复权轨、eastmoney 又是间歇性的），0.24 秒后推进就读到 null；
当天晚些时候 kline 补上了，但那一天不会再推进 ⇒ 永久留 null。
而 `summarize()` 的 `lastBenchmark` 取**最后一行** ⇒ 只要收尾那天是 null，整条同期对比就是 null。

现在每次推进会把历史上 `benchmark IS NULL` 的行补齐。**这不是「补跑历史」**：
第 1 条纪律管的是信号、委托与成交 —— 它们必须按真实时间往前走；而沪深300 在某一天的收盘价
是一个**与我们的决策无关的事实**，当时没有它只是取数失败，不是「那天还不知道」。
两者混为一谈会让这条修复看起来像在破纪律，所以写在这里。

## 3. 参数标定流程

```
① 划分数据：训练集 2018-01 ~ 2023-12，验证集 2024-01 ~ 2025-06，测试集 2025-07 ~ 至今
② 在训练集上搜索参数（下节）
③ 在验证集上筛掉过拟合候选（训练集表现好、验证集崩掉的直接淘汰）
④ 测试集只跑一次，作为最终报告，不允许据此回头调参
⑤ 入选参数写入 src/core/params.ts，engine_version +1，并在 CHANGELOG 记录标定依据
```

> ④ 曾经有一个**工具层的缺口**：`pnpm backtest --grid` 每次调用都会对**该次**的优胜者
> 跑一遍测试窗口。于是「测试集只跑一次」在实操上等于「**只准跑一轮网格**」——
> 一旦发现最优点落在网格边界、需要扩网格重跑，测试窗口就被多看了一次。
> 2026-08-12 标定 R1–R4 时就发生了这件事（两轮网格 × 两种基线 = 四次），
> 处理方式是**如实记下来，并只按训练集 + 验证集下结论**
>（[M2-偏差报告 §5.10](./notes/M2-偏差报告.md)）。设计网格时先把取值范围想宽一点，
> 比事后补跑便宜。
> **已修**（2026-08-13）：测试段改成显式开关 `--touch-test`，默认不跑。
> 前 5 次触碰里几乎每一次的优胜者最后都没被采用 —— 也就是说测试窗口是白烧的。
> **累计触碰次数：5 次**（R1–R4 四次 + `combine` 块一次，后者的优胜者已按孤峰判掉、
> 测试块不作为结论，见 [§5.14](./notes/M2-偏差报告.md)）。加一次就在这里改这个数。

### 3.1 判据：与出厂值配对比较，三态裁决

**这一节是 2026-08-13 补的，起因是这套流程跑了十一轮只写回了一个参数**
（[M2 §5.15](./notes/M2-偏差报告.md)）。每一轮的形状都一样：工具按验证集 Calmar 报出一个
优胜者，人看完表判定它是「孤峰」或「验证窗口正好友好」，然后否掉。也就是说
**真正在做决策的判据不在工具里**——唯一被写回的 `strategy.squeezeBbwPct` 靠的是人工
认出「16–30 是一整片高原」并核对两种基线，而不是工具排名的第一名（那是 30，被否了）。

所以「谁的分数最高」不是可用的判据。现在的判据是三件事：

1. **出厂值永远是候选之一，所有比较都与它配对。** 输出不再是「优胜者是 X」，
   而是「X 相对出厂值的改进是 Δ，可分辨 / 不可分辨」—— 后者才是能据以决定
   「改不改 `params.ts`」的形式。
2. **每个候选有一组折上的分数，不是一个点估计。** 同一次模拟按
   **标的子集 × 判定窗口内的时间片**切成折单元（默认 4 × 3 = 12 折，
   `--code-folds` / `--time-slices` 可调），逐折与出厂值配对求差：
   `Δ均值 ± 标准误`。项目一直在口头上用的「±1pp 噪音带」「正负交替 = 噪音」
   由此变成算出来的量。**折是切出来的、不是重跑的**，所以加折不加耗时。
   两个方向都要：横截面折答「换一批标的会不会翻盘」，时间片答「换一段行情会不会翻盘」，
   §5.14 定不下来的两个原因正好各占一个。
   **折上比的量是本折总收益，不是 Calmar** —— 一折只有 ~10 只 × ~120 根，
   最大回撤能小到 0.3%，Calmar 的分母趋零就炸（实测折间标准误 2.07，而整池 Calmar 才 0.427）。
   用总收益还有个附带好处：单位与 §5.5–§5.13 所有消融结论一致，可以直接对比。
   风险调整没丢，它在红线、排名（整池 Calmar）和写回门槛第 ① 条里。

   > **⚠ 判据用的 t 是「按时间片聚类的稳健值」，不是朴素的 `stdev(Δ)/√n`**（2026-08-19 改）。
   >
   > 病根：`√n` 收敛只在**折相互独立**时成立，而 12 折是**从同一次模拟里切出来的** ——
   > 同一时间片里的不同标的子集共享市场 beta（A 股同涨同跌）⇒ 标准误偏小 ⇒ t 偏乐观。
   > 现在改成均值的 CR1 聚类稳健估计，聚类单位 = 时间片：
   > `Var = G/(G−1) × (1/N²) × Σ_c (Σ_{i∈c} (d_i − mean))²`。
   > 等大簇时它化简为 `stdev(簇均值)/√G` —— 一句话：**横截面折不再贡献 √n**，
   > 多切标的子集只让每片更稳，**不增加独立样本数**。
   >
   > 报告同时给出朴素值并标着「未调整上界」，且**每次都印**调整状态
   > （有条件地印等于让「没印」重新变成一种可能，那正是这次要修的报告缺陷）。
   >
   > **仍然偏乐观，别写成「已经修好了」**：时间片之间也不独立（片连续、持仓跨片重叠），
   > 聚类只掐掉横截面那一层；彻底做要按时间片整块重抽的 block bootstrap，**未做**。
   > 另外**簇数默认只有 3（`--time-slices`）⇒ 自由度 2**，此时 `t ≥ 2` 的保证远弱于
   > 大样本直觉 —— 报告会把簇数与这句话一起印出来。
   >
   > 实验与全部数字见 [M2 §5.36](./notes/M2-偏差报告.md)，
   > 结案与未完成项见 [迭代计划 §4.6](./notes/下一阶段取舍与迭代计划.md)。
3. **裁决三态**：
   | 裁决 | 含义 | 该做什么 |
   |---|---|---|
   | `WRITE_BACK` | 有挑战者稳定优于出厂值且邻域是高原，三条同时成立：① 整池验证集 Calmar 不低于出厂值 ② 至少 3 折真被改动 ③ `\|Δ\|/标准误 ≥ 2` 且**受影响的折**里 ≥ 2/3 为正 | 走 ⑤，人工复核后写回 |
   | `KEEP` | **出厂值站得住** —— 没有挑战者的改进大于它自己的折间抖动 | **这是结论**。记进偏差报告，该参数归档为「已测、保持出厂值」（清单 4.9c） |
   | `INCONCLUSIVE` | 出厂值自己被红线淘汰，或折数不足以估离散度 | 先解决红线原因或折数，不下任何结论 |

   ② 与「受影响的折」这个口径是必要的：**改一个参数通常只动少数几折**
   （实测 `scoreThreshold` 0.55 只动了 12 折里的 5 折，`downtrendBuyPenalty` 一折都没动）。
   胜率若按总折数算，这类候选永远够不着 2/3 —— 那会把「影响面小但方向一致」
   误判成「无效」。

`KEEP` 时报告给出 `resolution.requiredClusters`：**要让已观测到的这个 Δ 变得可分辨，
大约需要多少个独立时间片**。这把「定不下来」变成一句可执行的话 —— 要么扩到那个量级，
要么承认这个参数在当前数据量下不可标定（按 M2 清单 4.9c 归档，不再反复重跑）。

> ⚠ **单位是「时间片」不是「折」**（2026-08-19 改，与聚类标准误同一次）。
> 旧字段 `requiredCells`（朴素口径）保留但**只为与历史报告可比，它系统性偏小**。
> 差别是可执行性上的：**多切横截面折降不了这个数**，只有拉长窗口才增加时间片。

> 单折的绩效**不可**与整池绩效横向比较（窗口短、标的少、回撤分母小），
> 也不可单独引用。它只有一个用途：同一折上两个候选之差。

**搜索方法**：

- **首版：粗网格 + 人工检查。** 关键参数不多（MACD 三参、ADX 阈值、组合得分/票数阈值、止损比例），粗网格完全够用，且结果可读。
- **P2：贝叶斯优化**（来源文档提及，用高斯过程 + EI）。只有在参数维度真的上去、且已建立可信的验证集流程后才引入——否则更高效的搜索只会更快地过拟合。

**过拟合红线**：
- 参数敏感性检查：最优参数邻域（±20%）的绩效若断崖下跌，说明是噪音峰值，不采用。
  **2026-08-13 起自动判**：同一维度上取值相邻的候选互为邻域（出厂值那一行天然是
  OFAT 候选的一侧邻居），任一侧的邻居掉到不足一半即标「孤峰」，落在网格边界则标
  「该侧邻域未测」。这两条以前都要人工看表，而 §5.14 的 `voteThreshold.trend = 4`
  正是靠人工看表才没被写回的
- 分年度稳定性：若某年绩效为负且幅度大，标注为「该策略在某类行情下失效」，写进文档而非藏起来
- 交易次数下限：全样本交易 < 30 笔的参数组，统计上无意义，直接淘汰
- **训练集年化为负者直接淘汰**（2026-08-12 加）：排名口径是验证集 Calmar，这是对的
  （用训练集排名等于直接过拟合），但它有个盲区 —— 一个在 6 年训练窗口里亏钱、
  却在 18 个月验证窗口里赚钱的候选会排到很前面。那不叫稳健，叫验证窗口正好友好。
  实例见 [M2 §5.14](./notes/M2-偏差报告.md)（`voteThreshold.meanReversion = 1`：
  训练 −3.73% / 验证 +2.77%，原先三条红线一条都拦不住，排第 2）。

> **跨段比 Calmar 时要知道一件事**（2026-08-12）：`--grid` 的每一段都带着完整段前历史做预热
> （否则测试集短于 300 根预热就永远 0 笔），2026-08-12 前分段绩效连预热段的净值点一起算，
> 于是验证集的年化被压小 5.1 倍、基准收益取的是全程涨跌（**符号都是反的**）。
> 已修（净值按 `split.from` 切回本段）。**残留**：训练集的起点就是数据起点，
> 头 300 根预热死区仍算在训练段内（占 21%），使训练集 Calmar 系统性偏低约 1.26 倍 ——
> 这是训练窗口的真实属性不是记账错误，但它让「衰减 > 50%」这条红线更不容易触发。

### 3.6 判定逻辑改动的验收门槛（2026-08-15 立）

> 上面 §3.1–§3.5 管的是**调参**（同一套逻辑换一个数）。
> 这一节管的是**改判定逻辑**（约束 5 / ADR-0003 要求先论证的那一类）。
> 两者的判据不能共用 —— 逻辑改动会改变交易的**集合**，而配对 Δ 的前提是两边测同一批东西。
>
> 立这一节的直接原因：[下一阶段取舍与迭代计划](./notes/下一阶段取舍与迭代计划.md)
> §1.1 拍板题 B 授权了第一次判定逻辑改动。**门槛必须先于改动写下来**，
> 改完再定就是自己给自己找台阶。

**四条一起卡，缺一不可**（2026-08-20 加了第 ⑤ 条「报分位必须写明零点定义」，
它挂在 ④ 那一节里，因为它管的是 ④ 用的那个数怎么才算成立）。

#### ① 先有论证，再有代码

改动的交易含义要先写进 docs/04（或 docs/05），**包含「这条论证可能错在哪」**。
一条只能事后解释、无法事先陈述的规则，与对着数据刻出来的规则在形式上无法区分。

#### ② 建仓数下降不得超过 15%

在一个整体亏钱的系统上，**任何减少交易的改动都会机械地改善绩效**
（§5.20 ⑦ 里八张网格几乎所有「改善」都来自建仓数下降 20–35%）。
报告必须同时给出改动前后的建仓数。

#### ③ 建仓级胜率不降

口径是 `groupPositions()` 的建仓级，不是逐笔（两者差 16pp，§5.18）。
并且**「提高胜率」不能单独当目标** —— 把 `profitProtectTrigger` 调低能机械做到
70% 胜率同时把盈亏比压到 0.5。

#### ④ alpha 上移，**且在独立子集上稳定** ← 这一条是新的

主判据是 `pnpm audit:random --match-regime --shuffle-spans` 的**配对胜率**。
它是唯一一个不受「少做」、beta、单笔妖股、`holdingBars` 内生性四种污染的量。

> **⚠ 零分布的时间结构（2026-08-19 加，迭代计划 §4.6）**。
>
> 真实建仓**不是独立发生的** —— 引擎在同一段行情里成批出手。零分布若逐次独立抽日就把
> 这种聚集打散了，方差偏小 ⇒ **分位偏向显著**。默认因此改成**按建仓月整块位移**。
>
> 实测（三种子、1675 次建仓）：**无条件口径下块位移是精确的**（吸附距离恒 0），
> 配对胜率 ALL 46.5 → 55.5 · TREND_UP 36.7 → 43.2 · TRANSITION 24.7 → 38.5
> —— 四层一致朝 50% 走，**旧分位确实偏向显著**。
>
> **`--match-regime` 那一档 2026-08-20 换成了 `REGIME_BLOCK`**（块 = 标的 × 一段连续
> 同状态行情，整段刚性平移到同状态的另一段 ⇒ 吸附恒 0，覆盖 99.8%）。
> 旧的「自动降级回独立抽日」已取消，`--independent-days` 仍可复现旧口径。
> 见 [M2 §5.36](./notes/M2-偏差报告.md) 与 [§5.42](./notes/M2-偏差报告.md)。
>
> **⑤ 报分位必须写明零点定义 —— 这是 2026-08-20 加的第五条门槛，与上面四条同级。**
>
> 实测同一批建仓、同一套参数，只换零点定义，ALL 的配对胜率是
> **46.5%**（独立抽日 · 同 regime）· **55.5%**（建仓月块 · 无条件）· **36.5%**（段块 · 同 regime）
> —— 跨度 **19pp**，比任何一次判定逻辑改动的效应都大。
> ⇒ **一份验收报告里的分位，若没写清零点定义，那个数不成立**；
> 改动前后**必须用同一个零点**比（跨零点的比较一律无效）。
> 而且那次换零点的实测还说明：新旧零点的差别**不只是方差，还有成分**
> （随机组 sd 几乎没动、均值上移）⇒ **不许把任何一档说成「才是对的」**。

> **⚠ 但它对「砍掉一批交易」类的改动有盲区，必须补一条。**
>
> **砍掉一批已知负 alpha 的交易，必然提升剩余部分的 alpha —— 那是算术，不是发现。**
> 主判据因此无法区分「找对了一个机制」与「删掉了任何一批差交易」。
> 这与「改善不能靠少做」是同一形状的陷阱，只是上升了一层：
> 那一条防的是绝对收益被少做污染，这一层里 **alpha 本身也会被选择性删除污染**。
>
> **补的这一条**：规则命中的那批交易，必须在**独立于规则推导过程的子集**上也显著更差。
> 最低限度是四个切法（代码前半 / 代码后半 / 时间前段 / 时间后段），
> 每一个子集上「命中批 vs 该子集基线」的差距都要同向且量级接近。
> 若某个子集上差距接近 0，说明规则抓的是某段特定行情而不是机制 —— **不予采纳**。
>
> 这条判据是怎么来的：候选「TREND_UP 持续 ≥ 11 根不买」在总量上看很好
> （砍 3.8%、命中批 −1.33%），但按时间切开之后 2022-07 之后的差距只剩 **−0.26pp**
> （而 2022 前是 −3.30pp，相差 12 倍）—— 它的效应几乎全部来自早期 23 笔。
> 光看总量数字完全看不出来。见 [M2 §5.23](./notes/M2-偏差报告.md)。

#### 一条程序纪律：**每个候选机制只报一次分位**

不许反复微调到分位达标为止 —— 那等于把随机基准变成一个新的过拟合目标，
而它是目前唯一可信的判据，污染了就没有替代品。
调整了就是一个**新候选**，要重走 ①–④，并在偏差报告里记成两条而不是一条。

#### 不适用的东西

- **配对 Δ / `|Δ|/stderr ≥ 2`**：那套判据的前提是两个候选测同一批交易，
  逻辑改动不满足这个前提。
- **训练集 Calmar ≤ 0 红线**：它是**候选参数**的淘汰线。逻辑改动的目的恰恰是
  让基线转正，拿它卡自己没有意义。

## 4. 数据质量校验

回测结论的可信度上限由数据质量决定。入库前置检查：

| 检查 | 处理 |
|---|---|
| 日期缺口（相邻两根跨越交易日 > 1） | 标记 `has_gap`，回测时该段跳过 |
| 价格逻辑错误（`high < low`、`close` 越界） | 丢弃该根并告警 |
| 零成交量非停牌 | 标记可疑 |
| 相邻收盘价跳变 > 20%（非除权、非涨跌停板放开） | 标记可疑，人工确认 |
| 复权因子突变 | 触发该标的日线全量重拉 |
| 多源比对偏差 > 1% | 记录到 `provider_health` |
