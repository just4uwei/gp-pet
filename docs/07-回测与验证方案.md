# 07 · 回测与验证方案

## 1. 为什么回测是 P0 的前置条件

来源文档给出的所有绩效数字（年化 17.33%、信息比率 1.96、胜率 58%、组合年化 21.47% 等）**均引自网络文章，无数据、无代码、无法复现**。把它们当作既成事实去设定出厂参数，等于把用户的钱押在无法验证的转述上。

因此本项目的立场是：

> 来源文档提供的是**规则结构**（哪些指标、如何组合、如何切换权重），这部分是有价值的。
> 它提供的**具体数值**（12/17/9、ADX 25、8% 止损、0.6 阈值）一律视为**待标定的初始猜测**，出厂默认值必须由本地回测产出。

回测 CLI 因此不是「锦上添花的 P2 功能」，而是决定默认参数的工具，需要在 M2 阶段就可用。

## 2. 三层验证

### 2.1 第一层：指标正确性（单元测试）

指标算错，后面全是空中楼阁。

**交叉验证方法**：取一段真实日线（沪深300 成分若干只，各 500 根），用三方独立实现计算同一指标并比对：

| 参照 | 用途 |
|---|---|
| Python `pandas-ta` / `TA-Lib` 脚本（`scripts/verify/`） | 主要参照，尤其是 Wilder 平滑类（ADX、RSI）易错 |
| 行情软件截图人工抽查 | 校验国内口径差异（MACD 柱是否 ×2、STD 是否除 n） |
| 手算 | 前 3 个值，验证种子值与预热逻辑 |

容差：`|ours - ref| / |ref| < 1e-6`（EMA 类因种子差异可能在前若干根偏离，只比对预热期之后）。

比对脚本产出的期望值固化为 `tests/fixtures/golden/*.json`，成为回归基线。

### 2.2 第二层：策略回测（CLI）

```bash
pnpm backtest --codes SH600000,SZ000001 --from 2020-01-01 --to 2026-06-30 \
              --params ./params/candidate-a.json --out ./reports/a.json
```

**回测引擎设计要点**（每一条都是常见的自欺来源）：

| 陷阱 | 对策 |
|---|---|
| 未来函数 | 引擎只允许访问 `candles[0..i]`；用 `Object.freeze` + 切片传入，禁止把完整数组给策略函数 |
| 信号当日成交 | 信号在第 `i` 根收盘产生 → 成交价用第 `i+1` 根**开盘价**，不用当日收盘价 |
| T+1 | 买入后至少持有到下一交易日 |
| 涨跌停无法成交 | 次日开盘价触及涨跌停则该笔交易作废（买入跳过，卖出顺延） |
| 复权 | 全程用前复权序列；回测报告中的收益率因此已含除权影响 |
| 交易成本 | 佣金双边万 2.5（最低 5 元）+ 卖出印花税千 1 + 过户费万 0.1，可配置 |
| 滑点 | 默认 0.1%，可配置 |
| 幸存者偏差 | 标的池由用户自选股决定，本身就有偏差 → **报告中明确标注「本回测不代表全市场表现」** |

**输出指标**：

```
总收益 / 年化收益 / 基准（沪深300）超额
最大回撤 / 回撤持续天数
胜率 / 盈亏比 / 平均持仓天数 / 交易次数
夏普比率 / 信息比率
逐笔交易明细（含触发的子信号 ID，用于归因）
按 Regime 分组的绩效（趋势市 vs 震荡市，验证权重切换是否真的有用）
```

最后一项尤其重要：整套设计的核心假设是「按市场状态切换策略权重能提升表现」。如果分组绩效显示切换后并不优于固定权重，这个假设就该被推翻，而不是保留一套复杂而无效的机制。

### 2.3 第三层：影子运行（Paper Trading）

回测好看不代表实盘可用。M3 起软件内置**影子模式**：

- 每条信号自动记录「若按此信号操作」的模拟持仓
- 面板展示模拟组合的累计收益、胜率、最大回撤
- 与同期沪深300 对比
- 运行满 3 个月前，UI 上对策略绩效**不做任何正面宣称**

影子运行的数据是本地的、真实前向的，比任何历史回测都可信。

## 3. 参数标定流程

```
① 划分数据：训练集 2018-01 ~ 2023-12，验证集 2024-01 ~ 2025-06，测试集 2025-07 ~ 至今
② 在训练集上搜索参数（下节）
③ 在验证集上筛掉过拟合候选（训练集表现好、验证集崩掉的直接淘汰）
④ 测试集只跑一次，作为最终报告，不允许据此回头调参
⑤ 入选参数写入 src/core/params.ts，engine_version +1，并在 CHANGELOG 记录标定依据
```

**搜索方法**：

- **首版：粗网格 + 人工检查。** 关键参数不多（MACD 三参、ADX 阈值、组合得分/票数阈值、止损比例），粗网格完全够用，且结果可读。
- **P2：贝叶斯优化**（来源文档提及，用高斯过程 + EI）。只有在参数维度真的上去、且已建立可信的验证集流程后才引入——否则更高效的搜索只会更快地过拟合。

**过拟合红线**：
- 参数敏感性检查：最优参数邻域（±20%）的绩效若断崖下跌，说明是噪音峰值，不采用
- 分年度稳定性：若某年绩效为负且幅度大，标注为「该策略在某类行情下失效」，写进文档而非藏起来
- 交易次数下限：全样本交易 < 30 笔的参数组，统计上无意义，直接淘汰

## 4. 数据质量校验

回测结论的可信度上限由数据质量决定。入库前置检查：

| 检查 | 处理 |
|---|---|
| 日期缺口（相邻两根跨越交易日 > 1） | 标记 `has_gap`，回测时该段跳过 |
| 价格逻辑错误（`high < low`、`close` 越界） | 丢弃该根并告警 |
| 零成交量非停牌 | 标记可疑 |
| 相邻收盘价跳变 > 20%（非除权、非涨跌停板放开） | 标记可疑，人工确认 |
| 复权因子突变 | 触发该标的日线全量重拉 |
| 多源比对偏差 > 1% | 记录到 `provider_health` |

## 5. 测试组织

```
tests/
├─ unit/
│  ├─ indicators/          每个指标：黄金用例 + 边界 + 属性测试
│  ├─ regime/              状态分类与迟滞
│  ├─ strategies/          场景 fixture → 断言 SubSignal ID 集合
│  ├─ combine/             权重与投票的组合逻辑
│  └─ risk/                风控规则表驱动测试
├─ integration/
│  ├─ providers/           用录制的 HTTP 响应 fixture 回放，验证解析与降级
│  ├─ storage/             迁移、裁剪、并发读写
│  └─ engine/              端到端：fixture 日线 → 信号，快照断言
├─ e2e/                    Playwright + Electron：窗口创建、点击穿透、气泡淡出
└─ fixtures/
   ├─ klines/              各类形态样本（金叉放量、假突破、震荡、连续跌停）
   ├─ providers/           各数据源原始响应快照
   └─ golden/              指标期望值
```

**CI 门槛**：`src/core` 行覆盖率 ≥ 90%（这是全部策略逻辑所在），其他目录 ≥ 60%。

## 6. 验收：软件本身的正确性

除了策略绩效，还需验证软件行为。手工验收清单（每次发版执行）：

- [ ] [06 §1](./06-桌宠交互与非干扰设计.md) 的 C1–C10 十条零干扰契约逐条通过
- [ ] 断网 5 分钟：桌宠进入 OFFLINE，无弹窗报错，恢复网络后自动重连
- [ ] 主数据源返回畸形 JSON：自动切备源，面板可见降级记录
- [ ] 系统时间跨越 15:00：确认轮正确触发，PROVISIONAL 信号被升级或作废
- [ ] 休眠 8 小时后唤醒：定时器恢复，补一次全量刷新，无重复提醒轰炸
- [ ] 自选股 100 只满载：单 tick 耗时 < 1s，内存不超预算
- [ ] 删除 `market.db` 后启动：自动重建，不崩溃
- [ ] 数据库为上一版本 schema：迁移成功，备份文件生成
