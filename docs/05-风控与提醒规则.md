# 05 · 风控与提醒规则

## 1. 风控层的定位

本软件**不下单**，所以风控层的产物不是「拒绝成交」，而是三件事：

1. **抑制**无执行意义的信号（涨跌停、停牌、T+1 限制）
2. **改写**信号（把弱买入降级为观察，把持仓风险升级为强制卖出提醒）
3. **附加**仓位建议文本（不做资金计算，只给比例建议）

## 2. 风控规则

### 2.1 硬抑制（信号直接丢弃，仅落库不提醒）

| 规则 | 条件 | 理由 |
|---|---|---|
| 停牌 | 快照标记停牌或成交量为 0 | 无法交易 |
| 涨停 | `close ≥ limitUp - 0.001` 且方向为 BUY | 买不到 |
| 跌停 | `close ≤ limitDown + 0.001` 且方向为 SELL | 卖不掉 |
| 数据陈旧 | 快照时间戳距今 > 5 分钟且处于连续竞价时段 | 结论不可信 |
| 数据不足 | 日线 < 40 根 | 见 [04 §1.10](./04-指标与信号引擎.md) |
| 新股次新 | 上市 < 60 个交易日 | 无稳定形态，指标失真 |

### 2.2 降级

| 规则 | 条件 | 动作 |
|---|---|---|
| T+1 尾盘 | BUY 信号且当前时间 ≥ 14:50 | 改为 `NEXT_DAY_WATCH`，文案「明日开盘观察」，提醒降至 L1 |
| ST / *ST / 退市整理 | 名称含 ST | BUY 信号一律降为 L1 并加风险标注 |
| 行业集中度 | 该标的所属行业在持仓中占比 > 20% | BUY 降一级并提示「行业集中度已达 X%」 |
| 极度扩张 | `BBW_PCT > 90` 且方向为 BUY | 降一级，文案「波动率处于历史高位，追高风险大」 |

### 2.3 持仓风控（仅对 `position` 表中有记录的标的生效）

这一类**不经过组合层得分**，是独立的强制通道——止损不需要投票。

| 规则 | 条件 | 动作 | 提醒级别 |
|---|---|---|---|
| 固定止损 | `(price - cost)/cost ≤ -8%` | `SELL` 强制 | **L3** |
| 回撤减仓 | `(price - peak)/peak ≤ -7%` 且当前仍盈利或微亏 | `REDUCE`，建议减仓 50% | **L3** |
| 盈利保护 | 曾达 `+5%` 后回落至 `+2%` 以下 | `REDUCE`，建议保护利润 | L2 |
| 移动止损 | 盈利 ≥ 5% 后，从 `peak` 回撤 ≥ 3% | `SELL` | **L3** |

`peak_price` 由每个交易日收盘时更新（`max(peak, high)`），存于 `position` 表。

> ⚠ 这些百分比直接采自来源文档，未经验证。8% 止损对高波动科技股可能过紧、对低波动蓝筹可能过松。**P1 迭代**：按标的自身 ATR 自适应（如止损 = `max(8%, 2×ATR14/close)`），并在设置中可切换固定/自适应。

### 2.4 组合级提示（不阻断，仅信息）

面板顶部常驻展示，不主动弹窗：
- 持仓行业分布与最大集中度
- 高波动 / 低波动标的比例（按 `ATR14/close` 的 250 日分位，> 70 分位算高波动）
- 当日已触发信号数（异常多说明市场剧烈波动或参数过敏感）

## 3. 提醒分级

「不干扰日常工作」是 P0 目标，所以提醒的**默认档位必须偏保守**：多数信号只改变悬浮条上的状态点，不弹任何东西。

> **2026-08-13 起渠道只剩两个**：状态点与气泡。托盘角标、托盘图标闪烁、系统通知
> （连同「可发声」这件事本身）全部移除 —— 提醒的可见出口唯有气泡。
> **级别没有合并**：L2 与 L3 表现相同，但冷却窗口（2h vs 当日一次）与每日上限不同，
> 那才是三级制真正在管的事。下表「是否可发声」一列因此整列作废。

| 级别 | 表现 | 触发条件 | 同键冷却 |
|---|---|---|---|
| **L1 静默** | 状态点变化 + 未读计数 +1 + 面板列表新增 | 得分达阈值但 < 0.75 的普通信号；`PROVISIONAL` 弱信号；信号失效通知 | 30 分钟 |
| **L2 气泡** | 状态点 + Bubble 窗口淡入，6s 后自动淡出，`showInactive` 不抢焦点 | 得分 ≥ 0.75 的信号；盈利保护类提醒 | 2 小时 |
| **L3 气泡（强）** | 同 L2 | `CONFIRMED` 且得分 ≥ 0.75；**全部持仓强制止损/移动止损/回撤减仓** | 当日一次 |

用户可在设置中整体上调/下调一档 —— 但**不作用于持仓强制类**：把止损从 L3 调成 L2
意味着跌停那天不响，而这类「少发」的错误用户自己发现不了（`alerts/candidates.ts`）。

### 3.1 提醒有三类来源，都过同一套闸门

`buildAlerts()` 产出的候选来自三处，**没有第四条路**：

| 来源 | 方向 | 级别 | 说明 |
|---|---|---|---|
| 策略信号 | 引擎判的方向 | 风控层定 | 主线 |
| 收盘失效提示 | **`NONE`** | L1 | 盘中那条没被收盘确认（docs/04 §6） |
| **观察点命中**（P2 续） | **`NONE`** | L2 | 用户确认过的盯盘条件成立了 |

后两类的方向都刻意用 `NONE`：同键冷却的键是 `code:direction`，沿用原方向会让上午那条
买入提醒的 2 小时冷却把它们一起吃掉。

**观察点是什么**：AI 解读的第四段（「如果判断错了，会先看到什么」）给出一个带具体数值的
失效条件 → 用户在表单里确认（可改）→ 引擎每轮机械比较 → 命中后走这四道闸门。
触发时刻**不涉及模型**，判定是一次纯比较。

**它不是策略参数。** 与 `src/core/params.ts` 的区别是硬的：后者是引擎的、全局的、
依据必须是本地回测标定（ADR-0003）；观察点是用户的、单标的、一次性、会过期，
依据是「用户确认」。两者混在一起会污染设置页那张标定状态表。
表结构与边界见 `storage/migrations/003_watch.sql` 的头注释。

命中提醒**不是**强制类：它照过防抖、冷却、频率上限与免打扰。
理由是「少发一条用户自己设的观察点」与「少发一条止损」不是同一量级的错误 ——
前者用户看得见（观察点页里那条还在「正在跟踪」），后者看不见。

到期未命中记为**已过期**，只落库与显示、**不发气泡**：
「你当时那个判断没兑现」是个结论，但一天几十条这种通知是骚扰。

## 4. 去重、冷却、防抖

四道闸门依次通过，任一不过则记录 `alert_log.suppressed_reason` 后丢弃。**被抑制的信号仍然入库**，用户在面板里能看到「今日被静默的 5 条信号」，不制造信息黑洞。

### 4.1 防抖：连续确认

盘中信号必须**连续 N 个 tick 成立**才允许提醒（默认 `N=2`，即 ~60s）。指标在阈值附近抖动时会反复触发又消失，单 tick 触发是骚扰的最大来源。

```
signalKey = `${code}:${direction}:${topSubSignalId}`
连续计数存内存 Map；不成立即清零
```

### 4.2 去重：同键冷却

同一 `${code}:${direction}` 在冷却期内不重复提醒：

| 级别 | 冷却期 |
|---|---|
| L1 | 30 分钟 |
| L2 | 2 小时 |
| L3 | 当日一次 |

例外：**持仓强制止损类不受冷却限制**，但改为「每次跌幅每扩大 2% 提醒一次」，避免既骚扰又漏报。

### 4.3 频率上限

- 单标的每日提醒（L2+L3）≤ 4 条
- 全局每小时 L2+L3 ≤ 6 条，超出的按得分排序保留最高的，其余降为 L1
- 全局每日 L3 ≤ 10 条

超限时未读计数仍累加、面板列表仍新增，用户主动查看不受任何限制。

### 4.4 免打扰探测

以下任一成立 → 所有 L2/L3 降级为 L1（不弹气泡，只改状态点并计入未读）：

| 条件 | 检测方式 |
|---|---|
| 用户设定的静默时段 | 设置中的时间段 |
| 全屏应用 / 演示模式 | Windows `SHQueryUserNotificationState`（值为 `BUSY`/`PRESENTATION_MODE`/`RUNNING_D3D_FULL_SCREEN` 时静默）；取不到则回退为「前台窗口尺寸 == 屏幕尺寸」 |
| 系统专注助手开启 | 同上 API 返回 `QUIET_TIME` |
| 手动免打扰 | 托盘 / 悬浮条右键菜单切换，可设 30min / 2h / 直到收盘 |
| 屏幕锁定 / 会话断开 | `powerMonitor` 的 `lock-screen` 事件 |

免打扰期间悬浮条也进入**低调态**：跑马灯停滚，状态点只在有信号时做一次极轻微的变化（不进 WATCHING）。

> **实现（2026-08-13）**：`SHQueryUserNotificationState` 在 Electron 里没有对应 API，
> 表里写的回退方案（比较前台窗口尺寸）同样需要原生调用。实现走 **PowerShell 子进程**
> （`-EncodedCommand` 传一段 P/Invoke），不引入原生 FFI 依赖 ——
> 判据是「这条探测失败的后果只是照常提醒，不是功能不可用」，不值得为它再养一个
> 需要跟 Electron ABI 对齐的原生模块。代价是每次探测起一个进程，所以：
> **分发路径只读缓存**（TTL 15s，一轮 tick 30s，最多陈旧一轮）、单飞、
> 连续 3 次失败即永久停用并留一条 warn。
> 停用后状态为 `UNKNOWN`，**判为可以提醒** —— 与本节的错误不对称一致。
> 代码见 `src/main/alerts/notification-state.ts`，聚合判定见 `src/main/alerts/dnd.ts`。
>
> 五个来源里，**手动免打扰排在优先级第一**：它只影响「显示哪条原因」，不影响结论，
> 但用户自己按下去的开关不该被「检测到全屏」这种解释盖过。
> 同理菜单里的「解除免打扰」只管得着**手动**那一项 ——
> 用聚合值判会让静默时段里的点击变成「解除一个我没开过的开关」，点了没反应。
> （悬浮条形态下双击是「开面板」，C8 的一键静默因此只在右键菜单里，见 docs/06 §4。）

## 5. 提醒文案规范

结构固定为四段，便于扫读：

```
[方向徽章] 名称 代码            置信 78%
金叉突破 · 趋势市
MA5上穿MA20 / MACD零轴上金叉 / 放量1.4倍
14:32  现价 12.34 (+2.1%)
```

规范：
- **不使用**「必涨」「牛股」「抄底」「稳赚」等词
- **不使用**「胜率」描述置信度（见 [04 §4.3](./04-指标与信号引擎.md)）
- 依据行最多列 3 条最高权重的子信号，完整依据在面板展开
- 卖出/止损类用暖橙色而非红色（A 股红涨绿跌，红色作警示会与涨跌色冲突）
- 每条提醒底部固定小字：**仅供参考，非投资建议**

## 6. 提醒可审计

面板提供「提醒日志」视图，列出每条信号及其归宿：

| 时间 | 标的 | 方向 | 得分 | 结果 |
|---|---|---|---|---|
| 10:32 | 600xxx | BUY | 0.78 | 已提醒 L2 |
| 10:45 | 000xxx | BUY | 0.64 | 静默（冷却期内） |
| 11:02 | 300xxx | SELL | 0.81 | 静默（检测到全屏演示） |
| 15:00 | 600xxx | BUY | — | 收盘失效（INVALIDATED） |

用户能回答「它是不是漏提醒了」，也能据此调整灵敏度。这是建立信任的关键界面。

> **两张表两件事，别合并**（2026-08-13 实现时定的）：
> `signal` 表回答「引擎判了什么」，面板的**今日信号**读它；
> `alert_log` 表回答「它有没有真的提醒我，没提醒是被哪道闸门挡的」，**提醒日志**读它。
>
> 于是 §2.1 的**硬抑制**（停牌、涨跌停、数据不足、次新股）**不进 alert_log** ——
> 那一类的原话是「信号直接丢弃，仅落库不提醒」，它已经带着原因躺在 `signal` 表里，
> 在今日信号里显示为「已静默：停牌」。再往 alert_log 写一遍，提醒日志就变成了信号日志，
> 两张表说同一件事，而「有没有漏提醒」这个问题反而被稀释了。
>
> 一条实现约束：`alert_log.signal_id` 是指向 `signal(id)` 的外键（`PRAGMA foreign_keys = ON`），
> 所以**落不了库的提醒不发**（`src/main/alerts/candidates.ts`）——
> 发出去却没有审计记录，等于在这个界面上凭空消失一条。
