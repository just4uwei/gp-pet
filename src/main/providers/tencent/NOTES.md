# tencent · 接口笔记

**最后核对：2026-08-11**（真实响应已录制到 `tests/fixtures/providers/tencent/`）

角色：备源。承担**快照 + 日线（含复权）+ 当日分时**，并可反推交易日历。

## 端点

| 用途 | 请求 |
|---|---|
| 批量快照 | `GET https://qt.gtimg.cn/q=sh600000,sz000001,...` |
| 日线 | `GET https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600000,day,2024-01-02,2024-02-05,60,qfq` |
| 当日分时 | `GET https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600000` |

- 编码 **GBK**。按 UTF-8 读会把股票名读成乱码，且不抛任何错。
  **但 `web.ifzq.gtimg.cn` 那两个端点是 UTF-8 JSON**，别顺手给它们加 `encoding: 'gbk'`：
  把 UTF-8 字节按 GBK 解，某个汉字会吞掉紧随其后的 ASCII 字节（GBK 尾字节范围含 `}` 与 `\`），
  JSON 结构直接被啃坏；反过来（GBK 当 UTF-8 读）只会出几个替换字符。
  **这两个方向的错误后果不对称**，拿不准时选 UTF-8。
- 不需要 Referer。
- 快照分片 ≤ 50 只/请求（docs/03 §2.4）。
- 日线 `param` = `代码,周期,起始日,结束日,根数,复权`；复权段取 `qfq` / `hfq` / 空串（不复权）。

## 快照字段（`v_sh600000="…"`，`~` 分隔，共 88 段）

| 下标 | 含义 | 备注 |
|---|---|---|
| 1 | 名称 | GBK |
| 2 | 六位代码 | |
| 3 | 最新价 | 停牌时等于昨收 |
| 4 | 昨收 | |
| 5 | 今开 | 未开盘 / 停牌为 `0.00` |
| 6 | 成交量 | **手**，需 ×100 转股 |
| 30 | 时间戳 | `YYYYMMDDHHmmss`，北京时间 |
| 33 / 34 | 今日最高 / 最低 | 41 / 42 是同一组值，用 33/34 |
| 35 | `价/量/额` 三合一串 | 冗余，不用 |
| 37 | 成交额 | **万元**，整数，精度不足 |
| 47 / 48 | 涨停价 / 跌停价 | **不可信**，见下 |
| 57 | 成交额 | **万元**，4 位小数，与新浪的元值完全一致，用这个 |
| 60 / 61 | 品种标签 | `   A` / `GP-A`、`GP-A-CYB`、`ETF`、`GP`（北交所） |
| 83 | 疑似状态位 | 正常股为 `0`，停牌的 bj430047 为 `5`。含义未确认，**代码未依赖它** |

字段数少于 58 直接报 `ProviderDataError` —— 宁可失败也不要解析出半截数据。

## 已知怪癖

1. **北交所不给涨跌停价**：fixture 里 `bj430047` 的 47/48 字段是 `-1`。指数则为 `0`。
   因此涨跌停一律**本地按板块比例算**（`src/core/code.ts priceLimits`），源值只在本地算不出时兜底。
   已用 fixture 交叉验证：`9.29 → 10.22/8.36`（主板）、`393.87 → 472.64/315.10`（创业板）、
   `4.759 → 5.235/4.283`（ETF，3 位小数档位）。
2. **停牌股整行是 0**：`bj430047` 的开盘/最高/最低/成交量全为 `0.00`，时间戳停在 `09:00:00`，
   但最新价与昨收仍为 `8.17`。判定见 `shared.ts inferSuspended`。
3. **日线的列序是「开、收、高、低」**，不是开高低收。写错不会报错，只会让影线上下颠倒。
4. **日线不给成交额**，只有量。`Candle.amount` 因此是 `number | null`。
5. **`count` 给小了会静默截断**：接口返回的是最近 count 根，而不是区间内的全部。
   `shared.ts estimateBarCount` 按区间工作日数 +20 富余估算。
6. **复权与不复权是两次请求**：响应里 `day` / `qfqday` / `hfqday` 三个键二选一，不会同时出现。
7. **前复权是「减价差」，不是「乘比例」**（实测，见 `tests/integration/providers/tencent.test.ts`）。
   2024-01 至 02 浦发无除权，`close − closeAdj` 恒为 `1.151`，而 `closeAdj / close`
   从 0.8229 漂到 0.8330。
   后果：`kline_daily.adj_factor`（存的是 `closeAdj / close`）是个**每根都不同的派生值**，
   只能用于「同一根 K 线的复权口径是否变了」这类漂移检测（`src/core/quality.ts
   detectAdjustmentDrift`），**不能**当复权系数去反推原价。
   指标不受影响 —— 它只吃 `*Adj` 一条序列（docs/03 §2.3）。
7. 基础信息只有名称与板块，**没有行业与上市日**。`capabilities.profile` 仍为 true
   （`SecProfile.industry` 是可选字段），但用它当主源会让行业集中度风控静默失效。

## 当日分时（minute/query）

**最后核对：2026-08-14**（真实响应人工核对过形状与每一列的含义；
`minute-sh600000.json` 是按核对结果**手写**的骨架，不是 `fixtures:record` 录的 ——
下次录制时要比对这个文件）。

```json
{ "code": 0, "msg": "", "data": { "sh600000": {
    "data": { "date": "20260814", "data": ["0931 9.11 18364 16769279.00", …] },
    "qt": { "sh600000": ["1", "浦发银行", "600000", "9.13", "9.18", "9.14", …] },
    "mx_price": []
} } }
```

- 每行空格分隔，四列：`HHmm  最新价  当日累计量(手)  当日累计额(元)`。
- **⚠ 第 4 列不是均价，是当日累计成交额。** 均价要自己除：`额 / (量 × 100)`。
  已与主源 trends2 同一分钟的 `f58` 交叉核对：
  `16769279 / (18364 × 100) = 9.132`，主源给的就是 `9.132`。
  直接把那一列当均价用会得到一个七位数，而它会被算进分时图的纵轴范围 ——
  **症状是整条分时线被压成贴着框底的一条直线**，图上看不出是哪一列读错了。
- **⚠ 第 3 列是累计量，不是这一分钟的量**（主源 trends2 的 `f56` 才是分钟量）。
  实测 09:30 = 5105、09:31 = 18364 = 5105 + 13259，而主源 09:31 给的正是 13259。
- **昨收在 `qt[4]`。响应里没有 `prec` 这个键**（网上示例里有，代码留了兼容路径，
  但真正在跑的是 `qt` 那条）。**别把 `qt` 当可有可无的东西删掉** ——
  删了就没有昨收，分时图的基准线与右轴涨跌幅一起消失。
- **`data.date` 是唯一的日期来源，拿不到就整段作废。** 用本机日期顶替会把
  休市日返回的「上一个交易日」标成今天（与主源 trends2 同一个坑）。
- 午休那段本来就没有点，解析器**不补**，由渲染层断线。

## 交易日历

不调用任何日历端点，而是拉 `SH000001` 的年度日线，有数据的那天即开市
（`shared.ts calendarFromIndexBars`）。只覆盖到指数数据的最后一天，之后是「未知」而非「休市」——
否则开盘前的今天会被写成休市。
